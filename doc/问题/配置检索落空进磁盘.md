# 配置检索落空进磁盘

现象：查 4090/SSH 等连接配置时，感觉「缓存里应有文件」却 `lore_search` 空，随后掉进磁盘 `.env`/子树 grep。证据任务 `3171117c0deb4fd1b3a1de9986099333`。逐条对齐；结论与改进改原条。机制长文：[分析/配置检索索引污染与空lore.md](../分析/配置检索索引污染与空lore.md)。

| # | 问题 | 状态 | 结论 | 改进方案 |

| 1 | 为什么 `lore_search scopes=['lore']` 搜 4090 配置是 0，却以为「缓存坏了」？ | 已确认 | **笔记 lore FTS 当前 0 条**；配置真源在工作区 md（已进正文 FTS），不在 lore 笔记域。提示把 lore 标成账号/落点首刀，空库仍 `ok`+0 hits，无「库空请改 work_content」强提示，易假归因成整库无配置。 | **未改**。P0：空 lore 回 `hint`；P1：配置落点提示改为先 `work_name`/`work_content`。 |
