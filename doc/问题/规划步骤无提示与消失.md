# 规划步骤无提示与消失

| # | 问题 | 状态 | 结论 | 改进方案 |
|:---|:---|:---|:---|:---|
| 1 | 「规划中」在干什么？为何长时间无提示，随后这步很快像消失了？希望每个步骤都展示，耗时长的有提示，不要让某些步骤消失。 | 待确认 | **表层**：任务簇里出现蓝徽章「规划中」+ 任务名/步标签，无结论行；转很久后徽章变成「已规划/思考完成」或簇折叠，感觉那一行没了。**机制**：Worker 在 `brain.plan()` 前发 `phase=plan`（文案「大脑规划中（等待模型）…」），流式用 `LlmLiveProgress`；完成后同 `step` 再发 `phase=planned`。PWA 把 `plan`/`planned` 合成同一 merge key `plan:{step}`，进行中 intentionally 不把服务端占位句画成正文，只等 `thinking_text`/`content_text` 或收口。**更深**：`rules-progress-local-vs-api` 要求远端 API 阻塞超约 2s 须心跳；`phase=act`/OCR/复盘已接 `ApiWaitProgress`，**规划等待未接**，首包前可长时间空转。消失感来自同卡原地翻态 + 下一步簇自动折叠，不是 DOM 删卡。 | **必要（按优先级）**：P0 规划阻塞接 `ApiWaitProgress`（或等价），结论行刷「已等待 Ns / 等待模型…」；P1 进行中 `plan` 也展示占位/等待文案，不空壳；P2 `planned` 收口须保留可回看的等待耗时与思考/输出区，禁止只剩短徽章。**可选**：把 `plan` 与 `planned` 拆成两张持久卡（砍掉后仍须满足 P0–P2）。未改。 |
| 2 | 「编排中 / 任务仍在编排（判定/出图）」是否也看不到信息？有时取消后再「继续任务」仍停在这句。 | 待确认 | **表层**：只有蓝徽章「编排中」+ 一句「请稍候…」+ 转圈，无判定/出图子进度、无思考、无已等待秒数。**机制**：新建后后台跑 `_finish_create_orchestrate`（先 `orchestrate` 判定，再可选 `plan_build` 出图）；`meta.awaiting_plan` 未清时，用户再发话（含「继续任务」）只发**闸门提示** progress 后直接 return，**不**附带当前子阶段、不挂 `LlmLiveProgress`/`ApiWaitProgress`。PWA 对 `orchestrate` 文案以 `…` 结尾判为进行中，**清空结论行**，只留标题，所以更空。真正的判定/出图流在另一路；闸门卡与真进度都 merge 到 `other:orchestrate:_`，后到覆盖先到。**更深**：与条 1 同属「远端等待可见」缺口；出图卡缺思考见 `任务图出图.md`。 | **必要**：P0 闸门/进行中须标明子阶段（判定中 vs 出图中）+ 已等待心跳；P1 进行中勿清空可读正文（标题/结论至少留占位句）；P2 真编排流持续刷同一可见卡（思考/输出或心跳），禁止只留「请稍候」。条 3 修取消与闸门冲突。未改。 |
| 3 | 侧栏已是「已取消」，时间线仍出现「仍在编排」转圈——状态矛盾，是否 bug？多次「继续任务」也不启动，编排步一直转。 | 已确认 | **表层**：侧栏/取消卡是 cancelled；多次输入「继续任务」无追问卡、无 Worker；编排步反复/一直「请稍候…」转圈，时间线顺序也乱（编排 20:09 插在已收到与已取消之间）。**机制**：① `cancel` 只改 status，**不清** `awaiting_plan`；② 后台 `_finish_create_orchestrate` 遇终态 `_still_awaiting→False` 直接 return，**同样不清闸** → 闸门键永久卡住；③ `_dispatch_goal` **先**拦 `is_awaiting_plan`，永远到不了 `route_followup` / `_continue_task`（本可 `reopen` cancelled 再拉 Worker）；④ 「继续任务」不是控制口令（正则只认裸「继续」），一律当普通追问 → 只刷闸门 progress；⑤ PWA `orchestrate`/`plan_build` 强制 `preambleJoin` 并进前段，后到的闸门卡插回取消卡前面，顺序更乱。**更深**：取消把「编排会话」打成终态，却留下「仍在编排」忙标记；续跑入口被忙标记吃掉，形成死循环：cancelled + awaiting_plan + 假进行中。 | **已改（P0/P1）**：`clear_awaiting_plan` / `release_awaiting_plan_if_terminal`；取消 API/控制口令清闸并推「编排已中断」收口；编排后台遇终态清闸；dispatch 遇终态+latch 先清闸再走续跑，禁止再发「仍在编排」。自检 `demo_awaiting_plan_cancel`。P2 时间线插入顺序未改。需**网关重载**后：旧卡死任务再发「继续任务」应能 reopen；新取消不应再卡闸。 |
