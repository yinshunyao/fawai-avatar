# 工具执行耗时

现象：取证步规划后跑 `fs_grep`/`fs_glob`，墙钟约数分钟，但工具卡只显示「工具结果」且耗时为数毫秒；簇头总耗时也远小于墙钟。逐条对齐；结论与改动都改原条。

| # | 问题 | 状态 | 结论 | 改进方案 |
|:---|:---|:---|:---|:---|
| 1 | 工具执行明明很长，卡上耗时为何只有几毫秒？ | 已确认 | **表层**：思考完成约 18:11（耗时 8s），工具结果约 18:15 却标「耗时 3ms」；簇头可出现 `766ms` 一类远小于墙钟的数。**机制**：`act`/`acted`/`observe_tool` 同 merge key。动作墙钟在末条 `acted.elapsed_ms=act_total_ms`；随后 `observe_tool` 完成卡把 `elapsed_ms` 写成 `format_tool_observation` 的格式化耗时（数毫秒）并覆盖。**更深**：时间线把「工具结果观察」当成整张工具卡的收口，却用观察格式化时长冒充工具执行时长。 | **已改**：`observe_tool` 完成卡 `elapsed_ms = act_total_ms + observe_format_ms`，并带 `act_elapsed_ms`；PWA 工具族合并取较大 `elapsed_ms`。 |
| 2 | 长工具执行期间为何看不到消耗时间，只有结果？ | 已确认 | **表层**：规划后长时间无新进度，结束后直接冒「工具结果」。**机制**：`phase=act` 只推一次「执行中」，阻塞在 `_execute_actions`（如大仓 `fs_grep`）无心跳；簇墙钟若相邻 progress 间隔 >180s 会按「从此恢复」清掉前段，收口后簇头耗时被截断。**更深**：进度契约对远端 API 已有 `ApiWaitProgress`，对本机长工具未复用同一「等待可见」纪律。 | **已改**：`phase=act` 用 `ApiWaitProgress`（`mark_api_wait=false`，约 2s「已等待 Ns」）；进行中簇不因长间隔清墙钟；facts 可读 `wait_elapsed_sec`。自检 `demo_act_wait_elapsed`。需网关重载后新任务验收。 |
