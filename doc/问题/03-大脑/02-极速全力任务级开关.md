# 执行配置任务级开关（含 Cursor Agent）

| # | 问题 | 状态 | 结论 | 改进方案 |
|:---|:---|:---|:---|:---|
| 1 | compose「极速」「全力」应是**任务级**设定，与「本机偏好、仅随下一条消息入站」现状不一致。 | 已确认 | **产品口径**：① **作用域=任务**：进行中拨开关立刻写该任务 `meta`（`mode_prefs` + 生效布尔），闭环下一拍可读。② **终态**：打开任务时底栏从该任务配置回填，不是全局盖上去。③ **新建继承**：无焦点任务时用**全局末次**（本机 `localStorage`）；建完后仍可改。④ **已结束再拨**：只改全局末次，**不**回写历史任务 meta。 | **已落地**：`POST /api/tasks/{id}/exec-config`；详情/列表带 `exec_config`；PWA 开任务回填、进行中拨动写 meta、离开任务恢复全局末次。 |
| 2 | 服务重启 / 刷新后打开任务，执行配置面板（含 **Cursor Agent**）像被「还原」。 | 已确认 | **根因**：底栏只读本机偏好、开任务不回填。**任务侧**：Cursor 线程 `meta.runtime=cursor_agent` 本就落库；四开关经入站/本 API 落库。**口径**：打开任务时面板跟该任务；Cursor 开/关展示跟 `runtime`；拨 Cursor 只更新全局末次与下一句路由，**不**把普通任务改写成 Cursor、也不剥掉已有 Cursor 线程。 | **已落地**：开任务 / 详情拉齐后 `syncExecConfigFromActiveTask`；列表摘要含 `exec_config`。 |
