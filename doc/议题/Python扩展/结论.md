# 结论

## 议题

在编码闭环之上，补齐 Cursor 式 **Python 会话扩展**：按任务在 `data/sessions/{task_id}/` 写临时代码，用主程序运行环境（默认 `.venv`）安装依赖，执行脚本并落盘 stdout/stderr/结果，供规划回灌。范围是后台工具，不替代改产品源码的 `fs_patch`，不做 Notebook / LSP / 交互调试。

## 已定结论

1. **规范名（已定）**：**Python 扩展**（会话说法：会话 Python、py_session、临时脚本沙箱）。
2. **会话目录（已定·1A）**：根路径 `{FAWAI_DATA_DIR}/sessions/{task_id}/`；缺则创建。相对路径只相对该根；禁止逃逸；禁止写 `.env`。
3. **执行形态（已定·2A）**：`py_run` 用主程序解释器跑脚本/模块/临时代码，捕获 returncode + stdout/stderr，落盘 `runs/{utc_ts}/`；**明确不做** pdb / 断点交互调试。
4. **解释器与装包（已定）**：优先 `sys.executable`，否则 `{work_root}/.venv/bin/python`；`py_pip` 仅 `{python} -m pip install …`。装包写入**共享**主程序环境；首期不做 uninstall / 整环境重建。
5. **工具三件套（已定）**：
   - `py_write`：`path` + `content` → 会话根内新建/覆盖
   - `py_pip`：`packages` → 主程序 venv 安装
   - `py_run`：`script` / `code` / `module` + 可选 `args` / `timeout_sec` / `result_path`
6. **闭环约束（已定）**：须有 `task_id`（Worker 已注入）；工具属后台、不受 `FAWAI_DRY_RUN`；与 `shell_verify`/`fs_*` 同档。
7. **选型边界（已定）**：临时算数/脚本/装包优先 `py_*`；改产品源码仍 `fs_patch` + `code_check`。
8. **明确不做**：Notebook 流、LSP、交互调试、向量沙箱、每任务独立 venv（本议题否决；共享主环境）。

## 依据摘要

- 编码闭环已对齐 Cursor 改码主路径，但「会话内起脚本算一算 / 验一验」仍靠裸 `shell`，解释器与落点不稳。
- 用户选定按任务隔离目录 + 跑测落盘（非 pdb）；装包进主程序 `.venv`。

## 可行性速览

口径：**全 AI 实现**；粗估、未核价。

| 想法 | 难易（对 AI） | 成本与时间（粗） | 可借用资产 |
|:---|:---|:---|:---|
| **会话根 + py_write** | **低**。难点：路径闸与 task_id 注入 | 约 **1～2** 次会话 | 可直接用：`BackgroundTools.task_id`、`WorkspaceFs` 路径闸模式 |
| **resolve 主程序 python + py_pip** | **低～中**。难点：无 venv 时失败文案；共享环境污染须写清边界 | 约 **1～2** 次会话 | 可直接用：`sys.executable`、`subprocess` + `-m pip` |
| **py_run 落盘 runs/** | **低～中**。难点：超时、截断回灌、result_path 闸 | 约 **2～3** 次会话 | 可直接用：`shell_verify`/`_exec_shell` 捕获模式、`obs_tool` 回灌 |
| **能力清单 + native tools + 规划提示** | **低**。难点：与 fs_patch 选型话术不打架 | 约 **1～2** 次会话 | 可直接用：`capabilities` / `native_tools` / `prompt_profile` |
| **冒烟 demo** | **低** | 约 **1** 次会话 | 可直接用：`demo_coding_loop` / `demo_fs_version` 模式 |
