# 结论

## 议题

macOS（及有桌面的多显示器环境）外接/多屏、以及 App 全屏占独立空间（Space）时，分身如何**按任务自主搜到目标界面**；搜哪块屏、是否切空间，由**大脑 LLM**驱动，而非代码写死轮询剧本。

## 已定结论

1. **问题定性（已定）**：现状 `obs_screen` 固定 `mss.monitors[1]`（主屏），外接屏与全屏 Space 上的窗口对模型不可见；点击虽用全局坐标，但无对应画面则无法正确规划。属 **C3 自主操控 / 观察** 缺口，不是偶发权限问题。
2. **谁决策（已定）**：跨屏/跨 Space **搜索策略由大脑规划**（选哪块屏观察、是否切空间、是否激活某 App）。**禁止**在闭环或控制层用关键词写死「先屏1再屏2再 Mission Control」类剧本；硬能力只提供**可枚举状态**与**原子动作**，闸门只裁候选，不替代选型——与 [观察选取策略](../观察选取策略/结论.md#已定结论) 同向。
3. **显示器清单（已定，系统侧硬能力）**：每次（或步首）可采到结构化 **`displays`**，注入观察 `meta` / 规划提示，供 LLM 选型，禁止让模型猜「有几块屏」：
   - 字段草案：`index`（mss 序号，`1…N`）、`id`（OS 显示器 id，若可得）、`bounds`（全局虚拟桌面 `left/top/width/height`，可含负坐标）、`is_main`、可选 `scale`。
   - `monitors[0]` 表示虚拟全桌面拼图时，须在 meta 标明 `target=virtual_all`，并给出与单屏一致的坐标原点说明。
   - **headless**：无 `displays`、候选剔除 `obs_screen`（既有闸门）。
4. **截屏目标由计划点选（已定）**：`obs_screen` 不再隐含「永远主屏」。计划在选用截屏时须带 **`screen_target`**（字段名可落在 `Plan` 或 `observe_args.obs_screen`，实现时二选一并写进功能说明）：

   | `screen_target` | 含义 |
   |:---|:---|
   | `main` | 主显示器（兼容现状默认） |
   | `index:<n>` | 指定 `displays[n]` |
   | `all` | 虚拟全桌面一张图（成本高，仅模型显式需要总览时） |
   | `frontmost` | 前台窗口所在显示器（按窗口全局 bounds 落入哪块屏） |

   - 步 0 / 未指定：默认 `main` 或 `frontmost`（放行实现时钉死其一；倾向 **`frontmost` 优先、单屏时等价 main**）。
   - 多图：允许同一步 `obs_screen` 采多块（如主屏+外接），摘要须**分屏标注**来源与 bounds；默认仍鼓励一步一块，由多步搜索覆盖，控 VLM/token。
5. **跨屏搜索闭环（已定，LLM 驱动）**语义与观察选取一致，只是证据多一维「在哪块屏」：
   1. 注入 `displays` + 任务目标。
   2. LLM 选 `observe_kinds`（含否 `obs_screen`）+ `screen_target`。
   3. 采观察 → 若未见目标，LLM 规划**换屏观察**或**空间/前台切换**后再观察——禁止控制层自动扫完全部屏再交给模型。
   4. 命中后 click/type 的坐标必须与**本张截图像素坐标系**一致（见下条）。
6. **坐标与点击（已定）**：截图 meta 必须带 `origin_x` / `origin_y`（该图左上角在虚拟桌面中的全局坐标）及 `width`/`height`。控制层 `click(x,y)`：若模型输出的是**图内像素**，执行前加 origin；若约定模型直接出全局坐标，须在提示与 meta 写死同一种约定——**禁止混用**。推荐：**模型看图出图内坐标，executor 加 origin**（与单屏习惯一致、外接负坐标不易错）。
7. **全屏与 Space（已定）**：
   - macOS 全屏 App 常在**独立 Space**；只截「当前可见 Space」可能看不到它。
   - **不**在编排器写 Mission Control 专用剧本。大脑用已有/扩展原子能力组合搜索：
     - **`hotkey`**：如 Control+←/→、Control+上（Mission Control）等——以能力说明与当前 OS 提示为准，不写死唯一组合。
     - **`app_focus`（待落地能力）**：按束名/App 名激活，系统通常会切到该 App 所在 Space/屏——作为「按任务找全屏窗」的优先手段，优于盲目滑 Space。
     - 可选只读 **`space_list` / 前台窗摘要**（AX / `CGWindowList`）：把「可见窗口标题、所在 display index、是否全屏」放进观察 meta，供选型；失败则降级为仅 displays + 截屏。
   - Linux 有桌面：多监视器走同一 `displays` + `screen_target`；Workspace/虚拟桌面若无稳定 API，本切片可「明确弱支持」，靠截屏换 `index` + 窗口激活（若有）。
8. **与观察选取 / 完成任务边界（已定）**：
   - 是否截屏、截哪块屏 → 观察 + `screen_target`（本议题）。
   - 是否 click / hotkey / app_focus → 完成任务能力清单（控制动作）。
   - 编码/文件类目标仍优先 `obs_fs`，不得因「支持多屏」就每步默截所有屏。
9. **明确不做（本切片）**：
   - 不在 loop 里自动轮询全部显示器/全部 Space 拼长视频给模型。
   - 不做纯规则「目标含 Chrome 就切第二屏」关键词路由。
   - 不在本议题承诺 OCR/AX 像素级控件定位（仍属 C3 深化）；窗口级 bounds→屏 映射可以做。
   - 不把「未放行」写成功能「已支持」。
10. **平台（已定）**：
    - **macOS 有桌面**：主路径（多屏 + 全屏 Space）。
    - **Linux headless**：不适用；保持剔除截屏。
    - **Linux 有 DISPLAY**：实现 `displays` + `screen_target`（mss）；Space/全屏弱支持须在功能说明标明。
    - **Windows**：本切片可不实现，功能/议题写「未支持」，禁止 silently 只测 Mac 却宣称全平台。

## 依据摘要

- 代码：`observe/screen.py` 写死 `monitors[1]`；`screencapture` 无 `-D`；文档无多屏条目。
- 用户定调：按任务自主在双屏搜索；mac 多屏与全屏要支持；**怎么搜由 LLM 大脑驱动**。
- 既有原则：观察方式由 LLM 选、硬闸门只裁候选（观察选取策略）；编排器禁止通道/界面专用剧本（与跨能力一致）。

## 可行性速览

口径：**全 AI 实现**；粗估、未核价；≠ 放行或开工。

| 想法 | 难易（对 AI） | 成本与时间（粗） | 可借用资产 |
|:---|:---|:---|:---|
| `displays` 枚举 + meta 注入 | 低 | 约 0.5～1 次 Agent 会话；运行期可忽略 | **可直接用** `mss.monitors`；mac 可补 Quartz/`CGGetActiveDisplayList`（需适配） |
| `screen_target` + 改 `capture_screen` | 低～中 | 约 1 次会话；坐标约定要测外接负原点 | **需适配** 现有 `screen.py` / `methods.py` / planner 提示 |
| 图内坐标 → 全局 click | 低 | 与上同批；单测用假 bounds | **需适配** `executor._exec_click` / `input_mac` |
| `app_focus`（osascript / `open -a` / AX） | 中 | 约 1～2 次会话；人机闸门：辅助功能已授权 | **可直接用** AppleScript `tell application … to activate`；Linux 用 `wmctrl`/`xdotool` 分支或硬失败 |
| 前台窗→所在屏 + 粗窗口列表进 meta | 中 | 约 1～2 次会话；全屏 Space 上「不可见窗」列表可能不完整（待核） | mac：`Quartz.CGWindowListCopyWindowInfo`（需适配）；失败则降级 |
| LLM 提示：多屏搜索策略（换 target / focus / hotkey） | 低 | 并入 planner 提示一小段；运行期多 0～N 次截屏 | 现有 `Brain.plan` + `observe_kinds` |
| 自动扫全 Space 拼图 | 高 / **明确不做** | — | — |

**人机闸门**：屏幕录制须覆盖外接屏（系统隐私里勾选）；辅助功能已有则 focus/hotkey 可用。

2. ~~字段挂载~~ → **`observe_args.obs_screen.screen_target`**。
3. ~~同一步多图~~ → 默认可一块；多块须分屏标注；鼓励多步换屏。
