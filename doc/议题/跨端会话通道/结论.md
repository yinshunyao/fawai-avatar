# 结论

## 议题

操作分身运行在 macOS 时，用户如何通过手机跨端对话，并支持多模态会话与展示；会话通道与操作层如何解耦，局域网与云端中继如何共用同一协议；多轮消息如何归到工作任务，以及「新会话」是否必要。

## 已定结论

1. **主通道**：自建 **Web/PWA**（手机浏览器打开分身会话页）。多模态展示（文本、图片、进度、任务卡片）以会话页为真源 UI。
2. **通道与操作解耦**：
   - **会话通道**只负责收发与展示载荷，不操控桌面键鼠。
   - **会话网关**跑在 Mac 本机：入站交给 **总管**（唯一接用户入口，见 [操作分身三层](../操作分身三层/结论.md#已定结论)）；出站把文本 / 观察截图 / 进度 / 卡片推回会话。
   - 工作任务闭环（观察 → 大脑 → 控制）不直连手机；禁止通道脚本替代总管编排。
3. **统一消息信封**（通道无关，LAN / 中继 / 未来其它适配共用）：
   - **入站**：`text` / `image`；`audio`、`file` 后置；控制口令（暂停、取消）进同一信封类型族；可选 **`task_id`**（焦点任务，完整 id 或唯一短前缀）。
   - **出站**：`text` / `image`（观察截图）/ `progress`（步骤进度）/ `card`（任务状态摘要）/ `error`。
4. **传输两档，同一 PWA**（只换连接端点，不换气泡协议）：

   | 模式 | 手机连哪 | Mac 怎么暴露 | 鉴权 |
   |:---|:---|:---|:---|
   | **局域网（首期）** | `http(s)://<Mac局域网IP>:<port>` + WebSocket | 本机绑定局域网地址 | 启动时一次性会话令牌（扫码或短口令） |
   | **云端中继（同协议预留）** | 中继公网 URL | Mac **出站** WebSocket/长连接挂到中继；不要求家宽入站端口 | 设备配对码 + 短时会话令牌 |

5. **云端中继职责**：只做帧转发与鉴权；不做业务编排、不替代总管、不解析为「替分身点桌面」。
6. **会话 vs 工作任务（已定）**：
   - **会话通道** = 人机气泡时间线（展示 + 入口）；历史默认同机一条时间线。
   - **工作任务** = 可并发、可 cancel/复盘的执行单元（隔离真源）。
   - 禁止用「新会话」假装多任务隔离；禁止靠 LLM 从混杂历史猜「这句话属于哪个 task」。
7. **建任务 / 追问 / 执行中追加（已定）**：
   - 入站**无** `task_id` → **新建**工作任务（goal = 本条文本/图注）。
   - 入站**有** `task_id` → **追问挂该任务**（由 PWA **当前打开的任务线程**带上；枢纽**不**用 `_active_task_id` 给普通文本做隐式归类；`_active_task_id` 仍只服务控制口令缺省）。
   - 任务 **running**：**允许追加**（软注入）。LLM（`analyze_running_append`）结合**当前状态**、**原 goal**、**近期步骤摘要**与**用户增量** → `apply`（并入 goal + `meta.pending_appends`；推 `phase=append`；**不** requeue / 不新开 Worker；当前工具跑完后下一步观察/规划前刷新 goal 并消费 pending）或 `new_task`（新建 sibling，`parent_task_id`）。**不做**打断当前工具、不做「结束后才首次分析」的静默排队。
   - 任务 **archived**：拒绝；须先取消归档或新开任务。
   - 任务**其它状态**（含 completed / failed / cancelled / pending 等）：**线程内路由**（LLM；`FAWAI_BRAIN_MOCK` 时规则兜底）→ **continue**（并入 goal；终态可 reopen 回 pending 再跑）或 **new_task**（新建，`meta.parent_task_id` 指向原线程）。**不做**终态一刀切 sibling；同目标换法/补救优先 continue。
8. **PWA 产品壳：任务线程（已定）**：
   - **宽屏布局**：左侧任务导航树（对话/归档）+ **中间对话框**；未选任务时中栏空态提示。
   - **窄屏**：仍可列表与对话切换（返回键），不强制双栏；功能导航收进顶栏右上角菜单，不展示左侧功能栏。
   - 一任务一条；点左侧进入线程；线程内发送自动带该 `task_id`；「新任务」空白 compose（创建后进入新线程）。
   - **归档**：把任务从主对话**收束为记录**（`status=archived`）；导航「对话 / 归档」分栏；可取消归档；执行中不可归档；已归档不可直接追问。
   - **不做**独立「焦点条 / 设为焦点」心智；左侧「任务管理」后台页负责打开对话 / 归档 / 取消 / 删除 / 复盘。
   - 「新任务」替代原「新会话清屏」主入口；归档**不**等于删除；**不**清服务端 `session_history.jsonl`、不做多设备多会话同步账本。
9. **放行后实现序**（通道首期已落地；本条补追问与任务线程）：
   1. 通道抽象 + 消息信封类型
   2. 局域网会话网关 + 令牌 + PWA 聊天气泡（文 + 图 + 进度）
   3. 总管接线：入站 → **建任务 / 追问**；出站推送观察图与步骤
   4. 中继适配器（同一信封），Mac 出站挂载
   5. PWA **任务对话列表 + 线程**；去掉焦点条
10. **明确不做（本议题）**：
   - 个人微信 / OCR 读聊气泡作主通道；不把多模态 UI 塞进 AutoCore 微信通道
   - 首期不做原生 App（PWA 即可）
   - 首期不做实时桌面视频流（用截图 + 进度卡；视频后置）
   - 未功能放行前不把具体中继厂商选型写进代码；议题只钉「出站长连接 + 帧转发」契约
   - 用「新会话」当第二套任务账本；靠 LLM 猜任务归属；首期多会话同步账本；焦点条作为主交互
   - 本仓不维护 `doc/or/`；本结论是讨论真源，**不等于**功能放行（功能面以 `doc/功能/` 为准）

## 依据摘要

- 分身价值在本机观察与控制；手机只需可靠遥控与富展示，故会话层与操作层必须拆开。
- 个人微信触达好但多模态弱（图、进度卡、流式差），作主 UI 会长期卡住展示上限。
- 局域网最快验证端到端；云中继用 Mac 出站可避免家宽端口与 NAT，且与 LAN 共用信封则不必二次拆通道。
- 总管已是「面对用户的唯一编排入口」；会话网关应挂总管，而不是另起一套对话编排脑。
- 议题实现序早已写「建任务 / 追问」，但首期只落地建任务；多轮若不显式绑 `task_id`，每条消息都会碎成新任务。
- ChatGPT 式多会话解决的是聊天上下文隔离；本产品隔离已由工作任务承担，故新会话只需清屏与重置焦点。

## 可行性速览

口径：**全 AI 实现**；粗估、未核价；不等于开工。

| 想法 | 难易（对 AI） | 成本与时间（粗） | 可借用资产 |
|:---|:---|:---|:---|
| **消息信封 + 通道接口** | **低**。难点：入站/出站类型边界与控制口令归类 | **落地**：约 **1～2 次**会话 / **约数小时墙钟**。**运行**：无额模型费 | **可直接用**：本仓 `Supervisor` 入站挂接。**仅参考**：AutoCore 通道 `poll`/`send` 形态（勿抄微信 OCR） |
| **局域网网关 HTTP+WS + 极简 PWA** | **中**。难点：令牌 UX、局域网发现、移动端上传图 | **落地**：约 **3～8 次**会话 / **约 0.5～1.5 日墙钟**。**运行**：本机带宽。**人机闸门**：本机防火墙放行端口 | **可直接用/需适配**：FastAPI 或 Starlette + WebSocket；静态 PWA |
| **多模态展示（图/进度/卡片）** | **中**。难点：大图推送与节流；进度与任务状态对齐 | **落地**：约 **2～5 次**会话。**运行**：本机存图 + WS 推送 | **可直接用**：`Observation.image_path`；LLM 多模态路由已支持 |
| **云端中继帧转发** | **中高**。难点：配对与重连；托管账号/证书 | **落地**：骨架约 **3～7 次**会话；托管开通为人机闸门。**运行**：中继流量 | **可直接用或需适配**：Cloudflare Tunnel 等托管隧道；或自建轻量转发。选型放行实现时再钉 |
| **追问挂任务（create/continue/线程内路由）** | **低～中**。难点：归档拒收；续跑 vs 另开；终态 reopen；goal 合并可读 | **落地**：约 **1～3 次**会话 / **约数小时墙钟**。**运行**：路由一次 LLM（可 mock）+ 再跑 Worker | **可直接用**：`SessionHub`、`brain/task_route`、`resolve_task_id`、`TaskRecord.meta` |
| **执行中追加（软注入 + LLM 分析）** | **低～中**。难点：步前刷新 goal；pending 消费时机；与 new_task 分流 | **落地**：约 **1～2 次**会话。**运行**：追加分析一次 LLM（可 mock） | **可直接用**：`analyze_running_append`、`meta.pending_appends`、WorkerLoop 步前 `get_task` |
| **用户图展示 + 会话附件暂存** | **低**。难点：入站 publish media_url；粘贴不即发 | **落地**：约 **1 次**会话 | **可直接用**：`/api/upload`、PWA compose、`/media/` |
| **PWA 任务线程列表** | **低～中**。难点：历史按 `task_id` 过滤；新建 compose 回填；与任务管理页分工 | **落地**：约 **1～2 次**会话 | **可直接用**：现有 PWA、`/api/tasks`、会话历史 |
