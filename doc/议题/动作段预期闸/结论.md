# 结论

## 议题

工作任务闭环是否必须在**每个成功工具步**后都进模（规划 / 观察反省）？如何用「一段动作 + 机读预期」在衔接正常时跳过 LLM，仅在偏离时召回？

## 已定结论

1. **问题定性（已定）**：现网成功路径多为 `plan → 1～2 actions → obs_reflect → plan…`；提示还鼓励每步 1～2 动作。机械探路（读配置 / ls / grep）被深度思考与观察反省双重加税。
2. **方向（已定）**：**动作段 + 预期闸**。规划一次排出有序动作；运行时用代码校验 `ok` 与可选 `expect`；全部符合则段中不 `plan`、机械成功不跑 LLM `obs_reflect`；失败或 expect 不满足 → 停段，走既有执行反省 / 重规划。
3. **两步落地（已定，用户明示实现）**：
   - **步 1**：定位/只读相位允许多只读 actions（约 4～8）；写/前台/shell 仍宜短。成功且**整批机械只读** → 规则摘要入 history，**跳过** LLM 观察反省（可环境变量强制仍走 LLM）。
   - **步 2**：`Action.expect` 机读闸（`contains` / `not_contains` / `contains_any` 等）；不满足则本动作记失败并打断段（衔接失败），进入既有失败路径。
4. **与既有层关系（已定）**：不新开「每步问要不要思考」的 LLM；不拆沙箱/租约/答复覆盖等硬闸。主脑委派仍保留。固定思考预算不再作为默认封顶（空则不传 `thinking_budget`）。本议题补「段内少进模」。
5. **明确不做（本切片）**：
   - 不做依赖槽 `$1.path` 自动填参（可后续）。
   - 不做无 expect 的超长盲跑剧本（默认仍靠 `ok` + 批上限提示）。
   - 不取消执行反省；只把观察反省从「每成功步税」收成「非机械或强制时才 LLM」。

## 依据摘要

- 任务 `ad2c74a3`：32 次主脑 `planned` 全开思考；规划墙钟约 387s；观察反省已关思考但仍占轮次。
- `doc/分析/工具与文本检索速度对照.md` C1：每步工具税过高 → 一轮多工具 + 反省按需/规则化。

## 可行性速览

口径：**全 AI 实现**；粗估、未核价。

| 想法 | 难易（对 AI） | 成本与时间（粗） | 可借用资产 |
|:---|:---|:---|:---|
| **多只读 + 机械跳过 obs_reflect** | **低**。难点：机械 kind 集合与编码写后仍要 LLM 反省的边界 | **约 1** 次会话 | `_BATCH_CONTINUE_ON_FAIL_KINDS`；`obs_reflect` 闸；planner 提示 |
| **Action.expect + 执行闸** | **低～中**。难点：expect 字段进 JSON/原生工具；失败文案可反省 | **约 1** 次会话 | `Action`/`_execute_actions`；既有 reflect 路径 |
| **段内完全无规划快跑（delegate 子闭环）** | **中**。本切片不做完整子闭环去 plan | 后续可选 | 主脑委派 |
