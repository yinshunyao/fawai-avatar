# 结论

## 议题

在已有 C4 Skill 能力与会话 PWA 之上：如何用**按需复盘**替代「每任务自动蒸馏/棘轮」，并在用户对话界面提供任务**查询 / 删除 / 总结（复盘）**，控制 LLM 与写库成本。

## 已定结论

1. **资源策略（已定）**：
   - **禁止默认**：任务 `completed`/`failed` 时自动蒸馏、自动全量棘轮。
   - **按需触发**：仅当用户在任务管理里点「总结 / 复盘」，或发出等价控制口令时，才跑蒸馏（及可选棘轮）。
2. **复盘一句话验收**：选定 ≥1 个任务 → **新建复盘任务**并出【复盘指令】→ 用户「放行」或附加建议 → **全维深析**（有 steps 默认喂轨迹）并回传分维【分析】+**【优化清单】**（`awaiting_apply`，此阶段不落盘）→ 用户勾选/改写/取消 → **同意执行前**先 ReleaseStore 整包存档 + 将改路径 `version_snapshot` → 只执行选中项（`skill`/`lesson`/`code_patch`/`rule_patch`/`prompt_patch`）→ 回传结果；**禁止**固定只写成功 Skill；禁改闸门仍有效。
2b. **全维分析（已定）**：分析须覆盖且可落到任务短码——**任务规划**、**任务执行**、**调度过程**（replan/reflect/stagnation 等）、**工具使用结果**、**结果判断**；禁止只给一句空泛摘要。
2c. **优化清单与第二道闸（已定，1C）**：清单项带编号；用户「全部 / 执行 1,3 / 不要 2 / 取消」或自由文本触发再分析；未选中不落地。
2d. **备份（已定，2A）**：执行选中写操作前：`ReleaseStore.snapshot` + 将改路径 `version_snapshot`；取消则不备份。
3. **任务管理（对话 UI，已定能力面）**：

   | 动作 | 行为 |
   |:---|:---|
   | **查询** | 列表任务（id 短码、goal 摘要、status、更新时间）；支持按状态/关键词筛选；可点开看详情 |
   | **删除** | 终态 `completed` / `failed` / `cancelled` 可直接硬删；非终态 `DELETE` → 拒绝并提示先取消。异于仅 cancel 留痕 |
   | **总结（复盘）** | 建复盘任务（单/联合）；先指令等放行；过程与结果在复盘对话框执行 |

4. **删除语义（已定，产品纠偏）**：
   - 终态（`completed` / `failed` / `cancelled`）可直接硬删；**禁止** `delete = cancel+purge` 把进行中任务一步删掉。
   - 非终态（pending / running / paused / waiting / blocked）：`DELETE` → 失败 + 文案引导先取消。
5. **复盘材料（已定：有轨迹则深析，不做用户二选一）**：
   - 【复盘指令】仍给对象一览 + 简要预览（人读）。
   - **执行分析**：任务 meta 有 `steps` 时**默认喂逐步轨迹**；另附 `replan_count` / `reflect_count` / `stagnation_count` / `reflection` 等调度字段。无 steps 时注明材料不足，仍须尽量分维作答。
   - UI/控制口令**去掉** brief|full 选项；API 忽略旧 `material` 字段。
   - Worker 结束须落盘 `meta.steps` / `meta.final_thought`。
6. **交互落点（已定）**：
   - **主入口**：会话网关 PWA 左侧「任务管理」后台页（筛选 + 表格列表；与系统日志同模式），不另做桌面 App；不做顶栏抽屉。
   - **辅入口**：控制口令 / `control` 信封，与管理页同后端。
   - REST：`GET /api/tasks`、`POST /api/tasks/{id}/cancel`、`DELETE /api/tasks/{id}`、`POST /api/tasks/{id}/review`、`POST /api/tasks/review`（均先建 waiting 复盘任务）。
7. **后端落点（放行后）**：
   - 总管/TaskStore：`delete_task`（终态可删）、`list_tasks` 筛选；Worker 结束写 `meta.steps` / `meta.final_thought`
   - 复盘服务：`propose_review_session` → 放行 → `analyze_review_tasks`（只出清单）→ 勾选 → `apply_review_plan`（备份后执行）；棘轮 stub
   - 枢纽：`start_review` / `_approve_and_run_review`（分析）/ `_apply_review_selection`（勾选执行）；cancel/delete 控制消息
8. **与自我进化关系**：本议题是 C4 的**触发与产品壳**；Skill/禁改仍以 [自我进化](../自我进化/结论.md#已定结论) 为准；每任务自动蒸馏仍为**明确不做**。
9. **明确不做**：
   - 每任务完成默认蒸馏/棘轮
   - 单次 DELETE 隐式 cancel+purge
   - 首期不做跨设备任务账本
   - 未写入 `doc/功能/` 前不开工

## 依据摘要

- 蒸馏与棘轮每步吃 LLM + 写库；全量自动成本高且脏写风险大——与短板「无质量门进化会污染选型」一致。
- PWA 已是主会话面，且 `/api/session` 已带 tasks 雏形；缺删除、筛选 UI 与复盘 API。
- 终态可直接删、进行中须先取消：避免误删运行中任务，同时不必对已结束任务多点一次「取消」。
- 用户不选素材深度：先简要省钱，模型判断不够再拉 steps。
- Worker 须把 `steps`/`final_thought` 写入任务 meta，否则模型要详情时无轨迹可补。

## 可行性速览

口径：**全 AI 实现**；粗估、未核价；不等于放行或开工。

| 想法 | 难易（对 AI） | 成本与时间（粗） | 可借用资产 |
|:---|:---|:---|:---|
| **TaskStore.delete（终态）+ list 筛选** | **低**。难点：状态机与 lease 清理 | **落地**：约 **1～3** 次会话 / **约数小时墙钟** | **可直接用**：`task/store.py`、`supervisor.py` |
| **任务结束落盘 steps/final_thought** | **低～中**。难点：meta 体积上限；截断策略 | **落地**：约 **1～3** 次会话 | **可直接用**：`WorkerLoop` 返回的 `steps`；`TaskRecord.meta` |
| **复盘按需加深 + distill** | **中**。难点：need_detail 二次分析；无可沉淀时诚实失败 | **落地**：约 **3～7** 次会话。**运行**：仅用户触发；补拉详情更贵 | **可直接用**：`skills/store.py`；落盘轨迹 |
| **棘轮（对照增强既有 Skill）** | **中高**。难点：可测指标；防回退 | **落地**：stub **1～2** 次；可信版 **5～12** 次后置 | 文件 Skill 库；评测任务后置 |
| **网关 REST + PWA 任务面板** | **中**。难点：移动端布局；与聊天同屏不抢主对话 | **落地**：约 **3～7** 次会话 / **约 0.5～1 日墙钟** | **可直接用**：`lan_gateway.py`、`index.html`、`/api/session` |
| **控制口令对齐面板** | **低** | **落地**：约 **1～2** 次会话 | `hub.py` control 解析 |
