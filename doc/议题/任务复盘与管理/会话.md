# 会话

## 2026-11-02

- **焦点**：自动蒸馏/棘轮太耗资源 → 改为用户触发的复盘；对话界面要有任务管理（查询、删除、总结）
- **要点**：
  - **明确不做**：每个任务完成时默认自动蒸馏、默认全自动棘轮
  - **复盘**：对选定任务做总结 = 可选「蒸馏写 Skill」±「棘轮」（写入有质量门；棘轮后置或弱化首期）
  - **任务管理 UI**：PWA/会话界面增加任务面板——查询（列表+筛选）、删除、对单任务/多任务发起复盘
  - 复用总管 `list_tasks`；需补**删除**（硬删记录，异于 cancel）；网关 REST + 控制信封；前端任务抽屉/页
  - 与 [自我进化](../自我进化/结论.md) 衔接：E1 写入仍走 `skill_*` 质量门；触发源从「任务完成事件」改为「复盘动作」
- **对结论**：新建议题；六节写齐；自我进化「每任务自动蒸馏」改为否决

## 2026-11-02（P0 收敛）

  - 逐步详情依赖任务结束时把 `steps` 落入 meta
- **对结论**：删除/素材两节已定；开放问题 P0 关闭；下一步等放行

- **对结论**：复盘验收口径已改；实现已跟进

- **要点**：`need_detail` 触发二次喂 steps；UI 去掉素材下拉
- **对结论**：素材节已改

## 2026-11-02（联合复盘）

## 2026-11-02（复盘任务化 + 放行）

- **焦点**：复盘也建任务；先出指令，等放行或附加建议，过程结果在对话框
- **要点**：`propose_review_session` → waiting；对话「放行」触发 `review_tasks`
- **对结论**：验收口径改为两阶段；P2 会话写入关闭

## 2026-11-02（全维分析 + 勾选后备份再改）

- **焦点**：简要分析无意义；须覆盖规划/执行/调度/工具结果/结果判断；优化动作先出清单请示
- **要点**：
  - 首轮「放行」只做深析，产出分维【分析】+【优化清单】（`awaiting_apply`），不落盘
  - 用户勾选/改写（执行 1,3 / 全部 / 不要 2 / 自由文本再分析 / 取消）；选中后先 ReleaseStore 存档 + 将改路径 `version_snapshot`，再只执行选中项
  - 动作扩展：`skill`/`lesson`/`code_patch`/`rule_patch`/`prompt_patch`；有 steps 时默认喂逐步轨迹
- **对结论**：复盘验收改为三阶段（指令→分析清单→勾选备份执行）；同步功能说明

## 2026-11-03（问询假成功与复盘采样）

- **焦点**：问询任务终稿只写过程元叙述仍 completed；复盘只见轨迹前缀，清单未跟「答非所问」
- **要点**：答复覆盖闸门（通用问询/状态）；复盘 `steps` 头尾采样+索引；分析规则/提示词强制升因并默认勾选；内置 `lesson_answer_must_cover_goal`
- **对结论**：与完成任务/分析规则同步；不绑单一业务场景
