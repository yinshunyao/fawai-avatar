# 结论

## 议题

如何落地能力四件套中的 **C4 自我进化**：用会话与任务轨迹训练可复用能力，并能规划执行任务、在闸门下自动更新**当前**代码与文档，完成产品版本管理与升版——且**不依赖** C3 GUI 接地先过关。

## 已定结论

1. **切片定位**：对应 [全能助手短板](../全能助手短板/结论.md#已定结论) 的 **C4 / M4**，本议题钉两切片：
   - **E1 知识沉淀**：轨迹复盘 → Skill/教训；规划前检索；写入有质量门（全自动棘轮后置）
   - **E2 自升级**：总管建任务 → 执行脑规划 → 用结构化工具改当前树；写前强制快照；可回退；产品升版可验收
2. **不堵 C3（已定）**：E1/E2 首期只跑**结构化 / 会话轨迹域**（工作区文件、产品代码与现行文档）。C3 窄场景可并行推进，但**不是**本议题开工前置。
3. **一句话验收**：
   - **E1**：完成或失败的任务轨迹可蒸馏为可检索条目；下一次同类目标规划能取用；脏写被质量门拦住或可回滚。
   - **E2**：给定「改进当前产品某能力 / 同步文档 / 升一版」类目标，大脑走 `fs_*` + `version_*`（调用）完成改动；禁改路径被硬拒绝；升版后存在**新建**的 `doc/版本/v{新}/评测结果.md`，旧 `v*` 正文未被动过。
4. **可改范围（已定）**：
   - 当前产品代码（`fawai_avatar/` 等，智能体黑名单除外）——含大脑/任务/fs 工具等，尽量放开
   - 现行文档：`doc/功能/`、`doc/议题/`、`doc/测试/`、`doc/AGENTS.md`、术语表、`评分量表.md`、版本总表等
   - 工作区业务文件（既有工作区闸门内）
5. **硬禁改（已定，仅本产品智能体写路径）**：

   尺子：弄坏则无法从坏进化自救。闸门只拦经 `fs_*` / WorkspaceFs 的写入；**Cursor / 人工改盘不受限**。

   | 禁改 | 含义 |
   |:---|:---|
   | `doc/版本/v*/**`（已存在） | 历史产品评测归档只读；升版只**新建**目录与评测文，并更新【总表】版本评测一览 |
   | `fawai_avatar/versioning/**` | 工作区版本管理实现；仍可**调用** `version_*` |
   | `fawai_avatar/runtime/releases.py` | 产品代码存档/选版回退实现 |
   | `fawai_avatar/runtime/keeper.py`、`code_watch.py`、`port_guard.py` | 外层保活 / 热重载 / 端口回收 |
   | `fawai_avatar/workspace/paths.py` | 禁改闸门自身，防智能体改名单自解锁 |

   另：`.env`、密钥与既有「不入快照」策略继续生效，不得因进化绕过。
6. **E2 执行契约（已定）**：
   - 复用 C2：文件类目标必须 `fs_*` / `version_*`，禁止 GUI 代替；超出清单 → `failed`
   - 写当前树前强制 `version_snapshot`；失败或验收不过可 `version_rollback`
   - 产品升版 = 改 `project.version` + **新建** `doc/版本/v{新}/评测结果.md`（遵循 `doc/版本/AGENTS.md`）；禁止改写既有 `v*` 评测正文
7. **E1 与知识线（已定方向）**：
   - 落点属 [知识经验存储](../操作分身三层/结论.md#已定结论)（L5）；载体首期倾向机读文件库（如 `data/skills/`），细节开放
   - 规划前注入可检索摘要；写入须质量门（首期：规则校验 ± 可选人审；全自动棘轮后置）
8. **与三层+两线**：
   - E1 → 知识经验线读写 + 大脑取用
   - E2 → 任务线承载；大脑规划；控制执行 `fs_*`/`version_*`；观察仅在需要回证文件态时介入
9. **实现落点（放行后，本议题不定开工）**：
   - 路径黑名单闸门（控制 / workspace 写路径）
   - Skill 读写工具进能力清单（如 `skill_search` / `skill_write`，id 待钉）
   - 复盘流水：任务完成事件 → 候选蒸馏 → 质量门 → 入库
10. **明确不做**：
    - 智能体不改上表最少核与已存在归档评测；不把 Cursor/人工编辑纳入同一禁改闸
    - 不等 C3 过关才开 E1/E2
    - **终态条件短卡蒸馏（2026-11-09 改口，已落功能）**：`completed`/`failed` 且命中「多法成功」或「已明确失败」时默认蒸一张短卡 → 价值台账 → 过门进 lore；`FAWAI_TASK_DISTILL=0` 可关。**仍否决**整段轨迹灌库、默认全自动棘轮、默认自动 `skill_write`。深度复盘仍见 [任务复盘与管理](../任务复盘与管理/结论.md#已定结论)。
    - 未写入 `doc/功能/` 前不开工编码；不得仅凭本结论自动放行

## 依据摘要

- 短板已定 C4 依赖「可记录轨迹 + 质量门」；无门则污染 C2 选型记忆。用户要求进化含**改当前代码/文档与升版**，故拆 E1/E2，避免把「自升级」误收成只写 Skill。
- 已有 `fs_*`、`version_*`、完成任务清单与总管任务线，E2 主要是闸门 + 升版文档纪律，不是再造文件层。
- 归档评测与版本管理源码一旦被自改污染，会失去回退真源与对照基线，故硬禁。
- 结构化域轨迹在 C2 已支持后即可产生，故可不堵 C3。

## 可行性速览

口径：**全 AI 实现**；粗估、未核价；不等于放行或开工。

| 想法 | 难易（对 AI） | 成本与时间（粗） | 可借用资产 |
|:---|:---|:---|:---|
| **E1 Skill/教训库 + 规划注入 + 质量门** | **中**。难点：脏写粒度；检索噪音；轨迹字段不齐 | **落地**：约 **3～8** 次会话 / **约 0.5～1.5 日墙钟**。**运行**：复盘与规划增 LLM。**人机闸门**：可选人审写入 | **可直接用**：任务线事件；大脑提示注入。**需适配**：文件 Skill 库 schema。**仅参考**：WorkBuddy Skill 形态 |
| **E2 自改代码/文档 + 快照闸门 + 路径黑名单** | **中高**。难点：黑名单漏网；大范围改动验收；禁改 `versioning` 却要用 `version_*` | **落地**：约 **5～12** 次会话 / **约 1～2 日墙钟**。**运行**：每步规划 LLM | **可直接用**：`workspace/`、`control/background.py` 的 `fs_*`/`version_*`；C2 能力清单与硬校验 |
| **产品升版闭环**（version bump + 新建评测） | **中**。难点：评测证据与量表对齐；禁止改旧 `v*` | **落地**：约 **2～5** 次会话。**人机闸门**：发版确认可后人机 | **可直接用**：`doc/版本/AGENTS.md`、评分量表、测试任务说明；`project.version` |
