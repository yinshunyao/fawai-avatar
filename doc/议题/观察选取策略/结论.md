# 结论

## 议题

工作任务闭环里，如何**选取观察方式**（环境态：脚本 / 代码 / 截屏等；以及**工具结果**的智能取证），避免每步默认截屏或整段灌入超大 stdout；选取与摘要由大模型按准确性、及时性、运行成本综合判断，并允许硬限定候选。

## 已定结论

1. **问题定性（已定）**：当前 `WorkerLoop` 在规划前固定截屏（`capture=True` 时 progress 固定「观察中（截屏）」）属于**观察选取缺失**，不是模型「偶然」选错工具。进程/端口/文件存在性等目标用截屏作主证据 → 达成率差、慢、贵（屏幕录制权限 + 可选 VLM）。
2. **观察 ≠ 仅截屏（已定）**：「观察」规范名保留；覆盖两类证据源，统一产出 LLM 可读摘要：
   - **环境观察**：截屏 / 工作区 / 脚本探活等（规划前采）。
   - **工具结果观察**：动作执行后的 stdout、读文件正文、探仓命中等——须**判定内容**再回灌，不得默认整包进上下文。

   首期方式目录（可扩展）：

   | 方式 id（草案） | 含义 | 典型适用 | 相对成本 |
   |:---|:---|:---|:---|
   | `obs_shell` | 脚本/命令查询（`ps`/`lsof`/`curl` 等只读探活） | 进程、端口、服务健康 | 低延迟、低 token |
   | `obs_fs` / `obs_code` | 工作区读文件 / 代码索引 | 仓内结构、配置、日志文本 | 低～中 |
   | `obs_screen` | 截屏（+ 可选多模态摘要） | 依赖可见 GUI / 窗口内容 | 高（权限+图+VLM） |
   | `obs_tool` | 工具结果智能取证（裁剪/定向抽/二次摘要） | 大日志、长 stdout、大文件读回 | 低～中（偶发二次 LLM） |
   | （后置）`obs_ax` 等 | 辅助功能树 / OCR | GUI 定位深化（C3） | 中～高 |

3. **三维评分（已定，综合、非单维否决）**：选取时对候选方式估（可粗分档，不必每步精确算价）：

   | 维度 | 含义 | 偏置 |
   |:---|:---|:---|
   | **准确性** | 对该子目标，该方式证据能否支撑正确下一步（任务达成率） | 权重最高；达不到则不得因「便宜」强选 |
   | **及时性** | 墙钟与回合数（含权限弹窗、等界面） | 同等准确时优先更快 |
   | **运行成本** | API/VLM token、本地算力、权限与打扰 | 准确与及时够用时压成本；截屏默认偏贵 |

4. **大模型接入（已定）**：观察方式由**执行脑（或专设观察选取步）**选型，注入方式清单 + 三维原则 + 本步信息缺口；**禁止**仅靠目标关键词正则分流到截屏/脚本。允许规则做**硬闸门**（见下），闸门只缩小候选集，不替代模型在候选内的综合选取。
5. **硬限定（已定，必要才用）**：
   - 目标语义明确依赖**可见 GUI / 屏幕内容** → 候选须含 `obs_screen`（可与其它方式并用）；不得因成本永久禁截屏。
   - 目标可被**结构化只读证据**充分回答（进程、端口、工作区文件、代码符号）→ **首轮禁止**以 `obs_screen` 为唯一/默认观察；截屏仅作结构化失败后的升级。
   - 无屏幕录制权限或 `capture=False` → 从候选剔除 `obs_screen`，模型须改选或 `failed` 说明缺权限。
6. **闭环形态（已定）**：取消「每步无条件先截屏」。语义顺序：
   1. **选取环境观察**（LLM）：本步需要哪些方式（可 0～N；可组合）。
   2. **执行环境观察**：采集并合并摘要（多源标明来源）。
   3. **规划动作**（LLM）：基于观察摘要 + 上轮工具结果摘要产出控制动作。
   4. **执行动作**（控制）。
   5. **观察工具结果**（`obs_tool`）：判定输出内容，生成可回灌摘要；再进入下一步的 1～3。
   - **「LLM 输出观察方式再规划动作」为强制语义**：不得先副作用再补证据。实现上允许**同一次**调用产出 `observe_kinds` + `actions`（省一轮），此时 `actions` 只能依赖**已采好的**环境观察与**上轮**工具结果摘要；禁止同调里先假设未观察内容。
   - progress 须反映真实方式（环境观察 / 工具结果观察分开写），禁止一律「截屏」。
7. **工具结果观察（已定）**：每次工具返回后都必须经取证再进 history / 下一轮规划。
   - **小结果**：可整段或轻裁后回灌（保留 ok/FAIL、关键路径与命令）。
   - **大结果**（数十 MB 日志、超长 stdout、大文件读回）：禁止「只截前 N 字」一刀切。须**智能取证**，策略可组合：
     | 策略 | 何时偏置 |
     |:---|:---|
     | 体量门禁 | 先报字节/行数；超阈才进压缩路径 |
     | 头尾窗 | 保留开头配置/命令回显 + 结尾错误栈 |
     | 目标定向 | 按当前子目标关键词 / 错误码 / 路径命中抽行 |
     | 结构优先 | JSON/表格式先解析再抽字段；纯日志按级别或 Traceback 块 |
     | 二次摘要 | 规则抽完仍过大时，用轻量 LLM 对**抽样块**摘要，并注明「已压缩、原文落盘路径」 |
   - 原文可落盘（工作区或任务附件），回灌只给摘要 + 指针；模型若要细读须再规划 `fs_read`/定向 grep，而不是默念全文件。
8. **与完成任务 / 控制的边界（已定）**：
   - [完成任务](../完成任务/结论.md) 管**副作用动作**选型；本议题管**只读取证**（含工具结果摘要）。
   - 只读 `shell`/`fs_read` 可作环境观察或动作；写操作只走控制。
   - 「`ui_observe` 由闭环自动调用」→「由观察选取决定是否截屏」；工具输出不自动等于已观察，须过 `obs_tool`。
9. **明确不做（本切片）**：
   - 不在本议题落地 OCR/AX 像素级回证（仍属 C3 深化）。
   - 不做纯规则评分表替代 LLM 对**观察方式**的选取（硬闸门只裁候选）。
   - 不做「把整份 几十 MB 日志无差别送进主规划模型」；也不做无指针的静默丢弃（须可追溯落盘或可再读）。
10. **二期落地（已放行并实现）**：LLM 同调输出 `observe_kinds` + `actions`；硬闸门裁候选 + 步 0 默认；`obs_tool` 规则智能压缩（头尾/定向/落盘指针）；进度分 `observe` / `observe_tool`。二次 LLM 摘要与 `obs_shell` 仍后置。
11. **截屏不是工具默认副作用（已定）**：`explore_search` / `fs_*` / `shell` **不会**顺带截屏。截屏来自闭环**每步开头**的环境观察选取。
12. **硬闸门漏判实证（已定）**：目标「web对话窗口支持直接粘贴图片么？ 不支持需要修改支持。」→ 仍默认 `obs_screen`。关键词闸门不能单独扛产品能力类目标；须靠 LLM 选观察 + 工具结果观察闭环。
13. **步 0 不默截屏 + 前台窗摘要（已定并落地）**：无 LLM `observe_kinds` 时，结构化 → `obs_fs`，其余（含 GUI / 点名 App）→ **`none`**，禁止因候选含 `obs_screen` 就盲截主屏。每步环境观察附加廉价**前台窗摘要**（App/窗口标题；可失败降级）。截屏仅当计划点选 `obs_screen`。本条不落地 `app_focus`/多屏；不修 VLM 误认 App 的判决。

## 依据摘要

- 时间线实证：服务/Cursor 是否在跑 → 先截屏再 `ps`，截屏对后台进程几乎无信息。
- 时间线实证（粘贴图任务）：多步 `explore_search` 前后仍默截屏；规划反复承认截到终端。
- 代码事实：`WorkerLoop` 每步硬闸门 `_observe`；`_format_exec_feedback` 对 stdout/content **硬截 2000 字**，无体量门禁、无头尾/定向抽、无落盘指针。
- 用户定调：LLM 先输出观察方式再规划动作；工具结果必须观察；超大输出要智能取证。
- 三维原则与评分量表「工具过程 / 成本」同向。

## 可行性速览

口径：**全 AI 实现**；粗估、未核价；不等于放行或开工。

| 想法 | 难易（对 AI） | 成本与时间（粗） | 可借用资产 |
|:---|:---|:---|:---|
| **LLM 选环境观察 → 再规划动作** | **中**。难点：同调 schema（`observe_kinds`+`actions`）与硬闸门并存；progress 分相 | **落地**：约 **3～6** 次会话 / **约 0.5～1 日**。**运行**：每步规划 token；截屏次数应降 | **可直接用**：`Brain.plan`；`choose_observe_methods` 改候选裁剪；`methods.collect_observation` |
| **工具结果观察 `obs_tool`（规则智能裁）** | **中**。难点：体量门禁阈值；日志 vs 代码 vs JSON 分流；落盘路径与 history 指针 | **落地**：约 **2～4** 次会话。**运行**：几乎无额外 API（规则路径） | **可直接用**：`_format_exec_feedback` 替换点；工作区落盘；`fs_grep` 可再读 |
| **超大输出二次 LLM 摘要** | **中**。难点：抽样块选择；摘要幻觉；何时触发 | **落地**：约 **2～3** 次会话。**运行**：偶发轻量补全 API | **可直接用**：`LlmClient`；摘要提示模板 |
| **硬闸门继续作候选裁剪** | **低**（已有）。漏判靠 LLM 选取兜底 | 维护成本低 | **已落地**：`methods.py` |
| **回归：非 GUI 不默截屏；大日志不整包进模型** | **中**。难点：造大 stdout fixture；断言 history 体积与「已压缩」标记 | **落地**：约 **2～4** 次会话 | **可直接用**：`demo_eval_priority`；单测喂假 ExecResult |
