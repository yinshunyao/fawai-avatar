# 结论

## 议题

工作任务闭环在动作失败时如何认真分析原因，并裁决重试、换方案或止损，避免原样空转重试。

## 已定结论

1. **定位（已定）**：规范名 **执行反省**。发生在单次 `WorkerLoop.run` 的动作失败路径上；**不等于**终态 [任务复盘](../任务复盘与管理/结论.md#已定结论)。
2. **流程（已定，2026-11-04 修订）**：动作失败 → 计算动作指纹 → `Brain.reflect` → 按 `decision` 分支：
   - `retry`：可微调参数再试，但**禁止**与上次完全同指纹
   - `alternate`：换工具或换命令结构；注入禁止复用上次指纹的约束后再 `plan`；若确认无进展，约束写明下一轮规划须 `status=failed`
   - ~~`abort`~~：**废除**——反省不再直接 `supervisor.fail`；任务终态只由规划 `success|failed`（或步数用尽）收口
3. **指纹守卫（已定，确定性优先于 LLM）**：同 run 内同指纹失败 ≥2 → 覆盖为 `alternate`；≥3 或 `alternate` 后仍同指纹 → 仍强制 `alternate` + 提示规划 `failed`（**不** abort）。
4. **反省输出（已定）**：JSON 含 `cause`、`decision`（`retry|alternate`）、`constraints`、`thought`；注入下一轮 plan 的 history；progress `phase=reflect`；meta 记 `reflect_count`。旧模型若输出 `abort` 由代码收成 `alternate`。
5. **Mock（已定）**：缺文件 / command not found → `alternate`；permission / lease → `alternate` + 提示规划 `failed`；其余首次 `retry`。
6. **明确不做**：不自动触发任务复盘蒸馏；不多假设并行试跑；不做 GUI 接地级根因（C3）；**本议题**不把成功路径做成「每步强制反省」。成功但整步空转 → 见 [步骤重复](../步骤重复/结论.md#已定结论)（代码先判重复，再偶发 LLM 判决）。

## 依据摘要

- 现网失败分支仅 `_format_exec_feedback` + `replan_count`，模型易原样重试。
- D5 已证明「能重规划」，但不强制「分析后换道 / 止损」。
- 任务复盘面向终态沉淀；执行中需要更短、可机读的裁决。

## 可行性速览

口径：**全 AI 实现**；粗估、未核价。

| 想法 | 难易（对 AI） | 成本与时间（粗） | 可借用资产 |
|:---|:---|:---|:---|
| **Brain.reflect + JSON 解析** | **低～中**。难点：模型仍无视约束 | 约 **1～2** 次会话 | 可直接用：`planner.py` LLM 调用与 JSON 解析 |
| **指纹守卫 + WorkerLoop 接线** | **低** | 约 **1** 次会话 | 可直接用：`runtime/loop.py` 失败分支、`replan_count` 模式 |
| **评测：alternate / 同指纹 abort** | **低** | 约 **1** 次会话 | 可直接用：`demo_eval_priority` D5 包装脑 |
