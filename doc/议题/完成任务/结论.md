# 结论

## 议题

在已有 LLM、总管与后台文件/版本工具之上，如何落地能力四件套中的 **C2 完成任务（含能力自知）**：让执行脑在规划时知道「现在能做什么 / 该选什么工具 / 做不到就拒绝」，避免默认乱点 GUI。

## 已定结论

1. **切片定位**：本议题只钉 **C2 MVP**，对应 [全能助手短板](../全能助手短板/结论.md#已定结论) 里程碑 **M2 的 C2 部分**。不解决 C3 接地回证，不解决 C4 进化。
2. **一句话验收**：给定可结构化完成的目标（优先工作区文件），大脑能从**能力清单**选型并产出可执行动作（含 `fs_*` / `version_*`）；目标超出清单时 `status=failed` 并说明边界，而不是假装点击完成。
3. **能力清单（机读，最小字段，已定）**：

   | 字段 | 含义 |
   |:---|:---|
   | `id` | 工具 id（与术语表工具行对齐，如 `fs_write`） |
   | `name` | 规范名或短名 |
   | `modality` | `background` / `foreground` |
   | `when_to_use` | 何时选用（一两句） |
   | `action_kind` | 控制层 `Action.kind`（可与 id 相同） |
   | `needs_foreground` | 默认是否要前台租约 |
   | `write_resources` | 写入时如何申报（`none` / `path_arg` / 固定模式） |
   | `available` | 当前是否可用（首期常量 true；后续可接权限探测） |

4. **首期清单覆盖（已定）**：
   - 后台：`fs_glob` / `fs_grep` / `fs_read` / `fs_write` / `fs_replace`；`version_snapshot` / `version_list` / `version_get` / `version_delete` / `version_rollback`
   - 通用：`shell`（查询优先；写文件优先走 `fs_*`）
   - 前台占位：`click` / `type` / `hotkey`（标明「仅当目标明确要求操作可见 GUI；本切片不做定位保证」）
   - 观察：`ui_observe` 由闭环调用，不要求大脑再发明「截屏工具名」
5. **选型策略（已定，写入系统提示 + 可选硬校验）**：
   - **结构化优先**：改/查工作区文件 → 必须选 `fs_*` / `version_*`，禁止用 GUI 代替。
   - **GUI 需理由**：仅当目标语义依赖屏幕上的第三方 App UI 时才产出 `click|type|hotkey`，并在 `thought` 写明原因。
   - **边界显式**：清单无匹配能力 → `status=failed`，`thought` 说明缺什么；禁止空动作假 `success`。
   - **租约不变**：`needs_foreground` / `write_resources` 仍走总管闸门；C2 不绕过。
6. **实现落点（放行后）**：
   - 新增能力注册模块（建议 `fawai_avatar/brain/capabilities.py` 或 `fawai_avatar/capability/`）
   - `Brain.plan` 注入清单摘要；扩展可解析的 `action.kind` 至后台工具
   - 可选：规划后校验「文件类目标却产出 GUI」→ 拒绝并重规划一次或直接 failed
7. **验收用例（本切片，已定）**：

   | 编号 | 目标 | 期望 |
   |:---|:---|:---|
   | A | 在工作区写入 `notes/c2_hello.txt` 内容 `hello` | 动作为 `fs_write`（或等价后台链）；非 GUI |
   | B | 读取该文件并回复内容 | `fs_read`；结论含 `hello` |
   | C | 「用鼠标在桌面画个圈完成写文件」类误导目标 | 仍走 `fs_*` 完成写文件，或 failed 说明不提供随意涂鸦；不得假点击成功 |
   | D（可选，M2 并行） | 两任务同时 `fs_write` 同一路径 | 租约写冲突：一方获批，另一方 blocked/拒绝 |

8. **明确不做（本切片）**：
   - 不实现 OCR/AX 定位、VLM 点击接地、L3 界面回证（属 C3）
   - 不实现 Skill/教训库与自动写入（属 C4 / 知识经验存储）
   - 不自动发现未登记的本地软件并安装插件
   - 不把「多模型厂商路由」绑进本切片
   - 未写入 `doc/功能/` 前不开工编码（本条已于放行后失效）

## 依据摘要

- 短板议题已定：缺 C2 则 C3 默认乱点；M2 应先窄域工具路由。
- 仓库已有 `fs_*` / `version_*` 与控制层转发，但大脑提示词动作枚举未覆盖，清单未注入——C2 是接线与策略，不是再造文件层。
- 租约与写冲突闸门已在任务线；C2 验收可复用，不必重做 L4。

## 可行性速览

口径：**全 AI 实现**；粗估、未核价；不等于放行或开工。

| 想法 | 难易（对 AI） | 成本与时间（粗） | 可借用资产 |
|:---|:---|:---|:---|
| **能力清单模块 + 与术语/工具 id 对齐** | **低**。难点：字段别漂；与控制 `kind` 同步 | **落地**：约 **1～3** 次会话 / **约数小时墙钟**。**运行**：无额模型费 | **可直接用**：术语表工具行；`BACKGROUND_KINDS`；`Action.kind` |
| **大脑注入清单 + 扩展 kind 解析** | **中**。难点：提示词约束被模型忽视；需轻量校验 | **落地**：约 **2～5** 次会话 / **约 0.5～1 日墙钟**。**运行**：每步规划 LLM | **可直接用**：`brain/planner.py`；`Controller` 已执行 `fs_*` |
| **验收 A/B（+可选 D）自动化或网关手测脚本** | **低～中**。难点：网关端到端依赖本机口令与权限 | **落地**：约 **1～3** 次会话。**人机闸门**：若走真网关需同网手机或本机浏览器 | **可直接用**：`demo_fs_version`；`SessionHub`+`WorkerLoop`；`FAWAI_DRY_RUN` 不影响 `fs_*` |

## 开放问题

| 优先级 | 问题 |
|:---|:---|
| P1 | 硬校验失败后：自动重规划一次，还是立即 `failed`？（建议首期：校验失败 → 附加约束重规划 1 次，再失败则 failed） |
| P1 | 能力清单存放：代码内常量 vs `data/capabilities.json`？（建议首期代码常量，与版本同发） |
| P2 | `shell` 写文件是否一律劝退到 `fs_*`（工作区外路径例外）？ |
| P2 | 用例 D 是否与 C2 同一次交付，还是单独冒烟？ |
