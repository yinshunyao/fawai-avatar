# 结论

## 议题

fawai-avatar 面对**大任务 / 复杂任务**时，如何判定复杂度、进入**计划模式**，把目标拆成带衔接关系的子任务图（依赖、串行、并行），并由总管按图启动与衔接各工作任务——而不是继续只在单 Worker 里逐步「下一步」。

## 已定结论

1. **现状判定（已定）**：当前**不能**稳定「认出大任务并进入计划模式」。
   - 执行脑：每轮产出下一步 `actions` / `done`（见功能「大脑」v1）。
   - 单任务内辅助：必要路径台账、主脑→快模型委派、过程相位——均不产出跨任务依赖图。
   - 任务线：总管可多工作任务并发 + `foreground_lease` / `resource_lease`（见功能「任务与事件管理」），但工作任务通常对应**彼此独立**的用户目标，**无**「一句大需求 → 任务图 → 按边调度」闭环。
   - 文档已写明：大脑 v1 为单任务执行脑；**总管侧编排脑后置**——本议题即钉该后置能力。

2. **产品一句话**：复杂目标先出**可验收的任务图**，再按依赖与资源约束调度多个解耦工作任务；简单目标仍走现有单 Worker 逐步规划，避免每条消息都付「出图」成本。

3. **职责分层（已定：三层大脑 + 租约；对齐 [操作分身三层](../操作分身三层/结论.md#已定结论)）**：

   | 角色 | 职责 |
   |:---|:---|
   | **编排脑（总脑）** | **编排向、稀疏**：进模判定、出图/改图、按规则或总脑决议启停节点；**租约冲突**仲裁；**执行中追加对话**先由总脑分析是否触及重排/租约，再下发；**不**吃步级轨迹 |
   | **监管脑（中间层）** | **任务向、自闭环**：接总脑（或规则调度）下发的节点授权后，**自行完成该子任务**；驱动执行脑逐步干；只回传**终态 + 产物契约**；不把步级状态推回总脑 |
   | **执行脑（步级）** | **步骤向**：观察→规划下一步→控制；可再委派快模型；受监管脑停条件与契约约束 |
   | **租约闸门** | 前台 GUI 全局串行；后台写清单冲突由总管/编排脑侧仲裁；监管脑与执行脑不得绕过 |

3.1. **三层协作与防过载（已定）** — 用户明示要中间监管脑；编排脑仍保持稀疏：

   - **监管脑有意为之**：每个图节点（或总脑授权的一小簇）对应一颗监管脑，挂在工作任务上；**自行把该任务干完**。此前「禁止中层监管脑」**作废**。
   - **下发路径**：编排脑决议（出图、改图、追加后重排、租约调整）→ **下发给监管脑** → 监管脑驱动执行脑。口语里「下发给执行脑」落在实现上先到监管脑，再由监管脑驱执行脑，避免总脑直驱步级。
   - **追加对话（强制总脑先行）**：任务执行中用户追加内容 → **编排脑先分析**：是否只影响当前节点话术、是否要重排未决节点、是否要改租约/资源清单。结论为「无图/租约影响」可把补充说明直接转给现监管脑；结论为「要重排或调租约」则总脑改图/调租约后再下发，**禁止**监管脑私自改兄弟节点或全局租约。
   - **成功路径不回编排 LLM**：监管脑报节点 `completed` 且 `produces` 兑现 → **规则**更新图、算就绪集、拉起下游监管脑；总管记账启停，**默认零次**编排脑调用。
   - **编排脑关注面（白名单）**：图结构；节点终态；就绪集；租约冲突；整图暂停/取消；**追加对话的图/租约影响分析**；稀有失败改图。**不关注**：执行脑步级 `step_label`、工具原文、反省细节。
   - **升编排脑（稀有）**：监管脑 `failed` 需改图绕行；产物契约未兑现；跨节点歧义；用户改计划；追加对话经路由判定需总脑分析（见上）。步级失败优先监管脑内反省/换道，不升总脑。
   - **并发与过载目标不变**：N 路监管脑（内含执行 LLM）并行；编排脑调用与**出图 + 追加重排 + 租约难例 + 失败改图**同阶，与步数×并发无关。

4. **何时进入计划模式（已定）**  
   - **判定权在编排脑**：复杂度由编排脑决策（`decide_complexity`）；非 mock 优先 LLM，失败/mock 用启发式回退。**禁止**用人审勾选「是否复杂」当进模闸门。
   - **出图后自动调度**：编排脑出图后立即按就绪集拉起监管脑，**无需**用户确认再执行（用户显式「先规划」只作进模强信号，不是暂停等人点确认）。
   - 编排脑判定参考信号（非穷尽）：多阶段交付 / 明确先后或并行 / 多种互斥资源 / 显式「先规划·计划模式」口令。
   - **通常不进**：单文件读写、单次查询答复、已定位窄改动、单一窄 GUI——编排脑应判 `enter=false`，走单 Worker。

5. **任务图最小语义（已定）**  
   图是编排脑的机读产出，节点调度后映射为工作任务：

   | 字段（节点） | 含义 |
   |:---|:---|
   | `id` | 图内稳定短 id |
   | `goal` | 该节点可独立验收的目标文案 |
   | `depends_on` | 前置节点 id 列表（空 = 可立即就绪） |
   | `parallel_group` | 可选；同组且彼此无依赖 → 允许同时 `running`（仍受租约约束） |
   | `modality_hint` | `background` / `foreground` / `mixed`（供租约与调度提示，非绕过闸门） |
   | `produces` | 衔接产物声明（路径、摘要键、停条件文案等） |
   | `consumes` | 依赖的上游产物键 |
   | `stop_when` | 节点成功机判/自然语言停条件 |

   边语义：`depends_on` = **必须串在前**；无依赖且资源无冲突 = **可并行**；有前台 hint 的节点之间即使无数据依赖也须排队拿 `foreground_lease`。

6. **调度与衔接（已定）**：
   - **就绪集**：依赖与产物齐 → **规则**拉起下游工作任务并授权其**监管脑**（见 3.1）。
   - **启动**：总管 `create`；注入上游产物 + 监管脑授权边界（goal / stop_when / produces）；监管脑再驱执行脑。
   - **衔接**：兄弟任务不互改内部轨迹；经总管侧产物契约仓传递（规则写读）。
   - **失败**：默认规则阻塞下游；需改图时升**编排脑**（监管脑不私改图）。
   - **追加**：一律先经编排脑分析再下发（见 3.1），与「成功终态不回总脑」不矛盾——追加是会话事件，不是步级汇报。
   - **委派**：快模型委派挂在**执行脑/监管脑之内**；不用委派冒充跨节点并行；节点终态不回调编排脑逐步点。

7. **与现有机制边界（已定）**：

   | 机制 | 管什么 | 不替代计划模式的部分 |
   |:---|:---|:---|
   | 必要路径台账 | 执行脑单任务内偏科闸 | 不出跨 Worker 图 |
   | 主脑委派 | 执行侧段内快模型 | 不建依赖边；≠ 监管脑；≠ 编排脑 |
   | 多工作任务 + 租约 | 并发与锁底座 | 不负责出图；租约难例可升编排脑 |
   | 执行反省 / 步骤重复 | 执行脑步级纠错 | 图级重规划属编排脑；任务是否放弃属监管脑可先判再升编 |
   | 执行中追加（会话） | 枢纽注入 | 计划模式下**先编排脑**再下发监管脑 |

8. **实现落点（放行后方向，未开工）**：
   - 编排脑：总管旁路角色；出图/改图/追加影响分析；与执行脑、监管脑配置或 prompt 角色分离。
   - 监管脑：工作任务上的「完成该节点」角色；可与现 `Brain` 主角色分化（监管提示 + 终态契约校验），内驱现有闭环作执行脑。
   - 持久化：`plan_graph` / meta 关联父计划、节点、监管脑所在 `task_id`。
   - 追加路由：计划模式任务的追问/追加 → 编排脑分析入口（再下发），与今日「追问软注入同 Worker」分流。
   - 复用：`Supervisor` / leases / `WorkerLoop` / 进度推送。

9. **明确不做（本议题）**：
   - ~~未写入功能目录前不开工~~（已于用户明示实现后放行落地 MVP）。
   - 不在单 Worker 逐步规划里塞整图 DAG 当「假计划模式」。
   - **不做**「每个子任务成功结束都回调编排脑再规划」的聊天式总控（成功衔接走规则）。
   - **不做**步级状态汇入编排脑上下文。
   - **不做**监管脑擅自改任务图或全局租约（必须经编排脑）。
   - **不做**人审「是否复杂 / 出图后是否开跑」闸门（编排脑判定 + 自动调度）。
   - 不承诺前台键鼠真并行；不承诺未报清单的后台乱写。
   - 首期不做多假设并行试跑、不做 Cursor 云子代理 / 远程沙箱 Worker 全集。
   - 不把「换更大模型」替代任务图与租约闸门。
   - 不在本议题重开 C3 接地或 C4 蒸馏设计。

## 依据摘要

- 用户诉求：复杂任务要拆子任务，并想清楚衔接、顺序、串并行与启动衔接——与三层议题「总管编排脑 + 多解耦工作任务」一致，只是编排脑尚未落地。
- 现网痛点：长目标挤在单上下文逐步点，易漏阶段、难并行后台、失败后难局部重开。
- 租约与多任务底座已在；缺的是**判定 + 出图 + 按图调度**，不是再造执行层。
- 用户补充（防过载）：子任务状态大部分总管不关心 → 成功路径规则衔接、编排脑稀疏。
- 用户定调（三层）：**要中间监管脑**，监管脑自行完成任务；编排脑主责编排与租约，以及对追加对话做重排/租约分析后下发——总脑不直管步级。
