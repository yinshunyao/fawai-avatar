# 会话

## 2026-11-04

- **焦点**：大/复杂任务能否识别；是否增加「计划模式」——拆子任务、钉衔接与串并行、再按图启动与衔接
- **要点**：
  - **现状缺口**：大脑 v1 是单任务执行脑（每轮下一步）；必要路径台账 / 主脑委派仍在同一 Worker 内；总管已有多工作任务 + 前台串行 / 后台并行租约，但任务多来自独立目标，**不会**从一句大需求自动出依赖图
  - **设计落点**：计划模式挂**总管侧编排脑**；执行仍归各工作任务执行脑；禁止在单 Worker 逐步 `plan()` 里硬塞整图
  - **必含能力**：复杂度判定（进计划模式 vs 直接逐步干）→ 显式任务图（依赖、串/并、衔接产物与停条件）→ 按就绪集调度 Worker → 完成/失败事件触发下游或整图暂停；前台 GUI 边强制串行，后台写资源仍走清单 + 租约
  - **与已有能力边界**：主脑委派 = 段内串行子目标；计划模式 = 跨 Worker 图调度；必要路径台账 = 单任务内偏科闸，不替代任务图
  - **明确不做（本轮定）**：不在议题内放行编码；不把「多假设并行试跑」塞进首期；不做 Cursor 云子代理全集；未写入功能目录前不开工
- **对结论**：新建议题；六节写齐；总表增行；术语补「计划模式」「任务图」

## 2026-11-04（三层：编排 / 监管 / 执行）

- **焦点**：用户明示要**中间监管脑**；监管脑自行完成任务；编排脑（总脑）主责编排与租约，以及追加对话触发的重排/租约调整——总脑先分析再下发
- **要点**：
  - **三层大脑**：编排脑（总脑）→ 监管脑（中间）→ 执行脑（步级）；监管脑接授权子任务后**自行干完**，不把步级状态推回总脑
  - **编排脑职责收窄**：出图/改图、租约冲突仲裁、**执行中追加对话**若可能影响任务顺序或租约 → **总脑先分析**，再下发监管脑（必要时改图/调租约后再派）
  - **成功衔接仍可规则化**：节点成功且契约齐 → 规则拉下游监管脑；不因此回调编排 LLM
  - **推翻**：此前「首期禁止中层监管脑」作废；中层即监管脑，有意为之
- **对结论**：重写 3 / 3.1 / 明确不做；术语改「监管脑」；总表与可行性同步
