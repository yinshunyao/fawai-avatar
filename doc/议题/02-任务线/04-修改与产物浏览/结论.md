# 结论

## 议题

在已有会话 Diff 着色与任务产物附件卡之上，加深**修改审阅**与**跨端预览**：diff 接近 Cursor 读补丁手感；交付物他端只消费浏览器可渲染投影。

## 已定结论

1. **放行并落地**（用户明示「按照你的方案来」）。规范名：**修改与产物浏览**（Diff 审阅 + 产物投影预览）。
2. **跨端原则**：他端只看投影（HTML/PDF/原生可渲）；原件另存；禁止本机绝对路径作出站真源。
3. **Diff（必要，实施先后）**：
   - P0：路径 + `+n/-m`；hunk 可折叠；截断后懒加载全文（完整 diff 落盘，不靠历史气泡塞满）。
   - P1：本任务改动清单入口；`confirm` 时卡上接受/拒绝（口令仍可用）。
4. **产物预览（必要）**：`.md` 用会话 Markdown 渲染；pptx/docx/xlsx 主机生成 `.preview.html`（可选 soffice→PDF）；失败回退摘录并标明「仅摘录」。
5. **明确不做（本切片）**：IDE Tab/内联编辑；像素级 PowerPoint；嵌 OnlyOffice；按 hunk 接受；左右分栏（可选后置）。

## 可行性速览

口径：全 AI 实现；粗估、未核价。

| 切片 | 难易 | 成本与时间（粗） | 可借用资产 |
|:---|:---|:---|:---|
| Diff 结构化 + 懒加载 | 低～中 | 约 1～2 次会话 | `pending_diff`、`phase=diff`、PWA `.step-diff` |
| confirm 按钮 | 低 | 约 0.5 次会话 | hub `confirm_diff`/`reject_diff`；口令已通 |
| 改动清单 | 低～中 | 约 1 次会话 | 进度 meta `path` 聚合；`write_set` |
| HTML 投影 | 中 | 约 1～2 次会话 | 现有 zip+xml 摘录；stdlib 生成 HTML |
| soffice PDF（可选） | 中 | 视环境 | 本机有 LibreOffice 才启用；无则跳过 |
| md 预览 | 低 | 同回合 | `markdown-render.js` |
