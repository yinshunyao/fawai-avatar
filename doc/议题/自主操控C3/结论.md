# 结论

## 议题

能力四件套 **C3 自主操控**：在授权范围内观察界面、控件级接地执行、并回证成败。对应 [全能助手短板](../全能助手短板/结论.md#已定结论) 里程碑 **M3 窄场景**。

## 已定结论

1. **切片定位**：本议题钉 **C3 窄场景 MVP**——单 App 可验收闭环（观察 → 接地动作 → 界面态回证）。不承诺任意桌面点准。
2. **首个 App（已定）**：**macOS 文本编辑（TextEdit）**。原生 AX 稳定。**首切片不做** Cursor / Chrome 等 Electron 控件级点准（可后置 VLM/OCR）。
3. **定位主路径（已定）**：**辅助功能树（AX）** → 带稳定 `ref` + bounds 的摘要；坐标 `click` 保留兜底。本切片不做 OCR/VLM 点准。
4. **观察方式（已定）**：新增 **`obs_ax`**。候选经平台闸门：Darwin 有桌面可用；headless / 非 Darwin → 剔除或失败摘要，不崩闭环。`obs_screen` / 前台窗摘要仍可用。
5. **控制动作（已定）**：
   - 接地：`ui_click` / `ui_type`（args 含 `ref`；`ui_type` 另含 `text`）。
   - 原语扩展：`double_click` / `right_click` / `scroll` / `press`（单键）。
   - 保留：`click` / `type` / `hotkey` / `app_focus`。
   - 前台动作必须持有 `foreground_lease`；`FAWAI_DRY_RUN` 作用于 GUI。
6. **回证 L3（已定）**：`verify_ui_ax`——动作后再采 AX，断言约定字符串/控件存在。GUI 窄场景未回证不得 `success`（对齐编码侧 `code_check` 纪律）。
7. **提示档（已定）**：桌面操控语义优先 `gui`/`full`；「界面」不得单凭前端改页词表否决 GUI；文件目标仍禁 GUI 代写（`file_no_gui`）。`gui` 档能力集须含 `app_focus` 与 ui_*。
8. **验收用例（已定）**：

   | 步 | 动作 | 期望 |
   |:---|:---|:---|
   | 1 | `app_focus` TextEdit；必要时 Cmd+N | 前台为文本编辑 |
   | 2 | `obs_ax` | 摘要含 `ref` + bounds |
   | 3 | `ui_click`/`ui_type` 写入 `fawai-c3-ok` | 接地成功 |
   | 4 | `verify_ui_ax` | AX 值含该串；失败 → failed |
   | 5 | lease + DRY_RUN | 无租约拒绝；DRY_RUN 不真点 |

9. **平台（已定）**：macOS 有桌面为主路径；Linux 有 DISPLAY 可键鼠兜底；`obs_ax` 首期 Darwin；非 Darwin/headless 硬失败摘要。
10. **明确不做（本切片）**：
    - Electron（Cursor/Chrome）控件级点准与 OCR/VLM 接地
    - 任意 App 通用闭环、手机 / adb
    - 用 GUI 代替工作区 `fs_*` 写文件
    - 在 loop 写死 App 剧本（选型仍由大脑）

## 依据摘要

- 短板议题：C3 质量取决于 L2 接地 + L3 回证；M3 先单 App。
- 现网失败根因：`fs` 提示档剔除 GUI + 无 AX/回证，模型只能自称无能力。
- TextEdit 优先于 Cursor：Electron AX 弱，不宜作首验收 App。

| 想法 | 难易 | 粗估 |
|:---|:---|:---|

| TextEdit demo / 系统测试说明 | 低～中 | 约 1～3 次 |
