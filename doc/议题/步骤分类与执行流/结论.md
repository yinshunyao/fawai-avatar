# 结论

## 议题

单 Worker 闭环是否必须「每步固定浅环境观察 → 规划 → 少动作 → 再进模」？如何用**步骤分类**支持「一段串行自衔接」与「一段只读并发、段末统一观察」？

## 已定结论

1. **问题定性（已定）**：动作段预期闸已允许多只读 + 机械跳过 LLM 观察反省，但仍有（1）步首相位固定跑浅 `obs_fs`；（2）批内串行；（3）无显式步型，UI/轨迹难区分取证与纯执行。
2. **方向（已定）**：引入 `step_kind` 五类——`sense` / `act_serial` / `act_parallel` / `analyze` / `finalize`。规划可显式输出；缺省由动作与观察启发式回填。
3. **步首环境观察（已定）**：`act_serial` / `act_parallel` / `analyze` / `finalize` 后，下一步若未显式点选 `obs_screen`/`obs_ax`（等非浅取证），**默认 `none`**，禁止再刷工作区顶层浅列表。`sense` 才按 `observe_kinds` 真采。
4. **段内与段末（已定）**：
   - `act_serial`：串行；`ok`/`expect` 停段；段末统一工具结果观察；机械成功规则摘要，否则一次 `obs_reflect`。
   - `act_parallel`：仅机械只读族并行；写/前台禁入（不合格则降级串行）；段末合并后一次观察/分析。
   - 不取消执行反省 / 步骤重复 / 租约。
5. **边界（已定）**：本议题钉**单 Worker 步级**；跨任务 DAG / `parallel_group` 仍归 [复杂任务计划模式](../复杂任务计划模式/结论.md#已定结论)。在动作段预期闸之上叠步型与并行，不废除旧功能。
6. **明确不做（本切片）**：依赖槽 `$prev` 自动填参；GUI/写并行；跨 Worker 并行图调度。

## 依据摘要

- 用户：空壳「观察完成（工作区文件）」过多；希望多纯执行段、前后自衔接或并发后统一分析。
- 计划草案「步骤分类与执行流」；分析文 C1/C2。
