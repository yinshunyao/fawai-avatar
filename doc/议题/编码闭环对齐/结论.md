# 结论

## 议题

在已有「会话 → 规划 → `fs_*` / `code_*` 改工作区」骨架上，按 **P0 / P1** 补齐朝 Cursor 级改码体验的核心能力：编辑精度、改后证据、仓检索、人机 diff；再上 Git / 多文件协调 / 上下文与工具循环形态。

范围：**结构化编码闭环**（后台工具），不堵、不替代 C3 GUI 接地。与 [自我进化](../自我进化/结论.md#已定结论) E2、[完成任务](../完成任务/结论.md#已定结论) 能力清单同一路由，不另造大脑。

## 已定结论

1. **定位（已定）**：规范名总称 **编码闭环对齐**。目标体感 = Cursor Agent 写代码主路径，而非 Tab 补全 / 内联编辑器。现网已支持「能改文件」；本议题补「改得准、验得了、找得到、人控得住」。
2. **依赖前提（已定）**：复用 C2 能力清单 + WorkerLoop + 执行反省 + 工作区闸门 + `version_*`；禁止 GUI 代替写代码。`FAWAI_WORK_ROOT` 须指向目标仓（默认 `.`）。
3. **落地分期（已定）**：

### P0 — 最小 Cursor 对齐（须先全部可验收再开 P1 主实现）

| 序 | 切片 | 规范名（建议） | 一句话验收 | 工具 / 行为 |
|:---|:---|:---|:---|:---|
| P0-1 | 精准补丁 | **精准补丁** | 改代码默认局部补丁；禁止无故整文件重写大源码 | 新 `fs_patch`（或增强 `fs_replace`：上下文锚点 + 唯一匹配校验）；失败明示；写前仍 `version_snapshot` |
| P0-2 | 改后回证 | **改码回证** | 写成功后须有机读回证，失败进执行反省换道 | 新 `code_check`（首期：可选 `py_compile` / 约定 lint 命令 / 简单语法）；结果回灌 history；无回证不得直接 `success`（编码类目标） |
| P0-3 | 跑测契约 | **编码跑测** | 编码目标可跑指定校验命令且不被误 dry_run 挡死 | 约定：`fs_*`/`code_*`/`code_check` 不受 GUI dry_run；或 `FAWAI_CODING_VERIFY=1` 下允许白名单 shell；禁止任意裸 shell 当「已验」 |
| P0-4 | 检索加厚 | **仓检索** | 改前能按内容/路径稳定找出相关文件，不靠瞎猜路径 | 加强 `fs_grep`（行号、上下文、head_limit）；多文件 `fs_read` 限额；`code_symbols`/`code_map` 保持；**不做**首期向量语义搜 |
| P0-5 | 人机 Diff | **会话 Diff** | 写后会话可见统一 diff；可选确认后再生效 | 出站 `card`/`progress` 带 patch 摘要；模式：`auto`（默认，快照可回退）与 `confirm`（确认前不落盘或落暂存） |

**P0 实现顺序（已定）**：P0-1 → P0-4（检索与补丁可并行后半）→ P0-2 → P0-3 → P0-5。理由：无精准补丁则 diff/回证噪声大；无检索则补丁找错文件；回证与跑测绑执行反省；Diff 闸门最后挂会话层。

**P0 评测门槛（已定）**：至少 1 套自动化：给定小仓「改函数签名 + 调用点」→ 只用 patch、有 check、会话有 diff 摘要；整文件重写大文件 → 硬校验失败或反省改道。

### P1 — 工程 Agent 体感

| 序 | 切片 | 规范名（建议） | 一句话验收 | 要点 |
|:---|:---|:---|:---|:---|
| P1-1 | Git 一等公民 | **Git 工作流** | 可 status/diff/log；提交须显式目标且可拒 | `git_status` / `git_diff` / `git_commit`（确认策略与会话 Diff 对齐）；**不替代** `version_*`（快照仍作写前安全网） |
| P1-2 | 多文件协调 | **多文件改动清单** | 一次目标产出路径清单 + 逐文件 patch + 统一回证 | Plan 须声明 `write_resources[]`；冲突走总管写清单；结束前清单全过 check |
| P1-3 | 规则与上下文 | **编码上下文** | 规划注入工作区 `AGENTS.md` / `.cursor/rules` 摘要（可截断） | 只读注入；不做完整 IDE「打开标签页」仿真；@路径可由用户话术点名 |
| P1-4 | 工具循环形态 | **逐步工具调用** | 编码任务可逐步 tool-call，而非仅整段 Plan JSON | 与现 Plan 循环兼容或双模；须保持能力清单硬校验 |
| P1-5 | 并行探仓 | **探仓子任务** | 大仓可后台只读并行检索再汇总 | 只读；写仍单写者+清单；不做 Cursor 云子代理全集 |

**P1 顺序（已定）**：P1-1 → P1-2 → P1-3；P1-4 / P1-5 可后置，不挡前三项验收。

4. **与现有功能边界（已定）**：

| 已有 | 本议题补什么 |
|:---|:---|
| 工作区文件 `fs_write`/`fs_replace` | P0-1 补丁为主路径；整写保留给新建/小文件 |
| 代码索引 | P0-4 检索加厚并列，不改「非向量」边界直至另议 |
| 版本管理 `version_*` | 写前快照保留；P1 Git 并存 |
| 执行反省 | P0-2/3 失败证据优先喂 reflect |
| 自我进化 E2 | 禁改名单不变；对齐后的补丁/回证服务于自升级质量 |
| 会话通道 | P0-5 Diff 出站；LLM 思考/正文直播（`meta.live`，不落历史） |

5. **明确不做（本议题）**：
   - 不对齐 Cursor Tab / Cmd-K 内联编辑、Notebook 专用流
   - P0 **不做** embedding 语义检索、LSP/SCIP、MCP 生态
   - **不做**无闸门的全盘自动 `git push` / force
   - **不**因本结论自动写入 `doc/功能/`；放行须用户明示
   - 不堵 C3；不以 GUI 键鼠假装改代码

## 依据摘要

- 现网会话可驱动 `fs_*` 改树，但编辑粒度与 Cursor 差距在：整文件写、缺 lint/测回灌、检索偏薄、无会话 diff 确认。
- v0.1.1 档位 B：文件闭环有证据；编码 Agent 质量未单列验。
- 短板议题北向含 Claude Code 级工具闭环；本议题把「朝 Cursor」拆成可放行切片，避免一次做 Git+语义搜+子代理。

## 可行性速览

口径：**全 AI 实现**；粗估、未核价。

| 想法 | 难易（对 AI） | 成本与时间（粗） | 可借用资产 |
|:---|:---|:---|:---|
| **P0-1 精准补丁** | **中**。难点：唯一匹配；大文件锚点漂移 | 约 **3～6** 次会话 / **约 0.5～1 日**墙钟 | 可直接用：`fs_replace`、路径闸门；仅参考：apply_patch / unified diff |
| **P0-2 改码回证** | **中**。难点：语言无关命令约定；假绿 | 约 **2～4** 次会话 | 可直接用：`observe/verify.py` 模式、执行反省、`py_compile` |
| **P0-3 编码跑测** | **低～中**。难点：dry_run 与安全白名单边界 | 约 **1～3** 次会话 | 可直接用：`Controller` dry_run 分支、能力清单 |
| **P0-4 仓检索加厚** | **低～中**。难点：大仓截断与噪声 | 约 **2～4** 次会话 | 可直接用：`fs_grep`/`code_*`；可适配 ripgrep 子进程 |
| **P0-5 会话 Diff** | **中**。难点：confirm 暂存与线程 UX | 约 **3～6** 次会话 | 可直接用：出站 card/progress、`version_*`；PWA 任务线程 |
| **P1-1 Git** | **中**。难点：脏树、确认提交、与 version 双账 | 约 **3～5** 次会话 | 可直接用：本机 `git` CLI；需适配沙箱与口令策略 |
| **P1-2 多文件清单** | **中**。难点：清单漏报与部分成功 | 约 **3～5** 次会话 | 可直接用：写资源租约、总管仲裁 |
| **P1-3 编码上下文** | **低～中**。难点：规则截断与冲突 | 约 **2～3** 次会话 | 可直接用：`skills_prompt_block` 注入模式、读 `AGENTS.md` |
| **P1-4 逐步 tool-call** | **高**。难点：与现 Plan JSON 双模一致 | 约 **6～12** 次会话 | 可直接用：LLM tool call；需改编排 |
| **P1-5 探仓子任务** | **中高**。难点：只读并行汇总 | 约 **4～8** 次会话 | 可直接用：后台并行任务模型 |

## 开放问题

| 优先级 | 问题 |
|:---|:---|
| P2 | 语义检索是否另开议题？ |
| P2 | Git 提交是否强制与 Diff confirm 绑定？（首期否：独立口令） |

已钉死（放行时）：

- `fs_patch` = 锚点 `old`/`new` 或 `hunks[]`（唯一匹配）；非 unified diff 输入
- `code_check`：`.py`→`py_compile`；`.json`→parse；其它可 `command` / `shell_verify`
- `FAWAI_DIFF_MODE` 默认 `auto`；`confirm` 用会话口令「确认补丁 / 拒绝补丁」
