# 结论

## 议题

工作任务闭环在**动作成功或未报失败**时，如何用廉价代码判定「整步 / 整套策略在空转」，仅在命中后再调 LLM 裁决换道或止损，避免每步或每次成功都烧反省 token。

## 已定结论

1. **定位（已定）**：规范名 **步骤重复**（守卫）。挂在单次 `WorkerLoop.run` 的**步末**（本步动作已执行、结果已回写 history 之后；下一轮观察/规划之前）。**不等于** [执行反省](../执行反省/结论.md#已定结论)（失败路径），也**不等于** [任务复盘](../任务复盘与管理/结论.md#已定结论)（终态）。
2. **两段式（已定，强制省成本）**：
   1. **代码判定（零 LLM）**：对本步生成**步骤指纹**，与本 run 内近期指纹窗比对；未命中重复 → **直接进入下一步**，不调模型。
   2. **LLM 判决（仅命中）**：命中重复阈值 → 再调轻量裁决（可复用 `Brain.reflect` 形态或专用 `stagnation` 提示），产出 `continue` / `alternate` / `abort` + `constraints`；注入下一轮 plan；progress `phase=stagnation`（或并入 `reflect` 并标 `trigger=step_repeat`）。
3. **步骤指纹（已定，确定性）**：首期只吃**可机读、稳定**字段，禁止用整段 `thought` 当主指纹（易漂、易假阳/假阴）：
   - 本步 `actions[]`：沿用现有 `action_fingerprint`（`kind` + 关键 args），按顺序拼成**步骤指纹**（多动作则串联或排序后哈希，实现钉一种且评测固定）。
   - 可选附带：本步 `observe_methods` 集合（区分「同搜+同瞎截屏」与「同搜但已换观察」）。
   - **明确不进指纹**：完整 thought、截屏路径、大段工具 stdout（stdout 体积/是否空可作次要启发式，不作首期主键）。
4. **命中规则（已定草稿，阈值可配置）**：
   - **同步骤指纹**在本 run 内累计 ≥ `N`（建议默认 **2**，即第二次完全同构步）→ 触发 LLM 判决。
   - 或：**连续** `K` 步步骤指纹相同（建议默认 **K=2**）→ 触发。
   - 与失败指纹守卫独立记账；失败仍走执行反省，成功空转走本守卫。
5. **LLM 判决输出（已定方向）**：与反省同形 JSON：`cause`（须点明「步骤重复」）、`decision`（`continue|alternate|abort`）、`constraints`、`thought`。
   - `continue`：允许再试，但须附「与上次差异」约束；若下一仍同指纹 → 代码层直接升为 `abort`（不再二次 LLM，省钱）。
   - `alternate`：禁止复用该步骤指纹；约束注入 plan（换工具 / 换 query / 换观察方式）。
   - `abort`：`supervisor.fail`，停止烧步。
6. **与现网死环对齐（已定）**：典型形态「截屏 → 规划 explore_search 同关键词 → 执行成功 → 再截屏 → 同规划」——步骤指纹在 **action 串**上会撞；代码命中后才问模型「换读文件 / 换观察 / 止损」，而不是每步反省。
7. **明确不做（本切片）**：
   - 不每步、不每次成功都调 LLM「有没有进展」。
   - 不做语义级「目标完成度」VLM/长上下文复盘（属 C3 回证 / 任务复盘）。
   - 不用 thought 相似度（embedding）作首期主判定。
   - （放行后本条失效）未写入 `doc/功能/` 前不开工编码。

## 依据摘要

- 失败反省已落地且「成功路径不强制反省」；实证空转常发生在 **ok 的 explore_search / 同策略规划** 上，现网守卫打不中。
- 用户定调：全部 LLM 成本偏高 → **先代码判重复，再 LLM 判决**。
- 已有 `action_fingerprint` / `fingerprint_fails` 可直接复用拼步骤指纹；接线点在 `WorkerLoop` 步末、失败分支旁。

## 可行性速览

口径：**全 AI 实现**；粗估、未核价；不等于放行或开工。

| 想法 | 难易（对 AI） | 成本与时间（粗） | 可借用资产 |
|:---|:---|:---|:---|
| **步骤指纹 + 窗内计数（零 LLM）** | **低**。难点：多动作拼指纹顺序约定；勿把 thought 塞进主键 | **落地**：约 **1** 次会话。**运行**：CPU 哈希，无 API | **可直接用**：`brain/reflect.py::action_fingerprint`；`loop.py` 步末 |
| **命中后轻量 LLM 裁决** | **低～中**。难点：提示与失败反省区分；`continue` 后再同指纹硬 abort | **落地**：约 **1～2** 次会话。**运行**：仅停滞时 1 次短补全（相对每步 plan 可忽略） | **可直接用**：`Brain.reflect` / `run_reflect` 扩 trigger；progress 模式 |
| **评测：同 explore 空转触发 / 换道后不再撞** | **低** | 约 **1** 次会话 | **可直接用**：`demo_eval_priority` 包装脑固定同动作 |

## 开放问题

| 优先级 | 问题 |
|:---|:---|
| P0 | `N`/`K` 默认取 2 是否过敏（合法「确认性再读」）？是否对只读探仓类 kind 把阈值调到 3？ |
| P0 | 步骤指纹多动作：严格保序串联 vs 排序去重集合？建议首期**保序串联**（同工具换序也算不同）。 |
| P1 | 与观察选取同轮：alternate 约束是否强制「下一轮禁止仅 obs_screen」？ |
| P1 | progress / meta：独立 `stagnation_count` 还是并入 `reflect_count`？ |
| P2 | 次要启发式：工具结果「命中数未变 / 摘要哈希未变」是否并入触发（仍零 LLM）？ |
