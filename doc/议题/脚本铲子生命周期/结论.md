# 结论

## 议题

对齐 Cursor `rules-cursor-tools`：智能体在调用已有工具、生成临时脚本、生成临时代码时，须**先查台账**、实现时**参数化/脱敏**，成功后按通用性**提炼为可复用铲（shovel）或 Skill**；Skill 记步骤，铲可执行。

## 已定结论

1. **规范名（已定）**：**脚本铲子生命周期**（别名：铲子优先、脚本提炼、shovel lifecycle）。
2. **选型序（已定）**：能力清单内工具 → `shovel_search` / 已有 `fawai_shovels` → 再临时 `py_*` 或 `fs_write`+`shell`；改产品源码仍 `fs_patch`，禁止用 `py_*` 改仓内业务文件。
3. **写前（已定）**：拟造临时脚本/临时代码前须先 `shovel_search`（可兼 `skill_search`）；默认软闸注入【铲子优先】，可配置；**不做**默认硬失败拦死（可选硬闸默认关）。
4. **实现约束（已定）**：需求走参数/env；禁止把未公开绝对路径、口令、客户名写进脚本正文；三维评分尺子与 `fawai_shovels/SHOVEL.md` 一致（完备性/通用性/效率）。
5. **写后提炼（已定）**：通用性自评 ≥3 → 落 `fawai_shovels/<类>/`（文首 meta + 同回合台账）或至少 `skill_write` 写清 `when_to_use` + invoke；≤2 → 留会话临时/工程专用，不进公共铲。默认**软提示**【铲子提炼】，**不做**任务完成自动蒸馏（与自我进化否决一致）。
6. **Skill ≠ 铲（已定）**：Skill = 可检索步骤/教训；铲 = 可执行单文件；规划可先搜铲再搜 Skill。
7. **复盘（已定）**：分析规则补「临时脚本是否应升铲 / 是否未参数化」；优化须通用。
8. **明确不做**：默认全自动棘轮升铲；把本案菜谱硬编码成专用闸；`shovel_register` 首期可不做独立工具（用 `fs_write` 到铲目录 + catalog `--check`）。

## 依据摘要

- 能力清单与部署族已有「优先 shovel」话术，但缺全台账检索与写前/写后纪律。
- `fawai_shovels` 已具备三维分与台账；需接到大脑规划与闭环软闸。
