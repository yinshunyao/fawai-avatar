# 结论

## 议题

C3 深化：系统截屏后的**接地识别**可配置——走通用 VLM 看图估点，或走 OCR API 出文字框再由文本模型选 `ref`。不自训模型；优先阿里云百炼 Qwen-OCR。

## 已定结论

1. **放行实现**：用户明示立项；写入功能「截屏识别接地」。
2. **配置项（模型配置页）**：
   - **截屏识别方式** `screenshot_grounding`：`vlm` | `ocr`（默认 `vlm`，兼容现网）。
   - **OCR 路由角色** `ocr`：供应商 → 模型（默认百炼 `qwen3.5-ocr`）；与 `asr` 同级，独立于 `vlm`。
3. **行为**：
   - `vlm`：截屏后仍附图进多模态规划（现状）。
   - `ocr`：截屏后调 OCR（须 `advanced_recognition`）→ 元素表 `ref|text|bounds`；规划优先吃表、**默认卸图**走文本路由；点击用 `ui_click(ref)`，坐标取框心（图内→origin/Retina），禁止模型再报裸像素为主路径。
4. **与 AX**：有 `obs_ax` 仍优先 AX `ref`；OCR 表补树空/脏（Electron 等）。`ui_click` 解析顺序：AX → OCR。
5. **OCR 契约**：DashScope 原生 multimodal + `ocr_options.task=advanced_recognition`；吃 `words_info` 的 `text` / `rotate_rect`（或 `location`）。OpenAI 兼容口仅作降级解析，不作首选。
6. **明确不做（本切片）**：自训检测器；OmniParser 本地部署；OCR 回证 `verify` 新方法；承诺无字图标全覆盖；用 `qwen3-vl-plus` 冒充 OCR 出框。
