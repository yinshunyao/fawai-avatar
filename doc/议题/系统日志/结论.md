# 结论

## 议题

控制类与执行类动作如何独立落盘、支持 Web 查询与**按大类/操作订阅**，同时不改动复盘的会话落点、不污染任务气泡。

## 已定结论

1. **会话分流（已定）**：
   - 成功的控制回执**禁止**再 `publish` 进会话历史。
   - 写入独立 **系统日志**（SQLite），经网关 REST + PWA 面板查询。
2. **复盘除外（已定）**：`review` 正文与状态卡**继续**进任务会话；不迁入系统日志主路径。
3. **失败反馈（已定）**：一律写系统日志；REST 仍 HTTP 错误；聊天口令失败可再 `publish` 一条 `error`（否则无气泡可感知）。
4. **存储（已定）**：`data/system_logs.sqlite`，与 `tasks.sqlite` 并列；字段含 `action` / `actor` / `task_id` / `ok` / `message` / `detail`；扩展后须能带 `category`（或等价）便于按大类筛选。
5. **订阅（新定）**：
   - 系统日志界面支持**订阅**：按**大类**与其下**操作**勾选；勾选决定**是否记录**（不是仅查询过滤）。
   - **默认全开、全记录**。
   - 订阅偏好持久化（本机/网关侧配置即可）；改订阅后仅影响之后的写入。
6. **可订阅大类与操作（新定）**（界面展示中文名；落盘可用稳定英文码）：

| 大类 | 操作（界面中文） | 记录要点 |
|:---|:---|:---|
| **任务操作** | 删除、归档、取消归档、取消、暂停、恢复 | 与现网控制动作一致（UI / REST / 口令 / AI 触发同源） |
| **文件操作** | 读取、写入（含替换/补丁等写类） | 路径；读/写涉及的**行号或行范围**（有则写入 `detail`） |
| **命令** | 执行命令 | 实际执行的命令行（`cmd` / argv） |
| **代码与程序** | 执行了哪些代码/程序 | 入口脚本、模块、解释器或已声明的程序标识 |
| **鼠标与截屏** | 点击 / 键入 / 热键；截屏 | 坐标或键；截屏路径或缩略引用 |

7. **明确不做**：
   - 任务 lifecycle / lease 心跳类全量进系统日志
   - 大脑规划「逐步思考 / 选型理由」原文进系统日志（**已执行动作**可记；未执行的候选步骤不记）
   - 改复盘落点
   - 把订阅面板当成第二套会话时间线替代「执行时间线」气泡（二者可并存）

## 依据摘要

- 现网控制成功回执已分流进系统日志；面板筛选仍是英文码、且仅任务操作六类。
- 用户需要按大类/操作**订阅记录**，覆盖文件读写行、命令、代码程序、鼠标与截屏；默认全记，便于事后审计与排障。
- 复盘仍任务化，应留在会话线程。

## 可行性速览

口径：**全 AI 实现**；粗估、未核价；不等于放行或开工。

| 想法 | 难易（对 AI） | 成本与时间（粗） | 可借用资产 |
|:---|:---|:---|:---|
| **订阅配置 + PWA 大类/操作勾选（默认全开）** | **低～中** | 约 **1～2** 次会话 | 可直接用：现有日志抽屉、`GET /api/system-logs`；需增订阅读写 API/本地配置 |
| **任务操作继续记 + 中文展示名** | **低** | 约 **0.5～1** 次会话 | 可直接用：`SystemLogStore`、Hub/Gateway 已写六动作；UI 现有中文按钮文案 |
| **文件/命令/代码/鼠标截屏写入闸门** | **中** | 约 **2～4** 次会话 | 可直接用：`control/executor`、`observe/screen`、能力表中文名；难点：统一挂载点 + 行号进 `detail` + 截屏体积策略 |
| **按 category 查询与列表展示** | **低** | 约 **1** 次会话 | 需适配：schema 增 `category`（或 action 前缀约定）+ 列表中文映射 |

2. **已落地**：失败日志「一键分析」→ 复用任务对话自动建整改任务（目标/要求/边界），做工具或调度增强。
