# 结论

## 议题

会话 PWA 与用户交互面如何按常规「读语言」架构支持多语言，并先交付中英文、可随时切换。

## 已定结论

1. **分层（已定）**
   - **目录（catalog）**：按 locale 分文件，键稳定、值可译；首期 `zh-CN`、`en`。
   - **运行时**：`t(key, vars)` / `tOr(key, fallback)`；静态节点用 `data-i18n` / `data-i18n-placeholder` / `data-i18n-aria` / `data-i18n-title` / `data-i18n-attr`；动态 UI 调 `t()`。
   - **偏好**：本机 `localStorage`（`fawai_locale`）；未设置时按 `navigator.language`（`zh*` → 中文，否则英文）；**不写服务端**。
2. **切换（已定）**：顶栏语言段 + 系统配置「界面语言」；切换立即重刷壳层文案与依赖 locale 的列表/表单。
3. **枚举与码表（已定）**：任务态 / 阶段 / 日志大类·操作等**稳定英文码**落盘或下发；界面展示名走目录键（如 `status.running`、`logs.cat.task`），禁止把英文码直接露给用户。
4. **设置项与日志目录（已定）**：服务端可继续带中文 `label`/`hint` 作兜底；前端优先用 `settings.field.*` / `settings.hint.*` / `logs.cat.*` / `logs.act.*` 覆盖。
5. **协议与展示分离（已定）**：复盘等口令仍发后端已识别的稳定词（如 `ok` / `全部` / `取消` / `执行 1,2`）；按钮可见文案可本地化。
6. **明确不做（首期）**
   - 不翻译模型 thought / 工具原始输出 / 用户消息正文
   - 不做服务端会话级语言账本、不做按用户账号同步语言
   - 不做完整 ICU 复数引擎；简单 `{var}` 插值即可
   - 不把语言偏好写入 `.env`

## 可行性速览

| 维度 | 判断 |
|:---|:---|
| 难易 | 低～中：单页 PWA，无打包器；目录 + 薄运行时即可 |
| 成本时间（全 AI） | 约 1 次会话可搭架构并覆盖壳层；长尾文案可随改 UI 补键 |
| 现成开源 | 不必引入 i18next；自研小运行时足够 |
| 人机闸门 | 无（纯 Web） |

## 开放问题

- 大脑 / 出站 progress 正文是否要按 UI 语言生成（会牵涉规划提示），首期不做。
- 第三语言（如日语）仅需加目录文件并挂切换项。
