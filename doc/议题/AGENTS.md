# `doc/议题` — 议题讨论与结论归档

## 目录用途

形成产品/技术思路的讨论区：记录会话要点，并维护可复用的结构化结论。  
**本仓不维护 `doc/or/`**。本目录只做**讨论与原则收敛**；「放行实现 / 实际已支持」见 `doc/功能/`（功能目录）。不套用 `01-or`～`99-ops`。

## 文档范围

| 允许 | 禁止 |
|:---|:---|
| 一议题一目录下的 `会话.md`、`结论.md` | 在 `议题/` 根目录平铺**议题正文**散文件 |
| 根目录唯一总表 `【总表】议题一览.md` | 再建第二份总览/索引表；与功能总表混成一张 |
| 提炼后的会话要点与定论 | 聊天全文原样粘贴 |
| 「明确不做」、开放问题、下一步 | 多议题混进同一对文件 |
| 想法的可行性速览（难易 / 成本时间 / 现成开源与 API；**全 AI 实现口径**） | 用人天/人周或「招人开发」口径评估；把粗估当成已立项排期或正式报价 |
| 为功能放行提供依据（链到结论） | 未经用户明示就把议题条目写入 `功能/`；另建 `or/` |

## 目录结构

```text
doc/议题/
  AGENTS.md
  【总表】议题一览.md
  {短名议题}/
    会话.md
    结论.md
```

- `{短名议题}/`：稳定中文或英文短名（如 `口型驱动方案`），**不用**日期作前缀。
- 新议题一次建齐 `会话.md` + `结论.md`；结论可先写「待定」骨架，不得缺文件。
- 根目录除 `AGENTS.md` 与 `【总表】议题一览.md` 外，不放其它散文件。

## 总表：`【总表】议题一览.md`（强制维护）

全目录**唯一**总览。三列，尽量短；用相对路径链接跳进议题文档章节，不在表里贴长文。

| 列 | 内容 | 链接建议 |
|:---|:---|:---|
| **议题** | 短名 | → `{短名}/结论.md#议题` |
| **要点** | 一两句当前焦点/骨架 | 可链 `#已定结论` 或会话最新段（若需） |
| **结论** | 一两句定论或「待定」 | → `#已定结论`；需要时再链 `#可行性速览` / `#开放问题` / `#下一步` |

维护时机（与会话收尾**同一回合**，缺一不可）：

- 新建议题目录
- 改了 `结论.md` 的已定结论 / 可行性 / 开放问题 / 下一步（以致表意变化）
- 议题改名或废弃（废弃可删行或标注废弃，勿留死链）

禁止：总表与各议题结论长期不一致；在总表堆会话原文或可行性整表。

## 想法讨论：助理同步分析（强制）

本目录以**想法讨论**为主：用户主要抛想法与边界，助理**不得只复述或只归档**。

用户每提出（或显著改动）一条想法时，同一回合须同步梳理并写入 `结论.md` 的 **可行性速览**（会话里可只留一句指向）。

**评估口径（强制）**：默认假设 **设计、编码、联调、文档、迭代全部由 AI 完成**（Cursor / Agent 编码循环 + 模型 API）。**禁止**用人天、人周、人力成本作主口径；仅当某步物理上必须真人（如系统权限弹窗点允许、真机插线、账号实名）才可单列「人机闸门」，且不得把闸门折算成人天工期。

| 维度 | 写什么 |
|:---|:---|
| **实现难易** | 对 **AI 自主落地** 的粗档：低 / 中 / 高；点出主要难点（1～3 条：如缺可机读反馈、权限闸门、双端差异、评测闭环难自动化） |
| **成本与时间** | **AI 墙钟/会话轮次**粗估（如「约 N 次 Agent 会话 / 约 X～Y 小时墙钟」）+ **运行成本类型**（编码期 token、运行期 LLM/VLM API、本地算力、设备与账号）；标明「粗估、未核价」 |
| **可借用资产** | 现成开源库、云/厂商 API、本仓库或其它已有能力；写清「可直接用 / 需适配 / 仅参考」——优先选 **AI 易接线、有文档/SDK** 的资产 |

约束：

- 多条想法按条对照，不要揉成一句空话。
- 不确定就写「待核」与待查问题，禁止编造不存在的库或报价。
- 可行性速览服务选型与优先级；**不等于**放行或开工（放行须写入 `doc/功能/`；开工只认功能表状态）。

## 编辑规则

### `会话.md`

按会话**追加**（最新在后），每段至少含：

- 日期
- 焦点（本轮在谈什么）
- 要点列表（压缩判断与分歧，不贴全文）
- 一句：本轮对 `结论.md` 改了什么 / 未改什么

### `结论.md`（整体框架，顺序固定）

每次会话收尾后**整篇按框架更新**（融入定论，禁止只按日期堆尾巴）：

1. **议题** — 一句话问题与范围
2. **已定结论** — 可执行判断（含「明确不做」）
3. **依据摘要** — 从会话提炼的关键论据（短）
4. **可行性速览** — 按想法条目、**全 AI 实现口径**：难易、AI 墙钟/会话与 API 等成本、可借用开源/API/已有能力；无新想法本轮可写「无变更」但章节保留
5. **开放问题** — 未决项，可带优先级
6. **下一步** — 可验收动作；未开工则写明仍停在议题讨论

成稿语气：只写读者要看的判断，不写「按本次讨论三条主线」类提纲旁白。  
判断变了就改对应节，不另起「变更日志」一级标题堆叠。

### 会话收尾（强制）

满足任一即视为应收尾，**同一回合**完成「追加会话 → 按框架更新结论 → **同步【总表】议题一览.md**」：

- 用户说告一段落 / 下次再聊 / 收尾等
- 本轮已形成可复用判断
- 本轮提出了新想法或改动了已有想法（须同步刷新可行性速览）

收尾检查清单：

- [ ] `会话.md` 已追加本轮
- [ ] `结论.md` 六节齐全且与当前判断一致
- [ ] 有新想法时 **可行性速览** 已按条更新（全 AI 口径：难易 / AI 时间与 API 成本 / 可借用资产；无人天主口径）
- [ ] **`【总表】议题一览.md` 对应行已新增或改到与结论一致**（链接有效）
- [ ] 未把聊天全文贴进任一文
- [ ] 未新建或写入 `doc/or`

| 相邻 | 边界 |
|:---|:---|
| `doc/` 根与术语表 | 稳定称呼、会话别名回写 `doc/术语与称呼索引.md`；全仓文档/代码边界见 `doc/AGENTS.md` |
| `doc/功能/` | 放行与已支持；本目录不替代功能总表 |
| 工程代码 | 讨论可指向实现方向，不在本目录写代码；落地后改功能表状态与代码列 |

编辑本目录前先读本文件；Cursor 规则真源见仓库 `.cursor/rules/rules-issue.mdc`（文档/代码总约束另见 `rules-doc-code.mdc`）。
