# 结论

## 议题

在已有能力清单、路径禁改、编码上下文注入之上，如何让执行脑在**改代码 / 自我进化**时守住设计与架构，在**日常运行**时让规则真正约束效果——接近 Cursor 跟 `doc/` 与 Project Rules 的体感，而不是只「读过提示词」。

## 已定结论

1. **定位（已定）**：规范名总称 **守规约束**。补的是「软注入不够」这一刀：把可判定的设计/架构/规则红线变成**机读校验 + 失败重规划**，与 [完成任务](../完成任务/结论.md#已定结论) 的 `validate_plan` 同构；**不**另造大脑，不堵 [自主操控](../全能助手短板/结论.md#已定结论) C3。
2. **两类约束对象（已定，须分开验）**：

   | 对象 | 主要场景 | 目标 |
   |:---|:---|:---|
   | **设计 / 架构** | 编码闭环、自我进化 E2 | 改树不拆三层边界、不漏文档映射、不碰禁区之外的「架构漂移」 |
   | **规则（效果）** | 任意工作任务规划 / 反省后重规划 | 相关规则进上下文；可机判违规则硬拦，其余仍靠模型 |

3. **三层约束策略（已定）**：
   - **L-边界**：路径逃逸、`.env`、进化禁改名单、租约、能力外假 success——继续只认代码硬闸（已有资产复用）。
   - **L-架构**：编码/进化类目标在 `plan` 之后做 **架构校验**；违规 → 附加约束重规划 **1** 次，再失败 → `status=failed`（对齐 C2 硬校验节奏）。
   - **L-规则**：规划前按目标类型从 **规则注册表** 取 3～5 条相关短约束注入；全书灌入与「截断 6 个 mdc」均否决为默认策略。
4. **与现有能力关系（已定）**：

   | 已有 | 本议题补什么 |
   |:---|:---|
   | [编码上下文](../编码闭环对齐/结论.md#已定结论)（AGENTS / rules 截断注入） | 从「只读塞提示」升级为「检索注册表 + 可校验条目硬门」；注入保留作软补充 |
   | [完成任务](../完成任务/结论.md#已定结论) 能力清单 / `validate_plan` | 扩展校验维度（架构/文档纪律），不平行第二套选型脑 |
   | [自我进化](../自我进化/结论.md#已定结论) 禁改黑名单 | 黑名单仍管「绝对不能写」；架构校验管「能写但写错层/漏文档」 |
   | [改码回证](../编码闭环对齐/结论.md#已定结论) `code_check` | 语法/约定检查保留；守规验收另加「触及路径 vs 声明文档 / 禁层」类清单项 |
   | [执行反省](../执行反省/结论.md#已定结论) | 校验失败走重规划；同指纹空转仍归反省/步骤重复，不混进本议题 |

5. **切片与 P0 默认（已定并已落地）**：

   | 序 | 切片 | 规范名 | 一句话验收 |
   |:---|:---|:---|:---|
   | S1 | 机读规则目录 | **规则注册表** | 代码常量；id / when / constraint / hard；规划命中最多 5 条 |
   | S2 | 计划后架构门 | **架构校验** | 分层写须 `doc_refs` 或 `architecture_skip_reason`；进 `validate_plan` |
   | S3 | 改后守规清单 | （并入闭环闸） | `write_set` 含分层路径且从未声明 → success 前强制补声明 |

   | 项 | 默认 |
   |:---|:---|
   | 注册表存放 | `fawai_avatar/brain/compliance.py` 常量 |
   | hard 配额 | 与 C2 共用重规划 1 次 |
   | 规则命中范围 | 任意目标可注入；架构硬门按写路径触发 |
   | S1～S3 | **同一切片**交付 |

6. **明确不做（本议题）**：
   - 不承诺模型 100% 自觉守软规则；不做「把全仓 `doc/` 每步塞进上下文」
   - 不在本议题实现 C3 GUI 接地；不以键鼠假装改架构
   - 不做完整 IDE 打开标签页仿真；不做无闸门的全自动架构重构
   - 不替代人审发版；产品升版评测纪律仍见 [自我进化](../自我进化/结论.md#已定结论) / `doc/版本/AGENTS.md`
   - 静态 import 禁令（如 brain 禁调键鼠 API）留 P2，本切片不做

## 依据摘要

- 现网：分层与租约靠代码；`context_inject` 只截断注入 AGENTS/rules，无架构合规校验器——自进化可改树，不能保证「改完仍符合设计」。
- Cursor 跟文档的体感 = 贴任务规则上下文 + 人回路；无人监督进化必须把红线校验器化，才能接近同等可靠。
- 仓内已验证模式：C2「提示 + `validate_plan` + 重规划 1 次」比纯提示稳——守规应复用该模式，而不是加长 system prompt。

| **架构校验** | **中** | 约 **3～7** 次会话（已完成） | `validate_plan`；`WorkerLoop` |

| **评测套件** | **低～中** | 约 **1～3** 次会话（`demo_compliance`） | `demo_c2` 模式 |
