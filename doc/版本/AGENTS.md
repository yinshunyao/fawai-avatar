# `doc/版本` — 产品版本评测归档

## 目录用途

每个**产品版本**归档一份文字评测结果：按固定维度打分、加权得出总分，并记录依据（测试任务、现象、未测项）。  
用于对比版本进步、发版门槛与找短板——**不是**工作区「版本管理」功能（快照/回退见 `doc/功能/版本管理/`）。

## 文档范围

| 允许 | 禁止 |
|:---|:---|
| 根目录唯一总表 `【总表】版本评测一览.md` | 第二份总览；与功能/测试总表混成一张 |
| 真源量表 `评分量表.md`（维度 / 权重 / 锚点 / 公式） | 每个版本私自改权重却不改量表 |
| `{版本号}/评测结果.md` 文字报告 | 密钥、口令、未脱敏客户路径 |
| `{版本号}/RELEASE_NOTES.md`（**英文默认**）与可选 `RELEASE_NOTES.zh-CN.md` | 只写中文说明却当 GitHub Release 正文、相对链接在 Release 页 404 |
| 链到 `doc/测试/` 任务与 `doc/功能/` | 把未跑任务写成满分；无依据猜高分 |

## 目录结构

```text
doc/版本/
  AGENTS.md
  评分量表.md
  【总表】版本评测一览.md
  v{主}.{次}.{修订}/
    评测结果.md
    RELEASE_NOTES.md          # 英文默认；GitHub Release 正文用这份
    RELEASE_NOTES.zh-CN.md    # 中文；文首互链英文
```

- 版本号与 `pyproject.toml` 的 `project.version` 对齐；预发布可加后缀（如 `v0.1.0-rc1`）。
- 根目录除 `AGENTS.md`、`评分量表.md`、总表外，不放其它散文件。
- **GitHub Release 正文**须用英文 `RELEASE_NOTES.md`，且指向评测/中文说明时用 **blob 绝对 URL**（`…/blob/vX.Y.Z/doc/版本/…`），禁止只写 `./评测结果.md`（Release 页会解析到仓库根导致 404）。
- 仓内互链可用相对路径；中英文说明文首须互相可跳。

## 何时必须写评测（强制）

满足任一则**同一回合**写入或更新对应 `{版本号}/评测结果.md`，并同步总表一行：

1. 准备发版 / 已改 `project.version`
2. 用户明示「做版本评测 / 出评测结果」
3. 里程碑能力合入后要对比上一代（如 C2/C3 落地）

未跑完量表要求的最低任务集时：总分可写，但须标 **「证据不足，上限封顶」**（见评分量表），禁止假装全测。

## 评测结果文档结构（强制）

`{版本号}/评测结果.md` 顺序固定：

1. **元信息** — 版本号、评测日期、评测人/方式、对照 `project.version`、环境摘要  
2. **总分与档位** — 加权总分（0–100）+ 档位 + 一句话结论  
3. **维度得分表** — 各维原始分（0–10）、权重、加权贡献  
4. **测试覆盖** — 已跑 / 未跑的 `doc/测试` 任务（区分冒烟 / 系统 / 端到端）；自动化出口与手测备注   
5. **分维依据** — 每维：证据、扣分点、与人类任务/智能体文献对齐的简注  
6. **相对上版** — 无上版写「首评」；有则写升降与原因  
7. **优先改进** — ≤5 条，按对总分杠杆排序  

成稿只写判断与证据，不写讨论提纲旁白。

## 协作约定

| 相邻 | 边界 |
|:---|:---|
| `doc/测试/` | 冒烟 / 系统 / 端到端任务怎么跑；**结果与打分**落本目录 |
| `doc/功能/` | 能力是否「已支持」；评测可引用，不替代功能表 |
| `doc/功能/版本管理/` | 工作区文件快照；与本目录无关 |
| `评分量表.md` | 维度与权重唯一真源；改权重须同回合改量表并注明生效版本 |

编辑本目录前先读本文件与 `评分量表.md`。
