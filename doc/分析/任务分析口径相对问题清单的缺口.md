# 任务分析口径相对问题清单的缺口

对照对象：`doc/问题/` 里已追到机制的条目，与 `doc/功能/任务复盘/分析规则.md`（及 `skills/review.py` 复盘提示、`.cursor/rules/rules-task-analysis.mdc`）现行强制口径。  
目的：钉清「按现有任务分析尺子复盘，会系统性漏掉什么」。**不等于**改规则放行；要补检查项须另开议题并同步三处真源。

关联：

| 类型 | 路径 |
|:---|:---|
| 问题清单 | [查看训练状态](../问题/查看训练状态.md)、[任务图出图](../问题/任务图出图.md)、[直播跟读](../问题/直播跟读.md) |
| 分析真源 | [任务复盘/分析规则](../功能/任务复盘/分析规则.md) |
| 已沉淀机制（未回灌规则） | [窗口满后的摘要与待办](./窗口满后的摘要与待办.md)、[观察预览与近窗再读](./观察预览与近窗再读.md)、[机械跳过与步骤重复](./机械跳过与步骤重复.md) |

## 总判

现行任务分析强在：**工具双栏、必要路径偏科、探索→改写、假成功/假归因、压缩 dump 未回读、shell 绕过**。  
对照 `doc/问题`，缺口主要有三类：

1. **工作记忆与调度**类失败模式未进检查表，容易被写成「模型忘了 / 调用失误」。
2. **产品面 / 通道面**问题不在尺子射程内，却常和「任务」一起被点名。
3. **`doc/分析` 已写清的机制**没有回写进分析规则与复盘提示，人工/产品复盘不会系统扫到。

## 1. 问题清单已钉、分析规则未收的失败模式

| 问题条目 | 已追到的机制 | 现行规则最近似项 | 为何不够 |
|:---|:---|:---|:---|
| 查看训练状态 #1 重复取证 | 规划看见过成功读；探索闸关 → `read_windows` 不注入；`plan()` 无执行前指纹拒绝；步骤重复要等**同指纹再成功一次**才事后裁决；最新观察换成铲子结果后，模型重排「取连接」 | 「同构守卫过窄」「压缩未读」 | 前者管参数微调撞不上指纹；后者管 dump 未读就 success。本案是**已成功取证仍被允许再排**，且发生在执行前；不是未读 dump，也不是指纹过窄 |
| 查看训练状态 #2 假串行 | 提示词假依赖（定位→读→铲）+ 动作段曾只鼓励只读并批；一轮只出一个动作 ≠ 执行层 fail-fast | 「同批只读被 fail-fast 掐断」 | 那是**一步内已排多动作却被 break**；本案是**规划从未并批**。表层「界面串行」与机制「假顺序约束」不是同一环 |
| 查看训练状态 #3 无图时记得做完什么 | 远窗机械摘要丢结论；简单目标无压不掉待办；有图时节点状态管完成、但不管结论；共用事实靠截断收尾想法会失真 | 「压缩观察未回读」 | 未回读是收尾闸；本案是**窗口满后结论与步骤身份一起掉**，以及**有图/无图两套记忆职责**。规则未点名待办 / compact / 共用事实钉图 |
| 任务图出图 #1 | 判定与出图串行、无流式；编排进度从不落 `thinking_text`；`Building plan` ≠ Worker `phase=plan` | （无） | 尺子只覆盖 Worker 闭环五维，**不覆盖编排脑出图 UX / 深度思考是否入模** |
| 直播跟读 #1 | 跟读锚点钉在思考限高框，普通输出在框外长出视野 | （无） | 纯通道 UI；硬套工具双栏 / 必要路径会答非所问 |

## 2. 按现行结构写复盘时的典型偏斜

1. **把记忆缺口写成调用失误**  
   双栏「调用」栏容易写「又读了同一 path」。若不先问「规划侧有没有压不掉的完成/结论记忆、已读窗有没有注入」，会漏掉产品层缺口，优化落到 lesson「下次别重读」。

2. **把提示词假依赖写成执行串行**  
   看到时间线一前一后，落到「同批未并」或工具层，却不查短/长提示是否把独立只读写成先后必要步。

3. **只认 failed / 空转 / 假成功**  
   重复取证、假串行可以发生在最终仍能答上的任务里。现口径标题偏失败终态，**效率型空转 / 可验收但浪费轮次**缺少显式升因位。

4. **通道与编排问题无出口**  
   出图无进展、思考框跟读错位，不进五维。要么被跳过，要么硬塞进 scheduling/execution，结论失真。

5. **分析沉淀与复盘尺子脱节**  
   `窗口满后的摘要与待办` 等已写清可复用模式，但 `分析规则.md` 失败模式表与 `review.py` 提示词未收同名项 → 产品复盘 LLM 与 Cursor 人工复盘**默认扫不到**。

## 3. 若补强分析口径（仅方向；未立项）

下列为**可选项**；落地须改 `分析规则.md` + 规则指针 + `review.py` 同回合，并区分「必要补进检查表」与「另开通道/编排复盘尺子」。

| 方向 | 建议落点 |
|:---|:---|
| 失败模式：**成功取证再排** | 症状：同 path/同窗成功后仍被 plan 出；查探索闸/`read_windows` 注入、执行前是否拒绝、步骤重复是否仅事后 |
| 失败模式：**提示词假依赖 / 可并未并** | 与「同批 fail-fast」分栏；查提示是否把无冲突只读写成先后 |
| 失败模式：**工作记忆缺口** | 远窗丢结论；无图无待办；有图共用事实未钉 / 只靠收尾截断；链到 [窗口满后的摘要与待办](./窗口满后的摘要与待办.md) |
| 失败模式：**近窗省略句诱再读** | 链到 [观察预览与近窗再读](./观察预览与近窗再读.md) |
| 范围声明 | 任务分析默认 Worker 闭环；编排出图 UX、会话跟读等标「非本尺子」或另写通道/编排复盘节，禁止硬套工具双栏 |
| 效率型空转 | 终态非 failed 也可升因：重复成功只读、可并批却串行烧轮次 |

**明确不做（对照问题清单仍成立）：** 不为单次任务发明「某配置 basename 禁再读」专用闸；执行前指纹拒绝若做，须是通用层，且与「结论不在则允许定向再读」同边界。

---

## 4. 与工具本身优先的关系

问题清单里多数根因在**规划注入 / 历史窗 / 提示词顺序 / 编排与 UI**，不是 schema 缺槽或报错误导。  
「工具本身优先」仍应先扫；扫完未见工具 bug 后，须进入上表记忆与调度模式，**禁止**因工具栏空白就默认结案为「模型不会用」。
