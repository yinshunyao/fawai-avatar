# 检索命中观察渲染

对照对象：`lore_search` / `task_context_search`（及同类返回 `hits` 的工具）经 `observe/tool_digest.format_tool_observation` 回灌规划时，命中列表是否可读。  
目的：钉清「工具报 N hits、观察却是 `?:?:`」的契约坑；**不等于**放行改码。

关联：`observe/tool_digest.py` → `_render_hits`；[任务内上下文查询](./任务内上下文查询.md)；案 `6d71d772…`。

## 现状

**已修（P0）：** `_render_hits` 兼容 grep 的 `path:line:text` 与 lore/task_context 的 `summary`/`snippet`/`msg_id`，有命中不得再渲成空的 `?:?:`。

**仍可选：**

| 序 | 项 | 验收 |
|:---|:---|:---|
| **P1** | 统一 hit 契约文档：`path?` `line?` `text|summary|snippet`；新检索工具出厂即兼容 | 新工具不靠个案补丁 |
| **可选** | UI 进度卡与观察共用同一 renderer | 人机看到的命中一致 |

## 明确不做

- 不为某一个 query / 某一台机房写专用渲染分支。  
- 不靠「加长近窗」掩盖命中不可读。
