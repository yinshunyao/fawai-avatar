# shell 非零退出掩盖已有输出

对照对象：`shell` 的退出码与主文案、动作段预期闸在工具已失败时的短路。  
目的：问询类目标里，链式命令的旁路失败不应盖住已经打出的身份证据，也不应把笼统 `tool not ok` 交给执行反省去编原因。  
关联：[动作段预期闸](../功能/动作段预期闸/说明.md)、[执行反省](../功能/执行反省/说明.md)、[工具结果观察](../功能/观察/说明.md)。不等于放行。

证据任务：`f09aa382ac0f4e19ae192edc73267e3c`（目标是查看某机 AI 训练状态，终态 `completed`）。

## 现状（已部分落地）

`shell` 以进程退出码决定 `ok`。非零时主文案优先取 stderr，stdout 仍在 `data`。

**已改（失败反省吃齐证据口径）**：

1. 动作段预期闸：工具已失败时**仍核** `contains` / `contains_any`；已命中则**不**盖成 `tool not ok`，保留原 message；未命中则写明缺标记，并附「工具原文」。
2. 执行反省主输入：失败动作附 `expect_pre_message` / `stdout` / `stderr` / `returncode`，并优先附本步工具结果观察摘要；提示词要求根因 grounded，禁止只凭短标签升成沙箱/工具族不可用。

证据任务原貌：`f09aa382ac0f4e19ae192edc73267e3c`（目标是查看某机 AI 训练状态，终态 `completed`）。该任务两次远程查看曾是：stdout 已打出进程命令行，随后 `tail`/`find` 非零，整段 `ok=false`，反省假归因；材料在观察卡里有，但反省主句曾被盖掉。

## 仍可复用的缺口

1. **主文案与退出码**：链式只读里，前半已打出身份行、后半旁路非零时，`shell` 失败句仍可能偏 stderr、不带 stdout 短摘（反省侧已可从 data 吃到，但 progress 主句仍可能偏）。
2. **问询终稿**：答复覆盖（默认关）仍不拦「进程身份与目标词不一致」以及「旁路失败写成整体无异常」。
