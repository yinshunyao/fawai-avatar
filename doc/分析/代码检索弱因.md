# 代码检索弱因

## 对照对象 / 目的

- **对照**：任务 `9cbc23ed528242b39567fe04810a93b6`（附图优化手机端 UI）上「每次都在看 index.html、检索像很差」的观感。
- **目的**：分清工具本身缺口 vs 调用/闭环；避免把「搜不到」误当成仓内无前端。
- **关联**：[附图后全程VLM与选档缺口](./附图后全程VLM与选档缺口.md)、[功能/工作区文件](../功能/工作区文件/说明.md)、[功能/代码索引](../功能/代码索引/说明.md)、[功能/编码闭环](../功能/编码闭环/说明.md)

## 一句话

**检索工具大体能搜到；差的是「定 path 之后不会用精确 pattern 钉行号，只会同文件小窗盲读」。HTML/CSS 符号索引与记忆配置开关、检索软偏好提示已补；探索进度闸仍默认关闭。**

## 证据（本案）

| 项 | 数/事实 |
|:---|:---|
| 工具面 | `fs_read`≈108、`fs_glob`≈52、`fs_grep`≈29、`code_symbols`≈1；写动作 0 |
| 路径粘滞 | 近期 acted 路径约 56/73 落在同一 `channel/static/index.html` |
| 真源 | 同文件存在 `button.send`（约 L449）、`button.stop`（约 L462）、窄屏相关约 L5940+；`@media` 多处 |
| 坏 pattern 例 | `pattern=<style>.*\.send` → `grep 0`（样式不在该结构里） |
| 宽 pattern 例 | `send\|stop\|button` 等顶满 `head_limit`（40），噪声淹没样式定义行 |
| 假终稿 | 已读 DOM/`viewport`/`@media` 仍称找不到 `.send/.stop` 样式、并臆测独立 CSS |

## 工具双栏

### 工具本身

| 点 | 判断 |
|:---|:---|
| `fs_grep` 正则现扫 | **能力够**：正确 pattern（`button.send` / 裸 `send` / `@media`）可命中。空命中多来自坏正则或错误结构假设，不是读盘失败。 |
| `\|` 字面转义 | 契约坑**已补旁注**（`grep_empty_escaped_pipe_hint`）；仍依赖模型改 pattern。 |
| `code_symbols` / 代码索引 | **已补 HTML/CSS**（id/class/selector/@media）+ 记忆配置开关 `FAWAI_CODE_INDEX`（默认开）。此前无后缀、无开关是缺口。 |
| `explore_search` | 产品侧**故意降权**（默认只 grep）；不是本案主失败面。 |
| 命中截断 | 宽 pattern + `head_limit` 顶满时，观察里未必先出现样式定义行；模型若不当「翻页/收窄」会以为没找到。属契约可增强，不是完全不能搜。 |

### 调用

| 点 | 判断 |
|:---|:---|
| 定 path 后相位错误 | 命中 `index.html` 后，把检索退化成反复 `fs_read offset/limit` 同构小窗（多步重复 `offset≤50`、同窗再读）。 |
| pattern 选型 | 少用 `button.send`；多用 DOM/`class='…'`/`@media` 宽扫；一次 0 命中后不换到类名正文。 |
| 证据未吸收 | 已有非空 grep 与 DOM 行号，仍规划找独立 `.css`，终稿假归因「样式不在文件里」。 |
| 进度闸未武装 | `FAWAI_EXPLORE_ONLY_GATE` / `FAWAI_LOCATE_BUDGET_STEPS` 等**默认关闭** → 只读空转缺少硬逼换道/改写。 |
| VL 放大器 | 附图任务曾全程 VLM 挤占近窗（见对照文）；加重「读了当没读」，**不是**「仓里没有 index.html」的主因。 |

## 机制根因（可复用）

1. **定 path 后检索退化成盲读**（探索→改写未切换的变体）：成功只读被当成进展；精确 `fs_grep` + 行号附近 `fs_patch` 未成为默认下一步。
2. **符号检索与前端真源错配**：索引面向 py/js/… 符号；巨型 HTML 内联 CSS 只能靠正文 `fs_grep`，模型却仍按「找 src/找 css 文件」世界模型行动。
3. **宽命中 + 低吸收**：顶满 head_limit 的噪声 hits 与小窗读互相加强；无「已有 path → 必须用目标选择器钉样式/逻辑行」的强制换指纹。
4. **探索空转闸默认关**：同构只读可烧满轮次而不被中止换道。

## 用户确认方向（本轮）

### 1. `code_symbols` 能否支持 HTML / CSS

| 问 | 答 |
|:---|:---|
| 现状（改后） | **已支持**。`.html`/`.htm`/`.css` 抽 `id`/`class`/selector/`@media`；HTML 内 `<script>` 复用 js 启发式。 |
| 开关 | 记忆配置 `FAWAI_CODE_INDEX`（默认开；只存 sqlite）。原先**无**独立开关；现已补。 |
| 不做满的 | 不把每个 DOM 节点当符号；不做语义/向量；复杂正则仍归 `fs_grep`；仍不做 JSON/Markdown 伪符号。 |

**结论**：HTML/CSS 符号索引已落地；关索引时工具拒建索并提示 `fs_grep`。

### 2. 有线索后偏 grep；确认相关处理后偏精确（软偏好，不定死）

用户口径（须保留「尽量 / 不定死」）：

```text
有线索（path / 命中目录 / 类名片段 / path:line）
  → 尽量 fs_grep 收窄取证，少同文件盲读小窗
已确认相关处理（样式定义块 / 函数体 / 明确选择器命中）
  → 尽量精确 pattern（button.send、完整选择器、锚定行附近）
  → 再小窗 fs_read / fs_patch
仍允许：宽搜翻页、code_symbols、必要时小窗读、换道
禁止落成：硬闸「有 path 必须 grep」「禁止 fs_read」
```

| 落点 | 建议 | 不定死怎么写 |
|:---|:---|:---|
| 【提示词·工具使用 / 任务规划】 | 「线索→尽量 grep；确认相关→尽量精确」 | **已落地**（软偏好，不定死） |
| 【闭环运行时】（可选 P1） | 同 path 重叠盲读 streak + 已有非空 grep → 软注入换指纹 | **未做**；注入不得写成禁读 |
| 明确不做 | 不为单一 basename / 手机端 UI 开专用第三层闸；不把「必须 button.send」写成唯一合法 pattern | — |

相对旧表里「下一步**必须**是精确 grep」：**改软**——与用户「不能定死」对齐。
