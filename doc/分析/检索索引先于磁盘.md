# 检索：索引先于磁盘（同意图不并行慢扫 + 先定目录）

对照对象：定位/查配置时「索引通道」与「磁盘现扫」的调度顺序，以及 `fs_grep` / `fs_glob` 的扫描根宽度。  
目的：缩短墙钟；有索引命中时不白等磁盘；磁盘扫尽量落在相关子树。**不等于**功能放行。

关联真源：

| 类型 | 路径 |
|:---|:---|
| 效率分层 / scopes | [检索范围由LLM决策.md](./检索范围由LLM决策.md) |
| 检索墙钟拆层 | [工具与文本检索速度对照.md](./工具与文本检索速度对照.md) |
| 宽根放行（`/Users` 等） | [检索根过宽仍放行.md](./检索根过宽仍放行.md) |
| 个人知识库 / lore | [功能/个人知识库/说明.md](../功能/个人知识库/说明.md) |
| 逐步问题 | [问题/检索索引先于磁盘.md](../问题/检索索引先于磁盘.md) |
| 规划文案 | `brain/planner.py`；`workspace/fs.py`（`_glob_root_too_broad` 仅挡 `path=/`） |

**已核：** 提示有「先高效、须收窄」；`fs_grep` 默认整 `work_root`；根宽度闸几乎不挡仓内整根；宽检索降质默认关且看命中条数。  
**已确认（用户）：** P0 软提示 + P1 同批 defer；先定目录再搜，尽量不整工作区 `fs_grep`。  
**新证：** 整根 `fs_grep`/`fs_glob` 仍在；模型明示「扩大到整个工作区」；追问易从零宽扫；「服务器进展」被做成本地仓搜。  
**落地：** 宽度闸；整根先 FTS；FTS 空 → **分目录分批 grep**（永不因 miss 扩整仓）；`act_parallel` 索引 defer；规划文案。  
**未做：** 结论文强制钉「检索根」；缩小默认 `FAWAI_WORK_ROOT`。

---

## 1. 现象（新证）

```text
目标：搜索 max_epochs 配置（语境含 insect / cls-vlm）

act_parallel（执行中）
  ├─ fs_grep  pattern=max_epochs     path=/…/ai-company
  ├─ fs_glob  **/*insect*.{yaml,…}   path=/…/ai-company
  └─ fs_glob  **/*cls*vlm*.{yaml,…}  path=/…/ai-company
→ 无 lore_search / work_name；pattern 有项目信号，根却是整 monorepo
```

这比「索引∥磁盘」更直接：**定目录信号已经在 pattern 里，却仍从整仓根扫。**

---

## 2. 现状机制（为何软提示不够）

| 层 | 行为 | 效果 |
|:---|:---|:---|
| 激励 | `act_parallel` 一次 4～8 动作少进模 | 模型倾向「多路宽搜一次打尽」 |
| 默认根 | `fs_grep`/`fs_glob` 的 `.` = 整 `work_root` | monorepo 作工作区时，`.` 已是灾难根 |
| 根闸 | `_glob_root_too_broad` 只拒「恰好 `/` + 字面量过短」 | `/…/ai-company`、`/Users` 都过 |
| 降质闸 | `FAWAI_WIDE_GREP_HITS` 看命中条数 | 挡不住「先扫完整棵树」 |
| 索引 | `lore_search(work_name/work_content)` 已有 | 规划未强制先走；执行不拒宽盘扫 |

与 [检索根过宽仍放行](./检索根过宽仍放行.md) 同一缺口：只读允许定向读仓外 ≠ 允许浅/整根当检索根。

---

## 3. 目标漏斗（已确认）

```text
① lore_search / 正文 FTS（work_name → work_content / lore）
    │ 有命中 → 定向读/改
    ▼ 空
② 定相关目录（name_index / 顶层目录名 / 窄 fs_glob）
    ▼
③ 分批 fs_grep(path=子目录₁…ₙ)  ← 索引 miss 也禁止回退整仓
    │ 仍不够 → 换下一批目录，而不是扩大到 work_root
```

## 4. 好办法排序（按杠杆）

只靠再写一句「请收窄」**已被本证否证**。下面按「改完是否真能挡住新证这类调用」排。

### 4.1 高杠杆（建议作必要项）

| # | 办法 | 做什么 | 为何对这张图有效 |
|:---|:---|:---|:---|
| **A** | **执行层拒整根磁盘检索** | `fs_grep`：`path` 缺失 / `.` / 解析后等于 `work_root` / 浅于约定（`/`、`/Users`、家目录、卷根）→ **拒绝**，文案要求先 `lore_search(scopes=[work_name])` 或给出子目录。`fs_glob`：整 `work_root` 仅当 pattern 含足够字面片段（如已有 `insect`）可放行**或**仍要求先走 `work_name`（更严、推荐先严）。 | 直接打掉 `path=/…/ai-company` 的 `fs_grep`；逼回流漏斗 |
| **B** | **同批 defer：索引先于磁盘** | 批内有 `lore_search` 与 `fs_grep` 时先索引；有命中则取消/跳过磁盘；空则用 hit 父目录改写 `path` 再扫。 | 补「模型仍同批开磁盘」 |
| **C** | **规划软提示对齐漏斗** | 改「缺 path → 优先 fs_grep」为「先 work_name/lore → 定目录 → 窄 grep」；禁止同意图索引∥磁盘。 | 单独不够，但是 A/B 的文案配套，减少拒后乱试 shell |

### 4.2 中杠杆（强烈建议，可与 A 同批）

| # | 办法 | 做什么 | 边界 |
|:---|:---|:---|:---|
| **D** | **`work_name` 作定目录主路径** | 对「项目名/配置名」类目标，能力菜单把 `work_name` 标效率 5、`fs_grep` 整根标禁用；工具测试与规划 search_menu 一致。 | 索引未建/未开 methods 时须降级提示，不能静默 |
| **E** | **拒因与 shell 分流** | 宽根拒绝文案写清「用 lore/子目录，禁止改 shell `grep -r`」 | 避免顶替成更慢的 shell |
| **F** | **运维：缩小 `FAWAI_WORK_ROOT`** | 若日常任务多在 `insect/`，工作区不要挂整个 `ai-company` | 不改代码也降灾难面；与产品多仓切换相关 |

### 4.3 低杠杆 / 慎用

| # | 办法 | 为何靠后 |
|:---|:---|:---|
| G | 从 goal 自动抽 `insect` 改写 `path` | 省一轮但易改错目录；不如拒 + 回灌让模型选 |
| H | 打开宽检索降质（按命中条数） | **不缩短扫描**；本证根因是根宽 |

- 按本案关键词写死「搜 max_epochs 必须去 insect」专用闸

## 7. 远端进展 vs 本地搜寻

```text
用户意图：确认服务器上训练进展
        │
        ├─ 本地有用（窄）：读已授权 SSH/主机配置、远端日志路径、用哪条 ssh shovel
        │
        └─ 本地无用（宽）：整仓 fs_glob(**/*.{yaml,yml,json})、grep max_epochs
              → 既不是当前 epoch，也不是 GPU/进程态
```

正确主路径：凭据/已知 host → `ssh` 查进程、日志、`nvidia-smi`（或既有训练状态铲子）→ 回报进度。  
整仓本地搜配置是**错面**；即使用户先前已搜到相关目录，再扩到整个工作区仍是错上加错。

规划提示须分面：

| 意图信号 | 应走 |
|:---|:---|
| 服务器 / 远端 / 训练是否在跑 / 进度 | 远端观测；本地只定向取连接 |
| 改本地训练脚本 / 查仓内超参定义 | 先索引定目录再窄 grep（本篇漏斗） |
