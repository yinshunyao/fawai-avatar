# 任务取消：及时打断工具与 LLM

对照对象：用户点停止后，进行中的工具调用与大模型问答何时真正停下、结果是否仍被处理。  
目的：缩短「已取消」到 Worker 闲置的墙钟；取消后丢弃未完成调用的结果。**不等于**功能放行。

关联真源：

| 类型 | 路径 |
|:---|:---|
| 任务取消验收 / 协作式边界 | [功能/任务与事件管理/说明.md](../功能/任务与事件管理/说明.md) |
| 停止按钮 / cancelling 进度 | [功能/会话网关/说明.md](../功能/会话网关/说明.md) |
| 逐步问题 | [问题/任务取消响应慢.md](../问题/任务取消响应慢.md) |
| 实现 | `runtime/loop.py`（`_call_cancellable` / `_execute_actions*` / `_halt_if_stopped`）；`runtime/llm_live.py`；`workspace/fs.py`（`subprocess.run`）；`channel/lan_gateway.py`（cancel API） |

**已核：** 功能说明写明协作式取消；LLM 规划等待可提前收束但孤儿调用可继续；shell/`subprocess.run` 不保证强杀；并行工具批无中途取消。  
**用户诉求：** 尽量及时取消操作中的工具和大模型问答；响应结果也不处理；现体感太慢。  
**未核：** 各供应商 chat API 是否支持客户端 abort 后服务端停算；本机 `rg` 被 kill 的残余锁/半写观察文件影响面。

---

## 1. 现象

```text
用户点停止
  → API：status=cancelled，推 cancelling / 「任务已取消」
  → Worker 仍可能：
       · 等整批 act_parallel 的 fs_grep 跑完
       · 等当前 shell / rg 子进程结束
       · LLM 线程/HTTP 在后台继续（主路径已丢弃结果）
  → 界面像「取消了但还在干活」
```

截图类：工具结果卡与「已取消」同秒出现——状态文案已出，阻塞工具未必已死。

---

## 2. 现状分层

| 层 | 现状 | 取消后 |
|:---|:---|:---|
| 总管状态 | `cancel` 立刻写 `cancelled` | 快 |
| 会话 progress | 有 Worker → `cancelling` 再等闭环收束；无 Worker → 直接 `cancelled` | UI 可快，收束慢 |
| 步间 / 动作间隙 | `_halt_if_stopped` / 串行循环读状态 | 间隙可停；**当前动作内不停** |
| LLM 规划 | `_call_cancellable` 轮询 0.2s；取消则 `(None, True)` | **结果丢弃**；线程/HTTP **不杀** |
| LLM 直播 | `LlmLiveProgress` 取消后不再 emit | 只停 UI 直播，不停底层流 |
| 串行工具 | 间隙检查；`subprocess.run` 同步等 | 当前命令常跑完 |
| **并行工具** | `ThreadPoolExecutor` + `as_completed` 收齐 | **整批跑完才返回**；中途不查取消 |

功能说明已诚实写了协作式边界；与用户「及时打断 + 不处理结果」仍有缺口。

---

## 3. 目标口径（待确认后落地）

1. **状态取消后尽快停资源**：进行中的工具子进程、可中断的 LLM 流应尽量 abort，而不是只标 cancelled 干等。  
2. **结果不处理**：取消后返回的工具/LLM 输出不得进入观察回灌、反省、下一步规划、写检查点业务结论（可留诊断日志）。  
3. **不保证**：不可杀的第三方阻塞、已发出的不可逆写（取消不能 undo）；须在边界写清。

---

## 4. 落地切片

下列均为**必要项**时的实施先后；可砍项单独标。

| 序 | 方向 | 说明 |
|:---|:---|:---|
| **P0** | **并行批可取消 + 结果丢弃** | **已落地**：`_execute_actions_parallel` 轮询取消、`shutdown(wait=False, cancel_futures=True)`、未完成槽位 `cancelled`。串行间隙停与 LLM `_call_cancellable` 丢弃仍保持。 |
| **P1** | **磁盘工具可杀** | **未做**：`subprocess.run` 仍可能跑完当前 `rg`。 |
| **P2** | **LLM 流真正 abort** | **未做**：取消后仍可能孤儿 HTTP。 |

### 可选（可砍）

| 方向 | 砍掉后 |
|:---|:---|
| 取消后强制跳过本步工具结果卡的「完成」渲染 | 只保证不入规划；UI 或仍闪一下原始命中 |
| 全局 CancelToken 注入所有 Background 工具 | P0+P1 按 kind 接线也可先验收 |

### 明确不做

- 取消后回滚已成功的 `fs_write`/`fs_patch`（那是 undo，不是 cancel）  
- 为取消去杀非本任务进程  
- 假装协作式已等于强杀（须改实现或改说明）
