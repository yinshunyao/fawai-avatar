# 假归因「超出能力」与节点失败不接管

| 项 | 内容 |
|:---|:---|
| 对照对象 | 计划模式节点失败收束；执行脑 `status=failed` 自述能力边界；编排脑是否自动改图 |
| 目的 | 区分「代码硬闸」与「模型假归因」；说明为何失败后不会有「另一主脑」自动接手 |
| 证据任务 | 父计划 `6917c303ba5d4f84aa24932c755f956c`（节点 `n4` 两次 failed） |
| 关联 | [复杂任务计划模式](../功能/复杂任务计划模式/说明.md)；[完成任务](../功能/完成任务/说明.md)；[主脑委派](../功能/主脑委派/说明.md)；任务复盘 [分析规则](../功能/任务复盘/分析规则.md) |

## 现状

1. **代码侧真实「超出能力」硬闸很窄**：`capabilities.is_beyond_capability` 只匹配实名/支付/破解等少数提示词；创意文案、PPT 脚本**不在**硬闸内。规划提示要求的「超出清单明示 failed」针对的是清单外动作或硬闸命中，不是禁止用 `fs_write` 落 Markdown 文案。
2. **同图对照**：同一父计划上 `n1`/`n2`/`n3` 已用读写文件完成同类「故事脚本 + 互动设计」并 `completed`；`n4` 目标同构却自裁 failed。
3. **`n4` 两轮轨迹**（监管脑 `plan_role=supervisor`）：
   - 首轮子任务：0 次工具，直接 `status=failed`，文案称创意超出 `fs_*`/`shell`。
   - 重试（`retry_nodes`）后：已 `fs_read` 上游 → `fs_write` 完整 `out_n4_pattern_logic_story.txt`（`write_set` 非空）→ 再读回校验 → **仍** `status=failed`，同一套「超出能力清单」假归因。产物已在会话 `shared/`，停条件实质已满足。
4. **节点失败后的调度契约（有意为之）**：`plan_scheduler` 在节点 `ok=false` 时标记节点 failed、**阻塞下游**、父计划 `failed`；**不**自动升编排脑改图。恢复靠手工「重试失败节点 / 整图重规划」或用户追问分流，见功能说明「节点失败默认」。
5. **「交由专用文案 Agent」不存在**：终稿建议的专用创意 Agent / 主脑代写文案，不是现网角色。现有「主脑委派」只是同节点内把机械步交给快模型，失败回灌本节点监管/执行闭环，**不会**在节点 failed 后另起一个文案主脑接管。

## 机制根因（可复用）

| 模式 | 本案表现 |
|:---|:---|
| **真硬闸误伤（工具本身 P0）** | `is_beyond_capability` 裸匹配「破解」→ 故事题「破解魔法桥密码」被当越界；`validate_plan` 禁止 success；`false_beyond` 被真硬闸短路。第三次子任务终稿写「依校验指示…超出能力清单」即此。 |
| **假归因终稿（结果判定）** | 把「清单以工具动作为主」误读成「LLM 不能生成正文 / 须有监管授权工具」；与同图已成功节点、本节点已写入产物矛盾 |
| **有 mutate 仍假失败** | `write_set` 已含目标产物键路径，仍 `failed`（含「编排元概念」变体）；须直接升 success，不能只靠再回灌一轮 |
| **台账闸抢戏** | 监管 goal 常含「路径」等材料词 → path_ledger 先回灌，假归因后置；会加重「分项阻塞=元概念」叙事 |
| **失败不自动升编排** | 设计为阻塞 + 父 failed；不是 bug。用户期望的「别的主脑接管」= 编排脑自动改图，当前未做 |

## 工具双栏（本案）

| 栏 | 结论 |
|:---|:---|
| **工具本身** | **P0**：裸「破解」硬闸误伤 + 假归因闸被短路；清单/校验文案诱发自裁。`fs_write` 本身正常。 |
| **调用** | 首轮零动作自裁；后轮已写齐仍假归因（含元概念变体）。选型应对齐 `n2`/`n3`：写会话产物 → `success`。 |

## 必要 / 可选路径（抽象）

| 路径 | 状态 |
|:---|:---|
| 必要：产出停条件要求的脚本正文并落到约定产物键/文件 | 重试轮**已就绪**却标 failed |
| 必要：向父图回传可衔接 artifact | 因节点 failed 未进入 completed 衔接 |
| 可选：再润色、拆页、做 pptx | 非本节点阻塞点 |

## 建议改法（优先级 = 实施先后）

诱因之一：能力清单硬规则曾写「清单无法覆盖时 status=failed」（compact「清单外目标 status=failed」），模型把「没有创意 skill」误读成整目标越界。

### 必要（已落地）

1. **P0 · 规划提示纠世界模型** — `capabilities_prompt_block`（全文 + compact）写清：清单=选型≠正文上限；授权/租约/产物键非 action_kind；`完成任务/说明.md` 同步。  
2. **P0 · 假失败回灌闸** — `brain/false_beyond.py` + `runtime/loop.py`（识别创意/元概念套话；至多回灌 1 次）。  
3. **P0 · 硬闸去裸「破解」** — 改为「破解软件」等具体词；儿童故事「破解…密码」不再 `is_beyond`。  
4. **P0 · 产物已齐直接升 success** — `should_promote_false_beyond_success`；假归因闸**先于** path_ledger；台账对假归因套话不抢戏。  
5. **P0 · Effort / 监管授权文案** — 全力开禁「无创意 skill」早退；`format_supervisor_goal` 明示运行时兑现元契约。  
6. **P1 · 单测** — `demo_compliance` 覆盖误伤「破解魔法桥」、元概念假归因、promote、台账不抢戏；i18n `phase.false_beyond` 中英已补。

下列均为必要项，编号仅表示实施先后。

### 可选（可砍；砍掉后主验收仍成立）

| 项 | 说明 | 砍掉后 |
|:---|:---|:---|
| 计划模式失败自动升编排脑改图 | 产品策略变更，须另开议题 | 仍靠「重试失败节点 / 整图重规划」 |
| 监管脑产物契约：failed 但 produces 文件已齐则升 completed | 与 promote 闸部分重叠 | P0 promote 已覆盖本案主路径 |
| 专用创意 Agent / skill | 不解决假归因，还扩角色面 | 不做 |

## 明确不做

- 不为「三年级数学 PPT / n4」单独加创意 Agent 或专用 skill 闸。
- 不把「节点失败自动换主脑」偷做成默认行为，除非议题改计划模式失败策略。
- 不以「换更大模型」作为唯一解；本案是硬闸误伤 + 判定与提示词世界模型错误。
- **不**在全力模式下取消能力清单选型约束或真硬闸；清单仍约束 action_kind，只禁止把清单当成「不能生成正文」的上限。
