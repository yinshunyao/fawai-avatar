# 失败反省吃齐证据

对照对象：执行反省主输入 vs 动作段预期闸失败包装。  
目的：异常失败时反省须看到 stdout / expect 前原文 / 工具观察摘要；成功预期路径继续轻量。  
关联：[执行反省](../功能/执行反省/说明.md)、[动作段预期闸](../功能/动作段预期闸/说明.md)、[shell 非零退出掩盖已有输出](./shell非零退出掩盖已有输出.md)。不等于放行议题。

## 原设计为何偏短

动作段 + 预期闸优化的是**成功少进模**；执行反省议题要的是**短裁决**（retry/alternate）。实现上把「工具已失败 → `expect failed: tool not ok`」当成够用标签，原文进 `data.expect_pre_message`，反省主输入却只拼 `result.message`，history 尾巴再砍到约 400 字——长 `cmd` 时真因到不了反省模型。

## 新口径（已落地）

| 路径 | 行为 |
|:---|:---|
| 成功 + expect 通过 | 仍轻量（机械批可跳过 LLM 观察反省；成功结果不堆反省证据块） |
| 工具失败 + expect 文本已命中 | 不改写 message，保留工具原文 |
| 工具失败 + expect 未命中 | `expect failed:…` 写明缺标记，并附「工具原文」 |
| 执行反省主输入 | 失败动作附 pre_message / stdout / stderr / returncode；优先附本步 `format_tool_observation` 摘要；提示词要求根因 grounded |

自检：`demo_action_segment`（`expect_keep_tool_fail_when_marker_hit` / `reflect_evidence_from_data` 等）。

## 明确不做

- 不为某一机房/某一取密脚本写专用闸。
- 不把成功路径也改成「每步反省全文 stdout」。
