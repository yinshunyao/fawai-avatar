# 工具与文本检索速度对照

## 1. 「慢」拆成三层

| 层 | 用户体感 | fawai 现状定性 |
|:---|:---|:---|
| **A. 单次检索算力** | 一次 `fs_grep` / `explore_search` 本身要等 | 有 `rg` 时通常亚秒～数秒；宽 path、无 `--max-count`、fallback Python walk 会拖长 |
| **B. 检索产品能力** | 搜不准 → 多搜几轮 | 无语义仓搜；符号索引启发式 + JSONL 扫描；lore 多为全表子串 |
| **C. 工具闭环回合** | 「点一下工具也要等很久」 | **主因嫌疑最大**：每 1～2 个动作就要再规划一轮 LLM；成功路径还可再跑观察反省 |

业界优秀编码 Agent 的体感快，往往是 **A 够用 + B 少轮次 + C 少 LLM 往返**；fawai 在 A 上已接 `rg`，但 **B/C 与头部产品差距更大**。

## 2. 当前状态（fawai）

### 2.1 文本 / 仓检索

| 能力 | 实现要点 | 速度相关边界 |
|:---|:---|:---|
| `fs_grep` | 优先 `rg --json`；无 `rg` 则 Python `os.walk`+正则 | **不向 `rg` 传 `--max-count`/`-m`**：子进程跑完整趟再解析；`head_limit` 只在解析侧截断 |
| `fs_glob` | 仓内 walk；仓外优先 `rg --files` | 宽根（如只读 `/`）仍易慢 |
| `explore_search` | 多 query 线程池并行 grep；符号 **默认关** | 并行只覆盖「多词同批」；单次仍是完整 `rg` |
| `code_symbols` / `code_map` | 落盘 `symbols.jsonl`；mtime 增量；Python AST + 他语启发式 | **明确不做** SCIP / LSP / Zoekt / 向量语义检索；查询为加载后子串过滤 |
| lore | KV/笔记关键词子串打分；笔记可选 sqlite-vec | 关键词路径：**全量加载再扫**；非 FTS5/BM25 倒排 |

### 2.2 工具调用墙钟结构（单步）

典型成功一步：

```text
observe（可选）→ plan LLM → 串行 execute 1～N actions
  → 工具结果观察回灌 →（常）obs_reflect LLM → 下一轮 plan …
```

| 机制 | 对速度的影响 |
|:---|:---|
| 提示「编码任务每步优先 **1～2** 个 actions」 | 定位类任务易变成「grep → 等 LLM → read → 等 LLM → …」 |
| `_execute_actions` **同批串行** | 即使模型一次给出多个只读动作，也不并行跑 |
| 原生 `tool_calls` 默认开 | 减 JSON 解析摩擦，**不减**「每轮一次 LLM」 |
| `obs_reflect` 默认开（成功工具后） | 多一次快模型调用；思考角色已关，但仍占墙钟与排队 |
| 软闸 / 重规划（铲子、架构声明等） | 触发时整轮 observe→plan→act 加长（见守规对照） |
| 工具观察 soft **默认关** | hits/stdout 全文回灌 → 下一轮 prompt 变大 → 规划更慢 |
| 主脑深度思考（默认开） | 机械检索步仍可能被思考拖慢 → 优先委派快模型（思考关）。固定思考预算不能当提速手段，见 [深度思考固定预算](./深度思考固定预算.md) |

### 2.3 做得怎么样（定性）

| 维度 | 评价 | 说明 |
|:---|:---|:---|
| 有 `rg` 时的单次字面检索 | **中～中高** | 引擎不弱；缺早停与进程级限流 |
| 无索引冷扫 / 宽根 | **偏低** | 与「整盘只读」产品选择绑定 |
| 语义「找到该改哪」 | **低** | 靠模型多轮猜关键词；Cursor 类产品有常驻语义/混合检索 |
| 工具「点一下就返回」体感 | **偏低** | 工具本身往往不贵，贵在前后 LLM 与闸 |
| 同批只读吞吐 | **中偏低** | 失败不掐后续已做；执行仍串行 |

**总判：** 用户骂的「工具和文本检索慢」，多数应拆成：**检索产品少一轮命中 + 闭环每步 LLM 税偏重**；不宜只怪 `rg`。

## 3. 业界优秀做法（对照口径）

| 做法 | 代表取向 | 解决哪一层 |
|:---|:---|:---|
| **常驻混合检索** | 后台建符号 + 向量/分块索引；Query 时 BM25∪embedding，再交 Agent | B：少盲 grep |
| **倒排 / 三元组正则索引** | Zoekt、部分 IDE「Instant Search」 | A：宽正则也亚秒 |
| **LSP / SCIP / tree-sitter** | 精确跳转、引用、符号，而非整仓启发式扫 | B：结构定位准 |
| **工具结果早停** | `rg -m`、流式读到 limit 就杀子进程；会话内结果缓存 | A |
| **一轮多工具并行** | 模型一次发多个 Grep/Glob/Read；运行时并行只读 | C + A |
| **探索子代理** | 只读探仓并行回灌摘要，主代理少踩坑 | C：墙钟用并行换 |
| **机械步用快模型 / 关思考** | 路由检索、压缩、反省与主推理拆开 | C |
| **少反省、按需压缩观察** | 成功路径不默认再 LLM；大 stdout 落盘+指针 | C |
| **预热索引** | 开仓/保存时增量更新，Agent 不 `ensure_index` 冷启动 | A/B |

Cursor 公开叙事偏：**IDE 绑索引 + Agent 工具循环**；相对 fawai，用户少感知「每次从零 rg 猜词 + 每步主脑重规划」。

## 4. 欠缺清单（按杠杆）

下列均为**对照结论**；落地须另开议题放行。

### 4.1 高杠杆（体感差主要来自这里）

| # | 欠缺 | 现状证据 | 业界对照 |
|:---|:---|:---|:---|
| C1 | **每步工具税过高** | 1～2 actions / 轮；成功后再 `obs_reflect` | 一轮多工具；反省按需或规则摘要 |
| C2 | **同批只读不并行** | `_execute_actions` for 循环串行 | 只读池并行；写仍串行/租约 |
| C3 | **无仓级语义/混合检索** | 功能边界写明不做向量仓搜 | Cursor/Continue 等：搜意图 → 少关键词试错轮 |
| C4 | **观察默认全文回灌** | soft 默认 0 | 大结果落盘 + 短摘要入模；按需 `fs_read` |

### 4.2 中杠杆（检索产品与索引）

| # | 欠缺 | 现状证据 | 业界对照 |
|:---|:---|:---|:---|
| B1 | **符号索引非工业级** | 启发式 + JSONL 子串；无 SCIP/LSP | 精确 go-to / find-refs |
| B2 | **无 Zoekt/FTS 类仓索引** | 每次 `rg` 冷扫（有忽略目录） | 预索引正则 |
| B3 | **lore 关键词全表扫** | `list`/`_load` 后子串打分 | SQLite FTS5 / 倒排；向量作补充 |
| B4 | **探仓默认降权且能力窄** | 优先单词 `fs_grep`；explore 仅多词 | 统一「搜索」工具背后自动并行多路 |

### 4.3 低～中杠杆（单次 grep 工程细节）

| # | 欠缺 | 现状证据 | 业界对照 |
|:---|:---|:---|:---|
| A1 | **`rg` 无 `--max-count`，且等子进程结束** | `subprocess.run` 全量 stdout 再 parse | `-m` + 流式早停 |
| A2 | **无会话级 grep/glob 缓存** | 同 pattern 多轮重跑 | 短 TTL 缓存 / fingerprint |
| A3 | **无 `rg` 时 Python walk** | fallback `_grep_python` | 部署依赖强制 `rg`；或内嵌索引 |
| A4 | **宽只读根产品选择** | `FAWAI_READ_ROOTS` 默认可 `/`；浅根（如 `/Users`）的 `fs_grep` 无宽度拒绝，见 [检索根过宽仍放行](./检索根过宽仍放行.md) | 默认定向读可留宽根；检索根须另设宽度闸 |

### 4.4 与「纪律」换速度的张力（不要误砍）

| 机制 | 换来的 | 速度代价 |
|:---|:---|:---|
| 写前铲子软闸 / 架构门 | 可测合规 | 偶发多一轮 LLM |
| 弱写入 / 可见副作用闸 | 少假 success | 收尾多一轮 |
| 能力面比 Cursor 窄 → 更常造铲/临时脚本 | 可观测落盘 | 多 `shovel_search` 与 invent 路径（见工具脚本对照） |

改进时应 **压缩 C 层无效 LLM**，而不是拆掉硬边界闸。

## 5. 效果 / 成本对照（一张表）

| 维度 | fawai（当前） | 业界优秀编码 Agent（典型） |
|:---|:---|:---|
| 字面 grep 引擎 | 有 `rg` 则强 | 同级或更强（+ 早停/索引） |
| 「搜到该文件」轮次 | 模型关键词试错偏多 | 混合检索一轮命中率更高 |
| 每工具墙钟结构 | 工具 ms～s + **规划/反省秒级** | 工具并行 + 规划轮次更少 |
| 符号/引用 | 轻量自研 | LSP/SCIP/树敏 |
| 知识库检索 | 子串 ± 可选笔记向量 | FTS + 向量标配 |
| 合规/租约 | 强（操作分身场） | IDE 场较弱或不需要 |

## 6. 改进思路（未放行；优先级 vs 可选项）

下列若立项，**均为必要方向时的实施先后**（后项仍在范围内）；可砍项单独标出。

### 6.1 必要（按序）

| 序 | 方向 | 要解决什么 | 可能落点 |
|:---|:---|:---|:---|
| P0 | **墙钟拆分仪表** | 先证实慢在 LLM 还是 `rg` | 任务统计：`plan` / `act`/`fs_grep` / `obs_reflect` 分项 `elapsed_ms` 汇总 |
| P0 | **检索步降 LLM 税** | C1 | **已落地**（议题/功能「动作段预期闸」）：多只读一段；机械成功规则跳过 `obs_reflect`；`Action.expect`；机械步委派快模型（思考关）。固定思考预算不作为提速手段，见 [深度思考固定预算](./深度思考固定预算.md) |
| P1 | **`rg` 早停** | A1 | `--max-count` + 可选流式；与 `head_limit` 对齐 |
| P1 | **同批只读并行** | C2 | `_execute_actions` 对只读 kind 线程/进程池；写/ shell / 前台仍串行 |
| P2 | **仓混合检索（窄切口）** | C3/B2 | 工作根内分块嵌入或 FTS；工具 `code_search`；**不做**则须接受多轮 grep |
| P2 | **lore FTS** | B3 | SQLite FTS5；向量保留作语义补充 |
| P3 | **符号索引升级** | B1 | tree-sitter 或可选 SCIP；查询走结构化而非整 JSONL 扫 |

### 6.2 可选（可砍）

| 方向 | 说明 | 砍掉后 |
|:---|:---|:---|
| 会话 grep 缓存 | 同 fingerprint 命中直接返回 | 主验收仍靠 P0/P1 |
| 探索子 Worker 只读并行 | 学 Cursor Task | 单 Worker 并行工具也可先做 |
| 默认打开工具观察 soft | 降下一轮 prompt | 与「hits 全文回灌」产品选择冲突；须单独议题 |
| 强制依赖本机 `rg` | 去掉 Python fallback | 无 `rg` 环境需文档安装 |

### 6.3 明确不建议

- 为提速默认关掉路径闸 / shell 禁绕过 fs。  
- 用「再加长系统提示教模型少搜」替代索引与并行。  
- 无仪表就先上重型 Zoekt 集群（个人分身场过重）。  
- 把个案「某次搜 / 太慢」写成硬闸菜谱。  
- 用固定思考预算腰斩深度思考来省 token 或换墙钟。主脑默认不再注入预算。见 [深度思考固定预算](./深度思考固定预算.md)。

## 7. 一句话结论

**当前：** 单次有 `rg` 的字面检索并不差，但缺早停/预索引/语义混合；**真正拖慢「工具 + 检索」体感的是闭环：每步少动作、串行执行、成功后再反省、观察偏胖，再叠加无语义仓搜导致的多轮试错。**

**以后：** 先用分项耗时证实占比 → 降检索相位 LLM 税与只读并行 / `rg` 早停 → 再谈仓混合检索与 lore FTS；守规硬闸不要为速度拆掉。
