## 1. 先分货架：多数「竞品」不是替代品

直接比「功能谁更多」会比歪。用户往往**同时需要**其中几类；fawai 抢的是其中一类付费/占用动作。

| 工具 | 它是什么 | 主交付 | 和 fawai 的关系 |
|:---|:---|:---|:---|
| **LangChain / Deep Agents** | 开发者 **harness / 库** | 可嵌入的 Agent 骨架（工具循环、子代理、checkpoint 等） | 你要**造** Agent 产品时用它；不是本机常驻分身成品 |
| **Dify** | **LLM 应用搭建平台** | 工作流 / RAG / 可发布的聊天应用与 API | 产出是「给别人用的应用」；不是替你在本机连跑多步操作 |
| **Cursor** | **IDE 内编码代理** | 仓内改码、Plan、diff、索引、终端 | 编码主场极强；仓外 GUI、整机多任务租约、手机指挥本机不是主叙事 |
| **Qoder** | 商业智能体工作台（含 Computer Use） | 编程 + 浏览器/桌面操控 + 生态连接 | 能力面与 fawai 最近的一类；封闭产品、模型与权限策略由厂商定 |
| **WorkBuddy** | 腾讯系 **办公桌面 Agent** | 文档/表格/PPT、本地文件任务、IM 远程入口 | 办公交付强；不承诺开源自改、硬闸与自我升版同一套 |
| **豆包工作** | 字节 **封闭办公套装** | 电脑操作、多模态、技能录制、手机调度 | 体感与生态强；模型锁定、不可自托管改核 |

```text
要搭应用 / API     → Dify（或 LangChain 自研）
要在 IDE 里改仓    → Cursor（或 Qoder 编码面）
要办公出稿 / IM 生态 → WorkBuddy / 豆包
要本机托管干活 + 自有模型 + 可改核 + 硬闸 → fawai 的楔子
```

## 2. 当前版本（0.1.4）实际优势（有评测边界）

评测：**81.3 / A**。含义是「主场景稳；次要短板明确」。优势须停在证据边界内，不把「已支持」写成「任意 GUI 可托付」。

| 优势面 | 0.1.4 已立住什么 | 仍弱 / 未过线 |
|:---|:---|:---|
| **本机操作分身闭环** | 观察→规划→控制→再观察；能力清单选型；文件目标强制 `fs_*`；极速/全力/分档/自动偏好 | 任意 App GUI 未承诺；C3 仅窄场景（TextEdit） |
| **安全硬闸** | 前台 lease、写限 work_root、禁 shell 绕过 fs、Web 出站脱敏 | 未做公证；Windows GUI/AX 不等同 macOS |
| **可恢复任务** | 检查点续跑、从步骤恢复、计划失败节点重试（保留 completed） | 真机同网手机 PWA 本轮评测未补 |
| **编码 / 文件后台** | patch / 检索 / check / Git / Diff / 版本快照；铲子生命周期；任务产物交付 | 相对 Cursor：仓级语义索引、worktree 隔离仍弱 |
| **计划与多任务** | 编排脑出图自动调度；前台串行、后台可并行+写资源仲裁 | 出图质量与人审默认形态未对齐 Cursor Plan |
| **记忆与进化** | lore 混合检索、任务内召回、成败价值台账、Skill imitate/avoid、任务复盘→可勾选改码；Skill/MCP 管理面 | 真 LLM「记一笔」类端到端本轮未强制；自动蒸馏棘轮未做 |
| **分发与模型主权** | 三端消费安装包 + Install 平滑升级；OpenAI 兼容自选模型；中英 PWA | Playwright 未预置进包；公证未做 |

相对 **0.1.3→0.1.4** 的增量叙事：执行模式面、Skill/MCP、成败台账与产物交付、安装平滑升级——抬的是**选型 / 轨迹 / 可监督 / 可扩展**，不是 GUI 托付度。

## 3. 用户「已经有那些工具」仍选 fawai 的真实理由

下列是**同一付费/占用动作上能切走**的楔子，不是功能清单堆砌。

### 3.1 要的是「这台电脑的托管干活」，不是「再建一个应用」

- 已有 Dify / LangChain：擅长沉淀可发布流程与 API。  
- 仍选 fawai：目标是**本机文件、shell、可选浏览器/窄 GUI、多任务租约**，手机发任务、本机干完、断线可续。这是操作分身，不是应用工厂。

### 3.2 要硬边界，不要「模型说已写入就算成」

- Deep Agents 一类路径权限**明示管不到**沙箱 `execute`；商业桌面 Agent 多为产品内策略，难审计。  
- fawai：写盘 / 租约 / shell 绕过 fs / 能力外失败是**闭环硬闸**；问询类有答复覆盖闸防假成功。适合「坏写一次很贵」的本机工作区。

### 3.3 要模型与代码主权，不要锁死生态

- 豆包绑自家模型；多数商业 Agent 闭源。  
- fawai：OpenAI 兼容任选；智能体可改产品树大部分路径（禁改回退/保活/闸门最少核）；运行时版本可存档切版。适合要**自托管、可改、可复盘升版**的人。

### 3.4 要失败后「改自己」的进化链，不只是聊天记忆

- Cursor / 商业产品有 Skills / Memories / 录制技能，但「轨迹 → 全维复盘 → 勾选改产品代码」不是默认主场。  
- fawai：任务复盘（工具优先口径）→ Skill / lesson / 规则 / 提示 / 代码；铲子先搜台账再生；与执行中反省同一进化链叙事。适合把助手当**可演进运行时**，而不是只会会话内变聪明。

### 3.5 要复杂任务的调度语义，不是单会话待办

- Cursor Plan 强在人审；Deep Agents 强在同上下文待办与隔离子代理。  
- fawai 计划模式：依赖图 + 监管脑节点 + 前台互斥 + 失败节点重试保留已完成。适合「多段可并行、键鼠不能并行」的本机长任务。

### 3.6 编码要对齐 Cursor，但入口不绑 IDE

- 后台编码闭环刻意学 Cursor（patch、check、Diff、守规注入）。  
- 入口是 PWA / 网关：不在 IDE 前也能下目标、看步骤流、从步骤恢复。适合「人不在电脑前，机子在干活」。

## 4. 什么时候不该推 fawai（避免假优势）

| 用户真实目标 | 更该用 | 原因 |
|:---|:---|:---|
| 给团队/客户发布稳定 AI 应用或 API | **Dify**（或自研 + LangChain） | fawai 不是 BaaS / 工作流发布平台 |
| 人盯着仓改代码、要 IDE 索引与 diff 人审 | **Cursor** | 编码接地仍是 IDE 产品更强；fawai 是对齐而非替代 IDE |
| 只要办公出稿、腾讯/字节 IM 生态一键通 | **WorkBuddy / 豆包** | 生态与多模态体感当前更完整；fawai GUI 仍窄 |
| 只想调库拼 Agent，不要运维常驻进程 | **LangChain / Deep Agents** | fawai 是整机产品，不是 SDK |
| 任意桌面 App「点哪都准」已是刚需 | 商业 Computer Use（豆包 / Qoder 等）或等 fawai C3 扩面 | 0.1.x 评测明示 GUI 接地仍缺，不得对外吹满 |

---

## 5. 一句话选型

**别人用聊天应用、IDE Agent 或办公 Agent；选 fawai 是因为要一台可自托管的本机操作分身：硬闸门、可续跑、可复盘改核、模型自选，且入口可以是手机。**

当前诚实卖点停在 **A 档主场景骨架**：后台文件/编码、执行模式与扩展面已可用；**不要**用「已有安装包 + lore」暗示任意 GUI 或全面碾压豆包/Qoder/WorkBuddy。下一刀若要抬「可托付」叙事，优先补真机同网、真 LLM 自我改进核心与 GUI 接地证据（见 v0.1.4 优先改进），而不是再堆对标功能名。
