# 修改与产物浏览预览

对照对象：Cursor 式 diff 审阅；手机/他端浏览器预览本机任务产物。  
目的：在已有「会话 Diff + 附件卡 + `/media`」之上，厘清浏览体验缺口与跨端预览策略。  
关联：`doc/功能/06-工作区与编码/04-编码闭环/说明.md`、`doc/功能/02-任务线/05-任务产物交付/说明.md`、`doc/问题/02-任务线/01-任务产物目录与预览.md`。

## 现状

| 面 | 已有 | 相对目标的缺口 |
|:---|:---|:---|
| 代码修改 | 写后 `phase=diff`；步骤卡内 unified diff 行着色；`confirm` 口令确认 | 非 Cursor 审阅：无文件清单侧栏、无 hunk 折叠导航、无卡上接受/拒绝按钮；大 diff 截断（约 200 行 / 进度体 ~2500 字） |
| 文档/办公产物 | `kind=file` 卡；图/音视频/PDF 页内；pptx/docx/xlsx **文本摘录**；另存 + Range | md 预览走 `<pre>` 未用会话 Markdown；办公非版式级；`.ppt/.doc/.xls` 弱 |
| 跨端 | 产物拷入 `session_media`，经 `/media` / `/preview` 取；禁止只给本机绝对路径 | 预览深度绑定「浏览器能吃什么」；他端无法依赖本机 Word/PPT |

产品边界（已定）：不对齐 IDE Tab/内联编辑；办公不承诺像素级 PPT 引擎。本分析谈的是**浏览/审阅加深**，不是替代 IDE。

## 跨端预览原则（推荐）

核心一句：**他端只消费「浏览器可渲染的投影」；原件另存；本机绝对路径永不作出站真源。**

1. **通道**：继续 LAN 网关（及可选隧道）上的 `/media` + Range；预览元数据走 `/media/{name}/preview` 懒加载，避免大文件塞进历史。
2. **投影分层**（按成本升序）：
   - **原生可渲**：图、音视频、PDF → 直接 `iframe` / media 标签（现状保留）。
   - **轻转换**：`.md` → 现有 Markdown 渲染；`.csv`/小表 → HTML 表；代码/文本 → 语法着色或 monospaced。
   - **服务端投影（跨端关键）**：pptx/docx/xlsx 在**主机**交付时（或首次预览时）生成旁路产物：`*.preview.pdf` 或 `*.preview.html`（及可选幻灯片缩略图），他端只打开投影；原件仍可下载。比嵌 OnlyOffice / 依赖手机 Office App 更贴本产品（主机有算力与依赖，手机只是遥控器）。
   - **降级**：转换失败或体量过大 → 文本摘录（现状）+ 明确「仅摘录」+ 另存。
3. **禁止当主路径**：指望他端系统「用本地 App 打开」；把未脱敏仓路径写进气泡；整包 Office 二进制塞进 WebSocket 历史。

## Diff 浏览（推荐形态）

对齐 Cursor 的是**审阅手感**，不是 IDE：

| 必要（实施先后） | 说明 |
|:---|:---|
| P0 结构化 diff 卡 | 文件路径 + `+n/-m`；hunk 可折叠；行着色保留；截断时「展开全文」走懒加载（媒体或任务附件存完整 unified / hunk JSON） |
| P1 任务改动清单 | 本任务 `write_set` 聚合入口，点文件打开对应 diff（对话内侧栏或气泡挂载），避免只在步骤流里刷过 |
| P1 confirm 控件 | `FAWAI_DIFF_MODE=confirm` 时卡上「接受 / 拒绝」按钮（仍可保留口令）；窄屏热区够大 |

可选（可砍）：左右分栏、按 hunk 接受、语法高亮主题。砍掉后主验收仍成立：可读完整改动 + 跨端同卡。

## 文档产物预览（推荐形态）

| 类型 | 本机 / 同网浏览器 | 跨端要点 |
|:---|:---|:---|
| Markdown / 纯文本 | Markdown 渲染 + 目录锚点 | 同；大文件懒加载分段 |
| PDF / 图 / 音视频 | 页内 | 已通；注意移动端 PDF 用浏览器能力或服务端翻页图 |
| pptx / docx / xlsx | 优先 **主机转 PDF/HTML 投影**；摘录作降级 | 他端永远打开投影 URL，不依赖 Office |
| zip | 列文件树 + 内嵌文本/小图可点开 | 树与内嵌预览均经 `/media` 子资源 |

## 与现能力关系

- 不推翻 `file_deliver` / `/media` / 附件卡；加深的是 **预览投影** 与 **diff 审阅 UI**。
- 编码闭环边界不变：人要深度仓内审阅仍可导向本机 IDE；会话内目标是「跨端也能看清改了什么、交了什么」。
