## 1. 问题钉死

缺的不是「再记一遍」，而是 **工作记忆有损之后的分页取回**。

```text
完整 history / observe dump / 检查点   ← 盘上还在
        │
        ▼  plan_history（有损）
近窗全文 + 远窗/compact 摘要     ← 进规划
        │
        ✗  Agent 无法按关键词/步骤把压掉的原文捞回
```

典型缺口：

| 缺口 | 表现 |
|:---|:---|
| 工具正文被近窗省略 / 远窗只留 path | 「刚才 grep 命中第几行」说不清，又不敢再读（见禁读分析） |
| 用户追问/澄清进了更早消息 | 近窗外；模型当没说过 |
| compact 只留结论 | 结论未写的细节（端口、字段名）丢失 |
| 与仓检索错位 | `lore_search`/`fts_search` 搜的是工作区/笔记，**不是**本任务对话轨迹 |

这是 MemGPT 意义上的 **Recall（本会话可搜）**，优先于跨任务 archival。

## 2. 建议做法（必要项按实施先后；后项仍在范围）

### 2.1 必要

| 序 | 做什么 | 为何 |
|:---|:---|:---|
| **P0** | Agent 工具 **`task_context_search`**（名可再定）：**仅当前 `task_id`**；query → 命中列表（step / role / 时间 / 短摘要 / 指针） | 主动分页；不扩近窗烧 token |
| **P0** | **`task_context_get`**：按 `msg_id` / `step` / `observe_path` **回灌原文或定向片段**（设硬顶+落盘指针） | search 只指路；get 才取证；对齐「正文不在上下文须再取」 |
| **P0** | 规划提示补一句：远窗/compact **没有**的本任务事实 → 先 `task_context_*`，文件类再 `fs_read`；禁止因「曾经读过」直接 `failed` | 与 [禁读与工作记忆](./禁读与工作记忆.md) 同向 |
| **P1** | 索引面结构化：每条信封带 `step`、`kind`（user/assistant/tool）、抽出的 `paths`、可选 `observe_dump` | 提高命中；少靠整段糊搜 |
| **P1** | 写入路径：工具结果若已 dump 到 `observe/`，search 命中优先回 **dump 指针**，get 读文件切片 | 避免把巨型 hits 再塞进 history 索引副本 |

### 2.2 实现形态（推荐）

同任务规模通常远小于整仓，**不必先上向量**。

```text
推荐真源（只读本任务）：
  ① runtime 内存 / 检查点里的 history 副本
  ② 同 task 的 session 信封（与 Web history API 同源字段）
  ③ 本任务 observe dump 路径列表（meta 或从 history 抽）

检索：先 子串/简易 FTS（任务私有 SQLite 或内存倒排）
合并：新近度加权（同 query 更偏近步）
禁止：扫整个 data/；禁止默认搜其它 task_id
```

| 方案 | 评价 |
|:---|:---|
| A. 每轮把全 history 塞回 prompt | **否**：与现有窗冲突，成本爆 |
| B. 只加大 `FAWAI_HISTORY_KEEP_RECENT` | **不够**：治标；长任务仍溢出 |
| C. 复用 `lore_search` 扫笔记/工作区 | **错面**：答非所问 |
| D. 本任务 search + get（上表） | **建议主路径** |
| E. 同任务向量 | **可选后置**；词法够用再上 |

### 2.3 可选（可砍）

| 项 | 说明 |
|:---|:---|
| 命中后自动把短摘注入下一轮规划 | 省一轮工具；误召回风险更高，可砍 |
| 跨任务 `recall_search` | 另议题；**不要**和本任务上下文绑死同一工具默认范围 |
| 对 compact 摘要建反向链（摘要句 → 源 msg） | 锦上添花 |

### 2.4 明确不建议

- 用「禁止再读」代替「可查询上下文」。  
- 把本任务全文每轮灌进 system。  
- 为任务上下文去 **再扫** `memory_index` / 整个 `data/`。  
- 首期就做跨任务 + 同任务混搜且默认不按 `task_id` 过滤（串味）。

## 3. 与现有部件怎么接

| 已有 | 关系 |
|:---|:---|
| `plan_history` / compact | **继续做工作记忆压缩**；查询工具补「外存分页」，不替代窗 |
| `step_todos` | 仍钉「待办状态」；细节证据仍靠 context_get |
| `GET /api/tasks/{id}/history` | Web 已有按任务拉全量；Agent 侧应对齐同一事实源，加 **搜+切片**，不要只暴露给人看 |
| `fs_read` / `fts_search` | 管**文件**；`task_context_*` 管**本任务说过/工具回过什么** |
| `lore_search` | 管工作区/笔记知识面；默认 **不** 混进 task 信封 |

## 4. 验收口径（若立项）

1. 人为把关键证据压出近窗后，模型能用 `task_context_search` 找回含该事实的步骤指针。  
2. `task_context_get` 能取出足够作答/改写的原文片段（或明确「仅有 dump 路径」再读文件）。  
3. 不得只因「历史里出现过同 path」且正文已不在上下文就 `failed`。  
4. 工具默认范围 = 当前 task；试图查别的 task 须显式参数且默认拒绝或另开权限。

## 5. 追问案复核（`6d71d772…`）

首轮已 `completed` 并写出训练进度结论；多次【追问】「预估什么时候训练结束」后反复 `cancelled` / 沙箱 SSH 失败。

| 层 | 结论 |
|:---|:---|
| 表面 | 「追加后连不上 4090」 |
| 工具本身 | search 有时真 0（live 空窗）；有命中时观察仍是 `?:?:`，等价于搜索对规划不可用 |
| 调用 / 路径 | 必要路径应是「用已有进度外推（可标陈旧）」；轨迹把「再 SSH」当刚需，并用错误凭证源 |
| 对「任务内搜索是不是太差」 | **部分成立**：不是「词法算法一无是处」，而是 **语料未垫齐 + 命中观察契约坏了**，体感上等于太差 |

通用优化（未改代码；立项后再动）：

1. **P0 工具** `_render_hits`（或分工具分支）识别 `summary` / `snippet` / `msg_id`，禁止空 `?:?:` 冒充命中正文。  
2. **P0 工具** `task_context_*`：live override 若过薄，与 `prior_context_messages` / 检查点 **并集** 再搜，禁止「只搜追问句」。  
3. **P1 闭环** 状态/预估类 goal：答复覆盖闸认「已有进度数字可外推」；未读配置真源前勿把远端 shell 失败写成唯一终局。

## 6. 一句话

**同任务上下文查询 = 给有损历史窗配 Recall：`search`（本 task）+ `get`（回灌/指针），先词法、后可选向量；命中必须对规划可读，live 窗不得盖掉 prior。**
