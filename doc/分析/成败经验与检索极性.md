# 成败经验与检索极性

对照对象：工具调用 / 任务执行轨迹 → 可检索记忆；以及 `skill_search` / `shovel_search` / `lore_search` / 跨任务 recall 对「好经验 vs 坏经验」的区分。  
目的：回应「搜到操作面做法却不知好坏、一味借鉴」——钉清缺哪一层、可用办法是什么；**不等于**功能放行。

**已核：** 同任务 history 含工具 `ok`/失败文；复盘 `apply_review_plan` 可写 `skill`/`lesson` 并打 `success`/`failure` 类 tags；`skill_search`/`shovel_search` 为子串打分、**不按 outcome 加权**；铲子文首已有设计态三维分（完备/通用/效率）但**不进排序、非运行成败**；跨任务无 Agent 情节索引；E1 不做任务结束默认自动蒸馏。  
**未核：** 外部产品「Memories / lessons」内部是否区分极性加权（按公开口径理解即可）。

**本轮增量判断：** 「给工具/铲子加一维全局评价 + 调用时必须对照当前任务」——**对铲子可行且比经验卡更简单**；对内置工具不宜同一套全局分。详见 §3.0。  
**落地状态（P0）：** 已写入功能 [成败经验与检索极性](../功能/成败经验与检索极性/说明.md)（Skill 极性分栏、铲运行成败账、`【成败对照】` 软闸）；经验卡 / 跨任务 recall 仍未放行。

## 1. 问题钉死（三层，不是一层）

体感「没有记忆、搜到就抄」拆开是三件事叠在一起：

| 层 | 缺什么 | 表现 |
|:---|:---|:---|
| **写路径** | 成败很少进入可搜外存 | 轨迹在任务 history / `meta.steps`；任务结束默认不晋升；复盘才写 Skill/lesson，且要人手选 |
| **检索极性** | 命中只按相关度，不按「该学还是该避」 | `failure` lesson 与 `success` skill 关键词撞上时同分；铲子三维分只在元数据、不进排序 |
| **消费方式** | 规划提示未强制「先判极性再借鉴」 | 模型把搜到的步骤当正例；反模式未标成 `AVOID` / `do_not_imitate` |

只抬 hybrid / 向量库，**解决不了**「好坏不分」；只加长提示「请记住成败」，也解决不了——没有可检索、带极性的条目可记。

与总对照的对应：情节跨任务弱 = M4；注入缺来源 = M7；程序记忆检索软 = M8。本篇补的是 **M8 的 outcome 维** + **轻量情节卡**（不必等完整 `recall_search` 才能止血）。

## 2. 现状（实现口径）

```text
任务执行
  → history / meta.steps（含工具 ok·失败）     ← 有信号，多数不可跨任务搜
  → 任务 status / review_outcome（复盘后）     ← 写在源任务 meta，检索不用
  → 默认：不自动蒸馏 Skill
  → 按需复盘：skill | lesson + tags(success|failure…) + source=tasks:…
       ↓
skill_search / shovel_search / lore_search     ← 相关度；无 outcome 加权、无极性栏
       ↓
规划借鉴                                      ← 易当正例抄
```

| 面 | 有无成败 | 能否被搜到 | 极性 |
|:---|:---|:---|:---|
| 同任务 `task_context_*` | 文里有 ok/失败串 | 仅本任务 | 无专门字段 |
| 跨任务任务列表 | status 在 blob | Web/`lore` task 通道子串 | 不排序 |
| Skill/lesson | tags 可含 outcome | 子串 | **不加权** |
| 铲子台账 | 无调用成败账 | 子串 | 三维分不进分 |
| lore 笔记 | 作者手写才有 | hybrid | 无统一 schema |

## 3.0 更简单切口：台账「成败维」+ 选型必看（本轮确认）

相对完整经验卡，先在**铲子（及同类可登记程序记忆）**上加一维**运行评价**，并在选型/调用前强制对照当前任务——实现面更小，且直接打中「搜到就抄」。

### 3.0.1 两套分不要混

| 维 | 含义 | 现状 |
|:---|:---|:---|
| **设计态三维**（完备/通用/效率） | 作者自评：脚本写得怎样、能不能进公共铲 | 已有；**不进** `shovel_search` 排序 |
| **运行态成败维**（建议新增） | 实际调用：近窗成功率 / 近失败摘要 / 极性提示 | **无** |

成败维才是「好不好用」；三维分是「该不该进台账」。二者并列，禁止用三维分冒充成败。

建议字段（落在旁路账或台账扩展，不必改脚本头每次手填）：

| 字段 | 说明 |
|:---|:---|
| `calls_ok` / `calls_fail` | 近 N 次或累计计数 |
| `rate` 或档位 | 如 `good` / `mixed` / `poor` / `unknown`（样本不足） |
| `last_fail_one_liner` | 最近失败一句（可选） |
| `updated_at` | 账龄；过旧降权 |

### 3.0.2 铲子 vs 内置工具

| 对象 | 是否适合「全局评价」 | 原因 |
|:---|:---|:---|
| **铲子 / Skill / lesson** | **适合** | 条目少、可登记、失败常与「这个脚本/这篇做法」绑定 |
| **内置工具**（`fs_grep`、`shell`…） | **不适合单分数全局踩死** | 失败几乎总是参数/cwd/目标错；`fs_grep` 全局 low 会误伤所有检索 |

内置工具若要记经验：记在**用法模式 / 经验卡 / lesson**（「整仓盲 grep」），不要给工具 id 打永久差评。

### 3.0.3 「必须根据当前任务考虑」怎么落地

只挂一个全局分、却不接消费层，模型仍会忽略。最小闭环：

1. **`shovel_search` 命中带出成败维**（与三维分并列展示）。  
2. **规划软闸（提示级，必要）**：选铲 / 造临时脚本前须 `shovel_search`（已有）→ 命中后须对照 **当前 goal**：`poor`/近失败与本任务同槽则优先换道或改参，禁止无视差评照抄 invoke。  
3. **硬闸（可选）**：样本足且 `poor` 时拒「无改参原样复用」；默认先软闸，防误伤。

「对照当前任务」= 看 **goal 槽位是否与 `last_fail` / when_to_use 同构**，不是只看数字高低。全局分是先验；任务对齐才是裁决。

### 3.0.4 与经验卡主线的关系

| | 台账成败维 | 经验卡 |
|:---|:---|:---|
| 粒度 | 按铲/Skill **条目**聚合 | 按 **任务结局 × 工具链** |
| 复杂度 | **低**（计数 + 展示 + 软闸） | 中（签名、合并、TTL、专搜） |
| 覆盖 | 台账内条目 | 未升铲的临时链、跨工具失败模式 |

**修订优先级：** 铲子侧把原 P2「成败轻账」**前移为与 Skill 极性并列的 P0/P1 简切口**；经验卡仍保留，专治「没登记进台账的链」与跨任务相似目标，不挡这条简刀先落地。

## 3. 完整主线：经验卡 + 检索极性（仍有效，可后置）

业界可抄的不是「再蒸馏一整本 Skill」，而是：

1. **薄条目、结构化、可机读极性**（experience / episode card）  
2. **检索与注入时显式分栏**：`imitate` vs `avoid`  
3. **完整程序记忆仍走人审复盘**（与现有「不做默认自动蒸馏」一致）

### 3.1 经验卡（写路径，轻）

任务终态（success / failed / cancelled 可定策略）写一条**短卡**到独立库或 lore 的固定 kind，**不**自动升成完整 Skill 步骤书。建议字段：

| 字段 | 作用 |
|:---|:---|
| `goal_sig` | 目标摘要 / 槽位签名（去路径噪声），供相似召回 |
| `outcome` | `success` / `failure` / `mixed` / `cancelled` |
| `polarity` | 派生：`imitate` \| `avoid`（failure→avoid；success→imitate；mixed 可拆两条） |
| `tool_chain` | 关键工具名序列（短） |
| `one_liner` | 一句「做成了什么 / 踩了什么坑」 |
| `source_task` | task_id + 时间（provenance） |
| `confidence` | 启发式：终态明确高；中途假成功经闸改判可降 |

与复盘分工：

| | 经验卡 | Skill / lesson（复盘） |
|:---|:---|:---|
| 时机 | 任务结束可自动（薄） | 人勾选后写（厚） |
| 内容 | 签名 + 极性 + 一句 + 工具链 | `when_to_use` + 可执行 steps |
| 污染风险 | 低（可 TTL / 同签名合并） | 高 → 故默认不自动 |

**明确不建议：** 每任务自动 `skill_write` 整篇步骤（与自我进化边界冲突，易污染程序记忆）。

### 3.2 检索极性（读路径，关键）

凡能返回「可执行做法」的入口，命中须带极性，排序与展示分开：

| 规则 | 说明 |
|:---|:---|
| **分栏合并** | 结果分 `imitate[]` 与 `avoid[]`；禁止混成一张「相关度榜」让模型当同一类抄 |
| **outcome 加权** | 同关键词下：带 `failure`/`lesson`/`avoid` 的条目进 avoid 栏；success/skill 进 imitate |
| **铲子** | 台账三维分可作次级排序；另可选「近 N 次调用成败」计数（有账才有） |
| **注入文案** | avoid 前缀固定为「勿模仿 / 已知失败模式」；imitate 为「可参考成功路径」 |

`skill_search` 最小改动即可先止血：读 tags / kind（`lesson` vs `skill`）→ 分栏 + 提示；不必等经验卡库上线。

### 3.3 规划消费（闸，轻）

在已有「先搜铲子 / Skill」软闸旁加一条语义约定（提示级即可，硬闸可选）：

- 命中 `avoid`：**禁止**把 steps 当本轮计划骨架；须换道或显式说明为何不适用。  
- 命中 `imitate`：可借鉴；仍须对当前 goal 做槽位对齐（防抄错环境）。

这与复盘「假成功 / 方法族未换道」口径同向，只是把结论前置到**检索结果形态**。

## 4. 与其它记忆刀的关系

| 方向（总对照） | 对本问题的贡献 |
|:---|:---|
| P1 跨任务 `recall_search` | 经验卡可先做「结局索引」子集；完整情节正文后置 |
| P1 provenance | 卡上 `source_task`；注入可点回任务 |
| P3 Skill/铲子进 hybrid | 抬召回；**仍须**极性分栏，否则召回越好越会抄坏例子 |
| Core blocks | 钉偏好，不替代成败情节 |
| 小模型 Rerank | 可选；极性分栏比纯分值更重要 |

### 5.2 可选（可砍）

| 方向 | 说明 |
|:---|:---|
| 经验卡向量通道 | 签名相似召回；词法够用可砍 |
| avoid / poor 硬闸 | 易误伤；先提示级 |
| 自动从失败卡升 lesson 草稿进复盘队列 | 仍须人审 apply |
| 内置工具全局差评分 | **不建议**；见 §3.0.2 |
| 小模型对「是否同构失败」分类 | 后置 |

### 5.3 明确不建议

- 任务结束默认自动蒸馏完整 Skill（污染程序记忆）。  
- 只靠更长系统提示「请记住上次失败」。  
- 检索仍一张相关度榜，把 lesson 当操作手册抄。  
- 用整段 history 灌进下一任务 prompt 代替可搜经验卡。  
- 给 `fs_*` / `shell` 等内置工具打永久全局低分代替用法 lesson。  
- 用设计态三维分冒充运行成败维。

## 6. 一句话结论

**P0 已落地：铲子运行成败维 + Skill imitate/avoid 分栏 +【成败对照】软闸。**  
经验卡补「没进台账的链」仍属后置。不要给内置工具打全局生死分。厚 Skill 仍走人审复盘。
