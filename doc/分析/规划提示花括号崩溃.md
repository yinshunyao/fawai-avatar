# 规划提示花括号崩溃

长系统提示在拼进 f-string 时，示例 JSON 的花括号未转义，大脑在调用模型之前就抛 `ValueError`。会话上的「规划中」因此没有正文，下一步直接进入执行反省。本文件只记录机制，不等于功能放行。

## 现状

`brain/planner.py` 的 `_system_prompt` 有两套 f-string。精简档里 expect 示例一直写成 `{{"contains":"…"}}`。全量档同一句曾写成未转义的 `` `{"contains":"…"}` ``：f-string 把 `"contains"` 当成表达式、把 `"…"` 当成格式说明，组提示时即 `ValueError: Invalid format specifier '"…"' for object of type 'str'`。规划模型还没有 token，闭环记成 `phase=plan` 的步骤崩溃，再走执行反省。反省只看见这句异常，容易说成「参数里的引号」。

全量档这一处已与精简档对齐，示例在提示正文里仍是 `` `{"contains":"…"}` ``。未改之前，凡走全量档的任务都会在同一步重复崩溃。

## 会话上为什么是空的

「规划中」卡片对应的进度只有占位句「大脑规划中（等待模型）…」，没有 `thinking_text` / `content_text`，也没有随后的「规划完成」。页面按进行中的规划相位只画徽章和步骤标题，正文要等思考流或规划完成才出现。所以空卡是没有规划产物，不是把已有正文藏起来。异常原文出现在下一张执行反省上。

## 改动

全量档动作段那句的花括号改为 `{{` `}}`，与精简档相同。组提示不再抛格式说明错误；模型看到的仍是 expect 示例 JSON。
