## 1. 先分清：弱的是「记忆系统」，不只是「搜得慢」

业界近两年反复强调一句：**Agent memory ≠ RAG。**

| | RAG | Agent 记忆 |
|:---|:---|:---|
| 主义务 | 从外部语料取证、 grounding | 跨回合/跨会话保留**可演化状态** |
| 写路径 | 通常人/管道更新语料 | Agent 或旁路要能 **写入、覆盖、失效、删除** |
| 难问题 | chunk、混合检索、引用 | **晋升、作用域、冲突、遗忘、溯源** |
| 向量库角色 | 基础设施 | 只是 archival 的一种索引，不是记忆策略本身 |

fawai **主知识面**已从「轻量子串 RAG」升到 **hybrid 预索引 + 可写笔记/Skill**；短板更多在 **记忆生命周期与情节面**，而不是「完全不会搜文件」。  
体感「记不住」仍会同时表现为：跨任务不会主动 recall、core 偏好没钉住、同类错再犯、仓内语义定位仍靠 grep/符号。

## 2. fawai 现状（按记忆类型拆）

业界常用四分法（CoALA / MemGPT 同族）：**工作 / 情节 / 语义 / 程序**。

| 类型 | 业界要装什么 | fawai 现状 | 强弱 |
|:---|:---|:---|:---|
| **工作记忆** | 本轮 prompt 预算内：目标、近窗、注入块 | 系统提示 + hybrid 知识摘要 +【索引配置】+ Skill/规则 + 压缩 history | 有；注入已跟 hybrid，预算与驱逐仍粗；正文被压掉后若仍禁再读，任务会被判死（见 [禁读与工作记忆](./禁读与工作记忆.md)） |
| **情节记忆** | 会话/任务轨迹可搜；驱逐前摘要 | 任务 history 落盘；规划用近窗+远窗摘要；跨任务仅 Web `tasks?q=` 子串 | **仍偏弱** |
| **语义记忆** | 事实/偏好/实体关系；时效与覆盖 | 笔记 FTS/向量进主搜；短 KV 退出主搜；旁路默认关 | **检索已抬**；写路径仍在；缺时效/冲突策略 |
| **程序记忆** | Skills / 规则 / 工具选用策略 | Skill + 铲子台账 + 规则；检索仍子串 | 中；沉淀靠按需复盘，默认不自动蒸馏 |

另外两条常被业界当成「检索面」而非纯记忆：

| 面 | fawai | 业界编码 Agent |
|:---|:---|:---|
| **仓证据检索** | hybrid 正文/文件名 + `fs_grep` + 符号 `code_index` | 常驻符号 + **混合语义**仓搜 + LSP |
| **工具/台账检索** | `shovel_search` / `skill_search` 子串 | MCP/Skills 描述 + 更宽内置工具面 |

**总判：** 主知识 **Hybrid 已落地**（亮点）；弱在 **情节可搜、core 块、事实时效、仓语义面、程序记忆检索档次**——不是「完全没记忆 / 完全没混合检索」。

## 3. 业界好思路（可抄架构，不必抄产品名）

### 3.1 MemGPT / Letta：把上下文当 OS 内存

```text
Core memory（钉在上下文的可编辑块：人设/偏好/当前目标）
  ↕ 模型用工具分页
Recall（对话历史可搜）  +  Archival（外存：向量/库/图）
```

要点：

1. **钉住的块**（core）≠ 整库灌进 prompt；块可由 Agent **显式改写**。  
2. **主动检索**：模型决定何时 `search_recall` / `search_archival`，而不是每轮只靠被动关键词注入。  
3. 上下文满了：**驱逐 → 摘要 → 外存**，不是静默丢掉。

对 fawai：hybrid + 规划注入已接近「archival 可搜」；仍缺 **窄 core blocks** 与 **recall 工具**。`lore_search` 与注入同引擎时，工具易成重复劳动（见 [lore检索工具意义](./lore检索工具意义.md)）。

### 3.2 混合检索（Hybrid），别只押向量

成熟做法几乎都是：

| 通道 | 擅长 | fawai |
|:---|:---|:---|
| **词法**（BM25 / FTS5 / `rg`） | 标识符、报错原文、专有名词 | **已有**：正文/笔记 FTS + `fs_grep` |
| **向量** | 同义改写、「上次那种偏好」 | **已有**：笔记向量 |
| **结构**（符号/LSP/图） | 谁调用谁、实体关系 | **部分**：`code_symbols`；无图 |
| **元数据过滤** | 用户/项目/启用态/时间窗/来源 | **弱**：启用态有；时效/provenance 弱 |
| **文件名/路径** | 规范命名时的第一召回 | **已有**：name index（Everything 同族） |

排名信号常见：**相关度 × 新近度 × 作用域 × 置信度**；再 Rerank（可选小模型）。  
fawai 现为 **通道基分 + 本地分 + 保底配额**；**尚未**统一 rerank / 新近度加权。

### 3.3 写路径与生命周期（比「多一个向量库」更重要）

生产向清单（公开架构共识）：

1. **晋升**：何时从对话 → 缓冲 → 语义事实（fawai 有缓冲/旁路开关；旁路默认关）。  
2. **冲突**：覆盖 / 追加 / **带时效的 supersede**。  
3. **作用域**：用户 / 项目 / 会话 / 全局。  
4. **遗忘**：一处 `forget` 同步清各索引。  
5. **溯源**：注入条目带来源任务/消息。  
6. **评估**：有无记忆的任务成功率；误召回——不只测检索 MRR。

对 fawai：启用/停用/删除与索引重建已有；缺 **时效版本、冲突策略、跨任务情节检索、注入 provenance**。

### 3.4 编码场特化：仓记忆 vs 用户记忆

| 套 | 内容 | fawai |
|:---|:---|:---|
| **Codebase memory** | 符号 + 分块嵌入；一次语义定位 | 符号有；**仓向量/混合 code_search 无**（正文靠 FTS/`rg`） |
| **User/project memory** | 短偏好/约定（core blocks） | 笔记 hybrid 有；**钉住的 core 块弱** |

操作分身还多一层：桌面/路径类短事实（适合精确 get，不宜主搜）与可执行铲/Skill。

### 3.5 GraphRAG / 知识图（可选，后置）

关系问句用图更稳。个人分身场：**先 hybrid（已有）+ core blocks**；图后置。

### 3.6 程序记忆闭环

fawai：Skill + 铲子已有；**默认不自动蒸馏**。提检索质量时，宜抬 **`when_to_use` / 台账 hybrid**，而不是重开全自动棘轮。

## 4. 欠缺对照（相对上述思路；已按实现修订）

| # | 欠缺 | 现状 | 业界锚点 |
|:---|:---|:---|:---|
| M1 | **无明确 core memory 块** | 规划注入 hybrid 命中摘要；短 KV 已降权，但未产品化为钉住块 | Letta memory blocks |
| M2 | **主动分页习惯弱** | 注入与 `lore_search` 同引擎 → 工具易重复；路由靠提示 + LLM，无硬「先搜再规划」闸 | MemGPT 工具分页 |

| M4 | **情节记忆不可搜（Agent）** | **同任务：已落地** `task_context_search/get`（见 [任务内上下文查询](./任务内上下文查询.md) / [功能说明](../功能/任务内上下文查询/说明.md)）；**跨任务**：仅 Web `tasks?q=` 子串 | Recall store（同任务已接；跨任务仍欠） |

### 5.2 可选（可砍）

| 方向 | 说明 |
|:---|:---|
| 小模型 Rerank | 召回 20 → 精排 5；抬 M3 剩余缝 |

- 用更长提示「请你记住」代替可检索外存。  
- 为补任务/观察检索而**再扫** `memory_index` / `lore/*.sqlite` 进工作区 FTS。

## 6. 一句话结论

**业界好思路的核心仍是：工作记忆钉住少量块 + 情节/语义外存可主动搜 + 词法∪向量∪结构混合 + 写入带晋升/覆盖/遗忘。**  
fawai **主知识 Hybrid（工作区 FTS/文件名 ∪ 笔记 FTS/向量）与规划同引擎注入已落地**；短 KV 已退出主搜。情节面下一刀优先 **同任务 search+get（补有损历史窗）**，再跨任务 recall；并行可考虑 core 块 / provenance / 仓语义，而不是再证明「要不要 FTS」。
