# 复盘进度与普通任务对齐

## 现状

复盘走 hub 旁路线程，不经 WorkerLoop。原先放行后只推一条无 `phase` 的 progress，随后阻塞在无 `on_delta` 的整段 LLM，界面约数十秒～两分钟黑盒；本案 `1c31cf85…` 静默约 102s。

普通任务规划：`phase=plan` 起步 → `LlmLiveProgress` 刷思考/输出；远端 API（如 OCR）另有 `ApiWaitProgress` 心跳。规则见 `rules-progress-local-vs-api`。

## 对照结论

| 点 | 普通任务 | 复盘（改前） | 复盘（改后） |
|:---|:---|:---|:---|
| 起步卡 `phase` | `plan` 等 | 常缺 | `analyzing` / `applying` |
| 长 API 等待 | 心跳或流式 | 无 | `ApiWaitProgress` + 首包后停 |
| 模型输出 | `on_delta` 直播 | 阻塞 `chat` | `LlmLiveProgress` |
| PWA 合并 | 按族/步稳定 key | `message_id` 易拆卡 | `other:analyzing:_` 等同相合并 |

## 改进方向

旁路能力（复盘、编排判定等）凡调远端 LLM，默认复用同一套 progress 契约，禁止「只发开始/结束」。功能验收落在 [任务复盘](../功能/任务复盘/说明.md)；个案见 [复盘进度无响应](../问题/复盘进度无响应.md)。
