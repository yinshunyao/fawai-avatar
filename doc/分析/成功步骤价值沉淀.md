# 成功步骤：该沉淀哪些「有价值」信息

对照：任务某步**已确认操作成功**之后，除全量 trajectory 外，哪些字段值得结构化留下，供本任务 Recall、复盘蒸馏、跨任务借鉴。  
目的：对齐「业务需求 / 操作命令 / 原始配置 / 代码脚本」四类主张，并补全缺口；钉清**本任务台账 → 可搜 → 三维评估后才进 lore**；**不等于**功能放行。

关联：[失败步骤价值沉淀](./失败步骤价值沉淀.md)；[成败经验与检索极性](./成败经验与检索极性.md)；[任务内上下文查询](./任务内上下文查询.md)；[脚本铲子生命周期](../功能/脚本铲子生命周期/说明.md)；[个人知识库](../功能/个人知识库/说明.md)；[自我进化](../功能/自我进化/说明.md)（E1：终态**条件**短卡蒸馏进台账/lore；仍禁整段与棘轮）。

证据动机：配置类任务常「命令族已齐、落点/凭据来源丢了」；远端类任务常「路径已见却未钉进产物键」。

## 0. 已确认机制（用户 2026-11-09）

```text
步成功 → 写入「成功价值台账」（本任务）
              │
              ├─ 落盘：先跟会话（会话重开加载）
              ├─ 可搜：专用检索（或扩 task_context 面）
              └─ 告知模型有此能力；是否搜索由模型自决
                        │
                        ▼（跨任务？）
              模型评条目：完备性 / 通用性 / 效率（对齐工具三维）
                        │
              三维都过 → 写入 lore 知识库 → 才可跨任务 lore_search
              未过     → 只留本任务台账，不进 lore
```

| 点 | 口径 |
|:---|:---|
| 维护时机 | **任务执行过程中**持续维护（步确认成功即追加/更新），不是仅终态 |
| 台账字段 | **四类主干 + 已认同补充**（落点、证据、副作用、材料来源、工具身份、失败对照、用户否决、产物指针等）一并入卡 |
| 落盘 | `{FAWAI_DATA_DIR}/sessions/{task_id}/success_ledger.jsonl`（会话重开加载）；可选再镜像 `meta` |
| 检索 | 台账**支持搜索**；规划提示写明能力；**搜不搜由 LLM 决定**（禁止关键词路由器代替） |
| 配置进 lore | 允许 **path + 键名 + 短摘非密值**；口令/Token 仍禁止进可跨任务检索面 |
| 跨任务 | **禁止**默认整卡进 lore；须 LLM 按 **完备性 / 通用性 / 效率** 自行评估是否过门，**都满足**才晋升 |
| 晋升落点 | 过门后**必须写入 lore 知识库存盘**（笔记等，走现有 lore 写入/FTS·向量索引），**不能**只标「可跨任务」却仍只躺在会话台账里——否则 `lore_search` 搜不到 |
| 三维打分 | 模型给完备/通用/效率分；**记忆配置** `FAWAI_LEDGER_GATE_THRESHOLD`（默认 **80%**）为过门线；评估可与主任务并发 |
| 与 E1 | 执行中显式 upsert 仍优先；终态条件蒸馏（多法成功/明确失败）补漏一张短卡再过门；未过门只留会话台账；禁整段轨迹 |

三维问什么（1～5 或定性过/不过均可，以模型结论为准）：

| 维 | 问什么 |
|:---|:---|
| 完备性 | 验收点、命令、落点、证据、材料来源等必要槽是否齐 |
| 通用性 | 换掉本案专名（主机号、单文件名）后是否仍成立 |
| 效率 | 复用成本（短卡+指针 vs 巨日志）；调用摩擦 |

未过门：可留在本任务台账供台账搜；**不**写 lore，故 `scopes=[lore]` 也搜不到。  
过门：`lore_note_upsert` / 约定写入路径入库 → 进笔记 FTS（±向量）→ 跨任务用 `lore_search`。

## 1. 字段主干（你列的四类 + 已认同补充）

| 类 | 字段名（抽象） | 记什么 | 勿记 |
|:---|:---|:---|:---|
| 业务需求 | `goal_slice` / `acceptance` | 本步验收点（短摘或必要路径槽） | 整份 OR 无裁剪 |
| 操作命令 | `commands` | 真正成功的 invoke + 关键参数 | 失败试错全流水（可链步号） |
| 原始配置 | `config_refs` | **落点 path + 节/键名 + 短摘非密值**（已确认允许短摘） | 口令/Token 明文进 lore |
| 代码/脚本 | `code_refs` | path、符号、或铲 id | 整文件贴卡 |
| 作用对象 | `targets` | host、cwd、本地 path、环境名 | 与命令混成一串 |
| 成功判据 | `evidence` | 关键一行证据 / 码 / mtime | 仅 `ok=true` |
| 副作用 | `side_effects` | write_set、远端是否改状态 | — |
| 材料来源 | `source_refs` | 凭据/配置来自哪份文件（路径+键） | 默认不写密 |
| 工具身份 | `tool_id` | shovel_id / skill / kind | 只留裸 shell |
| 失败对照 | `avoid` | 成功前换掉的错族（短） | 整段反省 |
| 用户否决 | `constraints` | 追问里的禁止项 | — |
| 产物指针 | `artifacts` | 报告/权重/diff 路径 | 「做完了」空话 |
| 三维分 | `completeness` / `generality` / `efficiency` + 过门结论 | 晋升 lore 前由模型自评；可与主任务并发 | 与铲子「运行成败维」勿混名 |

可选：环境快照、版本钉、耗时、澄清摘要。

### 「验收字段」是什么（说明，非另开一门）

先前问的「验收字段是否直接吃必要路径台账」，容易误会成新闸。这里只指台账卡上的 **`acceptance` / `goal_slice` 这一格写什么**：

| 说法 | 含义 |
|:---|:---|
| **验收字段** | 卡上「这一步算成功，是因为满足了哪条业务验收」的那一句（或几条短槽） |
| **不是** | 不是再造一套进度闸；也不是必须绑定「必要路径台账」代码模块 |

写什么都可以，例如：

- 用户原话短摘：「查到 4090 当前训练是否在跑」  
- 或拆成槽：`连接材料已齐` / `已拿到 nvidia-smi 结果`  

**与必要路径台账的关系（可选、不强制）**：若本任务已经在用「必要路径」分槽（连接/鉴权、作用对象、副作用…），成功卡的验收格**可以**抄「本步刚齐的那几个槽名」，免得和规划台账各说各话；**不强制**每张卡都去读那个模块。  
**已确认口径**：验收格要有；内容由写卡时填业务验收点即可；不强制耦合必要路径代码。

## 2. 分层（已钉）

| 层 | 存哪 | 谁搜 | 厚度 |
|:---|:---|:---|:---|
| 本任务台账 | `sessions/{task_id}/success_ledger.jsonl` | 台账搜；模型自决 | 可较全 + 指针；** alone 不够跨任务** |
| lore 知识库 | **必须实写** `lore/` 笔记（FTS±向量已开时进索引） | `lore_search(scopes=[lore])` | 仅三维过门骨架；短摘非密；脱敏 |

```text
本任务台账（厚、本任务可搜）
        │  LLM 评完备/通用/效率（可并发）
        ▼  过门 → 调用 lore 写入（实落盘）
   lore 笔记 + 索引（跨任务可搜）
```

禁止：过门后只改台账字段 `promoted=true` 却不调用 lore 写入——索引不会有条目。

## 3. 明确不做

- 任务结束默认把台账整表灌 lore（违背 E1 + 本轮三维门）  
- 代码关键词决定「何时搜台账」（须模型自决）  
- 把口令明文写入可跨任务检索的 lore  
- 仅 `ok=true`、无证据/落点的空卡当高完备晋升  
- 用「专名菜谱」（某机房、某 md 文件名）硬抬通用性进 lore
