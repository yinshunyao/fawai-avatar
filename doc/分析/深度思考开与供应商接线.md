# 深度思考开与供应商接线

对照任务 `dca2648deea84233aa996d531ad3707d`（主脑模型 `gpt-6-sol` / 小黄）。功能真源见 [LLM 接入](../功能/LLM接入/说明.md)；不等于放行。

## 两层含义不要混

| 层 | 谁决定 | 界面看到什么 |
|:---|:---|:---|
| **意图 / 角色默认** | `resolve_thinking`：主脑默认开、快模型与观察反省默认关；可被模型档案覆盖 | facts「思考开 / 思考关」（`thinking_meta.enabled`） |
| **真正发给供应商的思考开关** | `thinking_extra_body`，且仅当 `provider_supports_thinking_extra` 为真 | 无单独徽章；只能靠是否出现深度思考直播 / `thinking_text` 间接看出 |

深度思考正文来自响应里的 `reasoning_content` / `reasoning` / `thinking`（见 `LlmClient` 的 `_message_reasoning` / 流式 delta），经 `meta.thinking_text` 直播到步骤卡。

## 当前接线边界

`provider_supports_thinking_extra` 对下列写入 `extra_body.enable_thinking`（及可选 `thinking_budget`）：

- DashScope / 千问系（base_url / model 关键字，或 `provider_id=dashscope`）
- **内置小黄**（`provider_id=kklt`，或 base_url 含 `kklt.lol`）

未知 OpenAI 兼容口仍省略，避免未知参数报错。

档案「空=跟随角色」在小黄上与百炼一致：主脑会带 `enable_thinking=true`，快模型带 `false`。

## 小黄实测（Chat Completions）

对本机 `api.kklt.lol` + `gpt-6-sol`：

| 观察 | 含义 |
|:---|:---|
| `extra_body.enable_thinking` true/false **均不报错** | 配置可以、也应当写入 |
| 多数流式/阻塞回合 **无** `reasoning_content` | 步骤卡可能仍无「深度思考」展开正文 |
| `usage.completion_tokens_details.reasoning_tokens` 常有值 | 服务端可能在做隐式推理计费，但不等于可展示正文 |
| 偶发流式带回短 `reasoning_content` | 不稳定，不能当验收 |

因此：**接线解决的是「配置跟上角色/档案」**；**不等于**保证界面一定有思考反馈。可见正文仍取决于对方是否在 Chat Completions 里吐推理字段。
