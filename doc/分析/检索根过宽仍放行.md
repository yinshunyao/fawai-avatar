# 检索根过宽仍放行

对照对象：`fs_glob` / `fs_grep` 的搜索根（`path`）相对工作区（`FAWAI_WORK_ROOT`）可以扩到多宽，执行层会不会拦住。  
目的：解释「文件」栏出现 `/Users` 这类远超工作区的根时，是显示错了，还是工具按参数真的去扫。**不等于**功能放行。

关联真源：

| 类型 | 路径 |
|:---|:---|
| 工作区文件 | [功能/工作区文件/说明.md](../功能/工作区文件/说明.md)；`workspace/fs.py`、`workspace/paths.py`、`control/background.py` |
| 能力描述 | `brain/capabilities.py`（`fs_glob` / `fs_grep`）；`brain/native_tools.py` |
| 规划提示 | `brain/planner.py`（仓外须传 `path=`；禁止开场 `grep -r ~`） |
| 相邻分析 | [工具与文本检索速度对照.md](./工具与文本检索速度对照.md)（宽根慢、`head_limit` 不早停）；[检索索引先于磁盘.md](./检索索引先于磁盘.md)（整 `work_root` 亦视为过宽检索根） |

证据来自一次取证步：同批 `fs_glob`、`fs_glob`、`fs_grep`，参数为 `pattern=4090`、`path=/Users`、`head_limit=20`。界面「文件 /Users」来自该步 `meta.paths`，就是动作里的 `path`，不是另算出来的范围。

---

## 1. 现状

写文件仍限在工作区内。读和检索走 `FAWAI_READ_ROOTS`，未设置时默认 `/`（整盘只读）。相对路径相对工作区；绝对路径只要落在工作区或只读根内，`resolve_for_read` 就放行。

因此模型写出 `path=/Users` 时：

1. `/Users` 在默认只读根 `/` 之下，路径闸通过。
2. `fs_glob` 仅在解析结果**恰好是 `/`** 且 pattern 字面量不足 2 个字符时拒绝（`_glob_root_too_broad`）。`/Users` 不是 `/`，`4090` 也够字面量，两道都不挡。
3. `fs_grep` 没有对应的根宽度检查。仓外目录直接把该绝对路径交给 ripgrep（`rg`），等子进程跑完再按 `head_limit` 截返回条数。`head_limit=20` 不缩短扫描范围。
4. 仓外 `fs_grep` 只排除 `.git`、`.venv`、`__pycache__`、`node_modules`、`.pytest_cache`。`fs_glob` 仓外还会跳过 `Library` 等目录名；内容搜索这条更宽。

规划侧把「仓外要传绝对 `path`」写成正确用法，并把默认只读根描述成整盘。唯一明确禁止家目录开场搜索的句子，对象是 shell 的 `` `grep -r ~` ``，不是 `fs_grep` / `fs_glob`。宽检索降质（`FAWAI_WIDE_GREP_HITS`）默认关，且看的是命中条数，不看根有多浅。

---

## 2. 为什么会扫出工作区

这次不是界面把工作区显示成了 `/Users`，也不是工具自己把 `.` 改写成家目录。模型在「配置在本地磁盘、先定位连接信息」这一步，把搜索根设成 `/Users`；工具按已放行的只读根执行了。

必要路径是：已知配置目录或个人知识库里的落点，再对单文件或该目录做小窗读取。整棵用户主目录上的内容检索是可选旁证。本步把可选宽搜当成了定位本身。

调用侧选了过宽的根。工具侧让这个选择合法，而且提示把「别用 shell 搜家目录」和「仓外请传绝对路径、默认可读整盘」放在一起，模型用 `fs_*` + `/Users` 就同时满足了两句。软提示里的「收窄 path」没有对应的执行拒绝。

---

## 3. 和「允许读工作区外」的分界

只读根默认到 `/`，是为了配置、笔记可以落在仓库外，用绝对路径 `fs_read` 定向打开。这和「允许把检索根设成 `/Users` 或 `/` 再跑内容搜索」不是同一件事。

定向读一个已点名的绝对路径，应继续放行。未点名文件时，用浅根（`/`、`/Users`、家目录、卷根）做 `fs_glob` / `fs_grep`，应在工具层拒绝或要求先收到具体子目录。拒绝文案须与「路径闸拒绝（不在只读根）」分开，避免模型改去 shell `grep -r`。

---

## 4. 可选项（未放行）

下列是同一缺口的实施先后，后项仍在范围内；可砍项单独标出。

### 必要（按序）

| 序 | 方向 | 落点 |
|:---|:---|:---|
| P0 | `fs_glob` 与 `fs_grep` 共用根宽度闸：解析后的搜索根浅于约定（整盘、`/Users`、家目录、卷根）**或等于整棵 `work_root`**（且不是单个已存在文件）则拒绝，并说明先 `lore_search(work_name)` 或收到具体子目录/单文件 | `workspace/fs.py`；`fs_grep` 今日无此检查；与「索引先于磁盘」合流 |
| P0 | 能力说明与规划提示对齐：仓外绝对路径用于**已点名**文件或子目录；禁止用浅根代替「收窄 path」。删掉或改写「只禁 shell `grep -r ~`」这种会被 `fs_*` 顶替的句子 | `capabilities.py`、`native_tools.py`、`planner.py` |
| P1 | 浅根若将来显式放行，`rg` 须与 `head_limit` 对齐早停，且仓外内容搜索套用与 glob 相同的目录排除 | 见速度对照里的早停项 |

### 可选（可砍）

| 方向 | 砍掉后 |
|:---|:---|
| 界面把检索根标成「搜索根」而不是「文件」 | 不改变实际扫描范围；现标签容易读成「在读这一个文件」 |

### 明确不做

- 收回「工作区外可以定向 `fs_read`」。配置不在仓库里时，这条仍然需要。
- 只加一句「不要搜 `/Users`」或按某次关键词、某份配置文件名做专用闸。
- 把默认关闭的宽检索降质闸打开，当作根宽度的替代。那个闸看命中条数，挡不住先扫完整棵树。
