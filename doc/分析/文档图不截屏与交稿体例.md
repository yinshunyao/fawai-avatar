# 文档图不截屏，交稿默认报告

对照对象：任务执行时的环境观察选取，以及 success/failed 写给用户的终稿。  
目的：文档和附图任务不再去截本机屏幕；汇总给用户的结果默认可读，有结构时用表或流程图。用户另有体例时照用户。

| 类型 | 路径 |
|:---|:---|
| 观察 | [功能/观察](../功能/观察/说明.md) |
| 完成任务 | [功能/完成任务](../功能/完成任务/说明.md) |
| 规划提示档 | [功能/规划提示档](../功能/规划提示档/说明.md) |

## 现状

读文档、看图片、用户已经附图时，目标里的画面就是材料本身。观察候选若仍含截屏，规划会把「要看图」理解成截本机屏幕，多一步与任务无关的 `obs_screen`。

终稿写在 success/failed 的 thought 里。执行中把 thought 压到约 40 字，会话层再把给用户的正文裁到约 1200 字，报告就只剩一两句。会话能画 Markdown，原先不画 mermaid。

## 取舍

截屏只留给明确要看或操作当前桌面的目标（截屏、屏幕上、点击、键入等）。文档、图片文件、用户附图且没有这些要求时，候选去掉截屏和 AX，步 0 为跳过。点选截屏也会被丢掉。

终稿默认：一句结论，再分项；有对照用表；有步骤、分支、依赖或结构关系时加一段 mermaid flowchart。没有这种关系不硬画，也不编数字。用户写出一句话、简短、不要图表、纯文本等体例时，不再加图。执行中的短 thought 保留，避免规划 JSON 被长推理撑破。给用户的终稿放宽到约 8000 字，避免图被裁掉。

图画在会话里：mermaid 代码块换成图；库加载失败时仍留下代码块。窄屏图可横向滚动。

## 闸门生效后仍像在截屏

用户附图问「图里有什么」，续跑时候选已是工作区文件和跳过，实际观察也是跳过，没有新的截屏文件。模型每一轮仍把下一步写成截屏。规划卡按模型点选原文显示「下一步观察：截屏」，所以界面上像停不下来。

跳过观察的固定摘要仍写「需要画面时请点选截屏 / 控件树」，不看本步候选里有没有这两项。模型读到这句话，就继续点选截屏；硬闸门再丢掉；下一轮摘要又说同一句。提示词规模每步只增加几十 token，没有新截图进上下文。

根因在观察摘要的契约：文案要求一种观察方式，候选集不允许这种方式。规划卡展示的是点选，不是闸门之后真正会执行的方式。

附图并不是没发给视觉模型。文本模型与视觉模型分开路由，消息里出现图片才会进视觉模型。首步还没有任何桌面截屏时，规划已经走了视觉模型，所以当时发出去的图是用户附图，旁边同时有系统提示和「未截屏、要画面请点选截屏、前台是 Chrome」这段观察文字。模型的思考复述的是这条规则，把「这个图」收成桌面画面，而不是先描述附图。截到本机屏幕之后，它按那张桌面图作答。
