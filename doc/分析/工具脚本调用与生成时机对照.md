## 1. 问题拆成三件事

| 问题 | 含义 |
|:---|:---|
| **调什么** | 能力清单内工具、已有铲、临时脚本、产品源码补丁——选型序 |
| **何时造** | 什么时机允许写/跑临时脚本；造之前要不要先搜台账 |
| **造完怎么办** | 一次性丢弃、升公共铲、还是只记 Skill |

三者在两边都有纪律，但**执行强度**差很多：Cursor 偏「规则进提示 + 助手自觉」；fawai 已接上**写前软闸 / 写后软提示**（硬闸默认关）。

## 2. 当前状态（fawai）

### 2.1 选型序（已落地）

规划话术与能力清单一致：

```text
能力清单工具 → shovel_search / 已有 fawai_shovels → 临时 py_* 或 fs_write+shell
改产品源码 → 仍 fs_patch（禁止用 py_* 改仓内业务文件）
```

| 通道 | 用途 | 落点 |
|:---|:---|:---|
| 机读能力 | `fs_*` / `shell` / GUI 等一等公民动作 | `brain/capabilities.py` |
| 铲检索 | `shovel_search` 查文首 meta + 三维分 | `workspace/shovel_ops.py` |
| 会话 Python | `py_write` → `py_pip` → `py_run`（落盘 `runs/`） | `workspace/py_session.py` |
| 临时 shell 脚本 | `fs_write`（`.py`/`.sh`）+ `shell` | 写前计入「造脚本」 |
| 产品改码 | `fs_patch` + `code_check` | 编码闭环；与临时脚本分流 |

### 2.2 生成时机（闸门怎么选）

| 时机 | 机制 | 默认 | 设计意图 |
|:---|:---|:---|:---|
| **写前** | 本步计划含「造/跑临时脚本」且本 run 尚无成功 `shovel_search` → 注入【铲子优先】并**重规划一轮**（该批造脚本不执行） | 软闸开 | 逼「先搜再造」；**不**在任务开场空转时无故拦 |
| **写前硬拒** | 同上条件直接拒动作 | **关** | 避免简单任务被硬死；可 `FAWAI_SHOVEL_SEARCH_HARD=1` |
| **写中** | 提示：参数/env、禁止明文口令与未公开绝对路径；通用性≥3 才进公共铲 | 软 | 与 `SHOVEL.md` / Cursor 脱敏同尺子 |
| **写后** | 本 run 曾成功临时脚本且将 `success` → 注入一次【铲子提炼】 | 软提示开 | **不阻断** success；可另开任务升铲 |
| **明确不做** | 任务完成默认自动蒸馏 / 棘轮升铲 | — | 与自我进化否决一致 |

「是否算造脚本」由代码启发式判定（`brain/shovel_lifecycle.py`）：

- 算：`py_write` / `py_run` / `py_pip`；`fs_write` 到 `.py`/`.sh`；`shell` 里像 `python -c`、`bash notes/`、会话路径脚本等  
- 不算：`shell` 直接调 `fawai_shovels/` 或 `hipp-tools/` 的 invoke  

闸触发条件刻意写成：**只有本步真要 invent 才注入**，避免「goal 像脚本任务但还没动手」就烧一轮重规划。

### 2.3 做得怎么样（定性）

| 维度 | 评价 | 说明 |
|:---|:---|:---|
| 选型分流清晰度 | **高** | 能力 / 铲 / 会话 py / 产品补丁四条道文档与提示对齐 |
| 「先搜再造」遵守率 | **中～中高** | 软闸真会拦一批动作并重规划；模型搜一次后仍可乱造；硬闸默认关 |
| 临时脚本可观测 | **高** | `py_run` 落盘 stdout/stderr/meta；优于裸 `python -c` 无痕 |
| 升铲兑现率 | **中偏低** | 仅软提示一次；允许空 actions 直接 success；无自动 `shovel_register` |
| 启发式漏拦/误拦 | **中风险** | 未覆盖的 invent 形态可漏；误把正当 shell 当 invent 可能多一轮 |
| 可测性 | **高** | `demo_shovel_lifecycle` 冒烟；闸 marker 可断言 |

**总判（fawai）：** 「调用什么」与「何时允许第一次造」已工程化，**强于纯提示**；「造完必升铲」与 Cursor 工作区纪律一样，仍主要靠模型，**未做成硬资产闭环**。

## 3. Cursor 侧（对照口径）

| 机制 | 含义 |
|:---|:---|
| **内置工具** | Shell / Read / Grep / Write / MCP 等一等公民；大量探查不必先造脚本 |
| **`rules-cursor-tools`** | 先读 `hipp-tools/readme.md` → `.cursor/tools/readme.md`；能调则调；新建须三维分；通用性≥3 进 hipp-tools，≤2 进工程 tools |
| **一次性例外** | 单次 `ls`/`cat`/`git status` 等可不进台账 |
| **Skills** | 按需加载的流程说明；可带 `scripts/` 给 Agent 执行；判断在 MD，机械步在脚本 |
| **生成时机（实践）** | 探索用一次性命令；重复机械序列再固化工具/Skill；任务刚做完时「explore once, then codify」 |
| **执行闸** | 一般**无**产品级「未读台账禁止 Write 脚本」；靠 alwaysApply 规则 + 多轮纠错 |

强项：内置工具面宽，**少造脚本也能干活**；规则/Skill 作者成本低；Skills 按需加载省上下文。  
弱项：台账纪律多数是软的；违规常已写到盘上再改；升工具依赖助手自觉与人审。

## 4. 效果对照

| 维度 | fawai（当前） | Cursor（典型 + 本仓 tools 规则） |
|:---|:---|:---|
| 先查台账再造脚本 | 软闸可拦执行 + 重规划 | 提示纪律；常无执行前硬拦 |
| 临时脚本落点 | 会话 `py_*` 或显式路径；可观测 | 易散落对话/`/tmp`/业务目录（规则禁止但难拦） |
| 产品改码 vs 临时算 | 分流明确（`fs_patch` vs `py_*`） | Write/Shell 同一工具面，靠规则与习惯分流 |
| 升可复用资产 | 软提示 + 三维分尺子；默认可跳过 | 规则要求同回合改 readme；Skills 另轨；默认可跳过 |
| 内置能力覆盖 | 较窄 → **更常需要铲/临时脚本** | 较宽 → 少造文件也能完成同类探查 |
| 可测「是否先搜」 | 高（history marker / demo） | 低 |

**总判：** 在「造脚本前必须先露一次搜铲」上，fawai **比 Cursor 更硬一截**；在「少造脚本、靠内置工具做完」上，Cursor 更省。两边升台账都仍是**软兑现**。

## 5. 成本对照

| | fawai | Cursor |
|:---|:---|:---|
| 合规路径 | 多 1 次 `shovel_search` + 可能 1 轮重规划 | 读 readme / Skill 描述；命中则直接 Shell |
| 闸触发时 | 墙钟加长（observe→plan→act 拉长） | 通常无闸；做错再开一轮清理 |
| 上下文 | 能力清单 + 铲子话术；不全书灌 hipp-tools | alwaysApply 工具规则每轮固定付；Skill 按需 |
| 升铲失败 | 资产不增长，但任务可标成功 | 同；下次任务再造一遍脚本 |

**总判：** 简单探查 Cursor 往往更轻；fawai 在「会造临时脚本的任务」上多付搜铲/软闸，换的是**可复现落盘**与**可测闸**。

## 6. 生成时机选择：两边各自钉住了什么

| 决策点 | fawai 已选 | Cursor 常见 | 备注 |
|:---|:---|:---|:---|
| 开场是否强制搜铲 | **否**（要 invent 才闸） | 规则说先读台账，但无闸 | fawai 避免空烧一轮，合理 |
| 未搜铲能否造 | 默认软拦一轮；硬拒可选 | 能 | fawai 更稳 |
| 一次性探查要不要进台账 | 不强制（能力工具 / 短 shell） | 明确例外（ls/cat/git） | 对齐 |
| 重复机械步何时固化 | success 后软提示自评 | 第 2～3 次或任务刚做完固化 Skill/tools | Cursor 时机更「经验驱动」；fawai 时机更「任务收口」 |
| 自动升铲 | **否决** | 通常也无自动 | 一致 |
| 会话临时代码 | 正式通道 `py_*` | 常 Write 到仓或 `/tmp` | fawai 更干净 |

## 7. 改进思路（未放行；优先级 vs 可选项）

下列均为**思路备忘**。要落地须开议题 → 用户明示写入功能目录。

### 7.1 必要方向（若立项，按序；后项仍属范围，不是默认可砍）

| 序 | 方向 | 要解决什么 | 可能落点 |
|:---|:---|:---|:---|
| P0 | **搜铲质量，不只「有过一次 ok」** | 一次无关 `shovel_search` 即可永久过闸 | 要求 query 与 goal/invent 路径相关，或本步前 N 条 history 内有效命中 |
| P1 | **升铲可观测** | 不知道软提示有没有被兑现 | 复盘维：曾 inject【铲子提炼】/ 是否写入 `fawai_shovels` 或 `skill_write` |
| P2 | **invent 启发式收紧** | 漏拦 `python <<'EOF'`、误拦正当部署 shell | 白名单已有铲 invoke；黑名单扩常见 heredoc；单测表驱动 |
| P3 | **与远端/部署族对齐话术** | 升级类已「优先 shovel」，与生命周期闸重复或打架 | 统一「先 search 再 shell 调 invoke」一条链 |

### 7.2 可选（可砍）

| 方向 | 说明 | 风险 |
|:---|:---|:---|
| 默认打开搜铲硬闸 | 跟纪律更死 | 简单算数任务变重、失败率升 |
| success 前强制自评三维分字段 | 升铲率上升 | 延迟；模型乱填分数 |
| 独立 `shovel_register` | 比裸 `fs_write`+catalog 更难写坏 | 工具面膨胀 |
| 接近 Cursor「第 N 次重复再固化」计数 | 提炼时机更贴复用信号 | 跨 run 计数复杂；易误伤 |

### 7.3 明确不建议

- 任务结束**默认自动**把临时脚本拷进 `fawai_shovels`（与已否决自动蒸馏冲突；易进未脱敏垃圾）。  
- 用更长系统提示替代写前闸，指望模型永远先搜。  
- 为个案菜谱加专用硬闸（与复盘「优化须通用」冲突）。  
- 把 Cursor 全量 hipp-tools readme 灌进每一轮规划（烧 token，且 fawai 已有 `shovel_search`）。

---

## 8. 一句话结论

**当前：** fawai 把「工具 → 铲 → 临时脚本 → 产品补丁」拆开，并用**写前软闸**把「生成时机」钉在「先搜再造」；会话 `py_*` 让临时代码比 Cursor 裸 Shell/Write 更可观测。升铲仍与 Cursor 同属软兑现。相对 Cursor，fawai **调用纪律更可测、生成前更敢拦**；**内置工具面更窄，更依赖铲与临时脚本**。

**以后：** 优先堵住「搜一次无关铲就过闸」与升铲可观测；硬闸与强制升铲保持可选，不要为了「更像 Cursor 宽工具面」拆掉已落地的分流与闸。
