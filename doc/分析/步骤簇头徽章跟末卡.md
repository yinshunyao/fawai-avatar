# 步骤簇头徽章跟末卡

## 现状

同一 `#N` 步骤簇里，卡片按阶段族合并：观察、规划、工具（含工具结果）、反省 / 观察反省。簇头有两截：

- **徽章**显示本步步型（`step_kind`）。步首观察卡上的步型是上一段留下的，不拿来当徽章。规划还没给出步型时徽章留空。
- **标题**粘住规划给出的 `step_label`（业务短名）。没有业务短名时，标题才会退成末卡文案。

簇内各卡仍用阶段名（观察、思考完成、工具结果、观察反省）。成功且本步有动作时，闭环在工具结果之后仍会再推一张 `phase=obs_reflect`，那只是簇里的末卡，不再盖住整步徽章。

## 判断

簇头徽章就是这一步的类别。五类：

| 码 | 界面 |
|:---|:---|
| `sense` | 取证 |
| `act_serial` | 串行执行 |
| `act_parallel` | 并行只读 |
| `analyze` | 分析 |
| `finalize` | 收尾 |

步首那张「观察」卡上的步型，带的是**上一段**留下的 `pending_step_kind`（用来决定要不要跳过浅环境观察）。本段规划、工具、观察反省卡上的步型，才是本段 `Plan.step_kind`。同一簇里两行步型可以不同。

观察反省自己的进度只有三条：`advanced` / `stalled` / `enough_to_answer`。机械只读整批成功走规则摘要，文案是「跳过（机械成功·规则摘要）」，不另开一种步型。

## 不做

- 不把观察反省升成第六种步型。`obs_reflect` 在规划侧别名会收成 `analyze`。
- 簇内各卡的阶段徽章保持原样；只改簇头。
