## 现状

1. **软追加已能拉起 Worker**（假 running 空转已修）：本案 `plan_allow_session_worker=true`，父任务跑了约 9 步后 `completed`。
2. **产物已齐**：n5 的 `out_n5_final_ppt_script.md`（约 11KB）在 `shared/`；追加轮又 `fs_write` 了 `complete_ppt_script.md`（约 7KB，含 Slide 1–20）。
3. **会话终稿无报告**：末条助手气泡 = 末步 `thought`：「读取完整PPT脚本文件…然后向用户交付最终报告」。无页码正文、无粘贴、无「见某路径」的可验收交付。
4. **观察反省曾标 enough_to_answer**（写盘成功后）：随后又进一轮 finalize，模型仍输出意图句而非正文。

## 工具双栏

| 栏 | 结论 |
|:---|:---|
| **工具本身** | `fs_read` 大文件压缩省略，易诱发「读到了但仍缺正文」的错觉（契约易误导取证相位）。答复覆盖闸默认关，且**不覆盖「输出/交稿」类**；终稿通道只有 `thought`→气泡，无独立「交付报告」工具。意图句不在现有元叙述词表内 → 开闸也易漏。 |
| **调用** | 追加目标是「输出」；规划长期同构读压缩预览，后改写文件却把写盘当完成；finalize 步输出下一步意图而非载荷。 |

## 必要 / 可选路径（抽象）

| 路径 | 状态 |
|:---|:---|
| 必要：把可验收报告载荷交到用户可见通道（终稿 thought 或等价） | **未兑现**（意图句假成功） |
| 必要：材料可回读（产物路径或分段读齐） | 产物已就绪；压缩读未用于交稿 |
| 可选：再生成一份 md / 做 pptx | 重生 md 喧宾夺主，仍未交会话 |

## 机制根因（可复用）

| 模式 | 表现 |
|:---|:---|
| **假成功 / 答复未覆盖目标** | 追问要「输出」，终稿只有过程/意图 |
| **假成功 / write_set 当验收** | 文件已写 ≠ 用户气泡已见报告 |
| **交稿意图句漏检** | 「然后向用户交付」类句子不进现有 meta 词表；含数字会被当成有 substance |
| **用户多轮验收点未进判定** | followup 注入 history，success 闸仍主要看首条 goal |
| **压缩观察拖垮取证→交稿** | 反复同 offset 读；步骤重复 alternate 后仍未把已有正文灌进终稿 |

## 建议改法

下列均为**必要项**时编号仅表示实施先后；标可选的可砍。

### 必要（已落地；补强既有层，禁止本案升闸）

1. **交稿意图句常开** — `thought_is_delivery_intention`；空 actions success 回灌 `format_delivery_payload_prompt`（至多 1 次）再 failed（`delivery_intention`）。
2. **输出类载荷常开** — `goal_needs_delivery_payload_gate`（goal/followups 含直接输出等）；须正文或路径+摘要（`delivery_thin`）。
3. **追问验收点** — `compose_answer_goal`；loop / 复盘 / 可选答复覆盖闸均对照 followups。
4. **finalize 提示** — 禁止「准备读取/然后交付」当 thought；写盘 ≠ 交稿。

### 可选（可砍；未做）

| 项 | 砍掉后 |
|:---|:---|
| 大 Markdown 默认不压缩 / 自动分段读齐再允许 finalize | 仍可靠意图句闸 + 交稿校验拦假成功 |
| 会话自动附带产物文件卡 | 主验收仍须 thought 有摘要或正文 |

## 明确不做

- 不手改 `6917c303…` 库态「补发」报告（见禁止插手任务执行）。
- 不为「三年级 PPT」单开专用闸或专用 skill。
- 不把「换更大模型」当唯一解。
- 不回退软追加会话 Worker；本案问题在交稿判定，不在拉起。
