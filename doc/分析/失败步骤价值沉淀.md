# 失败步骤：负面台账能否对称扩展

对照：[成功步骤价值沉淀](./成功步骤价值沉淀.md)（正面台账已落地）；[成败经验与检索极性](./成败经验与检索极性.md)（Skill avoid / 铲运行成败维已落地）。  
目的：回答「参考正面台账，能否建负面台账」——机制可行边界与字段草案；**不等于**功能放行。

---

## 0. 结论（本轮）

**能扩展，且值得与正面台账对称**，但**不要做成「凡失败工具调用都入账」**。

| 判断 | 口径 |
|:---|:---|
| 机制形态 | 与成功台账同构：本任务 jsonl → 可搜 → 模型自决是否搜 → 三维过门才写 lore（标签偏 `avoid`） |
| 与已有 avoid 关系 | **互补不替代**：铲/Skill 成败维管「这个工具好不好用」；负面台账管「这步业务怎么踩坑」（命令/落点/错因/勿再试） |
| 写入时机 | 仅**已确认的有价值失败**（换道前的错族、用户否决、假成功戳破、同参必败）；禁止把整段试错流水灌进卡 |
| 跨任务 | 过门 lore 必须以 **avoid 极性** 入库；`lore_search` / 规划须按 avoid 消费，禁止当正例抄 |

正面卡上的短字段 `avoid` **不够**：那是成功卡上的对照一句；负面台账要独立成卡，才能本任务搜、过门后跨任务避坑。

## 1. 现状缺口

```text
失败信号今日在哪
  → history / 工具结果 / 执行反省          ← 有，难结构化复用
  → 成功台账卡上的 avoid 短句              ← 附属于成功，无独立检索面
  → Skill lesson / failure tags            ← 多靠复盘人手
  → 铲子运行成败维                         ← 只绑铲，不绑业务步骤
  → 负面步骤台账                           ← 无（本篇提议）
```

| 已有 | 仍缺 |
|:---|:---|
| 成功价值台账 + 门控升 lore | 对称的「踩坑卡」本任务可搜 |
| Skill imitate/avoid 分栏 | 执行中持续维护的步骤级负面卡 |
| 铲 outcome poor 软闸 | 非铲场景（配置错键、远端 cwd、假成功）的结构化避坑 |

## 2. 建议机制（与正面镜像）

```text
步失败 / 换道确认有价值 → 写入「失败价值台账」（本任务）
              │
              ├─ 落盘：sessions/{task_id}/failure_ledger.jsonl
              ├─ 可搜：failure_ledger_search / get；模型自决
              └─ 旁路三维门控（可并发）→ 过门实写 lore（tags 含 avoid）
```

| 点 | 相对正面的同 / 异 |
|:---|:---|
| 落盘 / 可搜 / 自决搜 | **同** |
| 旁路进度 + token 计入 stats | **同**（phase 建议 `failure_ledger_gate`） |
| 三维门控 | **同维名**；通用性问「换专名后是否仍应避免」；完备性问「错因+勿再试是否够」 |
| lore 写入 | **异**：必须带 avoid / failure 极性；规划禁止当 imitate 骨架 |
| 默认写入密度 | **异**：负面默认更严——一次失败不够格，须「确认错族」或用户否决 |

### 字段草案（相对正面）

| 类 | 字段 | 记什么 | 勿记 |
|:---|:---|:---|:---|
| 意图切片 | `goal_slice` / `intent` | 当时想达成什么 | 整份 goal |
| 失败现象 | `symptom` | 可见失败表现（短） | 整段 stderr |
| 已试命令 | `commands_tried` | 导致失败的 invoke+关键参 | 成功后的命令（那归正面） |
| 错落点 | `config_refs` / `targets` | 用错的 path/键/host | 口令明文 |
| 根因假设 | `cause` | 已确认或高置信错因 | 纯猜测连环 |
| 勿再试 | `do_not_retry` | 同参/同路径禁止再来 | 空话「小心点」 |
| 换道结果 | `recovery` | 后来怎么成功的（可链 success 卡 id） | 无 |
| 证据 | `evidence` | 一行失败证据 | 仅 `ok=false` |
| 工具身份 | `tool_id` | shovel / kind | — |
| 用户否决 | `constraints` | 追问禁止项 | — |
| 严重度 | `severity` | `blocker` / `wasted_loop` / `near_miss`（可选） | 每条都标 5 星 |

工具面建议：`failure_ledger_upsert` / `search` / `get`（或统一 `value_ledger_*` + `polarity=avoid`——实现时可二选一，产品名仍宜分正负以免模型混抄）。

## 3. 与正面台账、成败极性的分工

| 机制 | 管什么 | 典型消费者 |
|:---|:---|:---|
| **成功价值台账** | 做成了什么、怎么做成 | 本任务 recall；过门后 imitate lore |
| **失败价值台账**（提议） | 什么不能再试、错在哪 | 本任务避坑；过门后 avoid lore |
| **铲运行成败维** | 这个脚本好不好用 | `shovel_search` + 成败对照软闸 |
| **Skill avoid 栏** | 复盘沉淀的 lesson | `skill_search` 分栏 |
| **成功卡上的 `avoid`** | 成功路径上的一句对照 | 附带信息，不替代负面卡 |

禁止：负面台账与铲 poor **互相替代**；也禁止 lore 里正负笔记混成一张「相关度榜」当正例。

---

## 4. 风险与不做

| 风险 | 对策 |
|:---|:---|
| 失败刷屏、台账噪声 | 写入门槛：换道/用户否决/假成功/同参二败；禁每步自动 upsert |
| 负卡被当正例抄 | lore tags + 规划提示 + 检索分栏（对齐 Skill avoid） |
| 与 E1 冲突 | 仍非任务结束默认蒸馏；过门才写 lore |
| 双台账实现分叉 | 优先共享 jsonl/门控/旁路进度内核，仅 polarity 与字段差 |

**本切片不做（除非另放行）**：自动从所有 `ok=false` 灌负面卡；负面硬拒规划（先提示级）。
