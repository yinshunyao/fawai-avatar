# 任务复盘与多轮用户输入

对照对象：产品内「任务复盘」材料面 / 分析口径 / 勾选改写轮，相对源任务与复盘会话上的**用户多轮输入**。  
目的：钉清缺口与优化方向；默认原则仍是 **先工具与代码 bug，再策略与规则**。  
**不等于**功能放行。

**已落地：** `build_materials_text` 喂源任务 user_turns；改写轮回灌 prior + 复盘会话多轮；提示消解「建议 vs 工具优先」；清单工具层软置顶；功能说明 / 分析规则 / `demo_review` 已同步。  
**未核：** 现网若干多轮追问失败案上复盘产出是否系统性漏因（需抽样轨迹）。

---

## 1. 结论（先说）

（落地前）复盘提示词里「工具本身优先 / 双栏」写得够硬，但**材料契约缺用户多轮通道**：追问已不并入 `goal`，而 `build_materials_text` 又不喂 `meta.followups` / 澄清问答，分析官常只看见首条目标 + 头尾 steps。  
多轮上的失败（纠偏被忽略、澄清后仍按旧假设、追加未兑现）容易被误判成「规划偏科 / 规则不够」，从而**跳过工具面、直接开 lesson/rule/prompt**——与默认原则相反。

复盘会话自身的「自由文本再分析」也只带**最新一条** `user_guidance`，不回灌上一轮【分析】与清单，改写轮易从零重写。

**落地后：** 材料与改写入参已按 §4.1 P0–P2 补齐；验收见功能说明与 `demo_review`。

## 2. 现状（已核）

### 2.1 源任务：用户多轮怎么进执行

| 通道 | 落点 | 是否进 goal |
|:---|:---|:---|
| 终态追问 continue | `meta.followups` → Worker `_seed_followup_history`（`【追问】`） | **否**（新路径） |
| 执行中追加 | `pending_appends` → `_drain_pending_appends`（`【用户追加】`）；并记 `followups` | **否** |
| 澄清答复 | `followups` + mode=`clarification`；注入 history | **否** |

大脑靠 history / `task_context_*` 看见增量；列表与复盘若只看 `goal`，等于只看首条。

### 2.2 复盘材料实际喂什么

`build_materials_text` 当前块：`goal` / `final_thought` / `error` / 调度计数 / 可选 `reflection` / `steps` 头尾采样。  
可选：`user_guidance`（复盘放行或改写时用户写的附加建议）。

**未喂（已核缺口）：**

| 材料 | 后果 |
|:---|:---|
| 源任务 `meta.followups`（含 mode） | 看不到追问/澄清/追加原文与次序 |
| 澄清题面（`meta.clarification`） | 无法对照「答了什么仍走偏」 |
| 复盘任务自身 `followups` 历史 | 多轮附加建议只留最后一条 guidance |
| 上一轮 `review_analysis` / `review_items` | 改写轮无法「针对清单改」，只能整盘重析 |

`demo_review` 覆盖放行解析与清单 UI，**未**覆盖「源任务多轮 followups 进材料」。

### 2.3 口径与强制排序

- 提示词与 [分析规则](../功能/任务复盘/分析规则.md) 已要求：工具本身 P0 → 调用 → 必要路径 → 策略闸/lesson。  
- `_normalize_items` **只做编号规范化**，不按「工具层 / code_patch」重排，也不校验双栏是否落盘。  
- 提示另写「用户附加建议须优先尊重」——与「工具优先」未写冲突消解：用户若说「只改规则」，模型易跳过工具双栏。

### 2.4 复盘会话多轮（产品已有）

三阶段本身支持多轮：`awaiting_approval` 附加建议 → 分析；`awaiting_apply` 勾选 / 自由文本 revise / 取消。  
缺口在**改写轮上下文**，不在有没有入口。

## 3. 机制缺口（按工具 → 策略）

### A. 复盘材料契约漏用户通道（工具/代码 · P0）

复盘产品承诺全维深析，却未把执行侧已结构化的用户增量当作一等材料。  
这是**复盘工具面缺陷**（材料不全），不是「分析官不会用规则」。  
证据边界：代码路径已核；现网漏因比例未核。

典型误诊链：

```text
用户追问纠偏 → agent 仍按首条 goal 空转/假成功
     ↓ 复盘只见首条 goal
分析官：规划偏科 / 提示词不够
     ↓
清单：rule_patch / prompt_patch / lesson
     ✗ 跳过：task_context 过薄、followup 未注入、答复覆盖闸、工具报错误导等
```

### B. 改写轮无上一轮分析态（工具/代码 · P0）

`mode=revise` 只设 `user_guidance`，再调同一 `analyze_review_tasks`。  
用户说「第 2 条不要开闸、先修报错文案」时，模型看不到旧 items，难做增量修订。

### C. 「建议优先」压过「工具优先」（提示/规则 · P1）

须写清：附加建议只**收窄焦点与验收偏好**；分析顺序与双栏仍强制；工具面有明确 bug 时仍置顶 P0，可与用户偏好并列说明冲突。

### D. 分析规则缺「多轮用户通道」检查项（规则 · P1）

机制失败模式表无：纠偏被忽略、澄清后仍旧假设、追加未兑现、复盘改写丢语境。  
优化方向易默认落到新闸/新提示，违反「先工具契约」。

### E. 清单无代码侧工具优先软约束（策略加固 · P2）

完全靠 LLM 自觉；早期阶段可加轻量后处理（见下），禁止发明本案专用闸。

## 4. 优化方向（必要项按实施先后；后项仍在范围）

下列均为**建议立项项**，未放行。排序遵守：先补复盘材料/契约（工具），再改提示与分析规则（策略），最后才谈软闸。

### 4.1 必要

| 序 | 层 | 做什么 | 状态 |
|:---|:---|:---|:---|
| **P0** | 代码 · 材料 | `build_materials_text` 附加源任务 user_turns（followups + 澄清题面） | **已落地** |
| **P0** | 代码 · 改写 | revise 回灌 prior_analysis / prior_items + 复盘会话 followups 累积 | **已落地** |
| **P0** | 提示 | 固定「用户多轮通道」节；先评增量是否兑现 | **已落地** |
| **P1** | 提示 | 附加建议=焦点偏好；分析顺序仍工具优先 | **已落地** |
| **P1** | 分析规则 | 增多轮失败模式；禁追问专用闸 | **已落地** |
| **P2** | 代码 · 软约束 | 工具层项软置顶 + `selected_default=true` | **已落地** |

### 4.2 可选（可砍）

| 项 | 说明 | 砍掉后 |
|:---|:---|:---|
| 从 `session_history.jsonl` 再抽用户气泡 | followups 已够用时可不做 | 仍靠 meta.followups |
| 改写轮「局部修订」专用 prompt | 全量重析 + prior 材料通常够 | 成本略高但实现简单 |
| 联合复盘按任务分别挂 followups | 联合链更清晰 | 可先扁平时间线 |

### 4.3 明确不做

- 不为「多轮追问」新开第三条业务专用闸（禁本案故事线升闸）。  
- 不把追问正文重新拼回 `goal`（与会话气泡独立约定冲突）。  
- 不因多轮失败默认建议「换更大模型」或关掉反省/步骤重复。  
- 不在未见工具缺口时，用 rule/prompt 堆砌代替修材料契约。

---

## 5. 与「工具优先」的对齐自检

落清单前问：

1. 材料是否已含用户多轮？没有 → **先补复盘材料（P0）**，不要先写「规划要听话」类提示。  
2. 工具双栏是否已评？没有 → 不得只出 strategy 项。  
3. 用户附加建议是否只是偏好？是 → 可调焦点，不可废除工具 P0。  
4. 换掉文件名/机房号后优化标题是否仍成立？否 → 特例，进「明确不做」。

## 6. 建议落地顺序（均为必要，编号仅先后）

1. 材料喂 followups + 澄清题面（复盘代码）。  
2. 改写轮回灌 prior 分析/清单 + 累积建议。  
3. 提示增加「用户多轮通道」节 + 与工具优先的冲突消解。  
4. 分析规则补多轮失败模式（链回本对照）。  
5. （可选加固）清单工具项软置顶。

要立项时另开议题；本文件只备忘。
