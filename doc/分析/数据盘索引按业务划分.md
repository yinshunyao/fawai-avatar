# 数据盘索引：按业务划分（不二次缓存）

对照：`FAWAI_DATA_DIR`（默认 `data/`）相对工作区 `work_root` 的索引与查询。  
目的：配置与工具按**业务**组织；**索引缓存 / 知识库存盘本身不再被文件扫盘二次入库**；说清各 SQLite 是否已有库内索引、是否有查询工具。

关联：

| 类型 | 路径 |
|:---|:---|
| 个人知识库 | [功能/个人知识库/说明.md](../功能/个人知识库/说明.md) |
| 全文对照 | [全文索引与Everything对照.md](./全文索引与Everything对照.md) |

---

## 1. 两层不要混

| 层 | 含义 | 默认 |
|:---|:---|:---|
| **工作区索引** | 扫 `work_root` 源码/文档 → 写入 `data/memory_index/` | 开；业务改代码/找文件主通道 |
| **数据盘业务面** | `data/` 内按业务落盘的运行态 | **不要**再当「普通工作区文件」扫进 `memory_index` |

缓存库（`memory_index`、`code_index`、`lore/*.sqlite`）是**结果**，不是再索引的**源**。

---

## 2. 按业务划分（建议真源）

| 业务面 | 典型路径 | 索引形态（应有） | 二次文件 FTS？ |
|:---|:---|:---|:---|
| **A. 索引缓存** | `memory_index/`、`code_index/` | 自身即 SQLite/JSONL 缓存 | **禁止**再扫 |
| **B. 知识库存盘** | `lore/`（笔记/KV/缓冲） | 笔记 **lore FTS + 向量**（库内） | **禁止**再当正文扫；检索走 `lore_search` 笔记通道 |
| **C. 任务会话** | `tasks.sqlite`、`sessions/`、`session_*.jsonl`、`session_media/` | 任务库 **B-tree**；会话按 task_id 文件 | 默认不进工作区 FTS；检索走任务 API（见 §3） |
| **D. 观察落盘** | `observe/` | 暂无独立 FTS | 默认不进工作区 FTS；需要时另开「观察检索」议题 |
| **E. 模型与记忆配置** | `llm_settings.sqlite`、`memory_settings.sqlite` | 主键/键值 | 配置 API，不做全文 |
| **F. 系统日志** | `system_logs.sqlite` | ts/action/task/category 索引 | Web `/api/system-logs` |
| **G. 其它运行态** | `versions/`、`runtime*`、`skills/`、`analysis/`、`frpc.*` | 各业务自管 | 默认不扫进工作区 FTS |

**默认已建、服务业务检索的：**

1. 工作区文件名 + 正文 FTS（改仓/找材料）  
2. 知识库**笔记** FTS（±向量）  
3. 任务列表 API 的 `q` 子串过滤（goal/title/id）  
4. 系统日志列表过滤  

**尚未做、且不应靠「再扫 data」凑：** 任务 goal 的 SQLite FTS、观察 dump 全文索引、会话 JSONL 全文工具。

---

## 3. SQLite 记录：库内索引 vs 工具查询（已核）

| 库 | 库内索引 | 查询工具 / API | 全文 FTS？ |
|:---|:---|:---|:---|
| `tasks.sqlite` | `task_id` PK；`leases`/`events` 上 task/resource 索引 | `GET /api/tasks?q=`；`lore_search` 通道 `task`（业务已开 methods） | **无**独立 FTS；子串 |
| `system_logs.sqlite` | ts、action、task_id、category、analyze_task_id | `GET /api/system-logs`（Web） | **无** |
| `llm_settings.sqlite` | 表主键（providers/routes/profiles） | 模型设置页 / settings API | **无**（也不需要） |
| `memory_settings.sqlite` | `kv(key)` PK | 记忆配置页 | **无** |
| `memory_index/*.sqlite` | FTS5 + files.name 索引 | `name_index_search` / `fts_search` / `lore_search` | **有**（工作区源） |
| `lore/fts.sqlite` | FTS5 | `lore_search` 笔记通道 | **有**（笔记） |
| `lore/vectors.sqlite` | sqlite-vec | `lore_search` 向量通道 | 向量，非词法 |
| `session_history.jsonl` | 非 SQLite | `/api/session`、`/api/tasks/{id}/history` | **无** FTS |

结论：

- **关系库「有没有索引」**：任务/日志有常规 B-tree，够列表与按 id 取。  
- **「支不支持工具查询」**：任务已开 methods 时进 `lore_search`；日志仍走 Web API；观察/其它 `engine=none` 仅意向。  
- **不要**把 SQLite 文件再丢进工作区正文 FTS——既慢又脏。

## 4. 配置 UI（已落地）

记忆配置页：

| 单元 | 路径 | 索引方式 |
|:---|:---|:---|
| 工作区 | `FAWAI_WORK_ROOT` | 多选 FTS / 文件名（默认都开） |
| 可读区 | `FAWAI_READ_ROOTS` | 多选（默认空，防 `/`） |
| 数据区 | `FAWAI_DATA_DIR`（自系统配置迁入，仍写 `.env`） | **各业务独立多选**；索引缓存/配置库锁定；知识库=笔记 FTS/向量；任务会话=任务 API；观察/其它=可勾意向（engine=none 尚无全文库）；日志=可勾 |

真源 `FAWAI_INDEX_POLICY`。规划提示（含短档）与 `lore_search` 响应带【索引配置】/ `index_catalog` / `search_menu`（能力+效率）；LLM **应传 `scopes`** 选范围，缺省才混合已开通道。见 [检索范围由LLM决策.md](./检索范围由LLM决策.md)。

## 6. 禁止误解

- 索引缓存 / lore 库「再建一层文件 FTS」≠ 更强检索  
- `data/` 体积大 ≠ 应默认全文索引  
- 任务 `q=` 子串 ≠ SQLite FTS
