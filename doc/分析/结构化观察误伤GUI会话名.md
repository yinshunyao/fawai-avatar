# 结构化观察误伤 GUI 会话名

## 目标与终态

任务 `2ddc3563b7684328b1a49c6c74e68648`：发消息给微信「文件传输助手」。终态 `completed`，但时间线取证只有「工作区文件（未截屏）」，验证无截图；规划文案却写「下一步观察：截屏 / AX」。

## 用户多轮

材料有取消后续跑（「继续发送」）；无单独澄清截屏策略。

## 工具双栏

| 栏 | 结论 |
|:---|:---|
| **工具本身** | **P0 bug**：`_looks_like_structured_observe_goal` 用裸子串「文件」判结构化 → 候选只剩 `obs_fs`/`none`。`resolve_observe_methods` 在点选 `obs_screen`/`obs_ax` 与候选求交为空后，回落 `obs_fs`。进度卡「下一步观察：截屏」来自计划字段，实际执行已被硬闸静默改道。 |
| **调用** | 模型多次点选截屏/AX；无画面后改 `osascript` 键入并自认「缺乏 UI 验证」——属闸门坑诱发的换道，不是首选调用失误。 |

## 必要 / 可选路径

| 路径 | 类型 | 本案 |
|:---|:---|:---|
| 前台微信可见 | 必要 | `app_focus` 已验 frontmost |
| 画面/控件定位会话与输入框 | 必要 | 计划点选截屏/AX，**执行侧未采到** |
| 键入并发送 | 必要 | 后走 shell/osascript，无 UI 回证 |
| 工作区顶层列表 | 可选/误用 | 被闸门当成主观察 |

## 机制根因

1. **观察硬闸误伤**：产品名/会话名含「文件」→ 结构化 → 剔除 GUI 取证候选 → 点选截屏无效。  
2. **计划文案与实采脱节**：`planned` 展示 `plan.observe_kinds`，闭环用 `resolve_observe_methods` 后的结果，用户看到「要截屏」却只有工作区卡。

## 证据链

- goal 含「文件传输助手」→ `structured=True`，`candidate=['obs_fs','none']`，`resolve(['obs_screen'])→['obs_fs']`（修复前可复现）。  
- 会话卡：`观察完成（工作区文件）…未截屏`；`下一步观察：截屏` / `AX控件树`。  
- `stats.tools`：无截屏相关动作；有 `shell` osascript。
