# 检索范围由 LLM 决策（效率分层）

对照：曾「LLM 选工具 + `lore_search` 固定混合全开」→ 现为 **LLM 决策 scopes + search_menu 效率分层**，代码做闸门与执行。  
目的：少打无效盘、先快后慢；仍保留一段规划内并行/串行多步检索。

关联：`doc/功能/个人知识库/说明.md`；`index_policy.py`；`knowledge_search.py`；`brain/planner.py`；[记忆与检索业界思路对照.md](./记忆与检索业界思路对照.md)。

**P0 切片已落地**；P1 工具测试勾 scopes、P2 被动注入收窄仍为后续。本篇≠整包记忆产品放行。

## 1. 曾缺口 → 现状

| 层 | 曾缺口 | 现状 |
|:---|:---|:---|
| 选工具 | 指引偏「有搜就用混合」 | 提示要求先读 menu、传 scopes |
| 选范围 | 无 `scopes`，一次开齐 | `lore_search(scopes=[…])`；缺省才混合 |
| 效率感知 | 无相对耗时 | `search_menu`：efficiency 5→1 + 能力 + enabled |
| 多步 | 已有 parallel | 保留；文案要求可并行多 scopes / 串行先快后慢 |

## 2. 目标机制

1. **范围决策交给 LLM**：调用检索时显式带 `scopes`（或拆成多个专用工具调用）；代码按 scopes ∩ 策略已开 methods 执行。  
2. **能力 + 效率写入感知面**：【索引配置】/ `search_menu` 每条写清：能搜什么、相对效率、推荐工具、策略是否已开。  
3. **先高效后低效**：空命中或不够再扩范围 / 换慢通道；禁止默认全开混合当第一步。  
4. **多步规划保留**：同一段可并行多个**同效率档 / 互补面**窄范围检索；或串行「快→慢」。**缺口（另文，用户已确认要 P0+P1）：** 同意图下索引∥磁盘会钉死墙钟；且 `fs_grep` 常整仓扫——应先索引 → 定目录 → 窄磁盘。见 [检索索引先于磁盘.md](./检索索引先于磁盘.md)。

### 效率档（相对，供提示词；非绝对 ms）

| 效率 | 含义 | 典型 |
|:---:|:---|:---|
| 5 | 极快 / 库小 | 文件名索引、任务列表子串 |
| 4 | 快 | 笔记 FTS、专用 `name_index_search` |
| 3 | 中 | 工作区正文 FTS、日志子串 |
| 2 | 偏慢 | 笔记向量（嵌入） |
| 1 | 慢 / 现扫 | `fs_grep` / `explore_search` 大树 |

### 范围 id（`lore_search.scopes`）

| id | 能力 | 效率 | 策略闸 |
|:---|:---|:---:|:---|
| `work_name` | 工作区/可读区路径与文件名 | 5 | 区 methods 含 name |
| `work_content` | 工作区/可读区正文 FTS | 3 | 区 methods 含 fts |
| `lore` | 笔记 FTS∪向量 | 4/2 | 知识库 fts/vector |
| `tasks` | 任务会话 goal/title/id | 5 | 任务会话已开 methods |
| `logs` | 系统日志子串 | 3 | 系统日志已开 methods |

仓内现扫仍用 `fs_grep` / `explore_search`（效率 1），不进 `lore_search` scopes；菜单里并列写清。

## 4. 与「混合全开」的关系

- **兼容**：未传 `scopes` → 行为同今日混合（仅已开通道）。  
- **推荐路径**：LLM **应传** scopes；默认全开只作兜底。  
- 长期可再收紧为「未传 scopes 则只开效率≥4 的已启用项」（需另确认）。
