# 深度思考固定预算

对照对象：曾作为主脑默认的 `thinking_budget`（思考 token 上限）**512**。  
目的：说明用固定预算腰斩推理，换不来墙钟，也省不下 token。该默认注入已去掉。

关联真源：

| 类型 | 路径 |
|:---|:---|
| 现网行为 | [功能/LLM接入](../功能/LLM接入/说明.md)；`fawai_avatar/llm/thinking.py` 的 `resolve_thinking` |
| 谁在烧主脑思考 | 规划、执行反省、步骤重复、复盘走 `thinking_role=main`；快模型委派与观察反省默认关思考 |
| 提速应落在哪 | [工具与文本检索速度对照](./工具与文本检索速度对照.md)；[功能/主脑委派](../功能/主脑委派/说明.md) |

思考开启且预算为 0 或空时，请求不带 `thinking_budget`。只有调用参数或模型档案里的正整数才会封顶。档案留空不再自动写成 512。

---

## 结论

固定思考预算不能当作提速或省 token 的手段。

预算耗尽时，供应商停止推理通道，并接着生成正式回答。界面上的深度思考停在半句，裁决 JSON 仍会出来。半截推理加上一次被迫的裁决，比让这次想完更贵：错裁决会再进一轮规划，token 和墙钟都加在后面。

把 512 改成 1024、2048 仍是同一种封顶。机械步要快，应少进主脑，或把该段交给关闭思考的快模型。

## 为什么固定预算省不下来

| 现象 | 实际代价 |
|:---|:---|
| 思考在句子中间停止 | 推理没结束，只是通道被掐断 |
| 正式回答仍生成 | 该次调用的补全 token 含「残缺推理 + 裁决」 |
| 裁决依据不足 | 容易 `alternate` / `retry`，下一轮规划把 token 加回来 |
| 机械步也走主脑 | 不该想的步骤被切短，该想完的步骤也被切短 |

思考的开关可以按角色保留：快模型与观察反省默认关，主脑默认开。开了之后再用一个固定整数把推理切短，省的是这一次的推理长度，赔的是后面的空转。

## 提速落在少进主脑

下列都是已有机制，不靠思考预算：

1. 只读探路一次排多步，减少「一步一规划」。
2. 机械成功跳过观察反省。
3. 低风险子段委派快模型，该角色关闭深度思考。

主脑、执行反省、复盘仍需要把一次推理想完。请求在预算为空时不封顶。模型档案里手填的正整数仍会作为上限写进请求。

## 明确不做

- 用更小的固定预算换速度或换账单。
- 用调大预算假装解决腰斩；更大的常数仍会在别的任务半句处停下。
- 用本案的 SSH、引号或某条异常文案写一条专用提示。规划侧那次 `ValueError` 是提示组装的格式化缺陷，靠思考预算修不到。
