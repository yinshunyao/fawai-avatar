# 普通用户安装与跨系统分发

对照对象：fawai-avatar **当前可运行形态**（本机 Python 网关 + PWA），相对常见桌面分发手段（系统 Python / PyInstaller 冻成单文件 / 便携 Python 前缀 / Docker / 原生壳）。  
目的：回答「怎么给普通小白装到 Mac / Linux / Windows」，以及「要不要打一个带 Python 基础环境的三系统安装包」——形成可复用选型，**不等于**功能放行。

**已核：** 当前入口是 `venv` + `pip install -e`；Python `>=3.11`；无 PyInstaller/Docker/DMG/MSI；PWA 非宿主进程；keeper 用 `sys.executable` 拉起网关；`py_pip` 改同一解释器环境；运行时版本对包目录做快照/激活；macOS 要 Accessibility / Screen Recording 等 TCC；Windows 仅探测、未产品化 GUI/安装路径。  
**未核：** 便携前缀在三系统上的签名与杀软实测；App Store / 公证长期策略；Windows 能力矩阵达标时间。

## 1. 产品形态决定分发形态

fawai 不是「双击打开的单页桌面程序」，而是：

```text
本机常驻 Python 服务（gateway + keeper）
        ↑
   局域网 / 穿透 PWA（浏览器里聊）
        ↓
   本机工具 / 文件 / shell /（macOS）GUI
```

会话壳已定：**不做原生 App**（PWA 即可）。因此分发要解决的是「**把本机服务装上并保活**」，不是再做一个 Electron 聊天客户端。

对小白用户，真正要藏起来的是：克隆仓、建 venv、`pip install -e`、装可选 `.[browser]`、配 `.env`、记启动命令。

## 2. 候选方案对照

| 方案 | 小白体感 | 与现架构契合 | 三系统代价 | 判定 |
|:---|:---|:---|:---|
| **A. 让用户自装系统 Python + 照 README** | 差：命令行门槛高 | 与开发态一致 | 低（文档即可） | 只适合开发者 / 运维，**不当消费分发主路径** |
| **B. PyInstaller / Nuitka 冻成单 exe/.app** | 好：像普通软件 | **差**：冻死后难自进化写源码树、难 `py_pip`、难运行时选版 `copytree`、Playwright/Chromium 与 frpc 旁路二进制难嵌；keeper 子进程身份也变复杂 | 高（三系统分别打、体积大、排障难） | **不推荐作主路径**；最多给「无自进化、只跑固定版」的阉割通道 |
| **C. 便携 Python 前缀 + 预装依赖 + 一键启动器（三系统各一包）** | 好：双击/装完即开浏览器 | **好**：仍是真 Python 树；可保留可写包目录、venv/`site-packages`、`sys.executable` 语义 | 中：要做 **3 套产物**（macOS / Linux / Windows），但共享同一套「前缀布局」与启动逻辑 | **推荐主路径**（即「带 Python 基础安装包」的正确理解） |
| **D. Docker / 容器** | Linux 服务器尚可；Mac GUI / Windows 桌面权限与键鼠几乎不可用 | 适合 headless 编码机 | 对小白桌面不友好 | 只作 **Linux 无界面 / 云机** 旁路，不当三端统一方案 |
| **E. 原生壳（Electron/Tauri）包一层托盘** | 托盘/开机启动更像「软件」 | UI 仍可嵌 WebView 打开本机 PWA；**壳本身不是会话真源** | 多一层构建 | **可选后置**：主包仍是 C；壳只负责保活与打开浏览器，不替代 Python 运行时 |

「打包一个有 Python 基础的安装包」≈ **方案 C**，不是「再发明一个系统 Python 安装向导让用户点完再 pip」。

## 3. 推荐主路径：私有 Python 运行时前缀（三系统分发）

### 3.1 包里放什么（三系统同构）

每个系统一份安装包 / 压缩包，内容同构，二进制按 OS/架构换：

```text
FawaiAvatar/
  runtime/          # 私有 Python 3.11+（python.org / python-build-standalone / embeddable）
  app/              # fawai_avatar + fawai_lore（可写，供进化与运行时选版）
  site/ 或 .venv/   # 预装好的依赖（openai / fastapi / uvicorn / Pillow；mac 另含 gui）
  bin/              # 本系统 frpc；可选预置 Playwright Chromium
  data/             # 默认空；运行时状态落这里（或指到用户目录）
  Start.*           # 本系统一键启动（见下）
  Uninstall.*       # 可选
```

原则：

1. **永远用包内解释器**，不碰系统 `/usr/bin/python3` 或用户自己装的 Python。  
2. **保留可写源码/包树**，自我进化、`py_pip`、运行时版本快照才能继续成立。  
3. **依赖预烘焙进包**，小白安装时尽量 **0 次 pip**（升级走「换整包」或产品内选版，而不是现场编译）。  
4. **三系统 = 三份产物**，不要幻想一个 zip 通吃；共享的是布局与打包脚本，不是同一个二进制。

### 3.2 各系统交付物（建议）

| 系统 | 交付形态 | 启动体验 | 备注 |
|:---|:---|:---|:---|
| **macOS（优先）** | 签名 + 公证的 `.dmg` → `Fawai Avatar.app`，或「拖到应用程序」的目录包 | 双击 → 起 keeper → 自动打开本机 PWA；菜单栏可后置 | TCC（辅助功能 / 屏幕录制 / 按需完全磁盘）必须引导；权限挂在 **包内 Python/启动器身份** 上，换路径要重授 |
| **Linux** | `tar.gz` / AppImage；可选 `.deb` | `Start.sh` 或桌面入口；无界面机可装 systemd user unit | GUI 截屏键鼠本仓未落地；消费桌面包以「网关 + 文件/shell + 可选浏览器」为主，与功能边界一致 |
| **Windows** | `Setup.exe`（Inno/NSIS）或解压即用 zip + `Start.bat` | 开始菜单快捷方式；可选托盘 | **能力未产品化前不要承诺小白 GUI**；先做「服务起来 + PWA 能聊 + 文件/shell」再谈键鼠 |

### 3.3 启动器职责（薄）

启动器只做运维胶水，不重写产品。装完后主动作是**起本机 Web（会话网关）**：

1. 设 `FAWAI_*` / `PATH` 指向包内 runtime  
2. 起 `fawai-keeper`（或等价 `python -m …`）  
3. 健康检查通过后，**本机默认打开 `http://127.0.0.1:<port>/`**（不用局域网网卡地址）  
4. 远端 / 手机：**不代开**；用户自行在对方浏览器填局域网 IP / 穿透 / 中继与口令（启动横幅可展示供抄写）  
5. 失败时给出**中文**可读日志路径（不要只剩终端栈）

可选后置：开机启动、托盘「打开本机界面 / 退出」、日志一键打包——仍属壳，不是原生会话 App。

### 3.4 明确不要做的

- 不要把「先装官网 Python，再跑我们的 pip」当成小白主路径。  
- 不要用 PyInstaller 单文件当默认发布，除非另开「只读运行、关闭自进化/`py_pip`」产品线。  
- 不要为了分发去推翻「PWA、不做原生会话 App」；壳最多托盘。  
- 不要让安装器代开手机/远端浏览器，或把自动配对当首期必达。  
- 不要在 Windows 能力矩阵未达验收前，对外宣传「三端同等桌面操控」。

## 4. 分阶段（均为必要项的实施先后，除非标可选）

立项后范围已钉为 **三端同轮出包**（见 [议题结论](../议题/安装器与跨系统分发/结论.md#已定结论)）。下列 **P0→P2 是实施优先级**，后项仍在范围内；标「可选」的才可砍。联调可分端先后，但主验收须三端工件都齐。

| 优先级 | 内容 | 验收 |
|:---|:---|:---|
| **P0** | 定「前缀布局」+ 打包脚本（三端工件）+ 启动器起网关 + **本机默认开 `http://127.0.0.1:<port>/`** | 非开发者机器上 **无手动 venv/pip**；三端均可起服务并本机进 PWA |
| **P1** | macOS TCC 引导与签名公证；Linux tar/AppImage + 保活说明；Windows Setup/zip 冒烟；整包升级 vs 运行时选版分工写清 | 小白按提示能过权限；Linux 可保活；Windows 至少网关+文件/shell |
| **P2** | frpc / Playwright 预置或惰性下载体验；失败日志可读 | 旁路二进制不靠手敲命令 |
| **可选** | 托盘壳、自动更新、静默安装、商店 | 砍掉不影响「三系统能装能开」主验收 |

## 5. 与现有机制的摩擦点（选型时必须正面处理）

| 机制 | 对分发的含义 |
|:---|:---|
| **自我进化写 `fawai_avatar/`** | 安装树须可写；只读 Program Files / 签名只读 bundle 会逼你把可进化部分迁到用户数据目录——若走这条，要先改运行时布局再打包 |
| **`py_pip` 共用解释器** | 便携前缀可以；冻成单文件基本不行 |
| **运行时版本快照** | 需要包目录可 `copytree`；与「整包升级」要分工：选版管代码回滚，整包管 Python/依赖大版本 |
| **macOS TCC** | 权限跟进程签名身份走；便携 Python 必须稳定路径 + 代码签名，否则小白每次搬家重授权 |
| **frpc / Playwright** | 按 OS 带对应二进制；文档已写「不自动下载 frpc / 不自动 playwright install」——消费包应改为「包内预置或安装器一步完成」 |
| **Windows** | 今日探测有、产品面弱；分发包可以先做，但对外能力文案必须低于 macOS |

---

## 6. 结论（怎么操作最合适）

1. **最合适：三系统各打一份「私有 Python 运行时 + 预装依赖 + 可写应用树 + 一键启动器」**——这就是「有 Python 基础的安装包」，且适配现有 gateway/keeper/自进化/`py_pip`。  
2. **不要**把 PyInstaller 单文件当默认；**不要**让小白先装系统 Python；**不要**为聊天再做一个原生 App（与已放行边界冲突）。  
3. **立项范围**：三端同轮出包（[议题](../议题/安装器与跨系统分发/结论.md)）；联调可分端，主验收三端工件齐；Windows **安装器**与 Windows **GUI 能力**分开承诺。Docker 仅作无界面旁路。  
4. 本文为分析备忘；实现须经议题放行后写入 `doc/功能/`。

## 7. 可选项改进方向（未立项）

- 用户数据与代码树分离：`~/Library/Application Support/FawaiAvatar`（及 Linux/Windows 对等路径）放 `data/` 与可进化 overlay，签名目录只读——利于公证，但要先改路径约定。  
- 惰性组件：浏览器内核首次使用再下，主包装体积更小。  
- 极简「只读运行」通道：关自进化与 `py_pip`，才考虑真正的冻二进制（与主产品分轨，避免架构打架）。
