# 禁读与工作记忆

对照对象：规划里的「不要再盲读同一文件」，以及历史窗把已读正文压掉之后，下一步还拿不拿得到文件里的事实。  
目的：钉清这条禁读只该挡住空转，不该在上下文里没有所需原文时把任务判死。**不等于**功能放行。

## 1. 现状

文件仍是事实来源。规划用的历史是有损的：近窗会把过长正文收成「按 path/行号定向再读」；远窗只留工具名、路径和成败，并写「勿重复盲读同一大文件」。同一路径的旧读还会被去重。

与此并行的提示是：没有新问题就不要整文件再扫；同窗再读要带 `allow_repeat`，否则步骤重复会当同构步。步骤重复裁决也写「禁止无新问题继续盲读同一文件」。代码会丢掉「禁止再读某个已出现路径」这类约束，但只在约束里带上了那个路径时才丢。像「禁止再次读取本地配置文件」这种不点名路径的句子会留下来。

模型因此会把软提示收成硬禁令：既然不能再读，而当前上下文里又没有地址和口令，就 `failed`，并请用户把账号口令交出来。

近窗省略其实要求再读，远窗摘要却说别再读。两边对着，模型选了禁读。

## 2. 为什么不合理

禁读要防的是：同一窗口的原文还在上下文里，却用同一步指纹空转。

它防不住、也不该防的是：下一步要用的字段已经不在上下文里。压缩、去重、换一段、上次只读到别的小节，都会出现这种空洞。此时再读是取证，不是空转。读不到就失败，等于用规则制造一个完不成的任务。

向用户索要仍在可读文件里的口令，也和现有规划约束相反：远端凭据应从已授权文件读进环境变量，thought 里不写明文口令；用户不在电脑边时，不要改成「请把配置贴过来」。

`allow_repeat` 只豁免「明知同窗还要再看一次」。正文已经被压掉时，正确动作是换行窗、换小节检索，或在确需同一窗时声明 `allow_repeat`。缺这个标记不等于任务失败。

## 3. 应保持的边界

| 情况 | 下一步 |
|:---|:---|
| 本步要用的原文还在当前上下文里，再读同一窗 | 算空转；换指纹或进入改写/作答 |
| 只要 path，正文被压掉或根本不在本轮提示里 | 定向再读或按小节检索；禁止因此 `failed` |
| 同窗验收（刚改完要核对） | `allow_repeat` |
| 文件确实不可读（路径闸、文件不存在） | 按工具结果失败，并给出可复制命令 |

「不要盲读」只在第一种成立。第二种必须再读。

## 4. 若以后改提示（未放行）

下列为必要项，编号只表示先后。

1. 规划与远窗摘要改成：正文不在当前上下文时必须定向再读；禁止把「曾经读过」写成「禁止再读」后 `failed`。超窗 compact 已去掉摘要里的禁读句，并写明摘要里没有的事实要定向再读。机械远窗仍是 compact 失败时的退路。
2. 步骤重复清洗丢掉一切「禁止再读某文件 / 禁止再读配置」且未说明原文仍在上下文中的约束，不论有没有写绝对路径。
3. 收尾不得改问用户补一份仍可从文件读取的地址或口令。

不另开「某主机 / 某配置文件名」专用闸。
