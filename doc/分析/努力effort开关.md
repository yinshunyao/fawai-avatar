# 努力：Effort 开 / 关

对照对象：观察反省 `enough_to_answer`、执行反省 alternate、规划收尾闸；对话 compose 上的开关。  
目的：默认 **Effort 关**（平衡收束、可早交）；打开 **Effort** 后尽最大努力完成必要路径，避免把「差一点就能修」的失败升成「环境不能做」并交过期答案。  
证据任务：`6d71d77272ae4268974ae8e0fe6952ef`（用户要求实时重查 4090；相对路径 `expect probe_4090.exp` 失败后反省写「停止 SSH」、观察标 `enough_to_answer`）。  
已落地（见 [功能/Effort](../功能/Effort/说明.md)）；本篇保留机制对照。

## 命名（真源）

| 对外 | 存盘 | 含义 |
|:---|:---|:---|
| **Effort 关**（默认） | `meta.effort=false` / 缺省 | 平衡收束；证据够验收口径可交 |
| **Effort 开** | `meta.effort=true` | 尽最大努力；必要路径与新鲜度优先，可修复失败禁止早退；与 Fast（极速）解耦可同开 |

UI：compose 旁开关或勾选，文案用 **`Effort`**（中文旁注「尽最大努力」即可），状态是开/关，**不要**再用 Auto / Max 两档名。

与外部产品：

| 外部 | 含义 | 本方案 |
|:---|:---|:---|
| Cursor Auto | 模型路由 | **无关**；本开关不换模型池 |
| Claude Code effort | 读多少、验多少、坚持多久 | **语义对齐**；这里收成布尔开/关，不开多档 `low/medium/max`（除非以后另议） |

禁止把开关写成「自动选模型」。

## 本案暴露的缺口（为何要开 Effort）

1. **`enough_to_answer` 过软**：摘录/旧基线即可标够用；用户已要求「必须查现况」时仍可标够用。  
2. **失败包装 → 假归因**：`expect failed: tool not ok` + 相对路径 ENOENT → 反省写成沙箱 / expect 不可用，并 alternate 禁止再连。  
3. **必要路径可被软放弃**：可修复的 cwd/绝对路径错误，未强迫「先用已知绝对路径重试」就进交付。

Effort **关**：允许「差不多就交」。Effort **开**：上述三条收紧。共用同一套工具与闸门；差异在提示词门槛、软信号权重、止损时机。

## 产品形态（UI）

| 项 | 口径 |
|:---|:---|
| 位置 | 会话 compose 区（发送旁）：`Effort` / 中文「全力」 |
| 作用域 | **任务级** `meta.effort`；进行中可拨，立刻写回任务，闭环下一拍生效 |
| 终态 | 任务结束后留下最后一次设定；打开该任务时底栏展示终态 |
| 新建 | 跟随**全局末次**（与 Fast 共用一套末次表，不区分任务类型）；建完仍可改 |
| 可见性 | 任务头/步骤可显示「全力开」（解释为何轮次多） |
| 不做 | 不为开 Effort 另做第三套工具清单；不为某机房/脚本开特例闸 |

生命周期细节与现状缺口：[极速全力任务级开关](../问题/极速全力任务级开关.md)；Fast 侧对照：[Fast极速模式](./Fast极速模式.md)。

## 总原则

```text
Effort 关：成本与完成度折中；允许「证据够验收口径」就收；可修复失败仍建议修，但不无限追。
Effort 开：必要路径未齐或未标明硬阻塞前，禁止够用收尾；可修复失败必须先换道重试；接受更多轮次与 token。
```

「必要路径」沿用复盘尺子：抽象槽位（鉴权材料、作用对象、副作用/观测动作），禁止机房特例。

## 差异化矩阵（核心）

| 层 | Effort 关（默认） | Effort 开 |
|:---|:---|:---|
| **观察反省 · `enough_to_answer`** | 允许：本步证据已覆盖当前 goal 验收口径（未要求「必须刷新」时可用合理基线） | **谨慎**：默认倾向 `advanced`；仅当（a）必要路径均已尝试或硬阻塞已写明，且（b）证据相对用户最新约束仍新鲜（追问「必须查现况」则旧 epoch **不得**够用）才可 `enough_to_answer` |
| **观察 hints → 规划** | hints 软参考；规划可 early `success` | hints 若含够用/交基线，规划须对照必要路径台账；缺项则继续，不得只凭 hints 收 |
| **执行反省 · alternate** | 可放弃一条阻塞路径，改交已齐材料 + 手动命令 | **禁止**把「相对路径找不到 / 可拼绝对路径 / 已知凭证未用」写成环境不可达并停止；须先要求换绝对路径、`cwd`、或已定位铲子再 alternate |
| **假归因清洗** | 既有规则 | 加强：stderr 已是 `no such file` / `Permission denied` 时，constraints **禁止**升成「沙箱断网 / 工具族不可用」除非有独立证据 |
| **步数 / 烧轮** | 现网 `FAWAI_MAX_STEPS` + 既有探索/定位预算 | **拉长**「只读无进展」止损阈值；可选提高探索/定位强制与 abort 阈值 |
| **步骤重复 / 指纹** | 累计到阈即裁决 | 同构失败后优先参数级换道（path/cwd/绝对路径）再计空转；禁止「同指纹禁令」挡住唯一合理的路径修正 |
| **答复覆盖 / 问询收尾** | 默认纪律 | 更严：追问含「实时 / 重新连 / 必须查」时，终稿不得只复述 prior 基线冒充完成 |
| **深度思考** | 维持现配置（观察反省默认关思考） | 可选：规划 / 执行反省开思考；观察反省仍建议关 |
| **模型** | 不变 | **默认不变**（开 Effort ≠ 换更大模型）；「Effort 开时用更强模型」为可选项 |
| **委托 / 子目标** | 按现逻辑 | 更倾向拆必要路径子目标做完再交；`stop_when` 写验收而非「差不多」 |

## `enough_to_answer` 细则

标够用前须过表；**Effort 开时缺任一条则不得标**；Effort 关对「新鲜度 / 可修复失败」可放宽一档。

| 检查 | 问什么 | Effort 关 | Effort 开 |
|:---|:---|:---|:---|
| 验收对齐 | 证据是否答当前 goal（含最新追问） | 要 | 要 |
| 新鲜度 | 用户是否要求刷新/重连/不得用旧日志 | 若要求则要；未要求可用合理基线 | 凡要求刷新则必须有本轮新观测 |
| 必要路径 | 鉴权、对象、观测/副作用是否都尝试或硬阻塞 | 建议 | **强制** |
| 可修复失败 | 最近失败是否仅为 path/cwd/拼写且上下文已有正解 | 可够用并附手动命令 | **不可够用**；须重试正解 |
| 摘录边界 | 观察入模是否压缩摘录 | 可判断方向；收尾仍靠规划全文 | 同左；**禁止**因摘录不全标够用 |

提示词：在 `obs_reflect_system_prompt` 按 `effort==true` 注入门槛；写明「过期基线 ≠ 够用」「ENOENT+已知绝对路径 ≠ 工具不可用」。

## 闭环接线

```text
compose Effort 开/关 → inbound / task.meta.effort（bool）
        ↓
建卡写入 meta.effort
        ↓（若进计划模式）
bootstrap_parent_meta 整表替换时须保留 effort；监管子任务继承父 effort
        ↓
loop 规划 / 观察反省 / 执行反省 读 effort
        ↓
提示词门槛 +（可选）预算旋钮
```

|:---|:---|

## 明确不做

- 不把 Effort 开做成「关闭所有止损、死循环到账单爆」。硬闸（写租约、shell 禁绕过 fs、取消）两边都在。  
- 不把 Cursor Router 的 Cost/Intelligence 塞进同一控件。  
- 不为单机房 / 单 `probe_*.exp` 写专用门；路径修正规则须对任意「相对路径失败但绝对路径已知」成立。  
- 不在 Effort 关时禁止 `enough_to_answer`（否则日常问询会无谓拉长）。  
- 首期不做 `low/medium/high/max` 多档；只要布尔开/关。

## 验收口径（立项后）

| 场景 | Effort 关 | Effort 开 |
|:---|:---|:---|
| 普通事实问询，证据已齐 | 可较早 `success` | 可多验一轮，但允许收 |
| 用户要求实时重查；旧 epoch 在手；相对路径脚本失败且绝对路径曾读过 | 可交基线+手动命令（须标明未刷新） | **必须**用已知绝对路径/`cwd` 再探；未硬阻塞前不得 `enough_to_answer` 交旧基线 |
| 真硬阻塞（认证失败且无第二凭证） | failed/手动命令 | 同左；可多试一类换道后仍 failed |

## 一句话

**Effort 关 = 平衡收束；Effort 开 = 必要路径与新鲜度优先、可修复失败禁止早退。** 对话框默认关；开时 `enough_to_answer` 须过验收对齐 × 新鲜度 × 必要路径 × 可修复失败四关。
