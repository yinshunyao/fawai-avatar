# `doc/` — 全部可读文档

## 目录用途

本仓库**唯一**的可读文档根。  
代码、脚本、测试放在 `doc/` **以外**的目录。细则见 `.cursor/rules/rules-doc-code.mdc`。

## 文档范围

| 允许 | 禁止 |
|:---|:---|
| 给人读的 Markdown / 图示说明 | 可运行业务代码、可执行脚本主体 |
| 术语与称呼索引、实现映射 | 与代码树重复的长篇拷贝 |
| 各子目录自洽的 `AGENTS.md` | 无规范名的同义新词四处散落 |
| **议题**（讨论）、**功能目录**（放行/已支持）、**测试**（评估任务说明）、**版本**（版本评测报告） | **独立 `or/`**、人工平行需求树 |

## 两层真源（强制）

| 层 | 路径 | 回答什么 |
|:---|:---|:---|
| 讨论 | `议题/` | 在想什么、定了什么原则、可行性如何——**未等于放行** |
| 功能 | `功能/` | **准实现 / 实现中 / 实际已支持** 的功能面；实现与验收看这里 |

- **不维护** `doc/or/`，不套 `01-or`～`99-ops`。
- 写入功能目录须用户明示（放行 / 写入功能目录等）；助理不得只凭议题「已定结论」自动加行。
- 开工：只实现功能表中 `放行` 或 `实现中` 的条目；做完改为 `已支持` 并填代码列。

## 目录结构

```text
doc/
  AGENTS.md                 ← 本文件
  术语与称呼索引.md
  议题/                     ← 议题讨论（见 议题/AGENTS.md）
  功能/                     ← 功能目录（见 功能/AGENTS.md）
  测试/                     ← 可复跑测试任务说明（见 测试/AGENTS.md）
  版本/                     ← 产品版本评测与总分（见 版本/AGENTS.md；≠ 功能「版本管理」）
```

新增子树须带 `AGENTS.md`，并在本文件结构节登记。可选：根上产品地图；**不建 `or/`**。

## 术语与称呼索引（强制）

真源：`术语与称呼索引.md`。

- **规范名**：文档正文、代码注释锚点、LLM 工具称呼的唯一主名。
- **别名**：会话口语、旧称 → 同一规范名。
- **实现**：代码路径/符号；未落地写「未落地」。
- **工具行**：工具 id 与入口，与规范名对齐。

维护时机：新增能力、改名、落地、稳定新说法——**同一回合**更新。功能放行时规范名须已在表中或同回合补上。

## 文档 ↔ 代码关联

1. **功能总表「代码」列**或功能说明中的实现映射为优先入口；术语表「代码」列保持一致。
2. 代码入口注释指向规范名或 `doc/…` 路径。
3. 映射失效时同回合修功能表、术语表与代码锚点。

## 协作约定

| 相邻 | 边界 |
|:---|:---|
| `议题/` | 讨论与原则；稳定称呼回写术语表 |
| `功能/` | 放行与已支持清单；实现只认这里 |
| `测试/` | 可复跑任务说明；自动化代码不在本目录 |
| `版本/` | 每版文字评测、加权总分；任务怎么跑仍看 `测试/` |
| 代码目录 | 只放实现；长说明链回 `doc/` |
| `.cursor/rules/rules-doc-code.mdc` | Cursor 强制规则真源 |
| `.cursor/rules/rules-platform.mdc` | 跨平台：设计与代码须考虑 OS/headless；无法本机调试也要完成支持 |

编辑 `doc/` 前先读本文件与 `术语与称呼索引.md`。
