# 完成任务（C2）

## 验收

- 规划前注入**能力清单**；大脑仅从清单选型。
- 工作区文件类目标必须产出 `fs_*` / `version_*`（或说明失败），禁止用 GUI 代替。
- 超出清单能力时 `status=failed` 并说明边界；禁止空动作假成功。清单约束的是 **action_kind 选型**（不是正文生成上限）：缺无法等价完成的动作族、真硬闸（实名/支付/软件破解等；**禁止**裸「破解」误伤故事题）、或无界面却规划 GUI 才算越界。大纲/脚本/故事/PPT 文案 = 模型生成 + `fs_write` 落盘，**禁止**因「无创意 skill / 编排元概念不在清单」假 failed。计划模式的监管授权/租约/产物键由**运行时**兑现，不是工具。闭环：假归因「超出能力」回灌至多 1 次；**已写入且终稿自认内容齐仍假 failed → 直接升 `success`**。另：**假归因「找不到样式/源码」**——已有成功 `fs_read` 前端入口或非空 `fs_grep` 却空口结案 → 回灌至多 1 次（读命中行改写或分项阻塞）。
- **交稿体例**：面向用户的 success/failed 终稿默认写成报告：先一句结论，再分项；有对照用 Markdown 表；有步骤、分支、依赖或结构关系时加一段 mermaid 流程图（`flowchart`）。没有这种关系不要硬画，也不要编数据。用户已规定体例（一句话、简短、不要图表、纯文本等）时只按该体例。执行中的 thought 仍宜短。会话里的 mermaid 代码块会画成图。
- **交稿意图 / 输出类载荷（常开）**：空 `actions` 的 `success` 若 `thought` 是「读取…然后向用户交付」「准备输出最终报告」等**下一步计划**，一律回灌重写（至多 1 次）再 `failed`。追问/goal 含「直接输出 / 输出报告 / 贴出来 / 发给我」等时，终稿须有可验收正文，或「结论 + 产物路径 + 短摘要」；**写盘成功 ≠ 已向用户交稿**。判定对照 `goal` + `meta.followups`。实现：`answer_effect.thought_is_delivery_intention` / `goal_needs_delivery_payload_gate` + `runtime/loop.py`。
- **答复覆盖闸门**（**默认关**，`FAWAI_ANSWER_COVERAGE_GATE=1` 才启用）：问询/状态/查找落点/机器硬件盘点/输出交稿类目标在 `success` 时，`thought` 须直接含可验收事实；禁止「已获取/已汇总/已找到并结束」等过程元叙述与交稿意图句。硬件/服务器配置须先一句结论再分项（覆盖证据已有的 GPU/CPU/内存/磁盘/系统/路径等），禁止只报一两项；查找账号/路径须点明来源文档。材料被压缩时须先 `fs_read` observe 全文（优先相对 path）再总结，禁止只凭截断预览收尾。拒因细分：`meta_narration` / `delivery_intention` / `delivery_thin` / `inventory_thin` / `lookup_no_path` / `unread_dump` 等，失败文案与重试提示按因回灌缺维。材料不足 → `failed` / `need_input`。禁止在终稿写明文口令。查找落点优先 lore + `FAWAI_READ_ROOTS` 下 `fs_read`，禁止开场整盘 `grep -r ~`；禁止 shell cat/cp 绕过 fs。当前默认关闭是因启发式易把动作节点终稿误判为过程元叙述；**交稿意图句与输出类载荷闸不受此开关影响**。
- **过程相位**：规划按「定位 → 取证 → 改写/作答 → 验收」推进；宽搜/整文件盲读属可选。工具观察默认不压缩；取证看 hits / 小窗 `fs_read`。若显式打开 soft 且有未读 dump，仍可注入 `【压缩未读·禁宽搜】`。
- **必要路径台账**：多前置目标（同时暗示材料/落点与变更/副作用）须分清必要 vs 可选路径；抽象槽位含鉴权/落点材料、作用对象或脚本、副作用动作、**证据保真**（改写或答复所依赖的可回读原文）。各必要路径均须尝试或标明阻塞；一条阻塞时不得遗忘其他已就绪路径（须推进副作用，或 `failed` 时分项说明并兑现可复制命令）。规划提示注入；反省/步骤重复 `alternate|abort` 追加台账约束；`failed` 若「声称交命令却无命令体」或「未分项」则回灌重写一轮（`FAWAI_PATH_LEDGER=0` 可关）。不绑业务专名。
- **远端升级/同步**：优先 `rsync-ssh-deploy.sh` / `ssh-run-with-pass.sh`（凭据进 env）；可在 work_root 临时写脚本再执行；禁止无口令 BatchMode ssh 空探针当主路径。
- **自我纠错（方法族）**：SSH 认证失败 → 代码注入带密 shovel 换道约束；远端进度闸默认关，仅 `FAWAI_REMOTE_IDLE_GATE>0` 时对连续只读注入（见 [执行反省](../执行反省/说明.md)）；远程不在场答复否决「请贴配置」。
- 用例 A：写入 `notes/c2_hello.txt` → `fs_write`。
- 用例 B：读取该文件 → `fs_read`，结论含内容。
- 用例 C：误导「用鼠标画圈写文件」→ 仍 `fs_write`，禁止 GUI 代替。
- 超清单：未登记 App / 银行实名等 → `status=failed`，禁止假 success。

## 边界

- 不做 C3 GUI 控件接地；C4 见 [自我进化](../自我进化/说明.md)。
- 不做未登记软件的自动发现与安装。
- GUI 动作允许出现，但须在 `thought` 写明依赖屏幕的理由；文件类目标触发硬校验。
- 硬校验失败：附加约束重规划 1 次，再失败则 `failed`。
- 页面/布局改动的收尾见 [编码闭环](../编码闭环/说明.md) 可见副作用闸；与答复覆盖闸按目标分流，不叠用。实机截屏/浏览器验页属**可选**，不得升成必要路径；验窄屏用 `browser_*`+`viewport=mobile`。
