# 任务分析规则

分析失败/空转/假成功任务时的强制口径。适用于：Cursor 人工复盘、产品内「任务复盘」全维分析、讨论里点名某 `task_id`。

真源：本文件。Cursor 规则：`.cursor/rules/rules-task-analysis.mdc`。复盘提示词：`fawai_avatar/skills/review.py`。

## 强制视角

1. **智能体机制优先，禁止只复述终态文案**  
   不得停在「错误信息是什么 / 最后一步做了什么」。必须回答：闭环里哪一环（规划 / 观察 / 动作 / 反省 / 步骤重复 / 结果判定）为何未能把任务推向可验收副作用。
2. **优化须针对通用任务，禁止只修本案**  
   优化项须能迁移到同类目标（任意「改仓内前端/写文件/查因」），不得写成「下次对 Markdown 任务别读 index.html」这类单例补丁。单例仅可作证据，不可当优化标题。
3. **区分表面失败与机制失败**  
   | 层 | 问什么 |
   |:---|:---|
   | 表面 | 终态 `failed` 文案、最后 fingerprint、某步 `ok=false` |
   | 机制 | 为何长期无写动作、守卫是否误伤/误导、提示词是否注入错误世界模型、有无进度闸门 |

## 分析输出结构（强制）

按下列顺序写（产品复盘可落在五维里，但总述须能还原本结构）：

1. **目标与终态**（一两句）  
2. **机制根因**（1～3 条，可跨任务复用的失败模式名）  
3. **证据链**（短码/步号/工具统计/调度计数；点到为止）  
4. **通用优化清单**（每项：改哪一层、验收口径、为何通用于类任务；勾选前须能看到将改路径/知识库条目或补丁摘要，禁止只有抽象标题）  
5. **明确不做**（若本案不该靠改产品修的，写清）

## 最终答复用户（强制）

面向用户的正文（Cursor 聊天结论、产品【分析】总述与五维文案、清单标题/rationale）须同时满足：

| 要求 | 含义 | 禁止 |
|:---|:---|:---|
| **全面性** | 覆盖输出结构与命中的机制检查项；五维有材料则各有一句到位结论，缺材料则点明「材料不足」而非跳过 | 只写终态一句；只展开一维；漏写「明确不做」却暗示会改不该改的 |
| **准确性** | 断言须能落到证据（步号/工具统计/短码/调度字段）；区分表面与机制；不确定写「材料不足以判定」 | 臆造未出现的路径/框架/工具结果；把 abort 文案当唯一根因；夸大「已修/将修」 |
| **专业性** | 用智能体机制与产品层术语（规划/观察/mutate/反省/步骤重复/结果判定）；优化写清改哪一层与类任务验收 | 口语流水账；把「换更大模型」当唯一解；单例菜谱冒充机制结论 |
| **易读性** | 短段 + 编号/小标题；先结论后证据；术语首次可括注；清单一项一事 | 超长不分段；证据堆淹没结论；把 JSON/内部字段名直接甩给非技术读者当主文 |

产品复盘：`analysis` 与 `dimensions` 给人读，须过上表；`items` 的 `title`/`rationale`/`impact` 同口径，勾选卡还须有 `change_summary`/`preview`（由 payload 摘要，见 `items_for_ui`）。Cursor 人工复盘：聊天终稿同样过上表，不得只丢半成品提纲。

## 常用机制失败模式（检查清单）

分析时逐项过；命中则写入根因，未命中可略。

| 模式 | 症状 | 典型缺口 |
|:---|:---|:---|
| **探索→改写相位未切换** | 大量 `fs_read`/`fs_grep`/`fs_glob`/`explore_*`，`write_set` 空或无 `fs_write`/`fs_patch`/`fs_replace` | 无「证据已够则必须改写/澄清/失败」的进度闸门 |
| **同构守卫过窄** | 参数微调（offset/pattern 微变）导致指纹不撞，空转烧满轮次 | 仅步骤指纹；缺「只读探索连续 K 步」类启发式 |
| **alternate 幻觉约束** | 步骤重复/反省注入「禁止读已定位文件 / 去找不存在的 Vue/React src」等与证据矛盾的约束 | 裁决提示未要求约束必须 grounded；先验框架压过观察 |
| **守卫止损掩盖上游空洞** | 表面因 fingerprint abort，实质从未进入改写相位 | 只治重复、不治无进展 |
| **规划格式崩溃** | `无法解析 JSON` / 空 content，短任务直接 failed | 格式重规划不足或 tool_calls 回退未触发 |
| **假成功 / 边界未明示** | `completed` 但无验收副作用，或超清单却未 `failed` 说明 | 结果判定与能力清单脱节 |
| **假成功 / 死补丁（有 mutate 无目标副作用）** | `completed` 且 `write_set` 非空，但 diff 仅为未引用 CSS 变量/注释/空白，界面无变化；或收尾 `thought` 为 `native tool_calls` | 探索闸门只逼写出；缺弱写入检测与可见副作用收尾闸 |
| **假成功 / 答复未覆盖目标（问询元叙述）** | goal 在问状态/进度/是否/多少，终稿只写「已获取/已汇总/并结束」等过程，无事实载荷 | 结果判定只认 `success`+空 actions；缺答复覆盖闸；复盘若只喂轨迹前缀，会漏看末步 |
| **假成功 / 配置盘点过薄** | goal 查硬件/服务器配置或账号落点，终稿只报 GPU+CPU 一两项，缺内存/盘/系统/来源路径 | 答复覆盖闸未覆盖「查看配置/在哪里」类；finalize 提示未要求分项；压缩观察后未读全文 |
| **压缩观察未回读** | 工具结果已压缩落盘，success 只凭头几行；或失败文案笼统叫「过程元叙述」实为盘点过薄 | 缺 unread-dump 闸；拒因未细分；未强制 `fs_read` observe |
| **shell 绕过 fs 沙箱** | `fs_read` 越界后 alternate 教 `shell cat` 读绝对路径；凭据明文进轨迹 | 反省 constraints 未 grounded；缺代码侧清洗与脱敏 |

## 通用优化方向（写清单时优先这类）

优化项 `kind` 仍用复盘约定（`prompt_patch` / `code_patch` / `lesson` / `skill` / `rule_patch`）。内容优先：

1. **进度闸门（代码）**：连续 K 步仅成功只读探索且无写资源 → 注入硬约束并收紧原生写工具面；达中止阈值先强制改写一轮，仍无写入再 `failed`/`need_input`（须可配置；评测可测）。  
2. **裁决 grounded（提示词+代码清洗）**：步骤重复 / 执行反省的 `constraints` 必须引用已观察路径与工具结果；禁止臆造未出现的目录/框架；代码侧丢掉「禁读已定位文件 / 只能再读·继续盲读」等反证据或反进展约束；已定位到改点时 alternate 优先「改写动作」，并把「必须先读再改」收成「最多一次定向核对后立即 mutate」。  
3. **探索饱和启发式（代码）**：同一 path 重叠窗口反复 `fs_read` 并入软停滞（加速探索 streak），即使步骤指纹不同；**定位预算**（已有 path:line 后限制继续只读）与 **宽检索降质**（命中过宽/已压缩禁止同范围再搜）。  
4. **规划相位提示（提示词）**：目标为改产品/改文件时开场高带宽定位（explore_search / fs_grep+context）；已有明确 path+渲染点时优先 `fs_patch`/`fs_replace`，禁止无新问题继续盲读。  
5. **架构门勿掐死改写**：漏 `doc_refs` 应自动绑定 / skip 兜底后继续写，禁止二次校验直接整任务 `failed` 掩盖「其实已选对路径」。  
6. **lesson**：沉淀「守卫 abort ≠ 根因；先查是否从未 mutate；inject 文案无效则看工具面是否收紧」等可复用教训。  
7. **lesson（补丁失败 / 开读空转）**：`old not found` / `requires hunks` 表面文案 ≠ 机制根因。内置 `lesson_verify_read_not_endless_explore`——「请先 fs_read」≠ 无限只读许可证；alternate ≠ 已进入改写相位。反省开读应临时放行定向只读，禁止空 actions 直接 `failed`。  
8. **弱写入 + 可见副作用（代码）**：前端/布局类 `fs_patch` 后检测未引用 CSS 变量等死补丁；`success` 空 actions 仍强制说明用户可见变化；`write_set` 非空不得直接 `completed`。  
9. **lesson（假成功）**：内置 `lesson_write_set_not_acceptance`——mutate 成功 ≠ 目标达成；先查死补丁与收尾占位 thought。  
10. **答复覆盖（代码+提示词）**：问询/状态/查找落点/机器硬件盘点类目标 `success` 前校验终稿含可验收事实，拦截过程元叙述与过薄盘点；拒因细分并回灌缺维；规划/finalize 提示要求短结论+分项，压缩输出须先读 observe 全文；进度推送脱敏口令。  
11. **复盘轨迹采样（代码）**：长 `steps` 须头尾采样 + 步骤索引，禁止只截前缀；`outcome_judgment` 若点名答非所问，须升为机制根因并默认勾选优化项。  
12. **lesson（问询假成功）**：内置 `lesson_answer_must_cover_goal`——过程完成 ≠ 答到问点。  
13. **压缩未读闸（代码）**：有 `dump_path` 且未成功 `fs_read` 时禁止过薄 success；注入【压缩未读】硬约束。内置 `lesson_compressed_dump_must_read`。  
14. **禁止 shell 绕过 fs（反省清洗+lesson+执行硬拦）**：丢掉「改用 shell cat 读绝对路径」；内置 `lesson_no_shell_bypass_fs`；`shell_guard` 硬拦本地 cat/cp。查找落点优先 `FAWAI_READ_ROOTS` 下 `fs_read`（默认 `/`），禁止开场整盘家目录 grep。  
15. **远端部署相位**：升级/同步类须走 shovel（`rsync-ssh-deploy` / `ssh-run-with-pass`）或 work_root 临时脚本；无口令 BatchMode 探针失败 ≠ 能力边界唯一结论；abort 若约束要交命令则须 `format_abort_delivery`。  
16. **方法族自我纠错**：失败语义须升到换工具族（SSH 认证→带密 shovel）；远端目标只读空转须命中远端进度闸；远程不在场答复须否决贴文件——缺一则复盘标机制根因「同族微调未换道」。

## 禁止

- 只贴终态一句错误当分析结论  
- 优化标题绑死单一 goal 文案或单一文件名（除非 payload 必须改该文件，且 rationale 仍写清通用机制）  
- 把「换更大模型」当作唯一优化  
- 建议关闭步骤重复/反省来「绕过」空转（除非单开议题论证）  
- 最终答复缺全面性/准确性/专业性/易读性任一维（半成品提纲、臆造证据、术语堆砌难读、只展开一维交差）

## 与任务复盘五维的映射

| 五维 | 本规则侧重 |
|:---|:---|
| planning | 是否选型错误、相位（探索 vs 改写）是否错误 |
| execution | 是否长期无 mutate；工具组合是否空转 |
| scheduling | reflect/stagnation 是救命还是注入错误约束 |
| tool_results | 成功只读是否被误当成进展 |
| outcome_judgment | 终态文案是否掩盖机制空洞；问询类是否答到 goal 问点 |

## 例（机制口径，非单例菜谱）

某改前端任务：`fs_read`×40、`fs_grep`×17、无写动作；步骤重复多次 alternate 后硬 abort。  
- 机制根因：探索→改写未切换 + alternate 注入与证据矛盾的「禁止读入口文件」。  
- 通用优化：只读探索进度闸门；stagnation 提示强制 grounded + 已定位则改写优先。  
- 禁止优化：「下次做 Markdown 渲染时直接改 index.html」作为唯一条目（可作证据句，不能当机制解）。

某问询任务：goal 问「某资源现在状态如何」；终稿「已获取日志，汇总配置与进度并结束」，无状态/数字。  
- 机制根因：假成功 / 答复未覆盖目标；结果判定把过程叙述当完成。  
- 通用优化：答复覆盖闸门；复盘头尾采样并强制核对末步 thought。  
- 禁止优化：只写「下次查某某机器时先打开某文档」当唯一条目。
