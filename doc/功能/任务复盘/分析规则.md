# 任务分析规则

分析失败/空转/假成功任务时的强制口径。适用于：Cursor 人工复盘、产品内「任务复盘」全维分析、讨论里点名某 `task_id`。

真源：本文件。Cursor 规则：`.cursor/rules/rules-task-analysis.mdc`。复盘提示词：`fawai_avatar/skills/review.py`。

## 强制视角

1. **智能体机制优先，禁止只复述终态文案**  
   不得停在「错误信息是什么 / 最后一步做了什么」。必须回答：闭环里哪一环（规划 / 观察 / 动作 / 反省 / 步骤重复 / 结果判定）为何未能把任务推向可验收副作用。
2. **先评必要路径，再评工具细节（强制）**  
   分析须先做 **goal 拆解**：列出达成目标的**必要路径**（缺一则无法验收）与**可选路径**（加速/旁证，非必达）。  
   再问：各必要路径是否都被尝试或明确阻塞？是否偏科只攻一条而遗忘另一条已就绪路径？是否把可选探索当成必要路径烧轮次？  
   远端升级、改前端、查配置、写文件等**同一套尺子**——必要路径用抽象槽位表述（如「连接/鉴权材料」「作用对象或脚本/代码路径」「副作用动作」），禁止一上来陷进某机房、某文件名、某 env 键。
3. **工具双栏：工具本身 × 调用（强制）**  
   「工具细节」不得只写流水账式 `ok/message`。路径表之后须**分栏**评估（材料不足须点明，禁止跳过）：
   | 栏 | 问什么 | 优化可落到 |
   |:---|:---|:---|
   | **工具本身** | 能力/schema 是否缺必要槽；描述与真实行为是否一致；成功/失败返回与报错是否误导模型（易诱发假归因）；压缩/截断是否让观察不可用；能力清单是否漏掉本 goal 所需族 | 工具实现、错误文案、schema/描述、清单暴露、压缩策略 |
   | **调用** | 选型是否对族；参数是否足以推进必要路径；时机/相位是否错（该 mutate 仍只读）；同族微调未换道；成功只读是否被当成进展；已齐材料是否未用于副作用 | 规划提示、进度/换道闸、反省清洗、结果判定 |
   两栏都可为空结论（「工具面未见缺口」「调用未见明显失误」），但**不得只评一栏**。根因可同时命中两栏；优化须标明改工具层还是改调用/闭环层，禁止把工具产品缺陷一律写成「模型不会用」。
4. **优化须针对通用任务，禁止只修本案**  
   优化项须能迁移到同类目标（任意「改仓内前端/写文件/查因」），不得写成「下次对 Markdown 任务别读 index.html」这类单例补丁。单例仅可作证据，不可当优化标题。
5. **禁止把本案故事线升成新产品闸（强制）**  
   根因可用本案路径/文件名作**证据**；优化清单与拟改代码须落在**已有机制层**（必要路径台账、进度闸、grounded 反省、方法族换道、abort 交付、假归因清洗、答复覆盖、**工具 schema/报错/清单**等）。  
   **禁止**因单次轨迹发明「仅覆盖本 goal / 本缺密场景 / 本 basename / 本主机已齐」的第三层专用闸或专用提示词分支。  
   清单项写入前自检：**换掉本案专有名词（文件名、机房号、env 键、死链文案）后，标题与验收是否仍成立？** 不成立 → 特例，写入「明确不做」或只留证据句，**不得**进通用优化清单。  
   若现有机制**已能表达该缺口**，清单只写「既有层未兑现 / 需补强既有层」，禁止再开一条平行特例门。  
   工具本身缺口同样禁止写成「只修本案那一个 basename」；须写成可复用的 schema/报错/族暴露问题。
6. **区分表面失败与机制失败**  
   | 层 | 问什么 |
   |:---|:---|
   | 表面 | 终态 `failed` 文案、最后 fingerprint、某步 `ok=false` |
   | 机制 | 必要路径是否拆清/偏科；为何长期无写动作；守卫是否误伤/误导；提示词是否注入错误世界模型；有无进度闸门；**工具本身是否坑模型 vs 调用是否选错/用错** |

## 分析输出结构（强制）

按下列顺序写（产品复盘可落在五维里，但总述须能还原本结构）：

1. **目标与终态**（一两句）  
2. **必要 / 可选路径表**（抽象槽位；标明各条：已尝试 / 已就绪未推进 / 未尝试 / 误判为必要）  
3. **工具双栏**（**工具本身** | **调用**；各栏至少一句结论或「材料不足」；须能回指路径表与步号）  
4. **机制根因**（1～3 条，可跨任务复用的失败模式名；须能回指路径表与工具双栏）  
5. **证据链**（短码/步号/工具统计/调度计数；点到为止）  
6. **通用优化清单**（每项：改哪一层——含工具实现 vs 调用/闭环、验收口径、为何通用于类任务；勾选前须能看到将改路径/知识库条目或补丁摘要，禁止只有抽象标题）  
7. **明确不做**（若本案不该靠改产品修的，写清）

## 最终答复用户（强制）

面向用户的正文（Cursor 聊天结论、产品【分析】总述与五维文案、清单标题/rationale）须同时满足：

| 要求 | 含义 | 禁止 |
|:---|:---|:---|
| **全面性** | 覆盖输出结构（含**工具双栏**）与命中的机制检查项；五维有材料则各有一句到位结论，缺材料则点明「材料不足」而非跳过 | 只写终态一句；只展开一维；漏工具双栏任一栏；漏写「明确不做」却暗示会改不该改的 |
| **准确性** | 断言须能落到证据（步号/工具统计/短码/调度字段）；区分表面与机制、工具本身与调用；不确定写「材料不足以判定」 | 臆造未出现的路径/框架/工具结果；把 abort 文案当唯一根因；夸大「已修/将修」；把工具坑误判成调用或反之 |
| **专业性** | 用智能体机制与产品层术语（规划/观察/mutate/反省/步骤重复/结果判定/工具契约）；优化写清改工具层还是调用/闭环层与类任务验收 | 口语流水账；把「换更大模型」当唯一解；单例菜谱冒充机制结论 |
| **易读性** | 短段 + 编号/小标题；先结论后证据；术语首次可括注；清单一项一事 | 超长不分段；证据堆淹没结论；把 JSON/内部字段名直接甩给非技术读者当主文 |

产品复盘：`analysis` 与 `dimensions` 给人读，须过上表；`items` 的 `title`/`rationale`/`impact` 同口径，勾选卡还须有 `change_summary`/`preview`（由 payload 摘要，见 `items_for_ui`）。Cursor 人工复盘：聊天终稿同样过上表，不得只丢半成品提纲。

## 常用机制失败模式（检查清单）

分析时逐项过；命中则写入根因，未命中可略。

| 模式 | 症状 | 典型缺口 |
|:---|:---|:---|
| **必要路径未拆清 / 偏科遗忘** | goal 隐含 ≥2 条必达前置，规划未显式台账；执行长期只攻一条，另一条已就绪却不推进/不交付；或把宽搜、反复读说明等可选探索当成必要路径 | 规划无必要/可选分流；无「各必要路径均须尝试或标明阻塞」的进度与结果闸；一条阻塞时丢掉另一条已齐材料 |
| **探索→改写相位未切换** | 大量 `fs_read`/`fs_grep`/`fs_glob`/`explore_*`，`write_set` 空或无 `fs_write`/`fs_patch`/`fs_replace` | 无「证据已够则必须改写/澄清/失败」的进度闸门 |
| **同构守卫过窄** | 参数微调（offset/pattern 微变）导致指纹不撞，空转烧满轮次 | 仅步骤指纹；缺「只读探索连续 K 步」类启发式 |
| **alternate 幻觉约束** | 步骤重复/反省注入「禁止读已定位文件 / 去找不存在的 Vue/React src」等与证据矛盾的约束 | 裁决提示未要求约束必须 grounded；先验框架压过观察 |
| **守卫止损掩盖上游空洞** | 表面因 fingerprint abort，实质从未进入改写相位 | 只治重复、不治无进展 |
| **规划格式崩溃** | `无法解析 JSON` / 空 content；若仍整任务 Failed | 半截修补未生效、格式重规划不足、或软降级/兜底未触发 |
| **假成功 / 边界未明示** | `completed` 但无验收副作用，或超清单却未 `failed` 说明 | 结果判定与能力清单脱节 |
| **假成功 / 死补丁（有 mutate 无目标副作用）** | `completed` 且 `write_set` 非空，但 diff 仅为未引用 CSS 变量/注释/空白，界面无变化；或收尾 `thought` 为 `native tool_calls` | 探索闸门只逼写出；缺弱写入检测与可见副作用收尾闸 |
| **假成功 / 答复未覆盖目标（问询元叙述）** | goal 在问状态/进度/是否/多少，终稿只写「已获取/已汇总/并结束」等过程，无事实载荷 | 结果判定只认 `success`+空 actions；缺答复覆盖闸；复盘若只喂轨迹前缀，会漏看末步 |
| **假成功 / 配置盘点过薄** | goal 查硬件/服务器配置或账号落点，终稿只报 GPU+CPU 一两项，缺内存/盘/系统/来源路径 | 答复覆盖闸未覆盖「查看配置/在哪里」类；finalize 提示未要求分项；压缩观察后未读全文 |
| **压缩观察未回读** | 工具结果已压缩落盘，success 只凭头几行；或失败文案笼统叫「过程元叙述」实为盘点过薄 | 缺 unread-dump 闸；拒因未细分；未强制 `fs_read` observe |
| **shell 绕过 fs 沙箱** | `fs_read` 越界后 alternate 教 `shell cat` 读绝对路径；凭据明文进轨迹 | 反省 constraints 未 grounded；缺代码侧清洗与脱敏 |
| **工具本身缺陷被当成调用失误** | 报错笼统/与真实拒因不符、schema 缺关键槽、描述承诺做不到、压缩后不可回读，模型按误导信息规划 | 只骂「模型不会用」；未评工具返回/清单/压缩策略 |
| **同批只读被 fail-fast 掐断** | 一步内已排多字/备选 `fs_grep`，UI 却「另有 N 个动作未执行」；终稿只怪首条短词失败 | 只读失败仍 break 整批；应继续同批其余只读（写仍停） |
| **调用失误被当成工具无能** | 工具已返回可用材料或正确拒因，规划仍同族空转、错参、该 mutate 不调、不换道 | 立刻改工具实现而不查选型/相位/换道闸 |

## 通用优化方向（写清单时优先这类）

优化项 `kind` 仍用复盘约定（`prompt_patch` / `code_patch` / `lesson` / `skill` / `rule_patch`）。内容优先：

0. **必要路径台账（规划提示词 + 代码闸，已落地）**：`brain/necessary_paths.py`——开场/重规划提示分清必要 vs 可选；反省/步骤重复 `alternate|abort` 追加台账约束；`failed` 声称交命令却无命令体、或未分项 → 回灌一轮。分析时仍先验路径表是否偏科；关闸：`FAWAI_PATH_LEDGER=0`。  
1. **进度闸门（代码）**：连续 K 步仅成功只读探索且无写资源 → 注入硬约束并收紧原生写工具面；达中止阈值先强制改写一轮，仍无写入再 `failed`/`need_input`（须可配置；评测可测）。  
2. **裁决 grounded（提示词+代码清洗）**：步骤重复 / 执行反省的 `constraints` 必须引用已观察路径与工具结果；禁止臆造未出现的目录/框架；代码侧丢掉「禁读已定位文件 / 只能再读·继续盲读 / 必须进入改写相位」等反证据或逼写状态约束；已定位时步骤重复 alternate 补「换指纹：exact old→patch 或换工具」，禁止收成 mutate_prefer/强制写相位；薄 grep 先要正文。alternate 不得把恢复收成「只攻一条必要路径、丢掉另一条已齐路径」。  
3. **探索饱和启发式（代码）**：同 path 重叠窗可读加速 streak，但**探索进度闸门 / 定位预算 / 宽检索降质 / 观察 soft 默认均关**（多轮小窗取证不因步数逼写；检索体量靠 head_limit 翻页；读不到再 failed）。  
4. **规划相位提示（提示词）**：目标为改产品/改文件时——**已有明确 path+渲染点**优先 `fs_patch`/`fs_replace`；**仅缺 path** 优先 `fs_grep` / `fs_glob`（收窄 path/glob）；多词才 `explore_search`；禁止无新问题继续盲读，也禁止为探仓而探仓。  
5. **架构门勿掐死改写**：漏 `doc_refs` 应自动绑定 / skip 兜底后继续写，禁止二次校验直接整任务 `failed` 掩盖「其实已选对路径」。  
6. **lesson**：沉淀「守卫 abort ≠ 根因；先查是否从未 mutate；inject 文案无效则看工具面是否收紧」等可复用教训。  
7. **lesson（补丁失败 / 开读空转）**：`old not found` / `【补丁锚点未接地】` / `requires hunks` 表面文案 ≠ 机制根因（常为按意图编造 old）。内置 `lesson_verify_read_not_endless_explore`——读成功 ≠ old 已接地；「请先 fs_read」≠ 无限同构只读。**反省开读 / 开读须改写硬闸已退役**（不再禁 `fs_glob`/`fs_grep` 纠路径）；空转仍靠步骤重复换指纹，不靠禁定位。  
8. **弱写入 + 可见副作用（代码）**：前端/布局类 `fs_patch` 后检测未引用 CSS 变量等死补丁；`success` 空 actions 仍强制说明用户可见变化；`write_set` 非空不得直接 `completed`。  
9. **lesson（假成功）**：内置 `lesson_write_set_not_acceptance`——mutate 成功 ≠ 目标达成；先查死补丁与收尾占位 thought。  
10. **答复覆盖（代码+提示词）**：问询/状态/查找落点/机器硬件盘点类目标 `success` 前校验终稿含可验收事实，拦截过程元叙述与过薄盘点；拒因细分并回灌缺维；规划/finalize 提示要求短结论+分项，压缩输出须先读 observe 全文；进度口令脱敏暂关闭（见会话通道 / `redact.py`）。  
11. **复盘轨迹采样（代码）**：长 `steps` 须头尾采样 + 步骤索引，禁止只截前缀；`outcome_judgment` 若点名答非所问，须升为机制根因并默认勾选优化项。  
12. **lesson（问询假成功）**：内置 `lesson_answer_must_cover_goal`——过程完成 ≠ 答到问点。  
13. **压缩未读闸（代码）**：有 `dump_path` 且未成功 `fs_read` 时禁止过薄 success；注入【压缩未读】硬约束。另有 `【压缩未读·禁宽搜】`：未读 dump 时禁止宽搜顶替取证；hits 压缩后检索 path 进宽搜禁扫。**已源码小窗或 mutate 后丢弃未读 hits dump、抑制禁宽搜注入**（防检索误压拴死改写）。规划提示含过程相位（定位→取证→改写/作答→验收）。内置 `lesson_compressed_dump_must_read`。必要路径台账含**证据保真**槽。  
14. **禁止 shell 绕过 fs（反省清洗+lesson+执行硬拦）**：丢掉「改用 shell cat 读绝对路径」；内置 `lesson_no_shell_bypass_fs`；`shell_guard` 硬拦本地 cat/cp。查找落点优先 `FAWAI_READ_ROOTS` 下 `fs_read`（默认 `/`），禁止开场整盘家目录 grep。`not found (file missing)` ≠ 沙箱越界：反省须丢掉「禁读绝对路径 / 只许 fs_glob」；若文案已写「父目录存在/仅文件名缺失」勿纠拼接、换其它落点；`fs_glob` 支持 `path=` 只读根目录（不得静默只扫 work_root）。  
15. **远端部署相位（只补既有层，不新开特例门）**：升级/同步类应对齐已有远端进度闸 + shovel / 临时脚本方法族；无口令 BatchMode 探针失败 ≠ 能力边界唯一结论；宣称交命令或 abort 约束要求交命令时须兑现 `format_abort_delivery`（或模型自 `failed` 的同等交付）。**禁止**再设计「缺某 env 键 / 某凭据文件名 / 主机端口已齐」专用闸。  
16. **方法族自我纠错**：失败语义须升到换工具族（认证失败→带密 shovel；本地枚举被拦→`fs_*` 而非再 shell）；远端只读空转须命中**已有**远端进度闸；远程不在场答复须否决贴文件。复盘标「同族微调未换道」即可，**不要**把换道落成某一台机器或某一份 md 的操作菜谱。  
17. **假归因终稿（结果判定）**：工具结果是 `not found` / shell 闸拦截，终稿却写成「沙箱禁读目标文件 / 能力不足」等——升为机制根因；优化指向拒因与证据对齐、abort 交付兑现，而非本案路径纠偏脚本。  
18. **工具本身（实现/契约）**：复盘若判定 schema 缺槽、报错误导、描述与行为不符、压缩不可回读、清单漏族 → `code_patch`/`prompt_patch`（工具描述）优先落工具层；验收写「同类 goal 不再被该误导文案带偏 / 缺槽可传」。  
19. **调用（选型/相位/换道）**：命中同族空转、错参、该 mutate 仍只读、已齐材料未用 → 落规划/闸门/反省，**不要**因此重写工具实现；与第 16 条方法族换道对齐。  
20. **同批只读继续（代码，已落地）**：只读失败不掐同批后续只读（`should_break_action_batch`）；写/前台/`shell` 仍 fail-fast。复盘若再见「另有 N 个动作未执行」且未执行项全是只读备选检索 → 先核闭环版本是否含本项。  
21. **脚本铲子生命周期（提示词+软闸，已落地）**：造临时脚本却未 `shovel_search`、脚本写死路径/口令、成功可复用却未升铲/`skill_write` → 复盘须点名；优化指向规划提示/软闸/`fawai_shovels` 台账，禁止只修本案脚本文件名。见 [脚本铲子生命周期](../脚本铲子生命周期/说明.md)。

## 禁止

- 只贴终态一句错误当分析结论  
- 优化标题绑死单一 goal 文案或单一文件名（除非 payload 必须改该文件，且 rationale 仍写清通用机制）  
- **把本案故事线写成新产品闸**（例：缺 `DEPLOY_SSH_PASS` 且已读到 host → 强制按 basename 搜某凭据 md）——属于特例菜谱，即使包装成「通用远端」也禁止进清单  
- 在已有进度闸 / 方法族 / abort 交付能覆盖时，仍平行新增第三条「更贴本案」的门  
- 把「换更大模型」当作唯一优化  
- 建议关闭步骤重复/反省来「绕过」空转（除非单开议题论证）  
- 最终答复缺全面性/准确性/专业性/易读性任一维（半成品提纲、臆造证据、术语堆砌难读、只展开一维交差）  
- **只评调用不评工具本身，或只评工具本身不评调用**（须双栏；材料不足须点明）  
- **工具产品缺陷一律写成「模型不会用」**；或 **调用/相位失误一律改成重写工具**

## 与任务复盘五维的映射

| 五维 | 本规则侧重 |
|:---|:---|
| planning | 必要/可选路径是否拆清；选型是否错误；相位（探索 vs 改写）是否错误；是否偏科 |
| execution | 各必要路径是否都有尝试；是否长期无 mutate；可选探索是否喧宾夺主 |
| scheduling | reflect/stagnation 是救命还是注入错误约束 / 加重偏科 |
| tool_results | **须含工具双栏**：工具本身（schema/报错/描述/压缩/清单）+ 调用（选型/参数/相位/换道/结果是否推进必要路径）；禁止只罗列 ok/message |
| outcome_judgment | 终态是否按必要路径分项说明阻塞；假归因；问询类是否答到 goal 问点 |

## 例（机制口径，非单例菜谱）

某改前端任务：`fs_read`×40、`fs_grep`×17、无写动作；步骤重复多次 alternate 后仍空转，终由裁决/规划中止（表面像止损，根因是从未 mutate）。  
- 机制根因：探索→改写未切换 + alternate 注入与证据矛盾的「禁止读入口文件」。  
- 通用优化：只读探索进度闸门；stagnation 提示强制 grounded + 已定位则改写优先。  
- 禁止优化：「下次做 Markdown 渲染时直接改 index.html」作为唯一条目（可作证据句，不能当机制解）。

某问询任务：goal 问「某资源现在状态如何」；终稿「已获取日志，汇总配置与进度并结束」，无状态/数字。  
- 机制根因：假成功 / 答复未覆盖目标；结果判定把过程叙述当完成。  
- 通用优化：答复覆盖闸门；复盘头尾采样并强制核对末步 thought。  
- 禁止优化：只写「下次查某某机器时先打开某文档」当唯一条目。

某「把产物推到目标环境」类任务：必要路径至少两条——（A）连接/鉴权材料（B）作用对象或升级脚本/代码路径；可选路径含宽搜说明、lore 旁证。轨迹上 A 反复空转，B 早齐却未用于副作用/交付；终稿只抱怨 A 且假归因。  
- 机制根因：**必要路径未拆清 / 偏科遗忘**（B 已就绪被丢掉）+ 可选探索喧宾夺主；假归因为表层。  
- 通用优化：必要路径台账；一条阻塞时仍推进/交付其他已齐必要路径；结果判定按路径分项。  
- 禁止优化：绑死某凭据文件名、某 env 键、某机房号的搜密/部署菜谱。

某任务：工具返回 `permission denied`（真实是路径不在可读根），终稿写成「沙箱全面禁读」；同时另一条必要路径上已有可用 shovel 却未换道。  
- **工具双栏**：工具本身——报错未区分「越界 vs 无权限」，易诱发假归因；调用——已见正确族仍同族重试、未换道。  
- 机制根因：假归因 + 方法族未换道（两栏都命中）。  
- 通用优化：工具层细化拒因文案；调用/闭环层对齐换道闸与假归因清洗。  
- 禁止优化：只写「下次换更大模型」或只骂本案那一次参数。
