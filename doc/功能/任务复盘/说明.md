# 任务复盘

## 验收

- **不**在任务完成时自动蒸馏/棘轮。
- 任务管理：查询（状态/关键词）、取消、删除、**单条复盘**（PWA 暂隐归档操作与多选联合复盘；服务端联合接口仍保留）。
- **归档（PWA 暂隐）**：服务端仍可 `status=archived`；主列表默认隐藏；PWA 暂不提供归档/取消归档入口。
- **删除**：`completed` / `failed` / `cancelled` / `archived` 可直接硬删；运行中直接删 → 拒绝（须先取消）。
- **复盘流程（三阶段）**：
  1. 点「复盘」→ **新建复盘任务**，状态 `waiting`，**一张** `awaiting_approval` 卡同时承载**【复盘指令】**正文与「放行分析」钮（先文后钮，不另发指令气泡），**不立刻分析**。
  2. 用户「放行」或附加建议 → **全维深析**（有 `meta.steps` 默认喂逐步轨迹；覆盖规划/执行/调度/工具本身与调用/结果判断）→ 回传【分析】+**【优化清单】**，`review_phase=awaiting_apply`；**此阶段不落盘、不改文件**。
  3. 用户勾选：PWA 清单勾选控件，或对话 `全部` / `执行 1,3` / `不要 2` / 自由文本再分析 / `取消` → **同意执行前**先 `ReleaseStore` 整包存档 + 将改路径 `version_snapshot` → 只执行选中项。`awaiting_apply` 下裸「取消」走复盘第二道闸（结束为 `completed` + `last_review.cancelled`，不备份不改文件），**不得**被总管控制口令 `cancel` 抢走；显式「取消 \<task前缀\>」仍为总管取消。
- **分析口径（强制）**：见同目录 [分析规则.md](./分析规则.md)——**工具本身优先**（明确工具 bug 置顶 P0，早期尤甚）；**工具双栏**先本身再调用；**用户多轮通道**（源任务追问/追加/澄清与复盘会话改写）须进材料并先评是否兑现；智能体机制视角；再评必要/可选路径；优化须针对通用任务，禁止只修本案；区分表面失败与机制失败；**最终答复用户**须全面、准确、专业、易读；问询类假成功须升为机制根因并默认勾选优化。Cursor 与产品复盘同一真源。
- **轨迹与多轮材料**：分析阶段对长 `steps` 头尾采样 + 步骤索引（非只截前缀）；**须喂**源任务 `meta.followups`（及澄清题面），goal 仍只首条；指令预览不附 steps 时须标明「放行后再喂」。`awaiting_apply` 自由文本再分析须回灌上一轮【分析】+ 清单标题 + 复盘会话累积建议，禁止只留最新一句从零重写。附加建议只收窄焦点，**不得**废除工具优先。
- **优化项 kind**：`skill` / `lesson` / `code_patch` / `rule_patch` / `prompt_patch`。标明工具层的项软置顶并默认勾选。
- **勾选前可读详情（强制）**：清单与 PWA 勾选卡除 `title`/`rationale` 外，须给出 `impact`（改哪一层 + 验收）、`change_summary`（将改文件或将写入的 skill/lesson id）、可展开 `preview`（步骤摘要或 old→new 摘要）。**禁止**只甩抽象标题让用户盲勾；完整 `payload` 仍只留服务端，不整包塞进卡片。
- **单任务 / 联合**：服务端均可；联合一次综合承接链（`joint` 标签）。PWA 当前仅暴露单条复盘。
- **不做**用户侧「简要/全程」二选一；禁止一律写成成功 Skill；禁止分析阶段直接改代码；禁止为多轮追问新开专名专用闸。
- 成功与失败都可沉淀；失败走 `lesson`。
- 源任务 Worker 结束须落盘 `meta.steps` / `meta.final_thought`（及 replan/reflect/stagnation 等）；有追问/追加/澄清时 `meta.followups` 须可供复盘读取。
- **复盘任务自身**须写入并展示 `meta.stats`（总 token / 墙钟；分析段含 LLM；与普通任务侧栏摘要同口径）。见 [任务统计](../任务统计/说明.md)。
- **进度展示与普通任务同口径（强制）**：放行后分析/改写不得长时间黑盒。须立刻有 `phase=analyzing`（执行段 `applying`）步骤卡；远端 LLM 等待用 `ApiWaitProgress` 心跳（已等待秒数）；有流式则 `LlmLiveProgress`/`on_delta` 刷思考与输出；PWA 对 `analyzing`/`applying` 稳定 merge、可转圈与回看思考。禁止只发「已放行」一句后静默到整段结束。

## 边界

- 棘轮首期 stub。
- 写文件类 patch 仍受进化禁改闸门（最少核：`versioning/`、`runtime` 保活/选版、`paths.py`、已存在 `doc/版本/v*`；仅智能体）。
- mock（`FAWAI_BRAIN_MOCK=1`）用规则分析；真分析默认走 LLM（`FAWAI_REVIEW_LIVE=0` 可关）。
- 联合一次最多 12 个任务；不做每任务自动蒸馏。
- 复盘旁路不经 WorkerLoop，但进度契约对齐会话通道（`phase` + live/api_wait）；分析线程经 hub `emit_progress` 出站。
- PWA：`awaiting_approval` **单卡**（指令正文 +「放行分析」）；`awaiting_apply` 仍为「【分析】正文消息 + 勾选卡」（长文与清单分开，避免淹没）；勾选/放行/取消仅会话卡片内，不在输入栏上方 sticky 重复；仍可用对话编号。
- PWA 选择卡使能：仅**当前任务最新一张**且 `status=waiting`、卡后尚无用户回复/阶段推进的卡片可点；点击或回复后立即禁用，标签从「待放行」改为「已放行」（勾选卡改为「已选」）。直播追加消息时须同步旧气泡，禁止只追加新卡而留下可点旧钮。
