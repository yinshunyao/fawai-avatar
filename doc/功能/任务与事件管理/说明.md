# 任务与事件管理

## 验收

- 总管可 create / pause / resume / cancel / **archive / unarchive** 工作任务，并汇总状态。
- **任务短标题**：会话真源为任务 `meta.title`（另标 `title_source`）。创建时先用 goal 启发式写入（`title_source=heuristic`）；**第一次 LLM 规划**须给出与主题强相关的短名（`title`，≤16 字），覆盖为 `title_source=llm`。列表/顶栏只认该字段，任务 id 降为次要。**计划模式**：监管脑子任务命名后须把正式短标题提升到父计划会话的 `meta.title`（父侧仍是启发式时可写；已有 `llm` 名不因后续节点再改）；列表读到父任务仍为启发式时，可从子任务回填并落盘，避免刷新后又变回路径截断。
- 多工作任务可同时活跃；彼此状态隔离。
- `foreground_lease` 全局唯一；后台 `resource_lease` 按清单申报，写写冲突由总管串行化或拒绝。
- **归档**：非 `running` 可归档为 `archived`（主对话列表默认不展示）；可取消归档恢复原状态。PWA 暂隐归档入口（API 仍可用）。
- **删除**：终态 `completed` / `failed` / `cancelled` / `archived` 可直接硬删；非终态须先 cancel。
- **取消/暂停停步**：`cancel` / `pause` 写入状态后，工作任务闭环须在步间与动作间隙协作停步；取消后**不得**再开新动作、不得反省空转、不得把状态覆盖为 completed/failed。暂停则等到 `resume` 后继续同一次 run。取消进度：有 Worker → `cancelling` 再 `cancelled`；无 Worker → 直接 `cancelled`（会话步骤不得长期停在「正在停止」）。
- **进程中断续跑**：服务重启后见 [进程中断续跑](../进程中断续跑/说明.md)；步末/暂停落 `meta.run_checkpoint`，启动自动续跑，**不**整任务 `requeue`。
- 任务结束落盘 `meta.steps` / `meta.final_thought`（供复盘按需拉详情）。
- 闭环执行中 `supervisor.report` 等事件仍写入总管事件表；**会话可见进度**由工作任务 `on_progress` → 枢纽推送，二者分工（事件落盘 ≠ 会话时间线）。
- 列表支持 status / 关键词 `q` / `archived` 筛选（见任务复盘、会话网关）。

## 边界

- v1 进程内 + SQLite；不做跨机调度。
- 冲突策略 v1：写写必串行；写读允许并行。
- 工作任务闭环在动作失败时先 [执行反省](../执行反省/说明.md) 再重规划；结果含 `replan_count` / `reflect_count`（见 `demo_eval_priority` D5）。
- 取消为**协作式**：`WorkerLoop` 在步间/动作间隙读状态；**LLM 规划等待**用后台线程轮询取消，点停止后不必等本次 `plan` 返回即可收束（孤儿调用仍可能在后台跑完，但不继续 act）。单个 shell/`subprocess.run` 仍可能跑完当前命令；不保证强杀 OS 进程。
- **步骤异常优先内消化**：观察/规划/执行等步骤异常先走 [执行反省](../执行反省/说明.md)（`step_crash`）再重规划；仍逃出 Worker 时枢纽须 `supervisor.fail` + 终态 `card`/助手摘要，禁止只推 `error` 后卡在 `running`；SQLite 用绝对 `data_dir`。
- 按需复盘 UI/API 见 [任务复盘](../任务复盘/说明.md)。
