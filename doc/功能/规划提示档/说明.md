# 规划提示档

## 验收

- 规划前按本轮目的选档：`vision` / `fs` / `gui` / `browser` / `full`。
- `vision`：短提示 + 可附图走 VLM；能力清单为定位子集（含 `browser_*`）。
- `fs`：文件/代码/前端改页，或**已有工具历史且目标曾附图**（即使文案未命中 file hint）→ **不附用户图**，走文本模型；注入 fs 相关子集（含 `browser_*`）。
- `gui`：依赖可见 App UI 时保留 GUI 相关提示（含 `app_focus` / `ui_*`）；桌面操控语义优先此档，**不得**因「界面」等词误判进 `fs`；GUI 目标不因工具历史被卸图硬切。
- `browser`：打开/操作网页 → 注入 `browser_*` 子集；**优先于**用桌面键鼠点系统 Chrome；无头默认可。
- `full`：兜底接近原全量。执行中 thought 宜短；success/failed 终稿按交稿体例，不受 40 字限制。
- **有图 ≠ 全程 VLM**：首轮可 `vision` 附图；一旦已有工具回合且本轮非 GUI/截屏，强制卸图切 `fs`，禁止回落 `full` 仍每轮重塞用户图。
- 硬校验仍用全量能力清单；`plan.raw.prompt_profile` 与 `plan.raw.attach_user_images` 可观测；`planned` progress meta 同步带出。

## 边界

- 首期规则推断选档，不加「只为选档」的额外 LLM 轮。
- 不负责截断 JSON 的续写修复。
- `_FS_WEB_HINTS` 只覆盖改前端/网页代码；单独「界面」不否决 GUI（见 [自主操控C3](../../议题/自主操控C3/结论.md)）。
- 网页内操作见 [浏览器操作](../浏览器操作/说明.md)；与「改网页代码」分流。
- 不做「仅为本 case 文案」的专用选档闸；卸图条件是工具历史 + 附图/文件类抽象槽。
