# 任务内上下文查询

## 要点

同任务 Recall：规划近窗/compact 压掉证据后，Agent 用工具找回本任务历史中的话与工具结果，再按需回灌片段。

## 验收口径

1. `task_context_search` 仅当前 `task_id`；query 命中返回 index/role/摘要/paths/observe 指针。
2. `task_context_get` 按 `msg_id` / `index` / `observe_path` 回灌正文（硬顶）或 dump 切片。
3. 其它 `task_id` 默认拒绝。
4. 规划提示写明：摘要没有的本任务事实先 `task_context_*`。

## 边界

- 不搜其它任务；不做跨任务 recall。
- 不替代 `fs_read` / `lore_search` / `fts_search`。
- 不把全 history 每轮灌进规划。

## 终态追问 / 无检查点

成功/失败后 `run_checkpoint` 会清掉。再追问 reopen 时：

1. 枢纽快照 `prior_final_thought` / `prior_steps`；
2. Worker 新跑把此前结论 + 会话结论文垫进 history（在【追问】之前）；
3. `task_context_*`：live 过薄（只剩【追问】）时与检查点 / prior **并集**再搜；否则无 live 时读 prior + `session_history.jsonl`（优先 `kind=text` 结论文）。

## 命中观察

`observe/tool_digest._render_hits` 同时认 `path:line:text`（grep）与 `summary` / `snippet` / `msg_id`（lore、task_context），禁止把有命中渲成 `?:?:`。
