# `doc/功能` — 放行实现与已支持功能面

## 目录用途

登记产品**准做 / 正在做 / 已能用**的功能条目。  
实现与验收以本目录为准；**不等于**议题讨论区。议题里的「已定结论」**不得**自动写入本目录。

## 文档范围

| 允许 | 禁止 |
|:---|:---|
| 根目录唯一总表 `【总表】功能一览.md` | 第二份功能总览；与议题总表混成一张 |
| 可选 `{短名}/说明.md`（验收口径、边界、实现映射） | 预建空壳功能目录堆未放行想法 |
| 状态：`放行` / `实现中` / `已支持` | 把讨论中的开放想法当已放行 |
| 「来源」链到议题 `结论.md` | 另建 `or/`；在本目录写长篇争论文 |

## 目录结构

```text
doc/功能/
  AGENTS.md
  【总表】功能一览.md
  {短名}/                 # 可选；条目变复杂时再拆
    说明.md
```

- 新放行：优先只加总表一行；说明不够用时再建 `{短名}/说明.md`。
- 根目录除 `AGENTS.md` 与总表外，不放其它散文件。

## 总表列约定（强制）

| 列 | 含义 |
|:---|:---|
| **功能** | 短名（规范名，与 `doc/术语与称呼索引.md` 对齐） |
| **状态** | `放行`（准实现未交付）/ `实现中` / `已支持`（实际可用） |
| **要点** | 一两句能力边界 |
| **来源** | 链到议题 `结论.md` 相关节 |
| **代码** | 入口路径或「未落地」 |

## 写入闸门（强制）

写入或改状态为 `放行` / 新开功能行，须用户明示（如「放行 / 写入功能目录 / 可以做这个」）。  
助理不得仅因议题已定结论就加行。

实现完成后：状态改为 `已支持`，并填「代码」列；术语表实现列同步。

## 开工依据

只实现总表中状态为 `放行` 或 `实现中` 的条目。  
输入 = 该功能说明（若有）+ 来源议题已定结论 + 术语表。

## 协作约定

| 相邻 | 边界 |
|:---|:---|
| `doc/议题/` | 讨论与原则；本目录不替代议题总表 |
| `doc/术语与称呼索引.md` | 放行时规范名须已在表中或同回合补上 |
| 工程代码 | 落地后改本表状态与代码列；入口注释钉规范名 |

编辑本目录前先读本文件与 `doc/AGENTS.md`。Cursor 规则见 `.cursor/rules/rules-功能.mdc`。
