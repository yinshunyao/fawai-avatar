# 步骤分类与执行流

## 验收

- 规划可输出 `step_kind`：`sense` | `act_serial` | `act_parallel` | `analyze` | `finalize`；缺省由动作/观察启发式回填。
- **`act_serial` / `act_parallel` / `analyze` / `finalize`**：下一步步首环境观察默认 `none`；未显式点选 `obs_screen`/`obs_ax` 时**不**再跑浅 `obs_fs` 顶层列表。
- **`sense`**：按 `observe_kinds` 真采（可含 `obs_fs` / `obs_screen` / `obs_ax`）。
- **`act_serial`**：同批串行；`expect`/`ok` 停段；段末统一工具结果观察；机械只读成功 → 规则摘要跳过 LLM 观察反省（同动作段预期闸）。规划多步时倾向带精确或模糊 expect，无 expect 不拒。
- **`act_parallel`**：至少两个动作，且路径不冲突的读和写可以并行；同一路径的读与写、同一路径的多写、前台、`shell`、带 expect 的动作不并入。不合格则降级串行。段末合并后一次观察/分析。
- progress：`meta.step_kind`；PWA facts 可展示步型中文/英文标签（`step_kind.*`）。步骤簇头徽章展示**本步**步型（取证 / 串行执行 / 并行 / 分析 / 收尾）；不用末卡阶段名，也不用步首观察卡上的上一段步型。规划尚未给出步型时徽章留空。
- 步骤簇头在项数左侧展示**本步 token 合计**与**本步耗时**。token 为簇内各卡 `meta.tokens`（规划、观察反省、执行反省、步骤重复裁决）相加，不含任务级 `meta.stats`。耗时为本步 progress 墙钟（首条到末条）。与上一条间隔超过 3 分钟则只保留最新一段，避免「从此恢复」把空档和上一轮耗时叠进去；**簇仍在进行中时不得因长间隔清墙钟**（长工具无心跳收口会误截断）。墙钟不足 0.5 秒时改用各卡 `elapsed_ms` 之和。运行中约每秒刷新。无用量则不占位。工具卡收口（`observe_tool`）的 `elapsed_ms` 以动作墙钟为主，禁止被观察格式化毫秒覆盖。
- 自检：`demo_step_kind`；既有 `demo_action_segment` 不得被误伤。

## 边界

- 不等于取消执行反省 / 步骤重复 / 租约。
- 不等于复杂任务计划模式的跨任务 `parallel_group`。
- 不做依赖槽自动填参；不做 GUI/写并行。
- 在 [动作段预期闸](../动作段预期闸/说明.md) 之上叠步型；机械 kind 集合复用该模块。

## 环境变量

无新增总闸。并行线程数可选：

| 变量 | 默认 | 含义 |
|:---|:---|:---|
| `FAWAI_ACT_PARALLEL_WORKERS` | `4` | `act_parallel` 最大并发；`1` 等价串行 |
