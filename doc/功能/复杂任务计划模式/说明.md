# 复杂任务计划模式

## 验收

- **复杂度由编排脑判定**（`decide_complexity`）：非 mock 优先 LLM，失败/mock 启发式回退；**无人审**勾选。
- **先建卡再编排**：新建路径立刻 `create_task` + 建卡 + `phase=accepted`，再异步判定/出图（`meta.awaiting_plan`）；判定期间不拉逐步 Worker、线程内追问提示稍候（**仅非终态**）。取消/失败等终态须清 `awaiting_plan` 并收口编排进行中卡，禁止留下「已取消却仍在编排」；清闸后追问可 reopen 续跑。进模后判定（`phase=orchestrate`）与出图（`phase=plan_build`）是**两条**进度，各自合并本段直播与收尾，互不覆盖；未进计划模式时**不发**出图进度。两次模型调用都按规划同款节流直播（思考正文与输出）。出图收尾留在 `plan_build` 卡上；`phase=plan_graph` 且正文为「任务图已更新」只刷新右上角任务图。两条都不另开步骤流段。出图后升为计划父任务并调度。
- 判定进模后：编排脑出**任务图**，**立即自动调度**就绪监管脑（不等人确认）。
- **三层**：编排脑（判定/出图/租约/追加修订）→ 监管脑（节点授权内自行完成）→ 执行脑（步级闭环）。
- 节点成功且产物契约齐 → **规则**衔接下游；全部活跃节点完成后父计划 `completed`。
- **共用事实**：编排脑出图时可标 `shared_facts`（连接端点、训练任务、日志路径）。每个事实只有一个生产节点；消费节点依赖它，调度等事实写入后再拉起。正文按原文注入消费节点（超过约 1500 字则落在任务会话目录，注入一行结论和路径），不用收尾想法的前 120 字代替。口令不抄进各节点目标。节点内部超窗仍走规划历史窗的 compact，不再另做一份与节点平行的待办。
- **追加对话**：
  - `no_graph_change` / `dispatch_note` → 只下发监管脑 `pending_appends`；
  - **`reorder`**：真改未决子图（保留已完成）→ **cancel** 过时 running（`plan_superseded`）→ 按新就绪集拉起；淘汰节点进 `retired`，**不得**因此把父计划标 failed；
  - **`lease_adjust`**：更新 `modality_hint`；前台→后台时 cancel 后以同目标 pending 重拉；保留的 running 下发租约说明。
- **节点失败默认**：规则**阻塞下游**，父计划标 `failed`（不自动升编排脑改图）。
- **重试失败节点**（首选恢复，`retry_plan_nodes`）：保留上游 `completed`；仅把指定（或全部）`failed` 节点重置为可调度并拉起新监管脑；依赖未齐 / `cancelled` 不自动重试。API：`POST /api/tasks/{id}/plan/retry-nodes`，body `{ "node_ids": ["n2"] }`（可空=全部 failed）。
- **手工删除节点**（`remove_plan_nodes`）：活跃图 `retire` 指定节点、cancel 对应监管脑并标 `plan_superseded`；下游 `depends_on` 剥离对该 id 的依赖；**禁止删光全部活跃节点**（须停止/整图）。若父计划因失败而停且图上已无 failed，可重开并拉就绪集。API：`POST /api/tasks/{id}/plan/remove-nodes`，body `{ "node_ids": ["n3"] }`。
- **重新执行 / 显式整图重规划**：`replan_full_graph`——cancel 旧监管脑并标 `plan_superseded`；旧活跃节点进 `retired`；编排脑按根目标重新出图；**`version += 1`**；按就绪集拉起。**不保留**旧 completed 产物。
- **父计划追问分流**：
  - 显式口令「整图重规划 / 重新规划 / 全部重做」或 PWA「整图重规划」→ 整图重做（不保留 completed）；
  - 父为 `failed`/`cancelled` 且图上仍有 failed → **默认重试失败节点**（保留上游 completed），追问约束写入 `plan_dispatch_note` 并由新监管脑 `pending_appends` 继承；
  - **其余追加**（如「用 best.pt 不要 last.pt」）→ **软续跑**：`analyze_plan_append`，保留已完成，只续未决 / 下发约束；**禁止**默认整图重规划。
  - 父任务本身仍不跑逐步 Worker。
- **网关不阻塞**：进模判定 / 出图 / 整图重规划 / 追问路由 / 追加分析等同步 LLM，须经枢纽 `SessionHub._run_blocking`（`asyncio.to_thread`）调用；禁止在 uvicorn 事件循环里直接 `chat()`，否则整站 HTTP/WS（含网页查询）会卡死数十秒到数分钟。
- **默认关闭**自动进模：环境 `FAWAI_PLAN_MODE` 未设或 `0` 时不进；会话 compose **模式**面板里的 **计划模式**（`meta.plan_auto`）若显式带上，**优先于环境**——开则可判定出图，关则强制单任务。未带 `plan_auto` 时仍看环境（`auto`/`1` 才进）。任务 [Fast（极速）](../Fast/说明.md) 开时即使允许进模，建卡后也跳过判定、强制单 Worker。
- [执行配置自动模式](../执行配置自动模式/说明.md) 开时：首轮分析同相位决定是否 `plan_auto`/`enter`（未锁定时），不再要求用户先手拨计划开关。
- 全图节点已 `completed`/`cancelled` 后软追加（`dispatch_note` / `no_graph_change`）若无 running 监管脑可接：回落**同线程会话 Worker**（`plan_allow_session_worker`），禁止父任务空 `running`。续跑出站打 `plan_session_continue`（**不**劫持 `plan_append`/路由卡）；PWA 将用户泡与续跑进度挂同一 `#planEpochs` 宿主并按交互时序排列（勿回 `#msgs` 头顶，勿与用户泡分挂 `epoch.tail`）。
- `FAWAI_BRAIN_MOCK=1` 时判定/出图/修订走启发式。

## 会话呈现（单任务 + 有向图）

- **侧栏只见父计划**：`plan_role=supervisor` 的监管脑子任务不进 `/api/tasks` 与对话列表。
- **进度归并**：子任务 `emit_progress` / 终态卡改挂到 `plan_parent_task_id`；打开父会话时历史会并入旧挂在子 id 上的信封。
- **整任务状态为准**：侧栏徽章 / 父计划 `status` 只认父任务库态与任务图收束（`graph.all_completed()` → `plan_finish`）。监管脑节点完成卡用 `mode=plan_node_finish` + `node_status`，**禁止**把单节点 `completed` / 步骤 phase 写成父会话终态。出图自动调度后父库须 `running`，归并进度带 `parent_status`；`plan_finish` 须带 `parent_status` 刷新侧栏（勿粘「执行中」）。前端不得因建卡时的 `pending` 一直显示「排队」。**节点 failed 后下游停在 pending 时，侧栏须保持父库 `failed`**，禁止因「图上仍有非终态节点」把失败盖回「执行中」（仅误粘的 `completed` 可降为 running）。
- **会话脊柱 vs 节点卡（时间序强制）**：主时间线（`#msgs`）只留**进轨前**整任务事件（首条目标、进模/出图等）。监管脑进度按 `plan_node_id` 归入 `#planEpochs` 下的**计划轮次**：每轮 = 节点轨（**仅已启动/有活动**的节点卡）→ **本轮收束尾**（`plan_finish` / Failed / 结论文）。**未启动**（`pending`/`ready` 且无 `task_id`）节点**不**进会话轨，整体依赖右上角任务图；点图上未启动节点只高亮图、不建空卡。有活动的卡按更新时间升序（新的在下）。节点完成文案留在对应卡内，不与并行节点混成一条时间河。**禁止**把收束尾挂成整段节点轨之后的全局黑洞——否则重试后新节点会排到 Failed 前面，历史回放也会固化错序。**禁止**在节点轨已开后仍把追问/改图/续跑卡写回 `#msgs`——`#msgs` 整块在 `#planEpochs` 之前，会把追加顶到最前、旧节点卡沉底；中段桥接行须按 `ts` 插入 `#planEpochs`（与 epoch 混排）。
- **执行中软追加进节点流（强制）**：`no_graph_change` / `dispatch_note` 下发监管脑时，用户追加气泡与意见接纳卡（`mode=plan_append`）须带主展示 `plan_node_id`，插入该节点 `step-stream` 中段——**追加前子步骤 → 用户话 → 意见接纳 → 追加后子步骤**；禁止再贴在节点卡上方的脊柱空位，也禁止塞进 `plan-node-notes`（notes 在 stream 下会贴底）。多 running 节点时会话只挂主展示节点（入站所属监管脑节点，否则唯一/首个 target）；其它 target 仍收 `pending_appends`。改图类（`reorder` / `lease_adjust`）与无节点 stamp 的续跑卡走 `#planEpochs` 桥接行（仍在旧节点轨之后），不回 `#msgs`。
- **父计划结论文（强制）**：`plan_finish` 气泡的 `final_thought` 由 `_parent_summary` 生成——各节点只留**首行短预览**；**正文取最后一个有产物节点的完整 `user_summary`**（下游 `produces`/`consumes` 仍用短 `summary` 800 字）。过长时图内联可落会话文件，收束须读回全文进气泡。**禁止**按 120/4000 等固定字数硬切结论文正文；**禁止**把多节点长文各硬切拼成半截句/半截表。
- **并行节点单焦点细节（强制）**：同轮可多节点 `running`，但会话轨**同一时刻只展开并直播一个焦点节点**的步骤/思考细节；其它并行卡保持折叠，卡头状态与一行摘要仍刷新，细节入队至切回焦点再灌。无用户焦点时按图序认领第一个 `running`→`ready`→`waiting`。焦点节点终态后自动让出并认领下一活跃可焦点节点。
- **活跃步骤收起即停刷（强制）**：用户收起进行中的**步骤簇**或**深度思考**块后：不再写入其内部直播正文、不跟滚/钉到该更新点；簇头状态与摘要仍可刷新。禁止运行中强制把用户已收起的簇再打开。再展开时补灌收起期间的最新正文。
- **可焦点节点**：非 `completed`/`cancelled`，且非「前向失败不活跃」（上游 `failed` 导致的未启动下游）。点选此类节点（含尚无会话卡的未启动可焦点节点）→ 设为焦点并**收起其它可焦点并行卡、停止刷其细节**。已结束或前向失败不活跃节点：任务图/卡头可点开**钉住查阅**（灌入队细节），**不**抢细节焦点、**不**因其它节点抢焦点而被强制收起。澄清请求 `force` 抢焦点。用户手动折叠焦点卡后不自动改开其它活跃卡。
- **失败 → 重试的时间序**：`plan_finish` 收束并**封存**当前轮；「重试失败节点 / 整图重规划」**始终**先封存再开**新轮**（不依赖上一轮是否已 sealed；新节点卡在 Failed 之后）。已封存轮保留失败现场，不清掉重灌。同节点换 `run_id` / `plan_child_task_id` 也须换轮换流，禁止多 Worker 步骤叠进同一卡。回放须先按信封 `ts` 重建轮次，再按需补图，禁止用终态图抢先灌轨。
- **失败手工操作**：失败节点卡「重试本节点」；父计划失败时**收束结论气泡内**「重试失败节点」+「整图重规划」（后者文案标明丢弃已完成；挂气泡内，不 sticky 在输入栏上方）。节点卡另有「删除节点」（失败/未决/已完成可删，`running` 须先停）。
- **节点步骤流**：
  - **从此恢复**：绑**监管脑子任务** `plan_child_task_id`（`POST …/resume-from-step`），不绑编排器父 id；**截断**该步之后的上下文再拉 Worker，并把图节点标回 `running`、重开终态父计划。
  - **删除此步（挖上下文）**：`POST …/excise-step`（body `{ "step": N }`；打父计划 id 时须带 `plan_node_id`）。从该监管脑的 `run_checkpoint.traces` / `history` / `meta.steps` **挖掉这一环**，保留更早与更晚步骤；**不**自动拉 Worker，也**不是**「从此截断后续再恢复」。任务须非 `running` / 非 `archived`。
- **修订互斥**：同一父计划上 `full_replan` / `retry_nodes` / `remove_nodes` / `resume_from_step` / `apply_plan_revision` 进程内互斥；连点时后到者返回「计划修订进行中」，禁止双拉同节点 Worker。
- **追问分流补强**：仅显式整图口令才整图；失败默认重试失败节点；其它追问走软续跑（保留已完成）。
- **父任务用量**：侧栏父计划 token = 各节点子任务之和；耗时 = 会话开始到结束（见 [任务统计](../任务统计/说明.md)）。进度归并须附 `parent_stats`；前端另用节点卡汇总兜底，不得把当前节点 stats 当成父任务摘要、也不得空白。
- **任务图面板**：父线程**右上角浮层**（默认折叠小条，不占主会话纵向空间；点击展开看图）——按 `depends_on` 分层的有向流程图，节点状态（pending/ready/running/completed/…）随 `phase=plan_graph` 进度实时刷新。**点击图节点**→ 展开并滚到对应节点卡（双向锚）。
- 停止父计划时先 `cancel` 其下监管脑，再停父任务。

## 边界

- **产品默认**：会话不自动进本模式；简单/复杂目标默认同一 Worker 稠密闭环（见会话通道）。compose 开「计划模式」或环境 `FAWAI_PLAN_MODE=auto` 后才适用下列编排行为。
- 默认串行依赖链；同组无依赖可并行拉起；前台租约仍走既有闸门。
- **不做**出图后等人确认再跑；**不做**用户勾选「是否复杂」。
- **不做**连接错误自动无感重试；**不做**失败后自动升编排脑改图（仍靠用户重试 / 追加 reorder / 显式整图重规划）。
- 监管脑/执行脑**不得**私自改全局图或租约；修订只经编排脑 `apply_plan_revision`。
- 父计划默认不跑逐步 Worker（`plan_role=orchestrator`）；子任务 `plan_role=supervisor`。**例外**：图无活跃节点时的会话回落可对父任务开 `plan_allow_session_worker`。
- 会话内**拖拽改图 / 新增节点 / 改文案**仍为后置；当前交付为只读有向图 + 手工删节点/挖步 + 机读修订。

## 自检

```bash
FAWAI_BRAIN_MOCK=1 .venv/bin/python -m fawai_avatar.demo_plan_mode
```

覆盖：进模判定、串行调度、**reorder cancel+重拉**、**lease_adjust**、**整图重规划 full_replan**、**失败节点 retry_plan_nodes（保留上游 completed）**、**监管脑从步骤恢复 resume_plan_child_node**、superseded 不 fail 父计划。
