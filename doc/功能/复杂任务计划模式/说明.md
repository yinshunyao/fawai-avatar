# 复杂任务计划模式

## 验收

- **复杂度由编排脑判定**（`decide_complexity`）：非 mock 优先 LLM，失败/mock 启发式回退；**无人审**勾选。
- 判定进模后：编排脑出**任务图**，**立即自动调度**就绪监管脑（不等人确认）。
- **三层**：编排脑（判定/出图/租约/追加修订）→ 监管脑（节点授权内自行完成）→ 执行脑（步级闭环）。
- 节点成功且产物契约齐 → **规则**衔接下游；全部活跃节点完成后父计划 `completed`。
- **追加对话**：
  - `no_graph_change` / `dispatch_note` → 只下发监管脑 `pending_appends`；
  - **`reorder`**：真改未决子图（保留已完成）→ **cancel** 过时 running（`plan_superseded`）→ 按新就绪集拉起；淘汰节点进 `retired`，**不得**因此把父计划标 failed；
  - **`lease_adjust`**：更新 `modality_hint`；前台→后台时 cancel 后以同目标 pending 重拉；保留的 running 下发租约说明。
- **节点失败默认**：规则**阻塞下游**，父计划标 `failed`（不自动升编排脑改图）。
- **重试失败节点**（首选恢复，`retry_plan_nodes`）：保留上游 `completed`；仅把指定（或全部）`failed` 节点重置为可调度并拉起新监管脑；依赖未齐 / `cancelled` 不自动重试。API：`POST /api/tasks/{id}/plan/retry-nodes`，body `{ "node_ids": ["n2"] }`（可空=全部 failed）。
- **重新执行 / 显式整图重规划**：`replan_full_graph`——cancel 旧监管脑并标 `plan_superseded`；旧活跃节点进 `retired`；编排脑按根目标重新出图；**`version += 1`**；按就绪集拉起。**不保留**旧 completed 产物。
- **父计划追问分流**：父为 `failed` 且图上仍有 failed 节点时，**默认重试失败节点**；仅当用户话含「整图重规划 / 重新规划 / 全部重做」等显式口令（或 PWA「整图重规划」）才整图重做。父任务本身仍不跑逐步 Worker。
- **网关不阻塞**：进模判定 / 出图 / 整图重规划 / 追问路由 / 追加分析等同步 LLM，须经枢纽 `SessionHub._run_blocking`（`asyncio.to_thread`）调用；禁止在 uvicorn 事件循环里直接 `chat()`，否则整站 HTTP/WS（含网页查询）会卡死数十秒到数分钟。
- `FAWAI_PLAN_MODE=0` 可关；默认 `auto`。`FAWAI_BRAIN_MOCK=1` 时判定/出图/修订走启发式。

## 会话呈现（单任务 + 有向图）

- **侧栏只见父计划**：`plan_role=supervisor` 的监管脑子任务不进 `/api/tasks` 与对话列表。
- **进度归并**：子任务 `emit_progress` / 终态卡改挂到 `plan_parent_task_id`；打开父会话时历史会并入旧挂在子 id 上的信封。
- **整任务状态为准**：侧栏徽章 / 父计划 `status` 只认父任务库态与任务图收束（`graph.all_completed()` → `plan_finish`）。监管脑节点完成卡用 `mode=plan_node_finish` + `node_status`，**禁止**把单节点 `completed` / 步骤 phase 写成父会话终态。出图自动调度后父库须 `running`，归并进度带 `parent_status`；`plan_finish` 须带 `parent_status` 刷新侧栏（勿粘「执行中」）。前端不得因建卡时的 `pending` 一直显示「排队」。
- **会话脊柱 vs 节点卡**：主时间线（`#msgs`）只留整任务事件（用户话、进模/出图/改图、`plan_finish`）。各监管脑进度按 `plan_node_id` 归入 `#planNodeRail` 节点卡（挂在会话滚动区下部时间线；默认折叠；Running/Ready 自动展开）。卡上展示**更新时间**与 **token / 耗时**（来自监管脑子任务 stats）；有活动的卡按更新时间升序排列（新的在下），未启动节点垫底。节点完成文案留在对应卡内，不与并行节点混成一条时间河。
- **失败手工操作**：失败节点卡「重试本节点」；父计划失败时输入区上方「重试失败节点」+「整图重规划」（后者文案标明丢弃已完成）。节点步骤流「从步骤恢复」绑**监管脑子任务** `plan_child_task_id`，不绑编排器父 id。
- **父任务用量**：侧栏父计划 token = 各节点子任务之和；耗时 = 会话开始到结束（见 [任务统计](../任务统计/说明.md)）。进度归并须附 `parent_stats`；前端另用节点卡汇总兜底，不得把当前节点 stats 当成父任务摘要、也不得空白。
- **任务图面板**：父线程**右上角浮层**（默认折叠小条，不占主会话纵向空间；点击展开看图）——按 `depends_on` 分层的有向流程图，节点状态（pending/ready/running/completed/…）随 `phase=plan_graph` 进度实时刷新。**点击图节点**→ 展开并滚到对应节点卡（双向锚）。
- 停止父计划时先 `cancel` 其下监管脑，再停父任务。

## 边界

- 默认串行依赖链；同组无依赖可并行拉起；前台租约仍走既有闸门。
- **不做**出图后等人确认再跑；**不做**用户勾选「是否复杂」。
- **不做**连接错误自动无感重试；**不做**失败后自动升编排脑改图（仍靠用户重试 / 追加 reorder / 显式整图重规划）。
- 监管脑/执行脑**不得**私自改全局图或租约；修订只经编排脑 `apply_plan_revision`。
- 父计划不跑逐步 Worker（`plan_role=orchestrator`）；子任务 `plan_role=supervisor`。
- 会话内**拖拽改图**仍为可选后置；当前交付为只读有向图 + 机读修订。

## 自检

```bash
FAWAI_BRAIN_MOCK=1 .venv/bin/python -m fawai_avatar.demo_plan_mode
```

覆盖：进模判定、串行调度、**reorder cancel+重拉**、**lease_adjust**、**整图重规划 full_replan**、**失败节点 retry_plan_nodes（保留上游 completed）**、superseded 不 fail 父计划。
