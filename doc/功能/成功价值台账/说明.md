# 成功价值台账

## 要点

本步业务操作已确认成功后，Agent 用工具写入「成功价值卡」（本任务 jsonl），可搜可回灌；后台按完备性 / 通用性 / 效率自评，过门则**实写 lore** 供跨任务检索。是否搜台账由模型自决。

## 验收口径

1. `success_ledger_upsert` 写入 `{FAWAI_DATA_DIR}/sessions/{task_id}/success_ledger.jsonl`；字段含 acceptance / commands / config_refs / code_refs / targets / evidence 等。`acceptance` / `goal_slice` 须为人读短句（禁止 `true`/`false`）；过门写 lore 时标题由 `ledger_title.summarize_success_lore_title` 从验收句 / 目标 / 证据 / 命令族总结，拒绝布尔字面量当标题。
2. `success_ledger_search` / `success_ledger_get` 默认仅当前 `task_id`；其它任务拒绝。
3. 默认排队三维门控（可 `evaluate=false` 跳过）；完备/通用/效率折算百分比后均 ≥ 记忆配置 `FAWAI_LEDGER_GATE_THRESHOLD`（默认 **80**）才写 lore 并回填 `lore_id`，禁止只标 promoted。
4. 门控为旁路：会话时间线 `phase=success_ledger_gate` 提示排队/评估中/结果；`tokens` + `elapsed_ms` 写在进度卡，并计入任务 `meta.stats`（`llm_calls`）。
5. 规划提示写明台账能力；跨任务复用走 `lore_search(scopes=[lore])`。
6. 口令 / Token 不得进卡或 lore（写入前脱敏）。
7. 阈值与失败台账共用；在 PWA「记忆配置」可改。

## 边界

- 不替代 `task_context_*`（轨迹原文）或 `lore_*`（跨任务知识）。
- 执行中写卡仍为主路径；终态**条件**短卡蒸馏（E1，见 [自我进化](../自我进化/说明.md)）是补漏，不是整段灌库。未过门只留本任务台账。
- 不写死三维分数线；以模型 `pass` 为准。
- 失败试错整段勿灌进卡；失败对照用短 `avoid`。
- 门控用量进任务总统计与本旁路进度卡；不并入规划步 `plan.raw.usage`（避免与主脑规划混算）。
