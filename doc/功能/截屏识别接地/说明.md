# 截屏识别接地

## 验收

- 模型配置可设 **截屏识别方式**：`vlm`（附图多模态）或 `ocr`（OCR API 出文字框表）。
- 可配置独立 **OCR 路由**（供应商 → 模型），默认百炼 `qwen3.5-ocr`。
- 当方式为 `ocr` 且本步采了 `obs_screen`：调用高精识别，观察摘要含 `ocrN | text | bounds`；规划默认**不附图**；`ui_click`/`ui_type` 可用 OCR `ref`（如 `ocr1`）。
- 当方式为 `vlm`：行为与改前一致（截屏附图进 VLM）。
- AX `ref` 仍优先；OCR 失败时摘要写明原因，可降级附图（meta 标记）。
- **进度分卡（强制）**：本机截屏为 `phase=observe`；OCR API 为独立 `phase=observe_ocr`（等待中有心跳「已等待 Ns」；完成卡可展开模型/字框/通道）。不得把 OCR 耗时只挂在「截屏」一张卡上。

## 边界

- 不承诺无字图标点准；不做自托管 OmniParser。
- OCR 须 `advanced_recognition`；全文提取任务不算接地成功。
- headless 无截屏则本能力不触发。

## 自检

```bash
.venv/bin/python -m fawai_avatar.demo_ocr_grounding
```

## 实现映射

| 规范名 | 路径 |
|:---|:---|
| 截屏识别接地 | `observe/screen_grounding.py`；配置 `llm/settings_store` meta `screenshot_grounding` |
| OCR 客户端 | `llm/ocr.py` |
| OCR 元素表 | `observe/ocr_tree.py` |
| 观察挂接 | `observe/methods.py`（`obs_screen` 后处理） |
| 控件点击 | `control/executor.py`（AX → OCR） |
| 规划卸图 | `brain/planner.py` |
