# 编码闭环（Cursor 对齐）

## 验收

### P0

- **精准补丁** `fs_patch`：局部唯一匹配替换；多 hunk；匹配 0/多处失败；大源码禁止无故 `fs_write` 整写（须 `force_full_write`）。`hunks` 可为 JSON 数组字符串（自动解析）；`old`/`new` 含「…」或以 `...` 收尾视为截断并拒绝；目标 path 不存在时明确提示先 `fs_glob`/`fs_read`。
- **仓检索**：`fs_grep` 支持 `context_before` / `context_after`；`fs_read_many` 限额多读。
- **改码回证** `code_check`：按后缀跑默认检查（`.py`→`py_compile`）；失败不得把编码目标直接标 success。
- **编码跑测**：`code_check` / `fs_*` / `code_*` / `git_*` / `explore_*` 不受 `FAWAI_DRY_RUN`；白名单 `shell_verify` 可跑校验命令。
- **会话 Diff**：写后 progress/`card` 带 unified diff 摘要；`FAWAI_DIFF_MODE=auto|confirm`（默认 `auto`）；confirm 下须口令 `确认补丁` / `拒绝补丁`。

### P1

- **Git**：`git_status` / `git_diff` / `git_commit`（commit 须显式；不自动 push）。
- **多文件改动清单**：写类动作须填齐 `write_resources`；闭环汇总清单路径。
- **编码上下文**：规划注入 `AGENTS.md` / `.cursor/rules` 摘要（可截断）。
- **逐步工具调用**：编码类目标可走原生 tool_calls（`FAWAI_NATIVE_TOOLS`，默认开）；写入分层路径时自动绑定默认 `doc_refs`（见 [守规约束](../守规约束/说明.md)）；工具 args 若误嵌套一层 JSON/`args` 键，规划侧展平后再执行。
- **探仓**：`explore_search` 进程内并行只读检索。
- **探索进度闸门**：改文件 / 前端类目标若连续仅成功只读探索且 `write_set` 仍空，达到阈值后注入硬约束，并收紧原生工具面（只暴露写类 / 检查 / `done`）。达到中止阈值时**先强制一轮改写**（`【探索改写强制】`），仍只读成功才 `failed`。前端/页面类默认更紧（5 / 10）；同一 path 反复 `fs_read`、或同 path **重叠行窗**反复读，都会加速 streak（软停滞）；文案区分「已定位未写」与盲读。
- **定位预算**：`fs_grep`/`explore_search`/`fs_glob` 已给出 path 或 path:line 锚点后，只读探索步数达到预算（默认 3）注入 `【定位预算】` 并收紧 mutate 工具面——禁止同 path 空转再确认。
- **宽检索降质**：单次命中 ≥ 阈值（默认 20）或 hits 观察已压缩 → 注入 `【宽检索降质】`，禁止同范围再宽 grep；观察文案同步提示收窄 / 按行号读。
- **弱写入闸门**：`fs_patch` / `fs_replace` 成功后若 diff 仅为未 `var()` 引用的 CSS 自定义属性、或仅空白/注释，标注 `weak_write` 并注入 `【弱写入】`；在消化前禁止 `status=success`。`write_set` 非空 ≠ 验收通过。
- **可见副作用闸门**：页面/布局/样式类目标在已有写入后，空 `actions` 的 `success` 也须再走收尾轮；`thought` 须说明用户可见变化（附图目标须对照图中问题）。占位文案（如 `native tool_calls`）重试一次仍不合格，或自认无可见变化 → `failed`。
- **规划历史窗**：规划前压缩 history（近窗全文 + 远窗摘要，同 path 只读去重），降低中后期单步 prompt token。
- **工具结果回灌**：大段 stdout/lines 默认更紧的 soft/hard；`fs_read` 行预览有上限并提示按行号小窗续读。

## 边界

- 不对齐 Tab / 内联编辑；P0 无向量检索。
- 不自动 `git push` / force。
- 自我进化禁改名单仍生效。
- Diff confirm 默认关（`auto`）；强快照仍开。
- 探索闸门不替代步骤重复；二者可同时触发。闸门 inject / 强制改写靠 history 标记驱动规划侧 `mutate_prefer` 工具面，不只依赖模型读文案。
- 弱写入 / 可见副作用闸门不替代探索闸门：前者管「写出质量与收尾判定」，后者管「探索→改写相位」。
- **反省开读**：`alternate`/`retry` 且约束要求核对原文时，闭环注入 `【反省开读】`，在 `mutate_prefer` 工具面临时放行定向 `fs_read`/`fs_grep`/`fs_glob`（近 4 条 history），禁止因禁读面直接 `failed`。
- 历史窗只影响送入规划的副本；闭环落盘/检查点仍保留较完整 history。

## 环境变量

| 变量 | 默认 | 含义 |
|:---|:---|:---|
| `FAWAI_DIFF_MODE` | `auto` | `auto` 立即落盘并推 diff；`confirm` 暂存待确认 |
| `FAWAI_NATIVE_TOOLS` | `1` | 编码类目标用原生 tool_calls |
| `FAWAI_FULL_WRITE_LINE_LIMIT` | `80` | 已存在文件超过此行数禁止无 force 的 `fs_write` |
| `FAWAI_EXPLORE_ONLY_GATE` | `8`（前端类未显式设时按 `5`） | 连续只读探索注入约束的阈值；`0`=关；显式设置则覆盖前端特例 |
| `FAWAI_EXPLORE_ONLY_ABORT` | `2×GATE` | 连续只读达到后先强制改写一轮，仍无写入再 failed；空则按 2×GATE；`0`=只注入不止损 |
| `FAWAI_EXPLORE_REPEAT_READ_BOOST` | `3` | 同一 path 成功 `fs_read` 达此次数时探索 streak 额外 +1；`0`=关 |
| `FAWAI_EXPLORE_OVERLAP_READ_BOOST` | `1` | 同 path 成功 `fs_read` 行窗与历史窗口重叠时 streak 额外 +1；`0`=关 |
| `FAWAI_LOCATE_BUDGET_STEPS` | `3` | 已定位锚点后允许继续只读的步数；达阈值注入定位预算；`0`=关 |
| `FAWAI_WIDE_GREP_HITS` | `20` | 单次检索命中数达此值触发宽检索降质；`0`=关 |
| `FAWAI_WEAK_WRITE_GATE` | `1` | 弱写入检测与 success 拦截；`0`=关 |
| `FAWAI_VISIBLE_EFFECT_GATE` | `1` | 页面/布局类收尾须说明可见副作用；`0`=关 |
| `FAWAI_HISTORY_KEEP_RECENT` | `8` | 规划历史近窗保留消息条数 |
| `FAWAI_HISTORY_MAX_CHARS` | `18000` | 规划用 history 压缩后字符软上限 |
| `FAWAI_TOOL_OBS_SOFT_CHARS` | `2000` | 单条工具观察正文软阈值（超则压缩） |
| `FAWAI_TOOL_OBS_HARD_CHARS` | `6000` | 压缩后硬截断 |
| `FAWAI_TOOL_OBS_FS_READ_LINES` | `40` | `fs_read` 回灌最多展开行数 |
