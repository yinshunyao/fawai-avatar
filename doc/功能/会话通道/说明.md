# 会话通道

## 验收

- 统一**消息信封**：入站 `text` / `image` / `control`；出站 `text` / `image` / `progress` / `card` / `error`。
- 入站可选 **`task_id`**（当前打开的任务线程）：
  - **无** → 总管 **新建**工作任务。
  - **有**且 **running** → **执行中追加**（`analyze_running_append`）：结合任务状态、原 goal、近期步骤摘要与用户增量 → **apply**（`meta.pending_appends` + `meta.followups`；**不**把追问正文拼进 `goal`；先推追加确认 `card`，再推 `progress` `phase=append` + `timeline_segment=new` 开后段时间线；不 requeue、不新开 Worker；当前工具不打断）或 **new_task**（新建 sibling）。Worker 每步观察/规划前刷新 goal 并消费 pending 写入 history。
  - **有**且 **archived** → 拒绝；须先取消归档或新开任务。
  - **有**且 **waiting** 且 `meta.clarification.phase=awaiting_input` → **执行中澄清答复**（见 [执行中澄清](../执行中澄清/说明.md)）：本条视为答案，注入后续跑；**不**走 `route_followup`。
  - **有**且其它状态（含 completed / failed / cancelled）→ **线程内路由**（`brain/task_route`）：按原目标、状态与本轮话判断 **continue**（记入 `meta.followups`，**不**与首条 goal 合并；终态可 reopen 再跑；Worker 新 run 把 followups 注入 history）或 **new_task**（新建，`meta.parent_task_id` 指向原线程）。
- 新建 / 追问 / 追加后，用户入站消息的 `task_id` **改挂到实际任务**，保证线程里能看到首条指令；**会话气泡各自独立**，禁止把「【追问】…」拼进同一条用户绿泡或 goal 展示。
- 入站 **image** 须先落历史并 **publish**（带 `media_url`），再进入建任务/追问/追加，会话气泡可展示用户图。goal 可附 `[image:…]` 供大脑多模态读图；会话展示须解析为 `<img>`（合成气泡 / 回放同样），不得把标记原文当正文。
- 通道抽象可订阅出站、投递入站；**不**调用键鼠或截屏。
- 会话枢纽把入站交给总管；把总管/工作任务回报转为出站信封。
- **执行时间线（流式 progress）**：工作任务闭环经 `on_progress` 在执行中推送阶段 `progress`（`meta.phase`：`started` / `observe` / `plan` / `planned` / `act` / `acted` / `observe_tool` / `reflect` / `replan` / `finalize` / **`append`**；线程路由另有 `route`）；进入 LLM 规划前即推 `plan`，避免长等待黑盒。失败先 `reflect` 再 `replan`（见 [执行反省](../执行反省/说明.md)）。子步骤 `meta` 须带 **耗时 `elapsed_ms`**；规划轮带 **token `tokens`**（prompt/completion/total）与可选 **`observe_kinds`**；工具轮带 **`tool` / `cmd` / `paths`**；环境观察轮带 **`observe_label` / `observe_methods`**；工具结果观察轮 `phase=observe_tool`，**完成文案须附带工具结果摘要**（与回灌 history 同源，截断展示；禁止只写「观察工具结果完成」而无命中/输出）。PWA 时间线展示上述字段与摘要正文。禁止只写 kind 名如「执行中：shell」。**进度文案与 `meta.cmd` 须脱敏**（`channel/redact.py`：sshpass / expect `send` / password 等替换为 `***`），禁止把明文口令推进会话时间线。每次 `run` 带独立 `meta.run_id`；**追问续跑须新开时间线段**；**执行中追加**在用户气泡与追加卡处封口前段，后段用 `timeline_segment=new`（同 `run_id` 可多段）。终态**不再**批量重放 `steps`；保留终态 `card` + 最终助手 `text`。观察媒体标题按方式（如「观察（截屏）」），禁止写死「观察截图」。
- **最终助手文本**：优先用收尾轮 `plan.thought`（自然语言结论）；禁止把 shell/`top` 的原始 stdout 无条件当作用户可见回答。短工具确认文案（如写入成功）可作次选回退。问询/硬件盘点类终稿约束见 [完成任务](../完成任务/说明.md) 答复覆盖闸门。
- **Worker 崩溃收口**：`_run_worker_safe` 捕获异常后标记任务 `failed`、写系统日志，并仍发终态 `card` + 助手说明（库打不开等给出可行动提示）；不得只发 `error` 后留下 `running` 孤儿。
- **会话历史落盘**：默认 `{data_dir}/session_history.jsonl`；重启后枢纽加载；`/api/session` 回放近段；按任务完整回放走 `GET /api/tasks/{id}/history`（`SessionHub.history_for_task`）。PWA **打开线程须先拉该任务全量历史再渲染**，避免近段窗口只有末轮 progress 时用合并 goal 合成「原话+追问」假气泡。历史软裁剪（约 2000/1600）优先保留置顶用户及其任务的**多轮**时间线（按 `run_id` 留头尾；单任务 progress 硬上限约 240），禁止只剩追问后一段、也禁止一个胖任务挤掉其它任务的处理过程。若会话侧 progress 已被裁光但任务库仍有 `meta.steps` / `final_thought`，`history_for_task` **按步骤回放**时间线（`channel/task_timeline.py`，信封标 `meta.reconstructed`），避免打开旧任务只看见问题看不见处理。

## 边界

- 不做个人微信主通道。
- 原始 `audio` / `file` 信封入站仍后置；**语音输入**走网关转写为 text 后再入站（见 [语音输入](../语音输入/说明.md)）。
- 不替代总管做任务编排。
- 不在枢纽内二次调用 LLM 总结；结论依赖大脑收尾 `thought`（工作任务在「success 且刚执行过动作」时会再要一轮空 actions 结论）。
- **不做** LLM token 级流式吐到会话（仍是整段 plan 返回后再 `planned`）。
- **不做**靠 LLM 从混杂历史猜「这句话属于哪个任务」；归属只认信封显式 `task_id`。线程**内**续跑 vs 另开由路由 LLM/规则判断（与「猜归属」不同）。
- 普通文本**不**隐式用 `_active_task_id` 归类（该字段仅控制口令缺省）。
- **控制口令成功须 `publish`**：暂停/恢复/取消等成功卡必须广播（WebSocket 入站丢弃返回值）；否则侧栏状态徽章停在旧态。失败已 publish `error`。
- **复盘勾选闸优先**：任务 `awaiting_apply` 时，裸「取消」/「cancel」走复盘第二道闸，不走总管 `cancel`；「取消 \<task前缀\>」仍为总管取消。
- **不做**终态一刀切 sibling；失败后换法、同目标补救优先 continue。
- 历史有软上限（约 2000 条，裁剪后保留约 1600）；裁剪时优先整段保留置顶用户所属任务，并限制单任务 progress 体积；非多设备同步账本。
- 任务归属由 PWA **当前打开的任务线程**显式带 `task_id`；见 [会话网关](../会话网关/说明.md)。

## 实现映射

| 规范名 | 路径 |
|:---|:---|
| 会话通道 / 消息信封 | `fawai_avatar/channel/message.py`、`base.py`、`hub.py`（历史：`{data_dir}/session_history.jsonl`） |
| 缺 progress 时从 steps 回放 | `fawai_avatar/channel/task_timeline.py`（`history_for_task` 调用） |
| 进度/回放脱敏 | `fawai_avatar/channel/redact.py`（`loop._progress` + 回放共用） |
| 执行时间线回调 | `fawai_avatar/runtime/loop.py`（`WorkerLoop.on_progress`）→ `SessionHub.emit_progress` |
| 线程内路由 | `fawai_avatar/brain/task_route.py`（`route_followup` → continue / new_task） |
| 执行中追加 | `brain/task_route.analyze_running_append`；`SessionHub._append_while_running`；`meta.pending_appends`；`WorkerLoop` 步前消费 |
