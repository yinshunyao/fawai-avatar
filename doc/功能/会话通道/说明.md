# 会话通道

## 验收

- 统一**消息信封**：入站 `text` / `image` / `control`；出站 `text` / `image` / `progress` / `card` / `error`。
- 入站可选 **`task_id`**（当前打开的任务线程）：
  - **无** → 总管 **新建**工作任务：立刻建卡 + `phase=accepted`；编排脑判定/出图在后台（`meta.awaiting_plan`），完成后再进计划调度或拉逐步 Worker。
  - **有**且 **`meta.awaiting_plan`** → 提示仍在编排，不追问、不另开。
  - **有**且 **running** → **执行中追加**（`analyze_running_append`）：结合任务状态、原 goal、近期步骤摘要与用户增量 → **apply**（`meta.pending_appends` + `meta.followups`；**不**把追问正文拼进 `goal`；先推追加确认 `card`，再推 `progress` `phase=append` + `timeline_segment=new` 开后段步骤流；卡/进度 `ts` 锚定入站用户消息之后；不 requeue、不新开 Worker；当前工具不打断）或 **new_task**（新建 sibling）。Worker 每步观察/规划前刷新 goal 并消费 pending 写入 history。
  - **有**且 **archived** → 拒绝；须先取消归档或新开任务。
  - **有**且 **waiting** 且 `meta.clarification.phase=awaiting_input` → **执行中澄清答复**（见 [执行中澄清](../执行中澄清/说明.md)）：本条视为答案，注入后续跑；**不**走 `route_followup`。
  - **有**且其它状态（含 completed / failed / cancelled）→ **线程内路由**（`brain/task_route`）：按原目标、状态与本轮话判断 **continue**（记入 `meta.followups`，**不**与首条 goal 合并；终态可 reopen 再跑；Worker 新 run 把 followups 注入 history）或 **new_task**（新建，`meta.parent_task_id` 指向原线程）。
- 新建 / 追问 / 追加后，用户入站消息的 `task_id` **改挂到实际任务**，保证线程里能看到首条指令；**会话气泡各自独立**，禁止把「【追问】…」拼进同一条用户绿泡或 goal 展示。
- 入站 **image** 须先落历史并 **publish**（带 `media_url`），再进入建任务/追问/追加，会话气泡可展示用户图。goal 可附 `[image:…]` 供大脑多模态读图；会话展示须解析为 `<img>`（合成气泡 / 回放同样），不得把标记原文当正文。
- 通道抽象可订阅出站、投递入站；**不**调用键鼠或截屏。
- 会话枢纽把入站交给总管；把总管/工作任务回报转为出站信封。
- **执行步骤流（流式 progress）**：工作任务闭环经 `on_progress` 在执行中推送阶段 `progress`（`meta.phase`：`started` / `observe` / `plan` / `planned` / `act` / `acted` / `observe_tool` / `reflect` / `replan` / `finalize` / **`append`**；线程路由另有 `route`）；进入 LLM 规划前即推 `plan`，避免长等待黑盒。失败先 `reflect` 再 `replan`（见 [执行反省](../执行反省/说明.md)）。子步骤 `meta` 须带 **耗时 `elapsed_ms`**；规划轮带 **token `tokens`**（prompt/completion/total）、可选 **`model`**（实际路由模型 id）、可选 **`thinking`**（`enabled` / `budget` / `role`）与可选 **`observe_kinds`**；PWA 步骤 facts「模型」行同时展示模型名、思考开/关（及预算）与 token（如 `qwen3.7-plus · 思考开 · 预算 1k · token 3.6k`；缺一侧则只显示有的）；工具轮带 **`tool` / `cmd` / `paths` / `commands`**（`commands` 是每条动作的种类和关键参数，如 pattern、path、head_limit；PWA 在同一步工具卡上逐条展示，多条时不收成只剩工具名和去重路径；规划输出若是带 actions 的完整 JSON，模型输出区同样改成逐条命令）；环境观察轮带 **`observe_label` / `observe_methods`**，完成文案须附带 **`obs.summary` 预览**（含前台窗摘要；可选 meta `frontmost_*`），禁止只写「观察完成（跳过）」而无采到内容；工具结果观察轮 `phase=observe_tool`，**完成文案须附带工具结果摘要**（与回灌 history 同源，截断展示；禁止只写「观察工具结果完成」而无命中/输出）。**LLM 直播**：规划 / 反省 / 观察反省等待模型时，经 `stream=True` 把 **深度思考正文**（`reasoning_content` 等）与 **普通输出正文** 节流推到同一步卡（`meta.live=true` 只广播不落历史；字段 `thinking_text` / `content_text`）；PWA 步骤卡在进行中即展示可滚动直播区，禁止长时间只转圈无字；**完成后直播区仍常显**（不依赖展开详情、不随 `is-running` 消失），便于回看思考/输出；阶段收尾信封须带上 `thinking_text`（历史回放同路径）。深度思考块**排在结论正文上方**；自带展开/收起小按钮（进行中默认展开跟读，完成后/历史回放默认收起；用户收起写入 sessionStorage，刷新后仍不展示），禁止靠点击整步卡来开合思考区。**跟读定位**：`meta.live` 增量时外层 `#threadScroll` 须跟到正在刷新的直播块（深度思考/输出正文），禁止一律 `scrollBottom`（澄清卡、任务清单等常在直播块下方，钉底会把更新行挤出视野）；深度思考限高框（`.step-live-body`）在 token 超高后须自动滚到正文末行展示当前输出（`textContent` 更新后用 ResizeObserver + 多帧钉 `scrollTop`，程序滚动不误判为用户上翻）；用户在框内/线程内手动上翻后暂停自动跟读，回到底部附近再恢复。收起偏好写入 `sessionStorage`（按任务+步骤），页面刷新后仍保持收起不展示；历史回放默认收起，进行中直播默认展开。收尾仍推 `planned` / 反省完成等完整阶段（含 usage）；直播正文不重复堆进会话历史。**PWA 不在对话外另开「执行时间线」折叠菜单**：progress 直接插入对话流滚屏；同族阶段前端合并就地刷新（`plan`↔`planned`、`act`↔`acted`/`diff`/`observe_tool`、观察进行中↔完成、反省/`obs_reflect` 进行中↔完成）；**同 `#N` 收成步骤簇**（含该步的开始/任务命名；观察/规划/工具/反省等可展开收拢；**簇头标题优先粘住 `meta.step_label`（本步业务意图）**，缺省才回退任务短标题 / 实质进展文案；禁止把「观察反省」「规划中」等阶段名当成簇头主标题；**簇头徽章显示本步步型**（`step_kind.*`：取证 / 串行执行 / 并行只读 / 分析 / 收尾），不用末卡阶段名；步首观察卡上的步型是上一段的，不拿来当本步徽章；规划尚未给出步型时徽章留空；`phase=planned` 起即带 `step_label`，动作开始前已可见；新步开始时自动收拢上一步；历史默认收拢）；追加/路由/暂停取消等分段边界仍独立成行；簇头徽章为本步步型，右侧为项数，并展示本步 token 合计（簇内各卡 `tokens` 相加，不含任务级 `stats`）与耗时（本步 progress 墙钟；与上一条间隔超过 3 分钟则只保留最新一段）；终态/暂停等可悬停（窄屏常显）「从此恢复」→ 从该步续跑（见 [进程中断续跑](../进程中断续跑/说明.md)）；`cancelling`↔`cancelled` 合并收口，避免卡在「正在停止」；**每步时刻与 token/耗时/工具等 facts 默认可见**（合并步骤累计 meta）；结论行默认可见；过程细节（工具输出、长规划/反省正文、diff 正文）**默认折叠可点开**；`phase=diff` 的 unified diff **着色展示**（默认收在详情里，路径摘要可见）。阶段徽章走 `phase.*` i18n（见 [界面多语言](../界面多语言/说明.md)）。禁止只写 kind 名如「执行中：shell」。**口令分流**：后端规划 / 工具回灌 / 落盘 **不脱敏**（`redact_secrets` 透传，避免 ssh 下一行裸口令被抠掉后模型误判缺密码）；**发给 Web / 中继** 强制脱敏（`redact_for_client` / `message_dict_for_client`，见 `channel/redact.py`；规则 `.cursor/rules/rules-web-client-redact.mdc`）。每次 `run` 带独立 `meta.run_id`；**追问续跑须新开步骤流段**；**执行中追加**对话序强制为「前段步骤流 → 用户气泡 → 追加卡 → 追加分析 progress → 后段步骤流」：PWA **仅在追加卡/追问卡**封口前段（用户气泡乐观插入时不封口，避免 LLM 分析期间的 progress 插到气泡与卡之间）；开后段只认 `timeline_segment=new`（裸 `phase=append` 如「已吸收」并入当前后段，不再另开段；进模判定的 `orchestrate` / `plan_build` 同样并入当前段，并与同段 `accepted` 合成一条进度，后到覆盖先到；出图摘要 `plan_graph` 带正文时撤掉该条）；同 `run_id` 可多段。终态**不再**批量重放 `steps`；仍发终态 `card`（供侧栏徽章 / 历史信封）+ 最终助手 `text`（结果类主展示）。**PWA 将任务状态收尾卡**（如 `任务 … → completed`）**并入步骤流末条**（`phase=completed|failed|cancelled|archived`），不另起灰色任务气泡；创建/追加/澄清/复盘等交互卡仍用气泡。观察媒体标题按方式（如「观察（截屏）」），禁止写死「观察截图」。
- **最终助手文本**：优先用收尾轮 `plan.thought`（自然语言结论）；禁止把 shell/`top` 的原始 stdout 无条件当作用户可见回答。短工具确认文案（如写入成功）可作次选回退。问询/硬件盘点类终稿约束见 [完成任务](../完成任务/说明.md) 答复覆盖闸门。
- **Worker 崩溃收口**：`_run_worker_safe` 捕获异常后标记任务 `failed`、写系统日志，并仍发终态 `card` + 助手说明（库打不开等给出可行动提示）；不得只发 `error` 后留下 `running` 孤儿。
- **会话历史落盘**：默认 `{data_dir}/session_history.jsonl`；重启后枢纽加载；`/api/session` 回放近段；按任务完整回放走 `GET /api/tasks/{id}/history`（`SessionHub.history_for_task`）。PWA **打开线程须先拉该任务全量历史再渲染**，避免近段窗口只有末轮 progress 时用合并 goal 合成「原话+追问」假气泡。历史软裁剪（约 2000/1600）优先保留置顶用户及其任务的**多轮**步骤流（按 `run_id` 留头尾；单任务 progress 硬上限约 240），禁止只剩追问后一段、也禁止一个胖任务挤掉其它任务的处理过程。若会话侧 progress 已被裁光但任务库仍有 `meta.steps` / `final_thought`，`history_for_task` **按步骤回放**进度（`channel/task_timeline.py`，信封标 `meta.reconstructed`），避免打开旧任务只看见问题看不见处理；回放同样走前端合并与默认折叠。

## 边界

- 不做个人微信主通道。
- 原始 `audio` / `file` 信封入站仍后置；**语音输入**走网关转写为 text 后再入站（见 [语音输入](../语音输入/说明.md)）。
- 不替代总管做任务编排。
- 不在枢纽内二次调用 LLM 总结；结论依赖大脑收尾 `thought`（工作任务在「success 且刚执行过动作」时会再要一轮空 actions 结论）。
- **不做**把每一次 token 增量写入会话历史（直播用 `meta.live` 只广播；历史仍以阶段完成信封为准）。
- **不做**靠 LLM 从混杂历史猜「这句话属于哪个任务」；归属只认信封显式 `task_id`。线程**内**续跑 vs 另开由路由 LLM/规则判断（与「猜归属」不同）。
- 普通文本**不**隐式用 `_active_task_id` 归类（该字段仅控制口令缺省）。
- **控制口令成功须 `publish`**：暂停/恢复/取消等成功卡必须广播（WebSocket 入站丢弃返回值）；否则侧栏状态徽章停在旧态。失败已 publish `error`。
- **侧栏任务态终态粘性 + 续跑解锁**：已 `cancelled`/`completed`/`failed`/`archived` 后，禁止被迟到的 `progress`（如 `started`/`running`）或滞后的 `/api/tasks` 列表打回「执行中」。**用户显式续跑**须解锁后再同步非终态：追问卡 `mode=continue` / `meta.reopen`、执行中 `mode=append`、`phase=resumed`、从步骤恢复 API。PWA：`resumeUnlockedTasks` + `messageAllowsTaskResume` + `canReplaceTaskStatus(allowResume)`；`ingestMessage` / `renderThreadList`（按时间序遇续跑信号解锁、再入终态上锁）/ `refreshHome` 合并。禁止把任意 `phase=started` 单独当解锁（否则取消后迟到的 started 仍会污染侧栏）。
- **复盘勾选闸优先**：任务 `awaiting_apply` 时，裸「取消」/「cancel」走复盘第二道闸，不走总管 `cancel`；「取消 \<task前缀\>」仍为总管取消。
- **不做**终态一刀切 sibling；失败后换法、同目标补救优先 continue。
- 历史有软上限（约 2000 条，裁剪后保留约 1600）；裁剪时优先整段保留置顶用户所属任务，并限制单任务 progress 体积；非多设备同步账本。
- 任务归属由 PWA **当前打开的任务线程**显式带 `task_id`；见 [会话网关](../会话网关/说明.md)。
