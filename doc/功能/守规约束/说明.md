# 守规约束

## 验收

- 规划前按目标命中 **规则注册表**（最多 5 条）注入；不做全书 / 默认灌 6 个 mdc。
- 改 `fawai_avatar/{brain,control,observe,runtime,workspace,skills,channel,task}/` 等分层路径时，计划须带 `doc_refs`（指向对应功能说明）或非空 `architecture_skip_reason`；漏声明时：**先**对当前计划 `auto_default` / `architecture_skip_reason` 软兜底 → 仍需时再重规划 1 次 → 再兜底；**禁止**仅因漏 `doc_refs` 以「架构校验失败」整任务 `failed` 掐死改写相位。
- **逐步工具调用 / JSON 写**：写分层路径时，系统按 path 自动绑定该层默认 `doc_refs`（原生 tool_calls 与解析后的 JSON 计划同口径）；也可在写工具 args 带 `doc_refs` / `architecture_skip_reason`（提升进 `plan.raw`）。绝对路径若含 `fawai_avatar/` 会截到仓内相对前缀再匹配分层。
- **嵌套 args 展平**：模型若把 `path/old/new` 误包成 `args: "{...}"` 或 `args: {...}`，规划侧在原生 / JSON 入口统一展平到顶层，并补齐 `write_resources`，避免 `requires path` 与架构漏绑。
- 架构校验重规划：本轮禁用原生 tool_calls，强制 JSON；若仍漏声明则再按 path 自动补默认 `doc_refs`；再失败则 `architecture_skip_reason` 软兜底（标记 `architecture_soft_fallback`），禁止仅因漏声明堵死已选对路径的写尝试。
- 编码/进化类任务：若 `write_set` 触及分层路径却从未声明文档/跳过理由，success 前强制补声明（同 `code_check` 闸门形态）。
- 用例见 `demo_compliance`（默认 mock）。

## 边界

- 不承诺软规则 100% 被模型遵守；`hard` 与架构门才硬拦。
- 不替代路径禁改 / 租约 / 能力清单（与之叠加）。
- 不做 C3；不做静态 import 禁令（P2 开放项）。
- AGENTS 短摘要仍可作软补充（`coding_context`）；主约束以注册表为准。
- 原生自动绑定只填该层「第一个」推荐说明；若需点名其它说明，仍可在 args 显式传 `doc_refs`。

## P0 默认（放行钉死）

| 项 | 默认 |
|:---|:---|
| 注册表存放 | 代码常量 `brain/compliance.py` |
| 跳过字段 | `architecture_skip_reason`（plan.raw） |
| 文档声明 | `doc_refs`：字符串列表（plan.raw） |
| 分层写自动绑 | `ensure_architecture_decls(..., auto_default=True)`（原生 + JSON 解析后） |
| 切片 | S1+S2+S3 同一切片交付 |
| hard 与 C2 | 共用 `validate_plan` 重规划 1 次配额 |
| 规则命中 | 任意目标可命中注入；架构硬门绑分层写路径 |
