# 执行中澄清

## 验收

- 默认尽最大努力；仅当猜错代价高（不可逆写/删、提交、外发、花钱、互斥路线）时大脑可 `status=need_input`。
- 有明确互斥选项时 Plan 须带 `options`（≥2），会话以选择题呈现；用户回编号/标签/短 id。
- Worker 出澄清 `card`，任务 `waiting` + `meta.clarification.phase=awaiting_input`，检查点保留；不 fail / 不 complete。
- 同线程回复视为答案（不走 `route_followup` 拆任务）→ 注入 goal/history → 清 awaiting → 续跑。
- 进程恢复：**跳过** `awaiting_input`（及复盘 waiting），不自动拉 Worker。

## 边界

- 不做「凡歧义就问」；低风险缺省可合理假设继续。
- **Web 远程**：用户表示不在电脑边时，禁止用 options 要求「粘贴配置 / 拷进工作区」；应 `fs_read` 只读根或 `failed` 并给出可复制命令。澄清/追问原文命中远程不在场时，history 自动追加 `【远程操作约束】`（`method_recovery.format_remote_away_veto`）；`need_input` 若问句在要粘贴，会剥掉粘贴类 options。
- PWA 澄清卡内可点选项按钮（不在输入栏上方 sticky 重复；仍可用编号/标签打字）。
- **计划节点**：澄清选项挂在对应节点内作操作标签；父计划仍 `running` 时，同线程回复/点选项仍路由到等待中的监管脑子任务。
- 进程恢复**跳过** `awaiting_input`，禁止反复拉起导致澄清卡/提示叠多层。
- 不做多轮问卷引擎。
- 与复盘 `awaiting_approval` / `awaiting_apply` 字段隔离。
