# 进程中断续跑

## 验收

- 网关/保活重启后：原 `running` / `waiting` / `blocked` 任务自动拉起 Worker，**从检查点继续**（有 `meta.run_checkpoint` 时不从 step0 空 history 重跑）。
- `pending` 启动后自动首次执行。
- `paused` 不自动拉起；用户 `resume` 后：无活线程则补拉并续跑；同进程暂停等待中则只改状态。
- **执行中澄清** / 复盘 `waiting`（`awaiting_input` / `awaiting_approval|apply`）不自动拉起，须用户回复后再跑（见 [执行中澄清](../执行中澄清/说明.md)）。
- 任务正常结束（完成/失败/取消）后检查点清除。
- 同一 `task_id` 不得并发两份 Worker。
- **从步骤恢复**：非 `running` / 非 `archived` 任务可指定闭环步号 `step` 写入检查点并拉起 Worker（`POST /api/tasks/{id}/resume-from-step`）。PWA 步骤卡悬停（桌面）或常显（窄屏）出「从此恢复」。优先截断已有 `run_checkpoint`；终态无检查点时用 `meta.steps` 粗合成 history。**计划模式**节点步骤流绑监管脑子任务 id（非编排器父 id）；恢复时复用该子任务，图节点标回 `running` 并重开终态父计划（见 [复杂任务计划模式](../复杂任务计划模式/说明.md)）。
- **删除此步（挖上下文）≠ 从此恢复**：`excise_step_from_context` / `POST …/excise-step` 从 traces / history / `meta.steps` **挖掉指定步**，保留前后步骤；**不**拉 Worker。从此恢复则是**丢掉该步及之后**再续跑。二者入口并列在步骤卡/簇上。

## 边界

- 死在单步 LLM/shell 中途：最多从该步检查点重进一轮观察/规划，不保证半步精确回放。
- 检查点字段有长度截断，极端长 history 可能被裁。
- 从步骤恢复：`meta.steps` 仅尾部裁剪，步号很大时先验可能不完整；执行中须先停止再恢复。
- 挖步：执行中须先停止；`archived` 拒绝；删的是闭环步（簇头=整簇），不是工具子行。
