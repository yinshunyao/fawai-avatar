# 多屏与全屏观察

## 状态

**已支持**（单屏回归 + displays 自检；真机双屏 / 全屏 Space 待核）。原则真源：[议题/多屏与全屏观察](../../议题/多屏与全屏观察/结论.md#已定结论)。

## 验收

- 有桌面时，观察 `meta` 注入结构化 **`displays`**（`index` / `bounds` / `is_main`；可选 `id`、`scale`）；headless 无此字段且候选剔除 `obs_screen`。
- `obs_screen` 须带 **`screen_target`**（挂在 `observe_args.obs_screen`）：

  | 值 | 含义 |
  |:---|:---|
  | `main` | 主显示器 |
  | `index:<n>` | 指定 `displays` 序号 |
  | `all` | 虚拟全桌面一张图（仅显式总览） |
  | `frontmost` | 前台窗口所在显示器 |

- **默认**：未指定时用 **`frontmost`**；单屏时等价 `main`。
- 截图 meta 带 **`origin_x` / `origin_y`**、PNG/`capture` 宽高与可选 **`coord_scale_*`**（Retina 像素≠逻辑尺寸时）；模型出**图内坐标**，控制层按 scale 压到逻辑坐标再加 origin（`coord_space=global` 可绕过）；越界/荒谬点拒绝执行。
- 跨屏搜索由**大脑**选型（换 `screen_target` / `app_focus` / `hotkey`）；禁止 loop/控制层自动扫完全部屏或 Space。
- 控制能力 **`app_focus`**：按束名/App 名激活；macOS 主路径；Linux 有桌面尽力；失败硬摘要。
- 编码/文件类目标仍优先 `obs_fs`，不得因多屏支持而每步默截所有屏。

## 边界

- 不做：自动轮询全部显示器/Space 拼长视频；关键词「含 Chrome 就切第二屏」路由；本切片不做 OCR/AX 像素级控件定位。
- Windows：多屏弱支持（尽力 mss，meta 标 `windows_multiscreen_unsupported`）。
- Linux 有 DISPLAY：实现 `displays` + `screen_target`；Workspace/全屏标弱支持。
- 人机闸门：屏幕录制须覆盖外接屏；`app_focus`/hotkey 需辅助功能已授权。
