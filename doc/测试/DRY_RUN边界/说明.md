# DRY_RUN 边界

## 目标

确认 `FAWAI_DRY_RUN` **只**抑制 GUI/shell 真副作用；`fs_*` / `version_*` 仍实写。避免「开了干跑以为安全却改了文件」或「以为文件工具也被干跑挡住」两类误解。

## 前置

- 可写的临时 work_root。
- 两次对照：`FAWAI_DRY_RUN=1` 与 unset/`0`。

## 步骤

1. `export FAWAI_DRY_RUN=1`。
2. 经控制层执行一次前台类动作（click/type）或 shell → 应记录为干跑/不真执行（与现实现一致）。
3. 同一进程执行 `fs_write` 写 `dry_run_probe.txt` → 磁盘上**应有**该文件。
4. `version_snapshot` / 再写触发自动快照 → 版本库应有记录。
5. 关闭 dry_run，再确认 GUI 路径在授权环境下可真执行（可选，人机闸门）。

## 期望

- 文档与行为一致：干跑 ≠ 只读模式。
- 后台工具结果 `ok` 且文件内容可 `fs_read` 回证。
- 无 lease 时前台动作仍应被租约拒绝（dry_run 不能绕过租约）。

## 失败征兆

| 现象 | 优先怀疑 |
|:---|:---|
| dry_run 下 fs 不写 | 错误地把后台工具纳入 dry_run |
| dry_run 下仍真点击 | dry_run 未接入 GUI 路径 |
| dry_run 绕过 lease | 闸门顺序错误（先执行后校验） |
