# LLM 文本与多模态路由

## 目标

确认 API 密钥与路由：纯文本走文本模型；带图像走多模态模型。换模型或改 `.env` 后必测。

## 前置

- 复制 `.env.example` → `.env`，填好 `FAWAI_LLM_API_KEY` 与 `FAWAI_LLM_BASE_URL`。
- 默认：文本 `qwen3.7-plus`；多模态 `qwen3-vl-plus`（可用环境变量覆盖）。

## 步骤

1. 纯文本：`.venv/bin/python -m fawai_avatar.llm.client`（按模块自带试跑）。
2. 核对日志或返回：选用的是文本模型（或 `FAWAI_LLM_MODEL` 强制覆盖值）。
3. 构造一条含图像 content / `image_url` 的 chat（可用临时小图）；再调一次。
4. 核对本次选用多模态模型。

## 期望

- 无图：路由到文本模型；有有效回复或可解析错误码（非本地空 key）。
- 有图：路由到 VLM；密钥无效时应有明确 API 错误，而非静默空响应。
- 不因路由逻辑把纯文本误打到 VLM（除非强制覆盖）。

## 失败征兆

| 现象 | 优先怀疑 |
|:---|:---|
| `has_key: false` | `.env` 未加载或变量名写错 |
| 有图仍走文本模型 | `router.py` 未识别 image 形态 |
| 401 / 无效模型名 | base URL、模型 ID 与厂商控制台不一致 |
| 超时无体 | 网络或 DashScope 区域/代理 |
