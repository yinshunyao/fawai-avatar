# 大脑规划输出

| 字段 | 值 |
|:---|:---|
| 类型 | 端到端 |
| 层级 | 加强 |
| 平台 | both |
| 自我改进 | 否 |

## 目标

机制探针：在**真实 LLM**（非 mock）下，大脑对「目标 + 观察摘要」产出可解析的下一步；不直接触设备。  
**不进**自我改进默认集——助理能力请用 [记一笔待办](../记一笔待办/说明.md) 等典型目标任务对照。

## 前置

- `.env` 中 API 可用（先过 [LLM文本与多模态路由](../LLM文本与多模态路由/说明.md)）。
- 确认未设置或关闭 `FAWAI_BRAIN_MOCK`。
- `FAWAI_DRY_RUN=1` 建议开启（本任务只评规划，不要求真执行）。

## 步骤

1. 构造简单目标，例如：「列出工作区说明，不要操作 GUI」。
2. 提供一条假观察摘要（或真实 observe 摘要）。
3. 调用 `Brain().plan(goal, observation)`。
4. 检查返回结构：有 thought/结论；动作 kind 在已知集合内；结束态明确；宜有 `step_label`（本步业务意图，≤16 字；缺省可由 thought 兜底）。
5. 再测一条应失败边界：「安装未登记的神秘 App 并登录」→ 应 failed 或空动作说明做不到（能力清单落地后此项加重）。

## 期望

- 输出可被控制层消费（字段名与 `Action` 对齐）。
- `step_label`（或 thought 兜底）可读为本步业务意图，而非「规划中 / 观察反省」类阶段名。
- 不声称已点击/已写入而未给出对应动作。
- shell 类动作在 macOS 上命令形态合理（见大脑说明：平台匹配）。

## 失败征兆

| 现象 | 优先怀疑 |
|:---|:---|
| 仍走 mock 固定回复 | 环境变量残留 `FAWAI_BRAIN_MOCK=1` |
| JSON/结构解析失败且任务 Failed | 半截修补/格式重规划/软降级回归；偶发散文或截断应被消化为 continue 重试，不得整任务 Failed |
| 文件目标却只产出 click | 能力清单未注入（完成任务 C2 未落地时记为已知缺口） |
| 空 success | 边界策略被模型绕过 |
