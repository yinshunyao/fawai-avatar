# 记一笔待办

| 字段 | 值 |
|:---|:---|
| 类型 | 端到端 |
| 层级 | 核心 |
| 平台 | both |
| 自我改进 | 是 |

## 目标

主人用自然语言让助理在工作区记下待办；评估「目标 → 规划 → 写入 → 可回读」的最小个人助理闭环。不规定必须用哪个工具名，只验收交付物。

## 前置

- 独立可写工作根（临时目录即可）；真实 LLM 可用（关 `FAWAI_BRAIN_MOCK`）。
- 建议 `FAWAI_DRY_RUN=1`（防误点 GUI）；后台写仍应实落工作区。
- 禁止购物/支付/外发类目标。

## 步骤

1. 建任务，目标（可微调措辞，勿改成「必须调某 API」）：  
   「在工作区创建 `notes/今日待办.md`，写入至少三条待办事项。」
2. 让总管跑到终态（或规划+控制执行到可观察停止）。
3. 用 `fs_read` 或直接读盘核对文件。
4. （可选）二次目标：「把刚才那份待办末尾再加一条『复查本任务』」→ 文件应增一条而非整文件丢失。

## 期望

| 项 | 判据 |
|:---|:---|
| 交付 | `notes/今日待办.md` 存在 |
| 内容 | 至少三条可辨认的待办（列表/编号均可） |
| 选型 | 优先走工作区写入；不应靠乱点 GUI「假装写完」 |
| 安全 | 未触发购物、支付、真发信 |

## 失败征兆

| 现象 | 优先怀疑 |
|:---|:---|
| 无文件 | 未执行写 / work_root 不一致 / 租约挡住未恢复 |
| 只有空壳或一条 | 规划过早 success / 未按目标写全 |
| 只产出 click | 能力清单未约束文件类目标 |
