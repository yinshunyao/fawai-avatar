# 设备租约冲突

| 字段 | 值 |
|:---|:---|
| 类型 | 系统 |

## 目标

专门压测总管闸门：前台 lease 全局唯一；同一路径写写冲突串行/拒绝。避免并发任务互相抢焦点或写坏文件。

## 前置

- 可用 `demo_smoke` 内嵌断言，或用临时 `data_dir` 调 `Supervisor`。
- 不需要 GUI / LLM。

## 步骤

1. 创建任务 A、B，均 `set_running`。
2. A `claim_foreground` 成功；B 再 claim → 应失败，B 状态为 `blocked`（或等价不可用前台）。
3. A `release_foreground` 后，B 应能再次 running 并 claim。
4. 准备同一文件路径：A 以 write 申报 `claim_resources` 成功；B 再以 write 申报同一路径 → 应失败。
5. （可选）A 持 write、B 以 read 申报 → v1 允许并行则应成功。

## 期望

- 任意时刻至多一个前台持有者。
- 写写冲突：后到者被拒或排队策略与文档一致（v1：拒绝/串行化，不得双写同时持锁）。
- 释放后可再次获取。

## 失败征兆

| 现象 | 优先怀疑 |
|:---|:---|
| 两任务同时持有前台 | 租约未全局互斥 |
| 写写都成功 | 资源清单比较/规范化路径不一致（相对 vs 绝对） |
| 释放后仍 blocked 且无法恢复 | 状态机未清 blocked |
| 读被误拒 | 冲突策略从「写读可并行」回退错误 |
