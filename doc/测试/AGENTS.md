# `doc/测试` — 版本评估与找问题的测试任务

## 目录用途

维护**可复跑**的测试任务：发版前冒烟、对比版本回归、暴露边界与权限问题。  
本目录只放**可读任务说明**；自动化脚本与用例代码放在 `doc/` 以外（如 `fawai_avatar/demo_*.py`、后续 `tests/`）。

## 文档范围

| 允许 | 禁止 |
|:---|:---|
| 根目录唯一总表 `【总表】测试任务一览.md` | 第二份总览；与功能/议题总表混成一张 |
| `{短名}/说明.md`：前置、步骤、期望、失败征兆 | 可运行业务代码、密钥、口令明文 |
| 关联已支持功能与现成 demo 入口 | 把未放行功能当必测交付项 |
| 标注「人机闸门」（权限弹窗、真机同网） | 把讨论中的想法写成已自动化通过 |

## 目录结构

```text
doc/测试/
  AGENTS.md
  【总表】测试任务一览.md
  {短名}/
    说明.md
```

- 新任务：总表加一行，并建 `{短名}/说明.md`。
- 根目录除 `AGENTS.md` 与总表外，不放其它散文件。

## 总表列约定（强制）

| 列 | 含义 |
|:---|:---|
| **任务** | 短名；链到 `{短名}/说明.md` |
| **目的** | 评估版本 / 找哪类问题 |
| **层级** | `冒烟` / `回归` / `边界` / `端到端` |
| **关联功能** | 链到 `doc/功能/` 条目 |
| **自动化** | 现成入口（模块路径）或「手测」 |

## 单任务说明结构（强制）

每个 `{短名}/说明.md` 至少含：

1. **目标** — 本任务要证明或否证什么  
2. **前置** — 环境、环境变量、权限、是否 `FAWAI_DRY_RUN`  
3. **步骤** — 可照做的编号步骤  
4. **期望** — 通过判据（可观察输出 / 文件态 / 拒绝行为）  
5. **失败征兆** — 常见坏信号与优先怀疑点  
6. **关联** — 功能说明、demo/入口

## 使用约定

- **发版 / 换模型 / 改闸门**：至少跑总表中标为 `冒烟` 的任务。  
- **改某一功能**：跑该功能关联的 `回归` + 相关 `边界`。  
- **找未知问题**：优先 `端到端` 与带人机闸门的任务（网关、真截屏）。  
- **评测结果**（得分、总分、档位）写入 `doc/版本/{版本号}/评测结果.md`，并更新版本总表；**不要**在本目录堆日期变更日志或打分表。

## 协作约定

| 相邻 | 边界 |
|:---|:---|
| `doc/功能/` | 任务覆盖「已支持」为主；未放行能力可标「前瞻」但不挡冒烟 |
| `doc/议题/` | 验收用例可引用议题结论编号；放行仍看功能表 |
| `doc/版本/` | 跑完任务后的打分与总分落版本目录 |
| 代码 / demo | 说明里写调用入口；改入口同回合改「自动化」列 |

编辑本目录前先读本文件与 `doc/AGENTS.md`。
