# `doc/测试` — 冒烟 / 系统 / 端到端任务说明

## 目录用途

维护**可复跑**的测试任务说明，按三类物理分目录：

| 类型 | 回答什么 | 典型形态 | 大模型 | 用途 |
|:---|:---|:---|:---|:---|
| **冒烟** | 必要功能最小集是否还能跑通 | 短 demo / 断言；可 mock | **禁止依赖真实 LLM**（允许 mock） | 改代码后的快速回归 |
| **系统** | 机制与闸门是否按契约全覆盖 | 专项断言 / 手测对照；无「主人自然语言目标」 | **同上，无真实 LLM** | 发版前 / 大改后的整体功能验证 |
| **端到端** | 产品能否在真实链路上完成**典型个人助理目标**并衡量智能体能力 | 主人自然语言目标 → 规划/工具 → 可观察交付物（即原「基准」对照尺） | **真实全系统**（真实 LLM / 真实链路） | 自我改进、升版前后、换模型对照 |

本目录只放**可读任务说明**；自动化脚本与用例代码放在 `doc/` 以外（如 `fawai_avatar/demo_*.py`、后续 `tests/`）。

冒烟 + 系统合称「无模型功能验证」，用于版本功能是否可用；不以「智能体是否聪明」打分。  
端到端里：`自我改进=是` 的**核心**任务须是限制较少的助理向目标（记待办、整理、摘要、本地查询、起草不外发等）；工程套件 / 路由 / 网关 / 复盘等机制探针标 `自我改进=否`（多为加强），不挡默认能力对照。

### 端到端目标边界（强制）

| 鼓励 | 禁止纳入默认自我改进集 |
|:---|:---|
| 工作区内可回读的交付（笔记、清单、草稿、摘要） | 购物、下单、支付、充值、票务付款 |
| 明确「不要外发」的草稿类任务 | 真发邮件 / IM / 发帖 |
| 对照真实目录的查找与如实「未找到」 | 网银、转账、加密货币操作 |
| 沙箱内整理 / 归档 | 不可逆清盘、改系统偏好到难以复原 |

## 文档范围

| 允许 | 禁止 |
|:---|:---|
| 根目录唯一总表 `【总表】测试任务一览.md` | 第二份总览；与功能/议题总表混成一张 |
| `{类型}/{短名}/说明.md`：文首类型表 + 前置、步骤、期望、失败征兆 | 可运行业务代码、密钥、口令明文 |
| 关联已支持功能与现成 demo 入口 | 把未放行功能当必测交付项 |
| 端到端标注「人机闸门」（权限弹窗、真机同网）为加强项 | 把讨论中的想法写成已自动化通过 |
| 端到端任务标平台与是否进自我改进默认集 | 用真机同网/不可复现闸门当端到端默认通过硬条件 |
| 冒烟/系统任务写明可在无真实 LLM 下通过 | 把必须真实 LLM 的任务放进冒烟或系统 |

## 目录结构

```text
doc/测试/
  AGENTS.md
  【总表】测试任务一览.md
  冒烟/{短名}/说明.md
  系统/{短名}/说明.md
  端到端/{短名}/说明.md
```

- 任务目录**按类型物理拆分**；类型与路径一致，并写在总表与说明文首。
- 新任务：总表对应节加一行，并建 `{类型}/{短名}/说明.md`。
- 根目录除 `AGENTS.md` 与总表外，不放其它散文件。

## 总表列约定（强制）

总表分 **冒烟** / **系统** / **端到端** 三节。

### 冒烟、系统共有列

| 列 | 含义 |
|:---|:---|
| **任务** | 短名；链到 `{类型}/{短名}/说明.md` |
| **目的** | 评估版本 / 找哪类问题 |
| **关联功能** | 链到 `doc/功能/` 条目（或版本量表） |
| **自动化** | 现成入口（模块路径）或「手测」 |

### 仅端到端节

| 列 | 含义 |
|:---|:---|
| **层级** | `核心` / `加强` |
| **平台** | `both` / `macOS` / `Linux` — 本机可完成的默认范围 |
| **自我改进** | `是` / `否` — 是否进默认改进对照集 |

## 单任务说明结构（强制）

每个 `{类型}/{短名}/说明.md` 文首须有短表，再写正文：

**冒烟 / 系统**文首至少：`类型`（冒烟|系统）。  
**端到端**文首至少：`类型`（端到端）、`层级`（核心/加强）、`平台`、`自我改进`（是/否）。

正文至少含：

1. **目标** — 本任务要证明或否证什么  
2. **前置** — 环境、环境变量、权限、是否 `FAWAI_DRY_RUN`；冒烟/系统须可无真实 LLM  
3. **步骤** — 可照做的编号步骤  
4. **期望** — 通过判据（可观察输出 / 文件态 / 拒绝行为）  
5. **失败征兆** — 常见坏信号与优先怀疑点  
6. **关联** — 功能说明、demo/入口

## 使用约定

- **改代码后**：至少跑总表**冒烟**节。  
- **发版 / 大改机制**：冒烟 + **系统**节（改到的闸门优先）。  
- **自我改进 / 升版前后对照 / 换模型比能力**：跑总表**端到端**节中 `自我改进=是` 的核心助理任务；`加强` 与 `自我改进=否`（含优先改进评测套件）不挡默认对照通过。  
- **找未知问题**：优先助理核心集，再视需要加加强项（网关真机同网、工程套件、真截屏）。  
- **评分**：冒烟与系统不以「智能体是否聪明」打分；**自我改进=是** 的端到端结果才作为版本 D 维与进步对照的主证据线。  
- **评测结果**（得分、总分、档位）写入 `doc/版本/{版本号}/评测结果.md`，并更新版本总表；**不要**在本目录堆日期变更日志或打分表。

## 协作约定

| 相邻 | 边界 |
|:---|:---|
| `doc/功能/` | 任务覆盖「已支持」为主；未放行能力可标「前瞻」但不挡冒烟 |
| `doc/议题/` | 验收用例可引用议题结论编号；放行仍看功能表 |
| `doc/版本/` | 跑完任务后的打分与总分落版本目录；最低任务集见评分量表 |
| 代码 / demo | 说明里写调用入口；改入口同回合改「自动化」列 |

编辑本目录前先读本文件与 `doc/AGENTS.md`。
