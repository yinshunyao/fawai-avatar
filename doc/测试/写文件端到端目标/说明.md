# 写文件端到端目标

## 目标

用「主人目标 →（规划）→ 后台写入 → 回读校验」评估版本是否具备最小可交付闭环。能力清单（C2）落地后，本任务升级为强制：必须选 `fs_*` 而非 GUI。

## 前置

- 工作根可写；建议独立临时目录。
- `FAWAI_DRY_RUN=1`（防止误点 GUI）。
- LLM 可用；或暂时用 `BackgroundTools` 手工串动作当半自动基线。

## 步骤

1. **基线（无大脑）**：用 `BackgroundTools` 写入 `notes/e2e_hello.txt` 内容 `hello`，再 `fs_read` 确认。
2. **带大脑（有 key）**：目标设为「在工作区写入 `notes/e2e_hello.txt`，内容 hello」。观察摘要可写明工作根。
3. 执行规划出的动作（经控制层）；禁止手改文件冒充成功。
4. 回读文件，内容须含 `hello`。
5. （可选）误导目标：「用鼠标在桌面画圈来写这个文件」→ 仍应走 `fs_*` 或明确 failed（C2 验收 C）。
6. （可选）两任务同时写同一路径 → 一方获批、另一方 blocked（对照租约）。

## 期望

| 阶段 | 期望 |
|:---|:---|
| 当前（C2 未放行） | 后台工具链与控制转发可靠；大脑若乱点 GUI，记为已知短板而非本任务失败 |
| C2 已支持后 | 动作为 `fs_write`（或等价后台链）；结论可回读；误导目标不假点击成功 |

## 失败征兆

| 现象 | 优先怀疑 |
|:---|:---|
| 文件未出现 | 动作未执行 / work_root 不一致 / 租约拒绝未处理 |
| 大脑只产出 click | 能力清单未注入（见完成任务议题） |
| 回读内容不对 | 路径写错或编码问题 |
| 网关路径无任务 | Hub 未把入站接到总管 |
